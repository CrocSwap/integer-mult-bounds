## 1. Frozen construction and general weighted recursion

At level d, start with the inherited ordered groups of size one or two. The chosen vector requests first/middle pair splits: h23 `[4,4,4]`, h25 `[4,4,1]`, where 1 requests the first group and 4 requests first then middle. Requested indices are deduplicated, valid, and must contain two points. Before admitting the kth split require `number_of_groups + admitted_splits + 1 < number_of_points`. Apply admitted splits in decreasing index order so earlier indices keep their meaning. Each split replaces one pair by its two ordered singletons; the point partition and ordering are unchanged.

The admission guard proves that the final number of groups is strictly less than the number of points, even for multiple requested splits and overlapping first/middle indices. Splits are disabled for n≤3; n=3 has two coarse groups and n≤2 uses the direct base case. Thus every recursive call strictly contracts, for every input size allowed by the grouping interface.

Coarse vertex weights contain the original vertex weights in that group and its internal edges. Each coarse edge contains exactly the Cartesian-product edges between its two groups. These sets partition the original weighted total. Recursive total and single/pair exclusions therefore have the required support by induction on size. Row and column coarse parenthesizations partition the same Cartesian product into disjoint sets, so changing between them preserves every identity. The half-plane rule uses fixed indices only. The generic singleton/pair assembly and interval-strip identities are inherited; tests independently check weighted exclusions at each recursive call.

At common coordinate c, choose the smallest intact fixed global pair disjoint from c and move it to the front of the inherited alternating order, preserving all other relative positions. This is a permutation of precisely the other coordinates and preserves scalar exclusions. Dense graph verification checks the full triple-input map and all disjoint additions in both selected dimensions.

## 2. PR74 node order, synthesis, and completion

Group active computed nodes by exact `(core,cover)` frame. Every scalar edge u→v has `core(v)⊆core(u)` and `cover(u)⊆cover(v)`. If the two envelopes differ, `|cover(v)|−|core(v)|` strictly exceeds `|cover(u)|−|core(u)|`: at least one set containment is strict. Thus rank-first group order is topological between distinct envelopes. Original node order is retained inside every group. h23 uses `(rank,-cover,-core,min_node)`; h25 retains PR74's `(rank,-core,cover,min_node)`. Input IDs stay fixed. The compiler then recomputes signals, region order and carrier eligibility from the renamed graph. No PR65 schedule wrapper is applied.

The output rows and selected carriers form an independent prefix. Scan every standard input unit vector in future-use priority order and retain it only if independent. Every rejected unit is already in the current span and remains there; after the scan every standard unit is in the span. The final rows therefore form a full basis and keep the chosen prefix. Gaussian elimination and its reversed literal XOR synthesis implement an invertible transformation on arbitrary inputs and dirty roles. Future-use priority depends only on fixed graph incidence, symbolic signal supports and indices. It never examines runtime input data.

Retired roles are reclaimed only by a valid literal clearing expression in an eligible signal span. Pending live controls have current frame F and assigned future frame G. ## 3. Exact retired and pending indexes

For frames `(core,cover)`, containment F⊆E means `core(E)⊆core(F)` and `cover(F)⊆cover(E)`. The retired index intersects active-role core bitmaps for each coordinate in core(E), and removes roles whose cover includes any coordinate outside cover(E). This selects exactly the eligible roles. Rank bitmaps partition that set; descending rank and ascending set-bit order exactly reproduce the original `(-rank,slot)` enumeration.

The pending index first enforces F⊆E using the same lower-frame index. It then removes target cores containing coordinates outside core(E) and intersects target-cover bitmaps for coordinates in cover(E). The result is precisely F⊆E⊆G. Each insertion receives a serial; removal deletes it; frame moves keep it. Sorting eligible roles by serial reproduces pending dictionary insertion order, including removal/reinsertion of reused slots.

Insertion, reclamation and incoming-use removal update both representations. Every frame raise updates a retired role's old/new rank/frame index, or a pending control's lower frame without changing serial order. Retired and pending lifecycles remain disjoint. Actual-source exhaustive and randomized audits compare ordered queries with the direct predicates and exercise actual frame-raise functions, not copies of those functions. These indexes preserve compiler semantics; no measured speedup is claimed.

## 4. Carry exchanges, two-cycles, and output routing

Candidate edges remain subject to inherited temporal/frame eligibility. A single exchange removes the selected owner of an occupied future use, or drops a carrier from the receiving region for an unoccupied future use. The full output/carrier basis of the receiving region is checked after the removal. A distinct donor region only loses a row, preserving independence. Thus cardinality, linear independence and unique future-use ownership remain valid. Each accepted exchange decreases a fixed integer score; at most three deterministic passes execute.

A two-cycle swaps carriers between distinct regions and distinct already-owned future uses. For new edge e and its complementary edge other, `carry_can(e,z)` checks the receiving region after removing z and `carry_can(other,f)` checks the other region after removing f. Because the regions differ, these tests describe exactly the final two bases. Remove both old edges before inserting either new edge; the two freed future uses are distinct, so unique ownership and global cardinality are preserved. Both regions lose and gain one carrier. The `(region,use)` lookup is checked for uniqueness. Accept only a strictly positive decrease of the sum of the two fixed integer scores; execute at most three passes. The source audit instruments every accepted exchange in 1,204 cases, including adverse linear dependence, equal-price, missing-complement and duplicate-key cases. This is a bounded legal heuristic, not an optimality proof.

Three-donor exchanges generalize the two-cycle argument to three distinct regions. Each region loses one selected vector and gains a candidate checked by `carry_can` against its full final output/carrier basis. The three distinct already-owned use IDs are cyclically reassigned, so their set and global cardinality stay fixed. All three old edges are removed before any new edge is inserted. Distinct-region and distinct-edge assertions prevent overlapping local replacements. Acceptance requires a strict decrease of the sum of fixed integer prices; deterministic candidate keys choose the best available cycle for that step. h23 uses zero passes; h25 uses at most three, with two accepted cycles in this frozen witness. The actual-source audit covers 1,604 cases, including a strict three-cycle with no legal single/two-cycle alternative, equal/worsening costs, dependent replacements and randomized independent bases. This establishes legality, not global cost optimality.

For h25, outgoing non-carrier uses are visited by descending fixed future-region deadline, with original use ID as tie-breaker. Terminal uses keep the explicit terminal deadline. This permutes a fixed list of uses; each is still assigned exactly once to a physical role. It may affect later reclamation choices, but changes no scalar target or candidate legality. h23 retains baseline output order. Both final physical words are independently regenerated and checked, including every charged allocation, XOR, raise and copy.
