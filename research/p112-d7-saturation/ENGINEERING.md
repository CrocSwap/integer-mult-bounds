## Power of Ten assessment

Production control flow is structured and nonrecursive. New functions are
below sixty physical lines. Fixed domains bound every loop: eight coordinates,
120 root lines, 512 binary forms, 3,309,747 five-flats, 240 relevant frames,
42 frame-orbit generators, 756 saturated live supports and eleven pieces.
The frame search has an enforced 100,000-node cap and 10,000-entry stack cap.
Orbit queues have capacity 240; retained flat sets have capacity 5,040.
The independent packing oracle has a 50,000-node cap and checks exhaustion.
The full census, success witnesses and exhaustion/failure controls are in
the registered replay and tests.

External reads require regular, unlinked files below two million bytes.
Exact input and retained-source hashes are checked, then the reconstructed
labels and root order are compared to the live input. Mathematical `require`
guards remain active under optimization. New receipt output uses exclusive
creation outside the checkout. Context managers close owned files, and
subprocess errors propagate with 120-second limits. Production uses explicit
local state and direct calls; it has no network or shared writes.

Rule 3 deviation, managed allocation. Python integers, fractions and containers
allocate during replay. Fixed domains and enforced capacities bound live
collections; the flat census streams into 121 bins and at most 5,040 retained
masks. The graph contains at most 756 bounded integer adjacency rows.
The complete census and source-failure controls verify these limits. Enlarging
the parameter domain requires a new resource assessment.

Rules 8 and 9 deviation, test dispatch. `unittest` discovers the fourteen
methods in the one registered module. Its bounded dispatch supplies failure
reporting under optimization. Test-only temporary copying is limited to the
five-file vendor directory; all files close and temporary directories are
removed by context managers. A plugin or broader discovery path would require
a new lifecycle assessment.

Retained geometry and the original filter are copied byte-for-byte. They
contain managed arithmetic and fixed-domain library iteration inherited from
the credited sources; this package neither broadens nor edits them. Rule 10
diagnostics use warnings-as-errors execution and compilation, plus strict Ruff
rules for new Python. Source-preserving code is not reformatted. The generic
package runner supplies a fresh bytecode-cache namespace. Direct standalone
replays have Python's usual preexisting-bytecode limits.

## Decision trail

1. Inventoried both worktrees and all tracked, untracked and ignored files.
   No other process owned the worker. Created a fresh branch from fetched
   canonical main, preserving the previous branch and commits.
2. Read revision-six guidance, selected-source pointers, live handoffs and
   paginated open-PR/discussion overlap. The card's positive-control ceiling
   command passed. Chose a changed scope on one explicit C5 handoff.
3. Frame-only support refinements did not close the proposed next case.
   Rejected a `3,3,6^(b+2)` application because earlier deletion bounds
   already cover its support-only certificate. No novelty is claimed there.
4. The actual `2,4,5^9` profile passes the strict original weight filters.
   A common two-dimensional support bound of 76 admits quotient selection
   at support 34. A D7 edge then forces a saturated support partition.
5. The complete five-flat inventory gives a sharp packing maximum of three.
   A read-only review identified the need for the full120 capacity, rather
   than only a punctured capacity; the complete census checks that gate.
   A separate accumulated-union oracle corroborates the graph calculation.
6. Exact sources, proof, complete receipt and controls are preserved here.
   Disposable probes, exports and logs are removed after publication.
   Scope remains this profile and packing lemma; the frontier stays fixed.
