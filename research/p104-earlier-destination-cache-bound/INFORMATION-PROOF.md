# Information obstruction and main-only separator extension

## Exact statements and scope

The original proof establishes rational nonmembership in the cumulative
strictly earlier destination history at all 47 owned cuts and 18 additional
public cuts with live-source witnesses. This extension makes two implications
explicit. First, those nonmembership results exclude arbitrary deterministic
postprocessing of the stated history, not only scalar linear cache programs.
Second, at **33 of the 47 owned cuts**, an explicit separator supported solely
on the 400 main inputs makes the obstruction persist under every nonempty
restriction on helper inputs that is independent of the arbitrary mains.

The native history, source operations and whole-field frame interpretation are
fixed. A cache may use any number of private fields and any fixed computation,
but its only input-dependent information must come from the tested earlier
destination-coframe observations. Additional input reads, transported stock,
other charts, input-dependent metadata, changed native histories and main-dependent
helper preparation are outside the claim. No new kappa is asserted.

## From rational nonmembership to indistinguishable histories

Let A be the rational matrix of all earlier destination-coframe latent rows,
and let c be the latent row the omitted MOVE must deliver. Nonmembership
`c not in rowspan_Q(A)` supplies a rational vector t with `A t=0` and
`c t != 0`. Clearing its denominators gives an integer t with the same
properties. Every native input denotes an arbitrary complete array. Set the
difference between two input assignments to `Delta X_h=t_h z`, where z is any
nonzero permitted complete array.

The difference in every observation is zero. The destination coframe is the
same at each observation, so applying its full invertible frame operator
preserves this zero difference, including absolute phase and spectators. The
required target difference is the same invertible operator applied to
`(c t) z`, which is nonzero. A deterministic function receiving identical
ordered observations and fixed program metadata returns identical results;
it cannot produce both different targets. This allows arbitrary nonlinear
or operator-valued processing and arbitrary internal storage. It does not
grant extra observations outside the stated information interface.

The algebraic assertion holds on the full rational or complex input-array
space. On a prescribed exact digital grid it requires two legal assignments
with the indicated difference and representable targets. Integer t ensures
the cancellations are exact; it does not by itself establish a complete
physical width or recovery theorem. The universal input contract supplies
the usual arbitrary-array domain; a new restricted numerical domain must
separately establish this legal-direction premise. The five selected
foundational assumptions remain retained.

## Main-only separators survive helper restrictions

For each of the 33 certified cuts, t has support only among the actual main
coordinates. Fix any permitted helper assignment, however correlated or
nonzero it is, and use it in both executions. Vary only the mains by t z.
Linearity of the unchanged native program makes every destination-history
difference zero while its target difference is nonzero. Thus the argument
does not require that the helper restriction be homogeneous, contain zero,
be a scalar graph, or preserve any particular helper target. It requires
that at least one fixed helper assignment remain available for both main
inputs. A rule whose helper values depend on the mains is outside this claim.

In particular, restricting or correlating helpers alone cannot create an
earlier-history provider at these 33 cuts. This is an information statement,
independent of the price charged for those restrictions or source retirement.
The other 14 owned cuts are not excluded by these main-only certificates.
Neither a later-source test nor exact-zero cleanup is required by this
earlier-destination obstruction.

## Owned erasure is a separate interface

A zero-clear two-cache schedule can be a sufficient implementation pattern;
it is not asserted to be necessary for the retained owned-erasure contract.
The original native interpreter permits nonzero owned rows at CLEAR, and
the selected application retains allocation, completed-return, erasure and
physical cost obligations. Consequently a failed later-source provider is
only a failed condition for a specified zero-cleanup pattern. All cache
exclusions claimed here instead use the missing **earlier destination**
information, so they do not rely on zero-before-CLEAR being mandatory.
