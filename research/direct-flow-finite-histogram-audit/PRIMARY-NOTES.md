# Weighted ordered-word primary model

This file records the independently authored pure `build_cases(contract,raw_inventory)` model before any scientific execution. The coordinator supplies an explicitly shared input-authentication/CLI/canonical-whole-packet wrapper before both first seals. No source Flow import, checker, constructor, test, compilation or peer engine/result read occurred during model authoring. Historical exposure includes the author's S8 written audit of the same source Flow; this is not fresh source-unexposed discovery or independent end-to-end wrapper construction.

The mathematical input is the frozen nine-case contract, SHA256 `4fc49527e728be80abaa4c5f7f0bd62da30afaea70b71be2c77b8457136da1f1`. Raw cases read only the original full p7 JSON's `strictification.targets` and `strictification.paid`. Native moments, strictification and physical admission are not recomputed or adopted from other fields. The inventories are given positive integer weights, not instructions to expand7688 target labels or55998 paid labels.

For a unit degree h the model enumerates ordered words over target **support ranks**, assigns each word the product of its rank multiplicities, and groups by its full occurrence-count tuple. Its column product is multiplied along the word. It uses neither comb/factorial/multinomial formulas nor source Flow points/units. Every ordering contributes separately, thereby recovering the full integer multinomial weight by enumeration rather than a copied binomial implementation.

Requests are independently enumerated as complete ordered words of length h+1. The first h letters form the capped unit prefix; the last target letter is unrestricted. The model tests the scaled product of that prefix and aggregates the full word tuple/weight. This retains all target-slot multiplicities and does not truncate targets merely because the final source column exceeds the unit cap.

Paid paths are ordered support words, weighted by the product of paid multiplicities. Distinct orderings with identical product remain separate iterations; there is no source-style following-Counter recurrence. Only paths whose scale exceeds the global column cap are skipped. Empty current batches with scale<=cap are retained so lower-degree descendants can revive. Every terminal paid rank is emitted even when its new product exceeds the cap.

On each internal edge the model reconstructs full parent supply and child request dictionaries on complete count tuples, matches the integer minimum, and separately accumulates all unmatched paid/source/boundary jobs. Column-product collisions across different tuples do not make the model merge their matching classes. Path/paid multiplicity multiplies each actual match/residual; it is never replaced by a Boolean presence flag.

Every case returns all13 source Flow fields plus the complete mirror histogram in the frozen encoding, including rank-zero complements. Mirror complements preserve the unchanged full source_count denominator. The model also checks source/exit/boundary support, full rank conservation, source/unit bounds and mirror conservation; none relies on assertions. These identities are guards, not substitutes for whole histogram equality against the other model and actual canonical Flow.

The case domain includes raw ranks immediately below/at cap/height boundaries, revival, Pascal aggregation, multiplicity and partial matching. No science first or finite outcome is claimed yet.
