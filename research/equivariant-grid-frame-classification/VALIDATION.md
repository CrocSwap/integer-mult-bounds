# Validation scope

The claim is the written equivalence in README.md. Finite execution corroborates
its mechanisms and does not replace the dimension-uniform argument.

## Local environment and result

CPython 3.12.15, Clang 23.1.3, macOS 27.0.1 arm64. The interpreter is
`/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12`. No third-party
Python dependencies are used. Every invocation uses `-B`.

The direct exact replay passes. It enumerates 900 group/input fixtures,
5,100 equivariance comparisons, 4,375 two-dimensional and 59,049
three-dimensional seed matrices. Inputs with different numerator/denominator
representations are separate fixtures; they are not claimed to be distinct
rational points. The reported maximum observed errors are only maxima over
these finite fixtures, not optimal global radii.

The five finite group orders are 3, 8, 8, 6 and 2. The controls exhibit an
unstable nearest-point tie, coordinatewise nearest-even failure for a finite
reflection, the m=1 exception, shear error growth and a product of involutions
with infinite order. Checks use explicit exceptions and remain active under
optimized Python. No predecessor code or historical suite is executed.

Direct normal and isolated optimized runs passed in 4.91 and 4.88 seconds
wall time. The registered runner passed both commands in 10.32 seconds total.
These are replay-duration records, not performance comparisons. Both commands
are far below their individual 120-second timeouts.

Three deliberate verifier mutations were rejected under isolated optimized
execution. Removing the stabilizer filter produced `transport ambiguity`.
Replacing the invariant norm by the ordinary infinity norm, or omitting the
inverse transport, produced `transport changed invariant error`. These
mutations were exercised only in external scratch copies.

The optional receipt is generated by the verifier and binds every package
file by SHA256. It is written outside the checkout; no receipt is hand-written
or checked in. Default execution is read-only.

An isolated optimized standalone replay also passed from a Git-free,
read-only copy in an external path containing spaces. It generated its
receipt outside that copy. Standalone replay checks the mathematics; the
registered runner separately authenticates the declared Git provenance.

## Implementation constraints

The verifier is a closed collection of fixtures, with no matrix or point
inputs from the command line. Dimensions are at most 3 and finite group order
at most 8. Row reduction has at most 24 rows and 3 pivots. Candidate radius is
checked at 20, so each integer box has at most `41^3` candidates. Every loop
has a finite fixture, range, permutation or product bound; no recursion is
used. All functions are below 60 physical lines. Group shape and arithmetic
are trusted internal data; closure, inverses and determinant conditions are
checked before rounding. A computed fixed basis must satisfy every fixedness
equation and the rank/nullity count. Every transport must yield the same
output, including at stabilizer ties.

Rule 3, fixed allocation, has a managed-runtime deviation in verify.py.
CPython fractions, integer arithmetic, comprehensions and standard-library
iteration allocate dynamically. Scope is this single finite replay. The
fixed dimensions, groups, point lists and radius cap bound live collections;
there are no workers, subprocesses or retained histories in the verifier.
Normal and optimized execution exercise these bounds. A fixed-allocation
implementation would require a separately specified arithmetic runtime;
no production implementation is claimed.

Rule 10, maximum diagnostics, uses `-W error` in both registered commands.
No external Python static analyzer was available on PATH. The source is
also parsed by Python's AST parser. Repository-wide diagnostic configuration
is outside this isolated mathematical package; future integration should
apply the host's analyzer without suppressing findings.
