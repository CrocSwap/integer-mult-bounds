# Verification boundaries and resource limits

Build the Lever shaped the retained standalone checker. Prove It Works requires the complete exact replay, semantic mutants and committed-byte comparison. Power of Ten is applied to the new code, with the runtime/library deviations below. Frozen predecessor files are retained unchanged.

## Inspected bounds

- The application call graph has no recursive function. Native loops cover at most 788,035 annihilators, 776,806 flat masks, 160 orbit rows, 1,144 normals and 511 nonzero characters. Character unions have at most three members.
- A separate least-coset enumeration must recover the identical complete flat-mask inventory. Both include the empty live mask. The quotient-basis control rechecks all 120 root directions against pairs from each complete high-intersection family of size at most 336.
- Optional stabilizer sampling processes at most 512 walks, stores at most 4,096 walks and retains at most 32 nonidentity Schreier loops. Each retained map is checked to fix the first live mask. Stopping this optional sampling early only reduces pruning; it cannot omit a required orbit minimum.
- A cut family has at most 65,536 distinct masks. Total retained cuts per pair have the same cap. Shared-state sets have at most 262,144 masks. Exceeding a capacity fails rather than truncating scientific coverage.
- Rational matrices have eight columns. Persistent integer entries are limited to 1,024 bits after normalization. Products before normalization have bounded double width. GCD has a 4,096-step limit. Exhaustion fails, so it cannot become a false low-rank decision.
- Python reconstructs 120 roots, 1,200 Weyl normal rays, 1,144 retained directions, twelve permutations and 96 rank-control fixtures. Source JSON/input sizes are bounded before reading. These are fixed finite domains, not user-sized work queues.
- Every child has a timeout. Native commands create no descendants. Compiler subprocesses are ordinary bounded local builds; the registered launcher additionally cleans its verification process group. Tests compile mutations only inside their temporary directory. No output is written into the package.

## Failure behavior and diagnostics

External source bytes, fixture fields, rank/control identities and complete output ranges are validated. Native orbit limits are checked before addition, so `INT_MAX` start/count inputs produce a controlled range error rather than signed overflow. Internal bit indices and mathematical invariants have executable checks. All native exceptions return a nonzero status. Python checks each child status and complete marker; a timeout propagates as failure. Set insertion results are intentionally ignored when union/deduplication is the required operation. New-walk insertion, stream completion and subprocess results are checked.

Functions stay within sixty physical lines in the normal formatter. Native builds use `-Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror`; Python uses Ruff and warnings-as-errors checks. Tests run under `-O`, so acceptance does not depend on Python assertions. The native integer-rank algorithm is compared with a separate Fraction implementation on actual catalogue vectors. Three compiled mutants remove character independence, overcharge the common-cut allowance and truncate rank; each must fail its behavioral control.

## Runtime/library deviations

### Rules 1 and 3, library internals and allocation

Locations are `census.cpp`, `geometry.py`, `verify.py` and `test_verify.py`. Python and Boost exact arithmetic allocate during computation; their internal call graphs and allocators are not controlled by this package. Standard C++ containers and sorting also use library-managed storage and may use bounded internal recursion. This is a finite offline verifier, not a fixed-memory or real-time implementation.

The compensating controls are fixed input dimensions, explicit element/bit capacities, automatic object lifetimes, temporary-directory cleanup and child timeouts. Application code adds no recursion. Two independent flat enumerations, exact controls and the full replay exercise these bounds. No strict RSS or embedded stack guarantee is claimed. Before reusing the code in a persistent or real-time service, replace library-managed containers/arithmetic with a separately reviewed fixed-capacity design.

### Rules 8 and 9, required library callbacks

The C++ sorting predicates and Python unittest dispatch are bounded library interfaces, not dynamically evaluated code. Their targets are visible in source. The unchanged historical `vendor/bk2b.py` runs in a source-authenticated subprocess; its top-level enumeration is not imported into the verifier. Its fixed loops have `b<=8`, `t<=6` and at most fourteen pieces. Do not expand these scopes without updating their limits and controls.

## Deliberate limits

The finite direction-completeness argument still uses the standard Weyl-chamber theorem. The profile application credits PR3185's cover argument and rechecks its finite root-cover premise. PR3154's original reduction remains inherited. These are not made formal by successful compilation or replay. The package does not mutate, adopt or cold-replay either selected supplier.
