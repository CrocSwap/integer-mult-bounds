# Candidate CLEAR certificates — prepared only

`certificates.py --root ROUND --gate FIRSTGATE_CASE --out NEW_DIR` prepares `certificate.json` plus `status.json`; `build(root,work,out)` exposes the same operation. This module has only been AST-parsed. Root will run the separately pinned standalone `inputs/pr7620/verify_certificates.py` against the candidate and emitted certificate, including its unchanged corrupted-coefficient and cleared-field-as-term negative controls. This preparer does not call or replace that verifier.

The preparer binds the exact current 7620 source and original certificate artifact, first-gate candidate, manifest, exact output and exact receipt to their fixed SHA-256 pins. It performs one exact candidate public-column replay and for each of 167 CLEARs checks the original certificate's clear/owner/chart and origin, maps INIT and owned-MOVE clocks via the first-gate manifest, compares both original and candidate erased rows against their corresponding first-gate full-row observations, and tests the old coefficients against the actual current live rows. An old relation is retained only if the fresh equality succeeds.

For a failing relation it makes one deterministic Gaussian solve using precisely the old certificate's public support plus the fixed public roles 451, 1495, 902 and 985 when live. Sorted roles and pivots fix the choice; no alternate basis, candidate word, coefficient campaign or repair is attempted. It caps the basis at 86 rows, 20 million counted elimination term operations and two million stored terms. If the target is not spanned, a term is unavailable, bounds are hit, or any other check fails, it emits an explicit refusal and completed-clear audit rather than a partial or fabricated certificate. The known changed erased row is measured from the candidate's first-gate actual observation; no candidate coefficients are assumed in advance.

The output's rank metadata is null because no fresh other-live/full-public rank computation is done. `verified_exact` describes only these local public-column linear identities, and status says the standalone verifier remains pending. Neither the identities nor the standalone verifier establishes full-private erasure, residual reset, physical U, a same-premise comparison, cost or κ qualification. Common U and the inherited premises remain explicit. Root controls review, freeze and the single qualification run; runtime/memory are not measured.
