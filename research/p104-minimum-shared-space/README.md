# The fixed P104 shared correction space has minimum dimension 96

This closes the **96-versus-97 algebraic question** in
[Gonzalo Mier's PR #2173](https://github.com/CrocSwap/integer-mult-bounds/pull/2173),
head `d9b784ca86fba060f0264370536ccd322c89998a`. An explicit rational space of
dimension **96** supplies every `I-G/2` correction row modulo that target's
fixed pooled snapshot span. The predecessor proves the lower bound 96 and
exhibits a 97-dimensional space generated by natural correction rows. Our
witness allows arbitrary rational directions and attains the lower bound.

**This is a relaxed algebraic interface, not a chronological correction word
or a cheaper supplier.** Snapshot pooling grants access at different times;
constructing, transporting and restoring the new shared directions is not
priced here. No new κ or selected-frontier change is claimed.

## Exact model and evidence

The frozen 4,058-event PR #1972 channel, retained in PR #1991's native package,
has 104 source inputs, 104 target inputs and 72 arbitrary dirty helper inputs.
We replay all **280 independent input columns**, every frame and private
lifetime, and the original `G/2` endpoint. The inherited paid rank mass remains
2,368; no new native invoice is inferred from the dimension calculation.

At each of the 4,059 cuts, let `v_r(c)` be the current logical row of live
register `r` in the original channel. For target `t`, define

```
S_t = span_Q { v_r(c) : r != Y_t,
              frame(r,c) = frame(Y_t,c) as binary subspaces }.
C = I - G/2.
```

All live sources, helpers, private copies and other targets are eligible.
Rows from different cuts are pooled, and chart-basis changes within the same
subspace are free in this model. The snapshots themselves remain unchanged:
new shared rows are not fed back through the old word to create new snapshots.
The question is the least dimension of any rational subspace `H` of the full
280-coordinate boundary space for which `C_t in S_t + H` for all 104 targets.

The two checkers reconstruct 1,488 distinct rows seen in target-containing
frame classes. Individual pools have 1,053–1,080 distinct eligible rows.
Their source-coordinate ranks have histogram
`{2:12, 3:24, 4:32, 5:24, 6:12}`; the full ranks are these numbers plus 175.
These agree with the predecessor's 177–181 full-span ranks.

[WITNESS.json](WITNESS.json) contains only **41 weighted contacts**
`[target, cut, register, rational_weight]`, on 23 target rows. A cut is the
number of completed original events: cut zero is the initial state. All 41
contacts use dirty `D` helpers, and all weights are `±1/2` or `±1`.
The contacts are a certificate of vector-space membership, not 41 new
chronologically executable operations.

## Proof

Let `R` be the 8-by-104 matrix of **doubled integer root coordinates**, with
ports in the pinned lexicographic order. Exact enumeration gives

```
R R^T = 104 I_8,       G = R^T R / 4,
C = I_104 - R^T R / 8, C^-1 = I_104 - R^T R / 96.
```

In particular, `C` is nonsingular and `R C = -12 R`.

**The fixed-span lemma.** Every captured snapshot's source-coordinate
projection lies in `row(R)`. At cut zero, `S_t` contains all 175 non-source
coordinate units except its own target input `Y_t`. No eligible snapshot has
a coefficient on that missing input. These statements are checked on the
full frozen trace, not inferred from just its final `G/2` identity. Thus any
captured row can have all its non-source coefficients removed using those
175 units. In particular `pi_X(S_t) = S_t intersect X`, and this space is
contained in `row(R)`.

**Lower bound (the predecessor's bound, with a direct certificate).** If an
arbitrary full-boundary space `H` serves every target, then
`C_t in row(R) + pi_X(H)` for every `t`. The rows of `C` span all of `X`, so

```
104 <= 8 + dim(pi_X(H)) <= 8 + dim(H).
```

This also permits shared directions with dirty or target coordinates; those
coordinates cannot evade the projection bound.

**Attainment.** For a certified contact with projected row `x`, its unique
root-code coefficient row is `a = x R^T / 104`. Sum those coefficient rows
with the recorded weights, separately for each target, to form a rational
104-by-8 matrix `A`. The contacts and the fixed-span lemma give
`(A R)_t in S_t intersect X`. Both checkers verify the exact identity

```
R A = I_8.
```

Consequently `E = I_104 - A R` is an idempotent of rank 96. Define

```
K = E C = C + 12 A R,       H = row(K),
```

embedded in the first 104 boundary coordinates. Since `C` is invertible,
`rank(K)=96`. Also `K_t - C_t = 12(AR)_t` lies in `S_t`, so this single
96-dimensional space serves every target. The lower and upper bounds match.
Both checkers additionally compute the exact rank of the explicit `K`.
The independent checker verifies each of the 104 identities in all 280
coordinates, including cancellation of the snapshot's original dirty input.
The sparse checker also verifies the right kernel `C^-1 A = A - R^T/96`;
right multiplication by `C` changes the kernel of `E`.

The optional generator searches the 416 available local basis directions
using a rational linear system with 64 equations. It finds a full-rank
system and a 41-term solution. Acceptance does not rerun or trust that search:
the recorded contacts, `RA=I`, full-space memberships and ranks suffice.

## Reproduce and controls

Standard library, no network or predecessor checker imports:

```sh
python3 -I -B research/p104-minimum-shared-space/verify.py
python3 -I -O -B research/p104-minimum-shared-space/independent.py
python3.12 scripts/research_package.py --package research/p104-minimum-shared-space
```

The first checker uses sparse rational rows, reduced binary bases and sparse
elimination. The second uses dense integer rows on the independently checked
denominator-four lattice, explicit enumeration of every binary subspace, and
dense rational elimination. Only strict I/O and receipt encoding are shared.
Both compare against [RESULT.json](RESULT.json). `--out NEW.json` writes a
receipt exclusively to a fresh caller-selected path; default replay is read-only.

`test_package.py` tests all 41 coefficient sign changes, unavailable contacts,
use of a target's own row, missing initial dirty compensation and final helper
cleanup, a missing puncture, an incorrect transport rank, JSON/schema faults,
source and receipt drift, occupied outputs, and a read-only export without Git.
Reversing every frame basis is a positive representation-invariance control.
These checks also run with optimization enabled in the exported replay.

To regenerate the witness without modifying committed evidence:

```sh
python3 -I -B research/p104-minimum-shared-space/build.py --out /tmp/NEW-WITNESS.json
```

The registered replay uses CPython 3.12; source-export validation on CPython
3.14 is recorded in the PR. No native Clifford regeneration, chronological
owner assignment, new private-copy contract, global recursive moment,
precision/all-size argument, selected cold replay or formal proof assistant
check is part of this package. The predecessor's finite native realization
is inherited, not re-certified by our scalar replay.

## Open next questions

Dimension is an information-space quantity, not a count of paid child ranks.
The already known 208-rank end-cut correction is unfavorable under the
unchanged coverage contract (only `328/9` surplus rank units per call, as
reported in [PR #2082](https://github.com/CrocSwap/integer-mult-bounds/pull/2082)).
This package does not substitute 96 for 208 in that bill or rerun that cost
model. It resolves the explicitly requested dimension handoff only.

Can a changed chronological producer realize this complement, or another
96-dimensional complement, with useful transport sharing? Start by assigning
actual frame paths and source reads to the certificate's 23 nonzero `A` rows,
then replay arbitrary dirty restoration and charge every changed transport,
COPY, idle child and owner obligation. The existing fixed-path/retained-cost
obstructions remain applicable to their models. The present witness grants
pooled access and arbitrary new shared directions, so it supplies neither
such a schedule nor a favorable cost bound. See `TASK.json` for the handoff.
