# Complete replay through explicit dependencies

This is an integration result, not a new arithmetic method or kappa theorem.
The frozen PR6453 verifier supplies the complete scientific contract. The new
complete.py retains its body after exactly four declared textual edits:

- Point HERE to the retained source package.
- Add an optional service_factory parameter.
- At the existing local-source boundary, use the supplied service object.
- At the existing price boundary, use its explicit price module.

The verifier replays EDITS.json against the retained source bytes and requires
exact equality with complete.py. No constructor, regression, invariant, native
receipt, physical check, corruption control or final scientific field is removed.
The baseline runs the original verifier, not the edited file.

The service object has explicit read, load, need, replay, reverse_columns, native
and price fields. No imported function or class is replaced. No temporary source
file is written. The source's authenticated archive extraction is unchanged.
Native and price inputs come from the newly generated word and receipts. They
are not read from the previous component results.

The native dependency is PR6479: exact sparse prefix states plus independent
Gray-order Pauli tables. The forward dependency is PR6501: exact sparse integer
rows with binary denominators. The reverse dense-column checker is unchanged.
The price dependency is PR6505's checked root certificate plus PR6507's bounded
logarithm and exponential intervals. Their proofs and source credit are retained.
Their component gains are inherited and are not claimed as new methods here.

The root and arithmetic sources are specific to PR6453. They contain the original
intervals and preserve its complete displayed receipt. The source still checks
that each raw-root endpoint has its required sign, that both engines agree,
and that every compiler and outer inequality holds. A changed candidate must
produce a new bracket and complete receipt; no search result is cached as an
acceptance answer.

## Complete evidence

The baseline and integrated commands regenerate the original native word from
its third-anchor, lift and merge constructors. They run the clean-word and
intermediate-word regressions, public and owned row checks, zero-scratch proof,
all 799 transpose columns, every native map and main adapter, full mixed caller,
independent module check, all 7,488 physical contacts, ordinary work and complete
price/compiler/outer checks. The original corruption controls all execute.
The complete result, including diagnostic rejection strings, and the source
progress transcript must agree exactly with each other and the retained result.

The component checks do not alone prove this composition. In particular, the
same row engine is now used for the intermediate words and source corruption
controls; the same native compiler consumes the newly regenerated word; and
pricing consumes the generated local/native/physical results. The complete
comparison checks these new interfaces directly.

## Limits and credit

The result is source-specific. It does not prove any of native_all_columns,
owned_erasure, compiler, precision_tape or analytic_recovery. It does not change
selected PR6030. Finite replay, a conditional supplier result, independent
scientific acceptance and a materialized multiplier remain distinct claims.
