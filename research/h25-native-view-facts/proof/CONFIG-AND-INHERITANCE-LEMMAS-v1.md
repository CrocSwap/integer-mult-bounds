**L8 — `CONFIG_BINFMT_MISC=n` removes miscellaneous dispatch for both executions.**

Hypotheses: the actual original environment and transformed environment are associated with the same selected stock kernel source/configuration, with `CONFIG_BINFMT_MISC=n`, `CONFIG_MODULES=n`, and the required native ELF/script formats built in. This is an explicit prospective operating-TCB selection. It does not assert that an already selected host has this configuration. The proposed successor omits the current entry's private-binfmt construction; otherwise its mandatory `fsopen("binfmt_misc")` would be inconsistent with this model.

Conclusion: no ancestor miscellaneous handler, including an old preopened F interpreter, can alter the original-versus-transformed dispatch. There is no miscellaneous implementation to register, not merely an unobserved empty registry. Consequently no binfmt-registry query or handler-equivalence compatibility flag is needed for this branch. Original ELF, script/interpreter, loader and failed-exec behavior still use their actual selected source and must retain their finite caller resolution; this lemma does not replace those paths with another command.

Proof: [`fs/Kconfig.binfmt`](https://github.com/torvalds/linux/blob/v6.12/fs/Kconfig.binfmt), lines 145–169, defines the miscellaneous handler as a tristate feature. [`fs/Makefile`](https://github.com/torvalds/linux/blob/v6.12/fs/Makefile), line 35, includes `binfmt_misc.o` only through `obj-$(CONFIG_BINFMT_MISC)`. With the option disabled, that implementation and its initialization/registration are absent. `CONFIG_MODULES=n` also prevents loading it later. The source-selected native model excludes unreviewed replacement kernel code under the original T1/T2 and no-hostile-administration premises. Both P and V use this same kernel; the conclusion does not depend on trusting a compiler or reading a caller-supplied handler list.

**L9 — `CONFIG_COREDUMP=n` preserves the absence of the core bit, file and pipe-handler path.**

Hypotheses: both P and V use the same selected kernel with `CONFIG_COREDUMP=n`. The successor removes the current entry's CORE `(1,1)` installation and preserves the original inherited limit tuple and original self-limit operations. Ordinary fatal signals, original wait ownership and actual selected compiler/helper consumers remain in scope; no arbitrary native-totality or no-crash assumption is added.

Conclusion: disabling the common kernel feature in both executions removes the relevant core-file and core-pipe-helper dispatch. A normal fatal signal retains its signal exit status without the coredump-success bit in both executions. Thus a `WCOREDUMP`-dependent retained diagnostic has the same false core-bit input; this is a constructive closure of that specific diagnostic branch, not an unsupported assertion that every other diagnostic is equal. It does not require identifying the installed compiler as GCC 13.2 merely to establish the kernel status-bit relation.

Proof: `Kconfig.binfmt`, lines 171–177, defines `COREDUMP` independently. `fs/Makefile`, line 46, builds `coredump.o` only under that option. [`include/linux/coredump.h`](https://github.com/torvalds/linux/blob/v6.12/include/linux/coredump.h), lines 64–70, supplies an empty inline `do_coredump` when it is disabled. [`kernel/signal.c`](https://github.com/torvalds/linux/blob/v6.12/kernel/signal.c), lines 2889–2918, invokes that function for the core-class fatal signal, then calls `do_group_exit(signr)`. [`kernel/exit.c`](https://github.com/torvalds/linux/blob/v6.12/kernel/exit.c), lines 1053–1099, shows ordinary exit codes encoded in the high byte and fatal group-exit propagation. The no-op dump path neither writes a core image nor invokes the pipe core helper nor introduces the dump-success status bit. Signal notification's `CLD_DUMPED` branch at `signal.c`, lines 2104–2111, depends on that low-byte bit.

The existing GCC 13.2 `collect_wait` WCOREDUMP diagnostic is therefore a real consumer with an unchanged core-bit branch under these hypotheses. Actual raw process output, the other wait fields and every required failure/cleanup relation remain genuine observations. `proc_coredump_connector` is still called at `signal.c`, line 2894; this lemma does not falsely say all fault notifications disappear. That remaining common-kernel notification is the same operation in P and V, and any relevant external-effect premise must retain the original operating-TCB scope.

`CONFIG_CORE_DUMP_DEFAULT_ELF_HEADERS=n` is not a substitute. Its stanza at `Kconfig.binfmt`, lines 77–97, changes the default inclusion of partial ELF segments; it does not disable core dumping. `CONFIG_ELFCORE` similarly concerns ELF support objects. The decisive selected switch here is `CONFIG_COREDUMP=n`.

The old special CORE syscall restrictions are no longer required for suppressing a pipe helper under this model. If the implementation removes them, it must retain ordinary `setrlimit` support and self-only `prlimit64` semantics where required, rather than accidentally deleting those syscalls from the allowlist. If it retains any extra restriction, the original reached-operation proof must justify it. This is a source patch-scope consequence, not an edit instruction or executed experiment.

**L10 — `CONFIG_MODULES=n` closes module-autoload delegation, not every usermode helper.**

Hypotheses: the selected actual kernel/configuration is the same for P and V and has `CONFIG_MODULES=n`.

Conclusion: the original failed-format search does not invoke a module-loader helper, and generic `request_module`/`request_module_nowait` calls take the no-module stub. This removes that particular out-of-domain delegated process path without a broker or trusted compiler exception. It does not prove that every unrelated kernel helper API is disabled.

Proof: [`include/linux/kmod.h`](https://github.com/torvalds/linux/blob/v6.12/include/linux/kmod.h), lines 19–33, uses the real loader interface only under `CONFIG_MODULES`; otherwise both request functions return `-ENOSYS`. [`fs/exec.c`](https://github.com/torvalds/linux/blob/v6.12/fs/exec.c), lines 1730–1773, sets `need_retry = IS_ENABLED(CONFIG_MODULES)` and enters the `request_module("binfmt-%04x", ...)` retry only when true. With the option disabled, it returns the actual handler-search result without that request. Missing-path `ENOENT` remains before this format search. The exact finite source/ELF/script/interpreter closure and its failure consumers remain the main theorem's responsibility.

**L11 — The small stack has no readable `/proc/<pid>/attr/current` subject hook.**

Hypotheses: L1's complete active stack is exactly capability plus Landlock under the pinned stock implementation; the actual target process is live and the proc object is genuine.

Conclusion: a successful subject-byte read cannot be required as evidence for this model. The owning association should derive the absence of a subject-producing hook from the genuinely acquired stack and selected hook semantics, rather than call an unsupported read and label its error compatible. This is a correction to the added environment-association observer, not removal of an original scientific check.

Proof: [`security/security.c`](https://github.com/torvalds/linux/blob/v6.12/security/security.c), lines 4228–4239, dispatches `security_getprocattr` only to registered hooks and otherwise returns `LSM_RET_DEFAULT(getprocattr)`. [`include/linux/lsm_hook_defs.h`](https://github.com/torvalds/linux/blob/v6.12/include/linux/lsm_hook_defs.h), line 291, sets that default to `-EINVAL`. Capability's complete hook list at `commoncap.c`, lines 1444–1465, has no `getprocattr`. Landlock's setup at `landlock-setup.c`, lines 34–43, installs only its credential/task/filesystem/network lists; the exact corresponding lists in `landlock-cred.c`, `landlock-task.c`, `landlock-fs.c` and `landlock-net.c` contain no such hook. `proc-base.c`, lines 2775–2793, propagates the resulting negative value from the actual read. The current added `_security_subject`, lines 534–555 of the environment-association source, unconditionally reads that file; it therefore needs this explicit model branch. An ordinary serialized string or boolean cannot create the module association or the conclusion.

**L4a — Checked setup success proves absence of an applicable inherited filesystem domain.**

This strengthens the inherited-state argument without inventing an omniscient introspector. Actual C `enter_namespaces`, lines 355–369, calls `mount(NULL, "/", NULL, MS_REC | MS_PRIVATE, NULL)` and sets `root_private` only after success. `namespace.c`, lines 3759–3778, calls `security_sb_mount` before completing that operation. `landlock-fs.c`, lines 1335–1342, rejects whenever its filesystem-applicable domain is non-null. Under the selected stock hook semantics, actual checked success therefore implies no such domain at that point. The entry has one task and cannot have its credentials changed by another thread; its trusted setup performs no `restrict_self` until the specified installation. The fact can be derived from the existing source branch, not supplied as a compatible label. Setup failure remains a paid qualification failure and never counts as the original scientific negative.

The exact weaker conclusion must be retained: it does not prove the whole inherited domain is null. `landlock-ruleset.h`, lines 274–332, filters applicable domains by the union of their explicit masks. Its lines 364–370 add initially-denied filesystem rights, notably REFER, per layer when checking a filesystem-active merged domain. Thus an old network-only layer can matter after a new filesystem layer is added. Do not silently discard that layer.

Two constructive ways to discharge this remaining branch are available. The simple model can select a genuinely associated null initial domain at the original T1 native boundary. A more general theorem can prove that required reference operations are same-directory (which do not request REFER: `landlock-fs.c`, lines 1121–1143) or handle every remaining old-layer REFER consequence explicitly. Successful mount setup alone is not enough to assert that all later cross-directory references are allowed.
