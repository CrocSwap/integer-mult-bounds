Constructive kernel lemmas for the joined caller

These lemmas are contributions to the authorized proof-construction effort. They do not assume that a complete published proof already exists. Each lemma separates concrete hypotheses from a conclusion and gives an exact source argument that the parent and Pro can compose with the original case map. They do not require a current-host experiment or grant one. The original T1/T2 native association remains the genuine external qualification boundary for actual source/configuration/images and initial state.

All kernel references below are Linux `v6.12`, acquired as complete UTF-8 bodies from the GitHub API. `primary/INDEX-v2.json` records each repository path, tag, Git blob SHA and physical line count; `primary/SOURCE-SHA256SUMS-v1.txt` records full retained-file SHA256 values. Line references in this document are physical lines of those exact retained bodies, not normalized web-renderer positions. The versioned upstream links identify the original source.

**L1 — A small active security stack is a concrete, distinguishable model.**

Hypotheses: the genuine original native qualifier associates the actual kernel with the selected unmodified source semantics; original no-hostile-administration/interposition premises hold; a successfully acquired complete `lsm_list_modules` result contains precisely the selected `capability` and `landlock` module IDs. The acquisition must use flags zero, a bounded actual user buffer, the returned size/count, and preserve real failures rather than substitute a caller-supplied list. Initial Landlock and seccomp state are separate hypotheses, addressed below.

Conclusion: the active LSM dispatch cannot secretly contain AppArmor, SELinux, Smack, Yama or a BPF LSM transition that is absent from that complete list. The conditional AppArmor NNP countermodel is outside this selected model. The result is a factual module-selection branch, not a compatibility assertion and not a claim about the current host.

Proof: [`security/lsm_syscalls.c`](https://github.com/torvalds/linux/blob/v6.12/security/lsm_syscalls.c), lines 96–120, copies all `lsm_active_cnt` IDs, reports the required byte count, rejects nonzero flags and insufficient space, and contains no capability check. [`security/security.c`](https://github.com/torvalds/linux/blob/v6.12/security/security.c), lines 323–324 and 615–645, declares the active count `__ro_after_init`, registers each module ID with its hooks, and marks `security_add_hooks` as `__init`. Under the selected stock source and original exclusion of hostile kernel replacement, registration is an initialization operation. This proves the specific active-hook selection. It does not infer that a listed Landlock module has no per-task domain, or that an inherited seccomp filter is absent.

**L2 — Fresh user-namespace separation closes ancestor proc magic links.**

Hypotheses: the trusted entry creates a fresh child user namespace before any descendant; after setup it has empty capability sets and cannot recover namespace/capability authority; no outside actor is introduced into that fresh namespace contrary to the original exclusion interval. Same-namespace descendants are born only after the final view and restrictions. Pre-view file, directory, mount and namespace references are retired as the actual C owner specifies. The self-task case is handled by L3, not by pretending it needs an ancestor ptrace check.

Conclusion: a science task cannot recover an ancestor or sibling user namespace's writable root, cwd, executable or FD path through `/proc/<pid>` merely because the kernel UID is the same and the target is dumpable. Same fresh-namespace descendants expose only their inherited final-view references, subject to the reference-closure invariant.

Proof: [`fs/proc/base.c`](https://github.com/torvalds/linux/blob/v6.12/fs/proc/base.c), lines 709–723 and 1795–1815, requires `ptrace_may_access(..., PTRACE_MODE_READ_FSCREDS)` before the task link's `nd_jump_link`. Its root/cwd producers are at lines 222–249. [`fs/proc/fd.c`](https://github.com/torvalds/linux/blob/v6.12/fs/proc/fd.c), lines 175–193 and the link inode setup, uses the target file's actual `f_path` through that same proc-link machinery. [`security/commoncap.c`](https://github.com/torvalds/linux/blob/v6.12/security/commoncap.c), lines 135–156, permits the capability-subset shortcut only when the caller and target have the same `user_ns`; otherwise it requires `CAP_SYS_PTRACE` in the target namespace. Its `cap_capable`, lines 67–103, rejects a child-namespace caller seeking authority in an ancestor or unrelated same-level namespace. Numeric UID equality is therefore insufficient.

Landlock provides a second source argument: [`security/landlock/task.c`](https://github.com/torvalds/linux/blob/v6.12/security/landlock/task.c), lines 35–95, permits a landlocked caller's ptrace access only to the same or a more restricted descendant domain. An outside unconstrained ancestor does not satisfy that relation. This additional argument does not replace the fresh-namespace and reference partition.

**L3 — The actual entry does not overmount `/`; its self-root is not a hidden old-root escape.**

Hypotheses: the selected namespace primitive has its documented successful postcondition, with the task root/cwd belonging to the copied namespace; the current exact entry is `science_view_entry.c`, SHA256 `60af72915efea62f46ea376e2ba7ed0c616f99b09ca1beec0f4b0d8173609410`; its setup operations succeed as specified. The native author owns the complete `unshare` call-chain/invariant mapping.

Conclusion: the proposed counterexample based on attaching a new full root above an unchanged old `task.fs.root` does not describe this source. No `chroot` repair follows from that hypothesis. A proc self-root link still requires its own actual-reference argument, but the relevant root mount here is the one changed read-only in place.

Proof: actual `make_view` opens `/` and calls recursive `mount_setattr` on that copied root. The only `move_mount` attachments are the exact artifact parent and usage file. It never attaches a replacement full-root mount. [`fs/namespace.c`](https://github.com/torvalds/linux/blob/v6.12/fs/namespace.c), lines 3916–3994, copies the mount topology and remaps the supplied task `fs_struct` root/pwd mount pointers to the matching copied mounts while retaining the same dentries. `clone_mnt`, lines 1285–1345, retains the same superblock and root dentry and copies the mount ID mapping. `mount_setattr_commit`, lines 4573–4593, updates the targeted mount flags and, when recursive, every mount in that copied subtree. The read-only flag is added to the existing copied root mount, rather than hidden by a newly attached root. The two child mount attachments do not undo that root flag. Actual `make_view` separately re-resolves cwd and replaces old devnull stdin; old-root FD and mapping retirement remains an explicit source invariant.

This conclusion is about the actual constructor. It is not a universal statement that overmounting `/` always changes `task.fs.root`, and it does not rely on that false generalization.

**L4 — Inherited Landlock state has a precise setup branch; new domains accumulate.**

Hypotheses: the selected Landlock implementation is active. For the simple small-stack construction, the genuine original initial-state qualification selects a null initial domain. A strictly weaker setup hypothesis is that the inherited domain has no applicable filesystem component; any inherited network/signal/task effects would then need their own unchanged-case argument. Membership of `landlock` in the active list does not establish either initial-state fact.

Conclusion: an inherited filesystem-applicable Landlock domain would reject the constructor's move-mount operations. A network-only domain does not trigger that particular filesystem hook. On successful installation, the entry's new domain is inherited by subsequent credential copies/exec/fork and cannot erase older restrictions.

Proof: [`security/landlock/fs.c`](https://github.com/torvalds/linux/blob/v6.12/security/landlock/fs.c), lines 399–406, computes `get_current_fs_domain` using the `any_fs` access mask. Lines 1335–1384 reject mount, move-mount, unmount, remount and pivot-root if that applicable domain exists; `namespace.c`, lines 4271–4273, calls `security_move_mount` before attachment. Thus the setup failure is a direct hook consequence, not guessed inherited state. [`security/landlock/cred.c`](https://github.com/torvalds/linux/blob/v6.12/security/landlock/cred.c), lines 17–46, transfers the referenced old domain into prepared/transferred credentials. [`security/landlock/syscalls.c`](https://github.com/torvalds/linux/blob/v6.12/security/landlock/syscalls.c), lines 473–524, permits `restrict_self` under NNP or the specified capability, prepares credentials, merges the existing domain and commits the result. [`security/landlock/ruleset.c`](https://github.com/torvalds/linux/blob/v6.12/security/landlock/ruleset.c), lines 439–480 and 528–578, copies the prior layers and hierarchy and adds a new layer. Access is an intersection, not a reset.

A proof may therefore use an explicitly selected null initial domain at the original native entry cut, with later genuine association. It must not claim that the new source can infer that hidden state from the active-module list. This is a constructive model clause, not an instruction to probe the host or invent an omniscient runtime observer.

**L5 — Mount clones preserve the inode subjects used by the new Landlock rules.**

Hypotheses: the constructor succeeds under L3/L4; required path operations resolve within the resulting copied tree or its exact two writable clones; no forbidden old reference, automount replacement or external topology entrant is introduced. The entry adds its rules through the final-view handles. The required operation class is read/execute anywhere in that tree; ordinary file/directory/symlink/FIFO creation, writes, truncation, removal and within-artifact references; exact usage-file read/write/truncation; and the specifically admitted devnull operations. This is a class statement whose actual original call coverage must be supplied by the caller proof.

Conclusion: cloning the mount tree does not itself make those rules refer to different inode objects. Broad read/execute can be allowed at the final root while artifact writes are allowed at the artifact root, usage writes at the exact usage inode, and devnull access at its exact inode. It does not grant metadata control outside the read-only view or authorize arbitrary filesystems/delegation effects.

Proof: `namespace.c`'s `clone_mnt`, lines 1285–1345, preserves the superblock, root dentry and ID mapping. [`security/landlock/fs.c`](https://github.com/torvalds/linux/blob/v6.12/security/landlock/fs.c), lines 248–347, keys path rules by the backing inode's Landlock object, not a numeric mount ID or original pathname string. `find_rule`, lines 358–376, looks up the same backing-inode object. The access walk, lines 753–909, accumulates permissions from inode rules, walks dentry parents, and crosses mount roots with `follow_up`; it requires the requested rights in every active layer. Because the entry adds its root and exception rules after attachment, every allowed class has an actual rule on its final-view target/ancestor. The artifact rule is encountered at its cloned root before crossing to the copied parent; the usage rule is on the file itself. `hook_file_open`, lines 1496–1565, derives the actual read/write/execute request and records optional truncate/device rights for later FD-local checks. Truncation of an already opened file uses that stored right, not an invented present-path grant.

For link/rename, the two-path algorithm additionally checks that the move cannot gain access; within one artifact domain the source and destination share the same permitted hierarchy. Cross-domain or cross-mount links are not silently declared permitted by this lemma. Inherited pipes and other internal pseudo-filesystems use the explicitly recognized internal-filesystem branch, while their lifetime/writer ownership remains the genuine relay/guardian argument.

**L6 — Ordinary unprivileged exec has no capability, set-ID or secure-loader transition in the small-stack branch.**

Hypotheses: the original and transformed executions have the same non-root underlying real/effective/saved/fs UID and GID; original inheritable/permitted/effective/ambient capabilities are empty; every reached executable/interpreter in the associated finite closure has no set-ID mode and no file capability xattr; ordinary selected filesystem reads return the corresponding absent-capability result. The new entry drops capability sets/bounding authority, locks its securebits, sets NNP and adds NOSUID. The active security stack is precisely the L1 branch, and Landlock grants the required exec/read class as in L5. These are concrete initial/file facts, not an assumption that exec is compatible.

Conclusion: the relevant capability/credential hooks compute the same underlying unprivileged exec credentials and no new `secureexec`/`AT_SECURE` privilege transition for these images. NNP/NOSUID do not introduce the AppArmor subset denial in this branch, because that hook is absent. They also do not suppress an original set-ID/capability transition, because the hypothesized finite images have none. The lemma says nothing about arbitrary status-file observations of NNP, CapBnd, Seccomp or namespace IDs; actual original consumers must still be mapped.

Proof: [`fs/exec.c`](https://github.com/torvalds/linux/blob/v6.12/fs/exec.c), lines 1612–1661, handles set-ID only after `mnt_may_suid`/NNP checks and only when those mode bits exist. With no such mode, the original path makes no credential change; the new early returns have the same result. [`security/commoncap.c`](https://github.com/torvalds/linux/blob/v6.12/security/commoncap.c), lines 724–764 and 886–974, clears the proposed permitted set, treats the absent file capability result as no file capability, applies root-special handling only to the namespace root identity, and limits NNP downgrades to actual set-ID or capability-gaining transitions. Both are absent under the hypotheses. The resulting effective/permitted/ambient sets remain empty, UID/GID remain the same underlying kernel IDs, and the privilege-elevated `secureexec` condition is false. Clearing the bounding set does not alter an absent file/inheritable capability grant. Existing source-currentness and actual-image qualification must establish the finite file facts; another compiler's image pin does not establish them.

**L7 — Capability plus Landlock does not invent security-label xattrs on ordinary creation.**

Hypotheses: L1's exact active stack; ordinary selected filesystem creation; no default ACL or other creation metadata effect on the actual associated parents unless separately proved; same underlying creator IDs, umask and requested mode; L5 grants the required path-creation rights. The original metadata association supplies the relevant observed parent/object attributes or a separate genuine original native qualifier covers the exact filesystem primitive.

Conclusion: the selected LSM stack itself adds no AppArmor/SELinux/Smack-style creation label or differing security xattr to the new regular file/directory. This closes that specific security-label branch; it does not erase or waive POSIX default ACL, filesystem-native attributes, unmapped named ACL conversion or retained-tree negatives.

Proof: `commoncap.c`, lines 1444–1465, and `landlock-fs.c`, lines 1650–1679, enumerate the relevant registered hooks. Neither registers `inode_init_security`; Landlock's creation hooks check path access and return permission results, not metadata values. `security.c`, lines 1809–1853, obtains creation xattrs only from registered `inode_init_security` hooks, with the no-xattr case returning without installing a label. Therefore the selected LSM stack supplies none. Filesystem default ACL inheritance is a separate native/filesystem operation and is explicitly retained as a factual/consequence clause.

The useful composition is now concrete: L1 removes unknown LSM transitions; L4 states the necessary initial-domain branch; L6 proves the ordinary unprivileged exec credential result; L7 removes LSM-generated creation labels; L3/L5 preserve the final mount and inode/rule subjects; L2 plus actual reference closure prevents ancestor proc aliases. These are proved slices that Pro can use while constructing the full original observation implication. Original executable resolution/dispatch, exact primitive coverage, required faults, ordinary filesystem semantics and genuine association are to be joined by that main theorem rather than renamed compatible fields. No component publication or whole-caller acceptance is inferred from this handoff.
