# Omit 15,400 exact zero products from the complete q-Toeplitz replay

This is a finite certificate of an implementation improvement. The complete
fixed replay from James Reed's [PR3865](https://github.com/CrocSwap/integer-mult-bounds/pull/3865)
uses 300 rational matrix multiplications. This opt-in implementation reduces
their scalar multiplications from **22,050 to 6,650**, while comparing every
one of their **4,550 output entries** with the original implementation.
All thirty matrices and every original factor, Gaussian, inverse, width,
norm and final receipt check remain. There is no new factorization or kappa.

The predecessor's files and default command remain unchanged. [replay.py](replay.py)
loads the authenticated original code and replaces only its `multiply`
function with [kernel.py](kernel.py). No parameter, order, check or expected
result changes. Sparse matrix multiplication and exact zero annihilation are
classical. The contribution is their application to this complete fixed replay,
its exact operation reduction, conformance evidence and measured runtime.

## Why the omission is exact

For each entry, the original algorithm sums `left[i][k] * right[k][j]` in
increasing k order. The replacement starts every entry at rational zero and
visits k in the same order. It skips a term only when one rational operand
equals zero. Every nonzero summand therefore has the same value and order.
All entries, including the zeros, are materialized. No numerical threshold,
floating arithmetic, probabilistic check, rank surrogate or result cache is used.

The original command runs ten multiplications at each order n=1,...,6 for
each of five q values. Its dense count is `5*10*sum(n^3)=22050`. The count of
nonzero operand pairs per q and n is

```text
binom(n+2,3) + 5*binom(n+1,2) + 2*sum(k^2, k=1..n) + n^2 + n^3.
```

The terms come from the lower-by-lower product, five diagonal/triangular
products, two products of opposite triangular matrices, one diagonal/dense
product and the final dense product. Summing gives 6,650. The checker also
enumerates every actual operand pair, rather than trusting this expression.
The new matrix identities are implementation-equivalence identities; the
predecessor's factorization theorem is a cited input, not a new audit result.

## Evidence and timing

[verify.py](verify.py) checks all 300 complete products and generates a receipt
binding the nine package files by SHA256. The operand/output transcript hash is
`65582bc026421c9031681b874e3067e456bc74c39e71a6b717e6a1c3a4f39e82`.
It also checks all 6,561 ordered pairs of two-by-two matrices with entries
in `{-1/3,0,2/5}`, dense fixtures at orders one through six and an exact
nonzero `2^-2048` product. Four invalid matrix shapes reject. Three actual
source-byte corruptions reject before execution. All-zero and reversed-column
replacement kernels fail retained checks. Explicit exceptions keep acceptance
and rejection checks active under optimized Python.

The diagnostic baseline profile attributed 0.038 of 0.048 seconds to matrix
multiplication; the candidate profile attributed 0.014 of 0.025 seconds to it.
Profilers are outside the benchmark. Rational arithmetic is the changed cost;
startup, imports, source authentication and all other checks remain.

[BENCHMARK.json](BENCHMARK.json) contains fifteen alternating fresh-process
pairs on macOS arm64, CPython 3.12.15. Complete-command medians are **64.291 ms
and 58.847 ms**, an 8.47% median reduction. Ranges are 62.343 to 99.169 ms and
57.299 to 69.196 ms. Fourteen of fifteen paired candidate runs are faster; the
median paired reduction is 5.397 ms. All thirty processes finish successfully
with byte-identical stdout and no stderr. This is a descriptive host measurement,
not a portable speed guarantee or a CI timing threshold. The machine has eighteen
cores; orientation load averages were 3.16, 2.01 and 1.73. Concurrent work and
interpreter startup limit timing precision. The exact 15,400-product reduction
does not depend on these timing samples.

Each timed region includes interpreter startup, imports, all thirty matrices,
every retained check and stdout. Both sides use a fresh shared private bytecode
namespace with writes disabled, so both compile their standard-library imports.
The candidate additionally authenticates the source bytes. No scientific result
or matrix is reused across processes. Raw samples and implementation hashes are
generated by [benchmark.py](benchmark.py).

## Reproduce

From the repository root with CPython 3.12 and the standard library:

```sh
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -W error -B research/q-toeplitz-zero-products/replay.py
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -W error -B research/q-toeplitz-zero-products/verify.py
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/research_package.py --package research/q-toeplitz-zero-products
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/check_research_commit.py --package research/q-toeplitz-zero-products --check-source-history
```

Any installed CPython 3.12 may replace that interpreter path. The registered
manifest runs both the complete replay and conformance checks in normal and
optimized modes. Expected markers include `PASS_Q_TOEPLITZ_FACTORIZATION`,
`PASS_Q_TOEPLITZ_ZERO_PRODUCTS` and `PASS_REGISTERED_RESEARCH_PACKAGE`.
The normal command writes no artifacts. Set `TMPDIR` to a scratch directory
when directing temporary corruption-control copies to a particular location.

To reproduce timings, choose a fresh output file outside the checkout:

```sh
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -W error -B research/q-toeplitz-zero-products/benchmark.py --rounds 15 --output /tmp/q-toeplitz-benchmark.json
```

The benchmark refuses output reuse and propagates failures. It is optional,
because elapsed time is not a mathematical acceptance condition.

## Scope and engineering constraints

Canonical base is `7c49fe32c55de02c2c873655c804b16e4c3fef0a`, priority revision 8.
[SOURCES.json](SOURCES.json) pins the original code, receipt and README as live
inputs; the selected record and catalogue are historical provenance. Source
hashes must match before execution. The code compiles those authenticated bytes
directly, so a predecessor bytecode cache cannot substitute different code.
The ordinary import environment for this package and the Python standard library
remains trusted; the registered runner separately isolates bytecode imports.

This is the fixed PR3865 exact rational suite, not the production Gaussian core,
a native multiplier or a new negative mathematical result. Orders beyond six,
new q domains, physical time savings, all-size proofs, supplier admission and
the five selected framework assumptions remain outside the claim. No selected
cold replay, Lean, Docker, independent human review or proof-kernel review is
claimed. The selected frontier remains unchanged.

The autonomous local run playbook stopped after the first arithmetic improvement.
Build the Lever kept the replacement and conformance checker; Prove It Works
required complete intermediate matrices rather than just the final marker.
The benchmark checklist required complete fresh-process timing and error counts.
Power of Ten bounds matrix loops by six, fixture enumeration by 81 squared,
source inventory by five rows, live source reads by 128 KiB each and benchmark
rounds by 31, with thirty-second subprocess timeouts. New functions fit within
sixty lines and use explicit failure paths.

Python-managed rational and container allocation is a rule-3 deviation, bounded
by the fixed suite and fixture sizes. Rule-8/9 deviations are loading one fixed
authenticated Python module and replacing one explicit function; two deliberate
fault kernels occur only in controls. No source rewriting or arbitrary module
selection is exposed. A compiled implementation would be needed for a static
allocation policy. Warning-strict normal and optimized registered commands
provide recurring diagnostics. No production configuration changes are made.

## Open next questions

Does exact zero-product omission help a larger currently used rational replay
with comparably sparse factors? That would give greater practical benefit than
this short command. First profile one different complete replay and enumerate
its zero operands. No larger workload or equivalence contract is supplied here.
This package stops at its first improvement and reserves no follow-up.
