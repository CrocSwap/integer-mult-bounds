# Source-bound oracle v1

`oracle.evaluate(candidate_bytes, artifacts, policy)` is pure and uses exact rational comparisons. `artifacts` maps SHA256 to literal bytes. `policy` is a separately trusted reviewer input, installed after inspection of the independent evidence. A candidate cannot authorize its own receipt or expand its model domain. Every exact input and receipt is checked against its literal SHA256.

A scientific payload is the canonical JSON candidate without `receipts` and `requested_label`. Receipts bind that payload SHA, exact head, profile SHA and all source dependencies. This avoids the impossible digest cycle produced by making a candidate include receipts that hash the entire candidate. Producers retain their original immutable invoice; normalized consumer receipts bind the original invoice artifact in `evidence_sha256`. An arithmetic receipt additionally binds the normalized census and closure receipts. No original producer file is overwritten.

`SCHEMA.json` describes the candidate exchange. `oracle.py` defines required coverage, cost states and label transitions. The reviewer policy specifies every allowed charge ID, literal compiler tuple, source theorem artifact, arithmetic check ID and predicate ID. A model with altered law or tuple is rejected until a separately reviewed policy covers it. Predicate inventories belong to each source interface; the implementation does not treat 58 as a universal count.

The six planes are `paid_productive`, `ordinary`, `ownership_stock`, `precision_tape`, `compiler_reserves`, `bit_outer`. Every entry includes `id`, `value_or_symbol`, `unit`, `state`, `evidence_sha256`, `dependency_hashes`, and `invalidation_conditions`. Unknown entries have `value_or_symbol: null`, remain visible, and prevent complete-bill/funded promotion. Optimistic entries likewise prevent promotion. Ordinary symbolic finite-template bounds retain their units; they never enter the rank moment as scalar zero or an unjustified rank charge.

Labels describe separate evidence thresholds. Literal witness bytes allow WITNESS_READY; an independent all-column physical receipt allows PHYSICAL_CHECKED; census and fresh closure plus all resolved six-plane costs allow COMPLETE_BILL_READY. Exact independent arithmetic on those same receipts allows FUNDED_CONDITIONAL. A separate publication receipt allows PUBLIC_REVIEWABLE. SELECTED is only a read-only authenticated selected snapshot in the trusted policy; arithmetic cannot select a result. All retain the five explicit framework assumptions. A claim of PASS in an author result has no admission effect.

The arithmetic envelope carries funded/tested rational savings, strict rational root sign intervals, compiler tuple, positive strict/functional slacks, and named source-specific boolean checks. It consumes 04's independently derived receipt. `source_moment_screen` accepts 04's `moment` backend only in an explicit saving interval and returns MODEL_ONLY. It neither computes new roots nor promotes a positive budget. Passing a model screen requires physical and complete-cost admission.

Calibration imports preserve existing source-bound conclusions. They do not run another author verifier, phase census, native job, cold replay or independent root calculation. Until the new immutable 01–04 receipts exist, #5383 is WITNESS_READY with unknown closure/funding, even though its author result reports a positive κ. #5384 is a verification publication of #5377's construction; it supplies no additional productive fields or additive κ gain.

Security boundary: this is a compatibility checker for reviewer-pinned evidence, not a cryptographic proof checker for prose. SHA256 authenticates bytes against the supplied trusted policy. Review of physical arguments, applicability and authority remains necessary before a digest is added to that policy. Contract errors are input rejections, not counterexamples to a theorem.
