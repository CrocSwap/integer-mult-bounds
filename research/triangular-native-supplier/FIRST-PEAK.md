# Complete occupied storage at the first connected precision

Let $A=355763540965264$, $p=p_*=2^A+2$, $s=A+1$, $T=2^L$. Count canonical input and output, both declared full numerical files, and the sum of the historical extents of all reusable physical data and control tapes. At this first precision the complete auxiliary backing, including the installation, is less than **$pT/1024$**. The sum of the two main files and the canonical I/O can therefore be used at this precise entrance. This sharpens an eventual bound to the actual connected entrance. The source's standard scalar arithmetic and its bounded optional primitive have the stated costs. Work tapes start fresh or reset. Charge both canonical input intervals and every output byte this call produces. Unrelated caller-owned files and arbitrary injected callbacks have their own costs. These are analytic bit-tape bounds.

## 1. Count the field slots that an active finite program can use

Fix one raw rule and one rank in the installed periodic compiler. Write $G$ for the forest height, $S$ for the number of source ordinals, $z$ for the actual number of copies, $h_0$ for slots per copy, $R=zh_0$, and $B$ for the productive batch. The implementation gives $h_0=\sum_q T_0/q\ge S$ and $B\le R<(16/15)B$.

Fix a paid path and a depth. Every live unit is labelled by its future $f$; two units at the same path have different futures. Follow productive port **zero** towards its parent while that port is marked parent. The code places this exact parent at future $(0,f)$ of the preceding path prefix. The test guarantees that it is an actual live unit. Otherwise the port has an external source ordinal. At the root all ports are external. The terminal source contains its depth, its future $0^k f$ and the chosen port index zero. The depth recovers $k$ at a fixed initial depth. Removing the first $k$ zero labels recovers $f$. Thus the assignment is injective at each fixed path and depth. The total number of active units on one chain of process iterators is at most $(G+1)S$. Across all actual replicas there are at most $(G+1)R$ active strict units. This counts unfinished sibling iterators at every ancestor: process opens every future unit at that depth but descends into only one paid path at a time. It does not sum sequential paid branches. Neither the high rank counts in the full installed word nor a claim about average usage gives this bound. [Actual plan and process iteration](https://github.com/CrocSwap/integer-mult-bounds/blob/3f7c3c1f2a9a0963736562037e01fe41aec46b8c/research/bounded-general-multiplier/periodic.py).

At the last forest cut a recursive satisfy processes one group of $B_e$ fields at a time. The plan sets $B\ge15(\max_e B_e)h_0$. Hence each such active rank has $B_e\le B/15$, and the sum of batch widths on the nested chain is at most $15B/14$. Other copies already issued by the parent remain in the parent's count. For a stopped rank the base reads the existing fields serially. Each strict unit with $v=480$ or 264 has fewer than
$$
 Q_v=2^{64}(v+1)2^{28v}\le2^{13513}
$$
raw occurrences, port bindings, zero allocations, adapters, disjoint splits, and completions including the fixed raw structural allowance. Each structural occurrence can use its incoming fields and the newly allocated slots of the current instruction. Some raw alignment and scalar loops reuse one scratch field many times. Each per-column swap replaces the field and retires its prior version before the next column. Only the column indices survive. Thus these visits reuse the same vacancies. Their traffic is charged by the native clock. Even counting a private list of $Q_v$ simultaneous copies at each of $Q_v$ occurrences allows $2^{16}Q_v^2$ home/temporary slots per strict unit. This includes outputs staged before transfer and the constant number of snapshots needed during one scalar field pass. The paid continuations use their own counted units. [Strict unit and raw record census](https://github.com/CrocSwap/integer-mult-bounds/blob/3f7c3c1f2a9a0963736562037e01fe41aec46b8c/research/bounded-general-multiplier/PERIODIC.md#L107-L157) and [powered implementation](https://github.com/CrocSwap/integer-mult-bounds/blob/3f7c3c1f2a9a0963736562037e01fe41aec46b8c/research/bounded-general-multiplier/powered.py).

Consequently the active field slots at one complete carrier execution are bounded by
$$
 2^{19}Q_v^2(G+1)B .
$$
The productive fields occupy the actual entering extent: each of its $B$ fields has exactly $1/B$ of the row-split input. Thus the live slot extent, including unused high-water slots below, is bounded by $2^{19}Q_v^2(G+1)$ times that entering extent. On all seven carriers $G+1 < 2^{50}$. The count is independent of the payload values. No inactive site is assigned a data home.

**Allocation and historical indices.** Each binary bank set has capacity, available slots and live slots. Its allocate first pops a free index. Only when there is none does it use the previous capacity as the new index. Retire returns that index. Starting empty, capacity is the maximum simultaneous live cardinality seen so far even if different tickets or branches caused that maximum. The maximum index ever written is smaller than that capacity. Its slot access uses index times the declared fixed owner extent. The positive arena's high/free/live counters satisfy the identical invariant. A retired field returns its actual slot; its copy is fully written before retirement. A complex child starts at the parent's start plus *historical* high times its extent, not the current live count. The induction below accordingly adds the worst high-water interval of every ancestor, even if their peaks occurred at different times. Finishing a child returns to that base. For binary pages the analogous base is the previous marker plus that frame's declared extent; a page is scrubbed and popped before the same-depth sibling can open. New owners in the same compiled activation pop vacancies. New compiled activations open a new stack page. The bound therefore also pays for gaps left by prior larger sibling calls, touched zero slots, returned copies, and the maximum address used before truncation. [Binary bank positions](https://github.com/CrocSwap/integer-mult-bounds/blob/46783fbbfc219a3faffbea76f60a2810b85ab75a/research/native-stock-activation/raw_binary.py#L52-L94), [positive slots and child starts](https://github.com/CrocSwap/integer-mult-bounds/blob/46783fbbfc219a3faffbea76f60a2810b85ab75a/research/native-stock-activation/spool.py#L81-L124), and [top-only byte pages](https://github.com/CrocSwap/integer-mult-bounds/blob/46783fbbfc219a3faffbea76f60a2810b85ab75a/research/native-stock-activation/stack_tapes.py).

The [Lean module](lean/ActiveForest.lean) proves injectivity and the finite layer cardinality, the sum across depths and copies, and the free-first high-water identities. Its application to the emitted loops, source-event census, tape placement, and head bills is a written proof.

## 2. Preserve the stripe through layouts, radix switches and repairs

Each positive H freezes an unselected spectator coordinate. Each CRT slices the bytes of its opaque words. Both have at least $2^k$ stripes at this input, where $k=\lfloor s/2\rfloor-2=177881770482630$. The declared positive or exact coefficient words in the two CRT directions exceed $p/64$ bytes in these versions. All extents may be charged as complete bytes, including the larger residue class of the width split. The two stripe streams, a complete widened H with $2h+48$ additional bits per component, source copies, and root relocation each have extent at most $64(p+1)T/2^k$ per stream. A complex child partitions the existing field into smaller independent slots. The true complex reserves are part of the actual input volume, and the dynamic matrix slots of section 1 are separately counted. Field swaps and phase/sum sweeps have fixed extents. [Public stripe code](https://github.com/CrocSwap/integer-mult-bounds/blob/46783fbbfc219a3faffbea76f60a2810b85ab75a/research/native-stock-activation/striped_tensor.py), [native geometry and slabs](https://github.com/CrocSwap/integer-mult-bounds/blob/46783fbbfc219a3faffbea76f60a2810b85ab75a/research/native-stock-activation/complex_stage.py), and [positive arithmetic](https://github.com/CrocSwap/integer-mult-bounds/blob/46783fbbfc219a3faffbea76f60a2810b85ab75a/research/native-stock-activation/positive.py).

Each CRT compact repair writes one key **per group of $2^H$ back records**. Its length in bits is at most $L+8 \le p+8$. The original geometry gives $H=\lfloor L/(100G_0)\rfloor G_0 \ge L/100-G_0$, $G_0=64(\ell+s)\le64(128s^2+s)$, and $L\ge p/12$. The accompanying integer check proves $H\ge s+9$ here. Even if *every* group were marked, keys occupy less than one copy of the grouped payload on each spool. The marker file needs at most one byte per group. Noncompact individual switches allocate no per-address key. In the positive column repair the group has $2^{\rm suffix}$ complete complex records, where ${\rm suffix}\ge(s-3)^2\ge s+9$ at every native column request. Its key is at most $p+8$ bits. Marked streams and both radix buckets satisfy the same two-volume bound. These bounds do not require an unstated density coefficient. Each repair is serial and its work tapes have a fixed list of names. [Actual CRT key and shared back field](https://github.com/CrocSwap/integer-mult-bounds/blob/46783fbbfc219a3faffbea76f60a2810b85ab75a/research/native-stock-activation/compact_crt.py#L164-L209) and [positive grouped key](https://github.com/CrocSwap/integer-mult-bounds/blob/46783fbbfc219a3faffbea76f60a2810b85ab75a/research/native-stock-activation/compact_columns.py#L139-L181).

All ordinary calls in the first-entry product use the direct regime. No low or high chart catalogue is manufactured. The public binary rectangle inflates by less than nine, the fresh root's padded reserve by less than two, and the temporary radix transpose of a finite type axis by less than three. The returned type field has its original length. The maximum direct scalar bucket count is 22. The actual upper/lower adders, weighted splits, earlier-stage restores, and the five root placement spools are all included. Most of these extra charge factors cannot be simultaneous. It suffices to use $2^q$, with $q=262144$, for the volume multiplier of any macrolevel including its raw slots, local scratch, padding and the extent of the subcall. Indeed $4\log_2 Q_v + 8\lceil\log_2(1+\max_i\log_2 N_i)\rceil +512 < q$. The preceding slot, key, radix and primitive factors need less than this allowance. It is independent of the number of slots in the static instruction stream.

## 3. The sum of historical physical tape maxima

Each nested positive call divides the selected width $h\le p$ by $M=2^{3300000000}$. Including its root and stopped child, at most $2+\lceil s/3300000000\rceil=107810$ heights can be active. The direct cutoff admits at most eight positive same-stage divisions and one stopped level in each of six fresh stages. Reserve another 32 macrolevels for roots, CRTs, final streaming and small procedures. Use $d_0=107896$. At one height a single carrier includes the entire fixed-rank and powered program of section 1. The bound does not multiply by the total number of issued instructions to obtain a count of simultaneously active children.

Store the raw fields by slot in a single arena tape as in the source. Assign a fixed physical head to each primitive scratch role and bucket position. Store suspended intervals for the same role consecutively on its tape. Keep their base and end markers in the control stack and pop the top interval at return. A fresh earlier ordinary stage can have its own finite stack-head set. The source's numerical raw/graph and binary raw iterators retain only arena slots and descriptors on a paid yield. A transfer or scalar snapshot is closed *before* that yield. Open storage crossing the boundary of the positive supplier is the shared arena plus the complete staged root, if present. Ranks in the periodic forest that share an arena do not acquire separate physical heads per logical unit. Binary arenas use a fixed set of page names (weighted, matcher, exposed leaf, compiler slots, issued leaf, pending and returned), independent of the owner number. For the historical space bound, count each temporary call site, up to 22 bucket positions, and each pair of current and parent heights separately. The count is fewer than $2^{32}(s+128)^2$ virtual intervals on the fixed set of heads. A source pass over the 26 data-path modules in the [source census](check_active_forest.py) found 71 temporary or page call sites, literal work-tape sizes at most 22 and literal page tuple sizes at most three. Scanning each missed caller-supplied input/output or fixed transfer endpoint at a separate head still fits this slack. No program table entry is a request for a fresh physical head. Its issued fields use slots on the one owner tape. This layout is exactly the fixed-head interpretation of the existing temporary-file schedules. [Per-yield numerical lifetime and ordinary staging](https://github.com/CrocSwap/integer-mult-bounds/blob/46783fbbfc219a3faffbea76f60a2810b85ab75a/research/native-stock-activation/COMPLEX.md#L191-L215).

For an arbitrary head, sum all ancestors' maximum frame extents, reserving $2^{2q}$ at each height relative to the preceding stripe extent. This allows the local pad and the next child, and bounds the parent high even if an earlier sibling attained it. Across distinct invocations reuse the same base and slot-head assignment. Sum this per-interval bound over **all** the virtual intervals above, and allow initial file extents, final rewinds, cleanup and constant format overhead. The resulting logarithmic factor over $pT/2^k$ is at most
$$
 (2d_0+4)q + 32 + 2\,\operatorname{bitlength}(s+128)+16
 = 56569626770 .
$$
The stripe margin is $177825200855860$ binary bits. Thus all additional **payload** backing costs less than $pT/2^{1024}$, even when summing past maxima over distinct physical heads.

## 4. Add private state, installation, counters and output

This part has an additive allowance. In particular it cannot multiply a stripe by a fixed program size. Put $E=(s+1)^8$, $K=2^E$, $A_0=K^{8(s+130)}$. The old finite structural bound gives each carrier stream at most $J=2^{4736000000000000000}$ records and bits. All private per-input coefficient synthesis and retained tables use at most $D=2^{2^{20}(s+1)^2}$ bits. The seven complete installed programs, coefficient producer, coordinate lists, finite phase and scalar constants, and pointer-free table scans fit in the separate control allowance. Per macroheight $2^{64}(J+1)^8(p+1)^{64}(D+1)^8<K$ suffices as follows. There are at most $J^2$ static role records, selectors or extra-copy slots even if every site retained every fixed list. A dynamic column or atom list has at most $2p+4$ positions. Each phase word, ternary residue, address, CRT prefix and carry word needs at most $8p+8$ bits in the data phase. Private compiler rationals, tables and their arithmetic have the separate $D$ bound. The per-address one-axis Beneš routine uses less than $64(t+1)^3(\ell+1)^2<D$ bits even if all its recursion nodes are charged at root size, where $t=2^\ell$. Each fixed-cell copy block is at most 65536 bytes. These finite control lists, their software lookups, and schoolbook arithmetic on their values fit the stated local product even with a square array for every indicated count and temporary word. Difference-form scalar Karatsuba holds at most 32 words of at most $4r+64$ bits per halving of an $r$-bit scalar. Its three proper children run serially. The bundled short NTT leaf, if used, has four bounded 32-bit arrays. A bound $2^{16}(r+1)^2$ covers both implementations; the public data operands have $r\le8(p+1)$. All raw residues and coefficients have the listed true vector lengths rather than a vector indexed by an arbitrary whole payload. Source code, its authenticated archives, numerical semaphores and the elementary machine remain finite and covered. Summing control frames and charging even the historical maximum for every local role/depth gives $A_0$, without a $T$ factor. Root and geometric array end positions need fewer than $p$ bits by the payload estimate; this does not change any declared payload extent. [Private coefficient bound](https://github.com/CrocSwap/integer-mult-bounds/blob/46783fbbfc219a3faffbea76f60a2810b85ab75a/research/native-stock-activation/OUTER.md#L286-L370).

The native FileHead movement counters refer only to ordinary routes on opaque fields. Their successful control order and tape addresses are independent of every payload bit: the only byte-dependent check can reject an invalid private zero. To bound these diagnostic integers rigorously without an unknown time constant, simulate one entire successful ordinary invocation on symbolic zeros. Represent each opaque stream by its cursor, extent and frame bases. Reads return zero, XOR/copies/erasure preserve it, and each required zero check passes. Routing coefficients use the real geometry and static word as before. The simulated program has the same head positions and transfer sizes and uses only the $A_0$ control bound, including addresses, live intervals, weights and any transfer buffer. Ignore write-only meters while counting configurations. A terminating deterministic finite tape program with this bounded interior, at most $A_0$ heads and finite installed control visits fewer than $2^{4A_0^2}$ distinct configurations. A move contributes at most its actual extent, which has fewer than $p$ binary digits. Its total and its aggregate over all heads need fewer than $8A_0^2$ bits. Fresh ordinary invocation statistics reset, and only the most recent last_storage tuple is retained. Outer CRT totals count at most $T$ records in one macro, with at most $O(p^5)$ occurrences explicitly: at most $p$ stripe, level, layer-position, group and target choices each, times a fixed factor below 128 for the three CRTs and their switch rows; $256(p+1)^6(T+1)$ bounds these tallies. The numerical H counter counts the actual outer gate visits, bounded by the finite $D$ compiler and the stripe count. All observers, temporary integer copies, saved totals, separate control heads and installation together fit $A_0^{16}$ bits.

The integer $12[128(s+130)(s+1)^8+64]$ has only 446 bits. Thus $\log_2(A_0^{16})<p/12-64\le L-64$. Private backing costs less than $T/2^{64}$. Adding it to the payload remainder proves the announced $pT/1024$ total extra backing. Combine it with the actual permanent record format, the original input and the final output; no hidden native price constant enters.
