# P104 restricted updates lose the small-rank fixed-bit saving

Even repeatedly updating **one real coordinate** removes PR3059's one-bit
pointwise defect saving at ranks two and three. This remains true when only
even updates by 2 are allowed. The smallest such rank-two code has **33 states**,
just above the 32-state capacity of five bits.

For the fixed signed-integer P104 word, let
`D_r(x)=2^r L_r(x)-(2^r U_r)x`. Require an exact code that determines D_r and
updates from its code alone under every integer multiple of `s e_j`, for one
fixed real coordinate j. The exact minima below hold for **every** j separately.

| rank | immutable source | step 1 | step 2 | step 4 | full period cosets |
|---|---:|---:|---:|---:|---:|
| 1 | 3 states / 2 bits | 4 / 2 | 3 / 2 | 3 / 2 | 4 / 2 |
| 2 | 25 / 5 | 56 / 6 | **33 / 6** | 25 / 5 | 64 / 6 |
| 3 | 10,225 / 14 | 27,392 / 15 | 21,144 / 15 | 10,225 / 14 | 32,768 / 15 |

The displayed strides cover **every integer stride**: modulo the scalar period
q=2,4,4, the subgroup generated by s e_j depends only on gcd(s,q). In particular,
at ranks two and three the one-bit pointwise saving survives exactly when
s is divisible by 4, which leaves the defect unchanged. Proper restricted-update codes do have fewer states than the full
coset code; this does not always save a fixed bit. Their fibers can have unequal
sizes and need not be cosets of a subgroup.

## Exact contract and proof

For any function d on a finite abelian group G and an update subgroup H,
the exact minimum reached-state code is the signature

    S_H(x) = (d(x+h))_(h in H).

Equality of code states forces equality of every future output. Conversely,
translation by k rotates signature entries `h -> h+k`, giving a well-defined
permutation with inverse -k. [PROOF.md](PROOF.md) gives the general theorem
and its all-integer periodic reduction. This is the standard future-observation
partition applied to the changed P104 boundary; the general principle is not
claimed as a new automata theorem.

The primary implementation authenticates three unchanged PR3059 source files,
constructs exact prefix-lattice quotient actions, checks every coordinate action
against literal signed floors, verifies the code transitions and full-translation
controls, and compares all receipt fields. It covers 4, 64 and 32,768 lattice
classes. The independent implementation imports no predecessor or primary
executable code. It reconstructs the Gaussian floor word and closed ideal
coefficients, covers all 16 and 65,536 scalar-period-box inputs at ranks one and
two, and constructs a separate 32,768-state prefix-character image at rank three.
Both agree on every coordinate/step state count and complete normalized fiber
histogram. [INDEPENDENT.md](INDEPENDENT.md) supplies its independent completeness
argument. This is internal AI-assisted checking, not human or formal-kernel review.

These finite complete computations and written proofs concern **signed integer
inputs at ranks 1–3**. There is no rank-seven image count, all-rank state-count
extrapolation, physical native realization, supplier admission or new kappa.

## Recursive-cost decision

The tested mechanism changes PR3059's all-translation requirement to a highly
restricted update alphabet. Even this favorable change does not preserve the
fixed label-bit saving in these small cases. It is a scoped stop for these
alphabets, not a global obstruction to nonlinear residue consumers.

An abstract update permutation is not a free reversible circuit. A caller must
still pay code acquisition, update/decoder lookup, source access, defect-output
banks, routing, scratch and literal cleanup. In PR3059's retained-source dirty
consumer, the algebraic bill remains `2 C_A + 2 C_defect-add + 2 C_Q`; each
compute/add/uncompute defect addition pays two oracle calls plus the wide add
and all work/output banks. All borrowed dirt must return. No favorable complete
recursive comparison is established; unknown costs are not zero. Variable-length
coding or source-dependent updates change this contract.

Family decision: **narrow and stop** at the restricted-code state obligation.
The present update alphabet is a deliberately favorable mathematical screen,
not a claim that the full native caller has only these updates. A constructive
continuation must first bind its actual source-update alphabet and paid consumer.
