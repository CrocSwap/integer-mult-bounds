Let A=268435456 be the actual hard AS limit installed before query exec. A live
terminated string occupies at most A accessible bytes. The largest selected
formatted expansion has three such operands and a fixed literal contribution k.
Each listed literal contributes fewer than 1048576 bytes, so

    3*A + k < 3*268435456 + 1048576
            = 806354944 < 2147483647 = INT_MAX.

There is no precision, width, positional, wide-character, grouping, %n or
registered custom-format path in these calls. Overlapping strings do not weaken
the bound: each operand length is independently at most A. The loops can produce
more than a single call; output/event/working limits refuse that case rather than
accept a truncated report. The original source's fatal allocation branches
remain fatal. This bound addresses pre-write signed-count overflow; it is not an
elapsed-time, memory-fit or complete-output assertion based on exit 0.

The actual query environment is exact C with no LANGUAGE override. In the

Fresh ordinary stdout/stderr are narrow streams. glibc `libio/genops.c`,
`_IO_doallocbuf` lines 321–328, falls back to its short buffer when ordinary buffer
allocation fails. Narrow literal/string/byte serialization has no character-set
conversion allocation. Transport, short write, restart, pipe error or final flush
failure therefore reaches the actual traced write boundary or invalidates the
native trace. `_IO_cleanup` lines 793–805 flushes/unbuffers the streams; the native
observer continues through actual exit processing and terminal wait, rather than
stopping at return from main. The receiver compares genuine entry snapshots,
full successful return counts, both drains, retained bytes and independent
readback. A non-returning exit syscall has its own actual terminal-entry count.
