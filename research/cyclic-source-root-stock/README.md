# Sharp dirty-root stock for repeated cyclic source order

A scoped proof gives the exact root minimum for the fixed source projection
`B0 ... B(n-1) B0 ... B(n-1)` in the arbitrary-dirty binary connector model.
Every source and every nonzero-mask output is called exactly twice. With
unrestricted paid scalar binary frames and per-occurrence ports, the minimum
is **n-1 roots for every n>=5**. The small minima are one root at n=1,2,3 and
two at n=4.

The [proof](PROOF.md) applies Arham Tahir's PR2795 root-code criterion to a new
fixed-order question. A rank-two quotient would force two nonadjacent positions
with different nonzero labels. Their complementary mask is unreachable.
Avoiding that witness would require a four-cycle inside a longer cycle.
Conversely, every parity hyperplane containing ones is feasible. Thus for
n>=5 the feasible reader codes are exactly full space and those hyperplanes.

Source order alone can consume extra dirty stock despite identical child
incidence. Conorholds's PR2182 uses a different source word and already attains
n-3 roots for n>=4. This package classifies the repeated-order family; it does
not improve or replay that predecessor construction.

The explicit upper program pays 2n source calls, 2(2^n-1) output readouts,
and `(2n-5)*2^n+4` full-row root XORs for n>=5. At n=5 it has four roots,
10 source calls, 62 readouts and 164 root XORs. Every readout computes one
root combination, reads it, and uncomputes it. The proof gives complete
actual-port price expressions and reserves all arbitrary dirt. This is a
root-stock optimum, not a transfer-cost optimum or a profitable supplier.
No new kappa or selected-frontier change is claimed.

## Reproduce

From the worktree root, with the standard library only:

```sh
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -W error -B research/cyclic-source-root-stock/verify.py
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/research_package.py --package research/cyclic-source-root-stock
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/check_research_commit.py --package research/cyclic-source-root-stock --check-source-history
```

The manifest runs both normal and optimized warning-strict verifiers. Expected:

```text
PASS_CYCLIC_SOURCE_ROOT_STOCK codes=3290 quotients=85818 omissions=236 roots=n-1_for_n>=5
```

The exact replay covers all 3,290 codes containing ones at n=1..7 and all
85,818 surjective rank-two quotients killing ones at n=5..9. At n=5,6 each
quotient's missing mask is separately checked against its entire kernel and
prefix-difference set. Literal forward/inverse dirty programs and cyclic-arc
identities cover n=1..10. All 236 operation omissions at n=5 reject, as do nine
invalid argument cases; the n=4 four-cycle exception is a positive control.
Universal scope comes from the written proof, rather than those finite counts.

[RESULT.json](RESULT.json) is generated by `verify.py --emit`, not handwritten.
It binds the six local source/metadata files and records the enumerated results.
The default replay recomputes the receipt and compares JSON with types retained.
From an exported package, `python3.12 -I -O -W error -B verify.py` needs no Git,
network, solver or predecessor executable. A new receipt must first be emitted
to the external run directory and compared before publication.

## Open next questions

- Can a specified other double-permutation order have a closed-form root
  minimum? Begin with one changed source order and its exact difference set.
  The obstruction here relies on the cyclic-arc support and does not transfer
  automatically. No larger root-code search is justified without that question.
- Can a real recursive caller expose this repeated source order and benefit
  from reordering its children? Start with the caller's full chronology, stable
  ports and live-root ledger. Physical access, scheduling, restoration and
  completed consumer costs are missing, so no adoption benefit is established.

## Code bounds

The verifier has no recursion, external processes or mutable shared state.
Source count is capped at ten; RREF inventory dimension at six; quotient words
at nine. At most 2,825 code sets are retained at once, each with at most 128
masks; compiled programs are capped at 45,000 records. Functions are under
60 physical lines. Always-enabled `require` checks retain all conditions under
`-O`; warning-strict normal/optimized registered runs check the actual artifact.

Power-of-Ten rule 3 has a managed-runtime deviation in verify.py. Python's
integers, sets, tuples and JSON allocate during enumeration. The fixed domains,
streamed quotient inventory, bounded program size and 100,000-byte receipt
limit bound live allocations. No fixed-pool implementation or byte-exact runtime
heap bound is claimed. If the replay caps expand, first reassess these bounds
or introduce fixed-capacity storage. Rules 8 and 9 use ordinary direct Python
functions; standard-library iterators and JSON dispatch have fixed targets and
bounded inputs. No unavailable compiler diagnostic is claimed as run.
