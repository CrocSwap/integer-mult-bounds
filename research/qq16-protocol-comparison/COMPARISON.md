## Boundaries and variants

The external boundary is entry to the original `RootLayer.fast_core` machine,
with its prepared source payload and fourteen encoded descriptors, through its
completed output at the same public physical output port. Unchanged surrounding
root preparation and normalization are paid on both sides. The statement is
about one modified outer root. All descendant C nodes still execute the original
controller. It is not an all-node substitution or a new supplier recurrence.

A executes the original selected arithmetic with embedded children. B executes
that same arithmetic and the same finite selected binding with the
external-call adapter and one extra controller bank. Its parent and child
controllers sequentially share the **same scalar, leaf and monomial primitive
objects, including the same Ordinary/native object**. These objects are closed
before each ownership handoff. Consequently their complete primitive invocation
sequence, physical identity and allocator history match A. B here means this
shared-primitive variant. The earlier independent-engine candidate is retained
as an explored fixture/conditional invoice; closed tape bodies alone did not
prove equality of its native allocator free-list/encoded-address costs. C and D use
#4166's altered arithmetic and decoder service, with fixed-copy and adopted-bank
publication respectively. B receives no decoder, acquisition bank, compiler or
additional Ordinary/native pipeline. Any protocol optimisation subsequently offered to D must
also be offered to B, or appear as a separately named comparison.

At each call the matched protocol boundary starts before `prepare_child`, with
a gathered parent group and canonical heads, and ends after the complete child
return with the same parent target, saved PC, group, borrowed values and heads.
`PROTOCOL.md` delimits the matched child-body subtrace and the unmatched root,
header, stack-prefix and return effects. Equal ranks do not establish this
relation. An external child's complete `run` already contains its descendants,
constructor/setup work within the call, copies and return; those are charged
once.

## Physical volumes and the source-derived capsule injection

Write `P=prefixes`, `R=rows`, `L=14336 Gamma`, `U=R/L`, active width
`e=73 lambda`, physical spacing `K`, and actual component width `H_b`.
Let

    b = front + 3 compact_bits + before + e K + after + back,
    row_bits = 2 H_b coefficients 2^b,
    v = P U row_bits,
    V = Gamma v,
    B_bank = 14336 V.

Here v is one owner packet, V one complete family, and B_bank one complete
parent bank. The service bank has 448V bits. The inherited root stock must
satisfy its depth law, not just R divisible by L. Every spectator, coefficient,
front/back field and physical width is retained. `W_c`, native reserve a,
`H_b` and address guard `H_g` remain distinct. A child of rank r has width
`r lambda` and after field `after+(73-r)lambda K`; its full packet volume is
still v. A logical width estimate cannot replace these volumes.

For a protocol cut, let S be the sum of all parent parked body lengths and C
be the sum of the fifteen prepared capsule body lengths. The latter includes
one payload and fourteen canonical Count bodies. There is an injective
body-length comparison **C <= S** at every admitted source child:

1. Capsule payload maps to the distinct parent target packet/private role.
2. The eleven unchanged Count descriptors map to the same parent descriptors.
3. Child rows are copied from the parent's derived `unused` Count.
4. Child width is strictly less than parent width, so its canonical binary
   Count body is no longer than the parent `width` body.
5. Child after satisfies `after_child <= b <= row_bits`. Its canonical Count
   body is therefore no longer than the parent's derived `row_bits` Count.

All fifteen receiving roles are distinct and occur in the parked tuple. A
canonical Count body length is `max(1,bit_length(n))+1`, including RIGHT, so
monotonicity also covers zero-valued after fields. The current parent bank,
header, unused descriptors and all other packet/private roles provide
additional nonnegative length. Thus S also exceeds B_bank. This is a
quantified source-geometry argument; finite `capsule_injection` tests are
controls, and host integer calculations are not an encoded implementation.

## Generic protocol credit and complete-root threshold

Use the exact source tariff derived in `PROTOCOL.md`. With k=15 capsule roles,
r=732 parked parent roles, and the stated lifecycle marker correction epsilon,
the original-binding **shared-primitive** copy-external adapter has the prepared-call difference

    F_B - F_A = 4 C + 113 - 56 S - 26 r + epsilon.

This is a sum of reads, writes and unit moves. The componentwise invoice is
retained in the protocol checker. It is not a scalar allowance or a time
measurement. The body correspondence is an essential premise of this formula. Sharing the
actual closed primitive objects preserves native allocator history across all
parent/child calls; this is the constructive repair for the independent-engine
comparison gap. Equality of closed bodies without this history relation is
insufficient. The formula is not asserted for the explored independent-engine
candidate or frozen #4166 merely because their endpoint values agree.
A conservative source bound epsilon<=705 permits one correction for each of
704 packet roles plus the protected output; any tighter lifecycle certificate
may improve the bound.

The injection gives, at every original root occurrence,

    F_A - F_B >= 52 S + 26r - 113 - 705
                >= 52 B_bank + 18,214.

The complete root has exactly 510,662 Gamma such calls, including the full
493,097 Gamma later suffix. Let E_B include all additional controller-bank
construction, marker initialization and final
retirement not already included in the complete calls, including the extra protected-output
read at outer `ExternalMachine.run` entry; also include any
separately priced finite-control delta. Then a sufficient same-boundary
improvement condition is

    E_B < 510662 Gamma (52 B_bank + 18214).

Under an admitted E_B upper bound the right side minus that bound is a
constructive lower bound on the whole-root saving. If E_B is not supplied,
the checker leaves the net sign unknown and returns this threshold. Unknown
setup is never zero. The extra controller bank is an explicit time/space
tradeoff: B retains two distinct sets of parent/child payload, descriptor,
stack, packet and scratch-pool roles, and one shared primitive pipeline.

`RESOURCES.md` supplies the conservative successful-construction/final-marker
retirement bill `E_B<=64J+1024=66496`, where the explicit added controller
inventory is `J=20+704+8+15+1+256+16+1+2=1023` tapes. The original
Ordinary/native pipeline is not constructed or retired a second time. Fixed
source tables are compiled before input; host allocation/compilation wall time
is not a tape action. Call-body cleanup is already charged in F_B. The
implementation must perform the declared controller-only final retirement, or
use its separately proved closed-marker boundary; it must not retire the shared
primitive bundle while the parent still needs it. The bound includes the one
extra protected-output read at outer adapter entry.

Every admitted owner packet is nonempty, hence `B_bank>=14336 Gamma`, whose
integer value has 2,642 binary digits. Substitution in the displayed whole-root
bound is strictly positive even after all 66,496 setup/retirement actions; the
conservative minimum net saving has 5,294 binary digits. These are bit lengths
of exact action/volume integers, not feasible fixture sizes or elapsed-time
measurements. The minimum is deliberately weaker than the actual physical
packet bound.

The same argument is stronger than an unweighted total. Negating the three
source invoices and substituting `C<=S`, `S>=B_bank`, `r=732` and
`epsilon<=705` gives these per-call coordinate savings:

    reads_A  - reads_B  >= 16 B_bank + 7272,
    writes_A - writes_B >= 18 B_bank +  760,
    moves_A  - moves_B  >= 18 B_bank + 10182.

Their slopes sum to 52 and constants sum to 18,214, agreeing with the total
bound by an independent coordinate derivation. For each coordinate, multiply
by all `510662 Gamma` calls and subtract the entire 66,496-action startup and
retirement upper bound. This remains strictly positive at the same minimum
bank. Subtracting that total in each coordinate is conservative because each
nonnegative startup coordinate is at most its total; it does not charge startup
three times in the actual bill. No chosen-weight timings or sampled tariff
experiment is used.

Therefore, under the exact protocol correspondence and the source resource
premises, **B(copy) strictly improves A in reads, writes and unit moves
separately at every admitted nonleaf selected-root geometry**, even after this
extra-controller setup and retirement. In particular, the whole-root comparison
improves for every fixed positive weighting of those three action types.
This conclusion covers every original root occurrence, including all later
calls, and is generic to the protocol. It is not credited to QQ16. Separately
priced finite-control transitions must be added if a richer tariff is used;
the exact sufficient threshold remains the displayed inequality with that
additional charge. No production payload is executed to check these enormous
integers.

## QQ16 incremental comparison

Use disjoint complete operation sums, at the same external boundary:

    T_A = N_A + sum_original F_A,
    T_B = N_B + sum_original F_B,
    T_D = N_D + sum_retained F_D + sum_32_added F_D + T_service_D.

N includes all nonchild setup, full-bank gather/scatter, scalar/maps, control,
public output and final cleanup. The service term includes encoded acquisition,
compiler arithmetic, assembly, the service's nonchild work, all 336 Gamma
complete external child calls, extraction, publication and disposal. It does
not add these descendants or copies again. The exact decomposition is

    T_D-T_A = (T_B-T_A) + (T_D-T_B),
    T_D-T_B = N_D-N_B + T_service_D
                + sum_retained (F_D-F_B)
                + sum_32_added F_D - sum_16_removed F_B.

This separates the generic protocol credit from the incremental QQ16 expense.
The sixteen removed terms here are **external B calls**, not original A calls;
using A's larger embedded bill would credit the generic protocol change twice.
Before the recovery fence, retained native calls may receive different data.
Their C costs cannot be cancelled from literal position, rank or output
semantics. For the suffix, #4166's completed fence/bridge refinement supplies
the same logical complete bank under its proved internal role permutation.
Original and producer parent bindings both have 704 packet slots, eight private
slots and the same parked-role count. But frozen D uses independent primitive
engines, while the new fair B shares A's actual primitive pipeline and its
complete allocator history. **Same suffix payload does not resolve that native
execution-context difference.** Keep a signed nonheader call-context residual
for every such occurrence until a separate allocator/codec action refinement
or a legal D_shared adaptation is proved.

One exact component remains available: the extra two D header bits cost
28 tape actions per suffix child. Source `FiniteFields.write` costs `5h+4`,
`read` costs `4h+7`, and header `clear` costs `5h+7`, totaling `14h+18`.
The 493,097 Gamma later occurrences therefore contribute exactly
**13,806,716 Gamma extra header actions**, plus their unresolved nonheader
call-context residuals. This is not the complete suffix difference.

The semantic payload partition also covers 10,577 prefix calls outside changed
cores 0 and 4. Events 1, 2 and 3 each have 3,494 children and all 704 owner
families are disjoint from changed data families 0..223; source idle event 5
contributes 95 children on disjoint families. The census checks these actual
finite sets. #4166's complete helper-endpoint refinement ensures their other
live helpers are in the required state. This is a conditional semantic
refinement, not a conclusion from supports or counts alone.

There are therefore **503,674 Gamma same-payload external occurrences**, with
**14,102,872 Gamma explicit extra D header actions** and a signed nonheader
call-context residual on all 503,674 Gamma calls. The **6,972 Gamma retained
changed-core calls** keep their full call differences, including any payload,
header and context effects. Equivalently the incremental identity is

    T_D-T_B = N_D-N_B + T_service_D + 14102872 Gamma
                + sum_same_payload tau_nonheader_context
                + sum_6972_changed_core (F_D-F_B)
                + sum_32_added F_D - sum_16_removed F_B.

This exposes the actual known component without making an unsupported suffix
cancellation. A claimed D_shared improvement requires its own sequential
primitive-ownership proof because D changes the arithmetic invocation sequence.
Any child-return optimisation available to both candidates must also be offered
to the fair B baseline.

Header contents, including changed source PC/target fields, are validated;
fixed-length binary serialization has no content-dependent action tariff.

The already established publication identity is
`T_C-T_D = 11 B_bank + 4 - c_R` within that same installation. B_bank already
contains Gamma. This is not added a second time, and is not attributed to the
new protocol. The isolated 368-versus-16 native screen is still only its
homogeneous component tariff; generic protocol credit can make D beat A
without making D beat the stronger B baseline.

With `M=2q^2+100696145` and one common 678-tape root wrapper, A uses
`678+M`, B uses `678+M+1023`, and frozen C/D retain the conservative
bound `678+3M+2^20`. The independent-engine explored baseline used
`678+2M`; its unproved allocator-history cancellation is not the primary result. Acquisition fields,
448V service copies/protected returns and 224/16 output/private obligations
are additional backing. Historical high-water backing is retained after
erasure; no freed-space claim follows from blank current cells.

`exact_decomposition` checks the identity on complete nonnegative action sums
and rejects duplicate/out-of-domain occurrence pairing. Its retained-credit
form reproduces #4166's threshold. A synthetic control has A=40, B=10, D=35:
the generic protocol saves 30, recovery adds 25, and D still beats A by five.
This is solely an accounting regression, not measured source evidence.
