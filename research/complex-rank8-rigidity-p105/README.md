# Rank-8 rigidity on every P105 unit, via PR1560's frame-incidence criterion (no new κ)

**Status: finite verification of a conditional theorem. No κ claim and no construction.** The algebra is
an664's [PR1560](https://github.com/CrocSwap/integer-mult-bounds/pull/1560), open at head `eb9f6f15`. This package
extends the P107/P106 package of [PR1616](https://github.com/CrocSwap/integer-mult-bounds/pull/1616) (head
`7b3e4624`, open) by one level and answers its first open question. It is self-contained: it does not import or
read PR1616's files, and it rechecks the coverage of every level from quadruples up.

**Theorem.** Let X be a 7-subset of P112 and L = P112 \ X. Let K be an L × L matrix over a field of
characteristic 0 with rank K ≤ 8 that satisfies PR1212's (E). Then K = D (2 G_L) D⁻¹ for an invertible diagonal D.

**Corollary.** In the E-graph model, every decoder with exactly eight costly terms on P105 has cst ≥ 57 = 72 − 15,
PR968's floor 72 − p reached through PR1212 §8. P105 (p = 15) is the bottom of PR968's 72 − p range, as PR1616
noted. The conclusion is conditional on the open PRs cited below.

## Proof

PR1560's Corollary 2 gives the conclusion for a live set L and a pivot frame F ⊂ L whenever four finite
conditions hold, all computed from root incidences alone (stated as in PR1616):

- **(D)** For each pivot k, the seven vectors G_ik G_il (l ≠ k) on I_k are independent, and the 0–1 incidence
  matrix of the live frames against I_k has rank |I_k| − 7.
- **(G)** For each pivot pair, the graph on I_kl is connected; i and j are joined when some live frame meets
  I_kl in exactly {i, j}.
- **(W)** Every pivot pair lies in a block that has one complete live class and a live line of the other class.
- **Nonempty blocks:** each of the 14 blocks has a live non-pivot line.

This package verifies the premises on every unit:

1. **Coverage.** H is the group generated by `verify.py`'s 8 FRAME0-stabiliser generators. `verify.py`
   rebuilds all of it (172032 elements) by breadth-first closure. H maps P112 to itself and frames to frames, so
   it preserves (E), the four conditions and their conclusion (PR1212 §10 transport). Coverage is four levels
   deep. A k-subset contains a (k − 1)-subset equivalent to a level-(k − 1) unit r, so it is equivalent to a
   candidate r + {x}. `verify.py` regenerates every candidate and checks that it is the image of its listed unit
   under its listed element of H:
   - 2517 quadruple candidates onto 180 representatives (from the 24 triple orbits);
   - 18782 5-subset candidates onto 1614 units;
   - 156627 6-subset candidates onto 19295 units;
   - 1651528 7-subset candidates onto the **242802 P105 units**.

   The transporters are stored as element indices, not words, so `COVER.bin.gz` is 5.1 MB.
2. **Units.** For each P105 unit, `UNITS.json.gz` gives a pivot (an index into the 2025 frames). `verify.py`
   checks that it is a live frame and passes (D), (G), (W) and nonempty blocks, exactly:
   - Ranks are computed modulo the prime 1000003, which gives lower bounds over Q.
   - The matching upper bound comes from the seven kernel vectors, which lie in every kernel by PR1560's
     identity (6); `verify.py` checks it once for all 2025 frames as Σ v vᵀ = 8 I.
   - (D) and (G) use the family of all live frames.

The units lie in distinct orbits by `make_units.py`'s census: orbit sizes sum to exactly C(112,k) for k = 4..7.
The argument does not need it. ∎

### What changed from PR1616's verifier

The tests are PR1616's. Three implementation changes make the 242802 units affordable (about 3× faster per unit,
roughly 5 ms instead of 17 ms on one Apple-silicon core):

- rows are int bitmasks, and each live frame's trace on the non-pivot lines is deduplicated first;
- (G) uses union-find with an early exit;
- (D)'s modular elimination first takes a greedy chain of rows, each with a 1 in a column no earlier chain row
  touches. Those rows are independent over every field, so few dependent rows are reduced before the rank
  reaches its target. Only the row order changes, never the rows, so the rank lower bound is unaffected.

A GF(2) rank never reached the target (0 of 1600 (unit, k) checks), so there is no binary shortcut. In a scratch
comparison the new criterion returned the same verdict and statistics as PR1616's on 300 P105 pivots, 1200
random (unit, frame) pairs, and 800 sub-family controls with (W), (G) and (D) failures.

## Results and controls

- **All 242802 P105 units pass.** Their pivots use 118 distinct frames; each unit has 630–833 live frames, (D)
  ranks 38–45 and 2–11 fully live blocks.
- The first live frame in frame order passes for 230560 units; at most 20 live frames fail before a pivot. The
  unregistered `tally_earlier.py` (stdlib, a few seconds) reruns the exact criterion on all 17429 live frames that
  precede a pivot: each fails (W) (17210) or nonempty blocks (219). So in
  every unit, **the first live frame passing (W) and nonempty blocks also passes (G) and (D)**. The criterion
  tests (G) and (D) last, so the earlier frames were never tested for them.
- `control.pr1560`: PR1560's fixture passes; its coverage-failure control (3, 13, 14, 22, 23) fails (W) at
  PR1560's pivot and passes at (2, 5, 15, 16, 30, 41, 109, 116).
- `control.rank-and-graph`: on PR1560's fixture, the pivot alone and the first 250 live frames each fail (G), and
  (D) when it is checked by itself.
- `control.g-without-d`: **(G) does not imply (D) for frame sub-families.** On the P105 unit
  (2, 3, 7, 12, 13, 30, 45) at pivot frame 543, an 80-frame sub-family of the live frames passes (W), nonempty
  blocks and (G), but on I_3 (47 lines) its incidence matrix has rank 39, not 40. The certificate is exact: the
  vector −1, −1, +1 on lines 42, 66, 93 kills every row and is independent of the seven h_3l. With all live frames
  the same pivot passes. This answers PR1616's question "does (G) imply (D)?" negatively for arbitrary frame
  families; it was found by a random scratch search (16416 sub-families of 20–300 frames at 608 P105 pivots, one
  hit).
- `control.first-frame`: on every 997th P105 unit, the first live frame fails (W) 11 times out of 244.

## Reproduce

From the repository root, Python 3.10+, standard library only:

```sh
python3 -I -B research/complex-rank8-rigidity-p105/verify.py --cover
python3 -I -B research/complex-rank8-rigidity-p105/verify.py --part 1/1
```

- `--cover` checks the model, generators, H, triple orbits, all four coverage levels and the five controls. It takes
  8 s and about 700 MB.
- `--part 1/1` checks all 242802 units: 200 s wall on 10 Apple-silicon cores (1861 CPU-seconds; about 5 ms per
  unit on one performance core). `--jobs` defaults to the CPU count.
- The registered replay (`python3.12 scripts/research_package.py --package research/complex-rank8-rigidity-p105`)
  runs `--cover` and `--part 1/3`, `2/3`, `3/3` and passes in 249 s wall here. Its timeouts (120 + 3 × 340 s)
  assume at least four runner cores; with fewer, run the parts by hand.
- Also run: `--cover` and `--part 7/50` under Python 3.10 and 3.14, and the 20 `tests/test_research_*` tests.
- Mutation controls (scratch copies): a non-live pivot fails with `pivot`, a first-live-frame pivot that fails
  (W) fails with `W`, and one changed level-7 element index fails `census.cover7`.

Expected final lines:

```text
PASS_COMPLEX_RANK8_RIGIDITY_P105: checks 13; every k-subset of P112 (k = 4..7) is equivalent to a unit
PASS_COMPLEX_RANK8_RIGIDITY_P105: checks 3; P105 part 1/1: every unit has a pivot satisfying PR1560 (D), (G), (W) and nonempty blocks
```

To regenerate the data (needs numpy; about 9 minutes with 10 processes, including the exact pivot search):

```sh
python3 -I -B research/complex-rank8-rigidity-p105/make_units.py --out-dir /some/new/dir
```

The pivot of each unit is its first live frame, in frame order, that passes the exact criterion. The census and
unit order reproduce the 242802 representatives of PR1616's unregistered `search_p105.py` run exactly, and that
run's float-rank pivots are the same frames. A from-scratch run reproduced both committed data files byte for
byte. numpy only proposes the grouping; `verify.py` checks every
transporter and pivot exactly. Line IDs are those of PR1560 and PR1616.

**AI review.** OpenAI Codex did a read-only adversarial review of `verify.py`, `make_units.py`, this README and
the metadata. It compared `criterion()` with PR1616's, and checked the bitmask rank bound, `chain_first` (it only
reorders rows), the four-level coverage induction including `closure()` and the cover parsing, and the 3-way
split (80934 distinct units per part, all 242802 covered). It found no soundness defect. Its one low-severity
point, that the (G)/(D) observation in Results came from a scratch run, is addressed by shipping `tally_earlier.py`.
This is not a human review.

## Open next questions

1. **Do (D) and (G) hold at every pivot that passes (W) and nonempty blocks?**
   - *Why it matters.* In the P107, P106 and P105 searches, the first frame passing (W) and nonempty blocks
     never failed (G) or (D); at P105 that is all 242802 units. Later frames were not tested. A lemma would leave
     two counting conditions and remove every rank computation from these replays.
   - *First step.* `control.g-without-d` shows that (G) alone does not force (D) for an arbitrary frame family,
     so a lemma must use that the family is all live frames (or a property such a family has). Search deeper
     deletions (P104 and below) for a pivot passing (W), nonempty blocks and (G) whose full live family fails (D).
   - *Blocker.* No candidate lemma yet.
2. **Nine or more costly terms.**
   - *Why it matters.* The rank-shape card asks for masked supports that change an assumption of the eight-term
     bound; this line now reaches P105 (p = 15) for exactly eight costly terms.
   - *First step.* State the nine-term E-graph equations and check whether PR1560's identity (6) argument has an
     analogue.
   - *Blocker.* No nine-term rigidity statement exists to verify.
