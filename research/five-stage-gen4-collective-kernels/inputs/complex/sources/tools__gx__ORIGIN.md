# tools/gx/ and tools/certificate/gcert1-p11-pr193.json.gz: where they come from

Everything in this directory is Python 3 (standard library only). No Lean is run by these scripts.
"The outside repository" means github.com/CrocSwap/integer-mult-bounds (Apache-2.0, `LICENSE` and `NOTICE`
of that repository; `NOTICE`: "A sharper exponent for integer multiplication, Copyright 2026 Douglas Colkitt").

## The scripts (this project)

| file | what it is |
|---|---|
| `gxcore.py` | loads a certificate of format gcert/1, brings it to normal form, and is a Python mirror of both Lean checks (labels and scalars); cut points and label data for the generator |
| `gxunit.py` | split plan of the kernel evaluations, the unit of the word, expected exponents |
| `gxbind.py` | the texts of the generated Lean modules (check, histogram, price, certificate and final modules) |
| `gxgen.py` | certificate -> Lean data modules and one module per kernel evaluation |
| `gxrate.py` | rate lemmas, unit price list, final theorem modules, comparator challenge / solution / configuration |
| `gxdry.py`, `gxmut.py` | dry run (mirror, sizes, plan, exponents); mutants that the mirror must reject |
| `gxconv.py` | converts the earlier format gcert/0 to gcert/1 when a step scales its target (the in-place pair step of #193) |
| `gsmirror.py` | a second, separately written Python mirror of the scalar check `GS.scalCheck` / `GS.yCheck`; `gxbind.py` calls it for the check parameters |
| `gx.py`, `gxrun.py` | the reference checker of the format (`gx.check1`: labels and exact scalar identity) and its command line |
| `gxpaths.py`, `regen_check.py`, `refcheck.py` | written for this repository: relative paths; regenerate and compare; `gx.check1` on a gcert/1 file |

The scripts are the working copies with path edits only (absolute paths of the author's machine replaced through
`gxpaths.py`; templates read from `tools/gen/templates/`; `foldlib.py` / `foldgen.py` taken from `tools/gen/`).
The sentences "Generated by checks/..." that the generators print into Lean files name the scripts by their
working paths; they are kept so that the generated modules come out byte for byte.
No script of the outside repository is included, imported or executed.

## The certificate `tools/certificate/gcert1-p11-pr193.json.gz`

sha256 of the file: `15251deb0c11e0504d7b297c9786818888a93f08b92b03c6c122784b70488633`
(gzip stores a time stamp; sha256 of the uncompressed JSON: `c64d2a95431c3cf24452de7391cce780bd71521da44ce23923ebb235f6c7962c`).

It is ONE explicit program (numbered registers, every addition, every frame) for the helper circuit at
h = 22: 1,320 ports, 9,412 slots, 262,944 unit moves. **The design of that circuit is not this project's.** It is the
"paired-cube" circuit of the outside repository as of pull request #193 (which builds on #191, #184, #168 and #144).
The outside repository publishes the design as generator scripts, frozen data files and a ledger; it has no file
of this kind. This file was produced by this project's own code, which

1. loaded the following files of the outside repository **as data** (JSON; nothing was executed):
   - at pull request #168, commit `4a3c769e5c5430e7114c4d3e099ff34664677f17`:
     `references/paired-cube/sources/local_L1.json`,
     `references/paired-cube/sources/tmod_TE_TD_TB3_1_1_4_full_6.0617964e-4.json`,
     `references/paired-cube/sources/pmod_J0_full_6.0666810e-4.json`,
     `references/paired-cube/sources/qmod_climb3u_best.json` (the local modules),
     `references/paired-cube/selected-module/matching-arcs.json` (carrier arcs),
     `references/paired-cube/physical/frames.json` (moved frames);
   - at pull request #193, commit `187e1010ac8b259af8e9b5166f68b64bc27b4b47`:
     `research/source-assisted-v4/data/physical-pairs.json` (the hand-over pairs);
2. rebuilt the circuit from them step by step, following the algorithms of the outside scripts (read as text),
   and checked the result exactly (every published count reproduced; the scalar identity as an identity of
   linear maps with arbitrary contents of the helper registers);
3. converted it to gcert/1 with `gxconv.py` (tested by `gx.check1`).

Step 1 and step 2 (the rebuild scripts and the outside inputs they read) are NOT part of this repository;
the inputs can be fetched from the outside repository at the two commits above.
What this repository proves about the file does not depend on how it was made: the Lean kernel checks the
generated modules (labels, scalar identity, price), and `regen_check.py` shows that those modules are exactly
what `gxgen.py` / `gxrate.py` produce from this file.

## Check it yourself

    python3 tools/gx/regen_check.py                       # regenerates the Lean modules and compares
    python3 tools/gx/gxdry.py tools/certificate/gcert1-p11-pr193.json.gz      # Python mirror of both checks
    python3 tools/gx/refcheck.py                          # the reference checker gx.check1 on the certificate
