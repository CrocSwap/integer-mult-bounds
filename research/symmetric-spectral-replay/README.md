# Faster complete alternating-plane replay with symmetric powers

This contribution was produced by Nick Petalas. Apache-2.0.

The complete primary replay of Ali Romman's [PR5624](https://github.com/CrocSwap/integer-mult-bounds/pull/5624)
takes **25.24% less median wall time locally** after computing only one triangle
of each symmetric adjacency power. All five alternating fresh-process pairs
improve. The result is a scoped implementation-equivalence proof, exact finite
conformance evidence and local performance evidence. It makes no new claim
about the predecessor's decoder theorem, no new kappa and no selected-frontier
change. Optimization stopped at this first verified improvement.

## The change and its proof

The retained primary uses the 336-by-336 adjacency matrix A of an undirected
plane graph. Its existing graph checks establish symmetric adjacency. Starting
with P=I, its five updates compute A P, hence P=A^k at every reached step.
Every such power is symmetric because

```text
(A^k)^T = (A^T)^k = A^k.
```

The new `symmetric_step` computes `(A P)[i,j]` with the original integer sum
only for i<=j, then assigns that integer to both `[i,j]` and `[j,i]`. The upper
entries therefore equal the original recurrence, and the power invariant
proves equality of the lower entries. Both implementations return fresh dense
integer matrices and leave the input unchanged. No modular or floating-point
substitution occurs.

`replay.py` retains the complete primary implementation. Its only executable
changes are insertion of that nine-line helper and replacement of the one
power-update expression. `verify.py` checks this exact byte-level adapter
against authenticated predecessor source before executing either consumer.
The retained `RESULT.json` is byte-identical to the predecessor's result.
The original package is unchanged.

This is a recurrence-specific helper. A symmetric arbitrary P need not commute
with A, so symmetry of A and P alone is insufficient. The helper has no public
arbitrary-matrix input contract. Two counterexamples explicitly make the
entrywise comparison reject use on a directed graph or a symmetric
noncommuting P. Signed commuting and zero matrices remain positive controls.

## New verification evidence

The new check compares all 112,896 entries at each of the five reached steps,
for **564,480 full-fixture entry comparisons**. It compares the entire final
scientific result with both the original consumer and its retained expected
result. All original spectrum/projector checks, 651 principal-minor checks,
native and tariff checks, and four scientific rejection controls execute
unchanged in each complete consumer. These predecessor checks are retained
coverage, not new mathematical results claimed here.

The entrywise instrumentation also counts the actual summands visited by each
loop shape. On every reached 20-regular graph step it records

```text
original:   2,257,920 integer summands
symmetric:  1,132,320 integer summands
saved:      1,125,600 per step, 5,628,000 across all five steps
```

The calculation still produces every dense entry. It avoids 281,400 duplicate
entry sums across those five steps; mirrored assignments are not free and
remain in the measured command.

An independent literal recurrence checks all 1,099 labeled simple graphs on
one through five vertices, for five powers each and 133,525 entry comparisons.
Ten new rejection controls cover changes to each of the three pinned source
files, missing/extra inputs, an absent source expression, an unrelated
scientific-code edit, removal of the substitution, and the two premise
counterexamples. Two signed/zero commuting controls pass. Explicit exceptions
keep all these checks active under optimized Python.

Every direct verification prints a generated receipt bound to all nine package
files by SHA256. No receipt is hand-written and verification writes no files.
The timing record is generated by `benchmark.py`; verification checks its
source/result bindings, five successful pairs and summary arithmetic. It does
not impose a performance threshold on other machines.

## Local timing and limiter

[BENCHMARK.json](BENCHMARK.json) records five alternating baseline/candidate
pairs of the **complete primary CLI**, each in a fresh process. Timed work
includes interpreter startup, geometry, native checks, all powers, all minors,
tariffs, rejection controls, complete result comparison and output. Both sides
use the same CPython 3.12.15, `-I -W error -B`, standard library and fixed fixture.
All ten commands exit successfully, emit the same complete-success marker and
write no stderr. Exact result equivalence is checked separately above.

| Complete command | Median seconds | Range seconds |
|---|---:|---:|
| Original primary | 0.477749666 | 0.463201875 to 0.488030500 |
| Symmetric primary | 0.357171625 | 0.355174584 to 0.378462125 |

The median wall-time reduction is 25.2387494%. The ranges do not overlap.
These are local measurements on macOS 27.0.1 arm64 with 18 logical CPUs.
Starting load averages were 1.14, 1.56, 1.62; final averages are retained in
the timing record. Other activity was not controlled. A separate correctness
process overlapped the start of the final series; alternating processes and
the recorded ranges expose this noise. No universal speed ratio is claimed.

An untimed-for-comparison cProfile run located the dominant work at the
original power expression: its inner generator resumed 11,854,080 times and
took 0.298 seconds of exclusive profiled time. `sum` calls took 0.643 seconds
cumulatively in the 1.019-second profiled `compute`. Profiled times are diagnostic,
not benchmark samples. The change removes duplicate CPU work in that measured
path. Remaining geometry, elimination, accumulation and process startup limit
the end-to-end gain. No persistent cache, skipped check or alternate fixture
explains the improvement.

## Implementation constraints

The changed helper is nine lines, has no recursion and uses fixed fixture bounds
of 336 rows and 56,616 upper-triangle entries. New verification functions are
under sixty lines. Small-graph loops have at most 1,024 masks at a size, ten
possible edges and five powers; reached matrices have at most 112,896 entries.
Source and receipt reads are capped at 1 MiB per file. The benchmark has five
pairs, two commands per pair and a 30-second subprocess timeout. Every exit
code, output marker, stderr result and explicit output write is checked.

Power of Ten deviations are confined to this isolated replay:

- Rule 3: Python exact integers and dense lists allocate during computation.
  The fixed domains above bound live matrices and collections; no persistent
  cache is introduced. A fixed-allocation native port would need a separate
  implementation and memory analysis.
- Rule 4: the inherited `compute` remains 85 lines. Keeping it byte-identical
  outside the single recurrence substitution preserves the complete source
  comparison and makes retained checks inspectable. Splitting that frozen
  consumer is outside this change; the new helper is nine lines.
- Rules 8 and 9: the equivalence verifier compiles two fixed local modules
  after authenticating the predecessor and checking the exact adapter. Its
  one temporary step wrapper has a visible fixed target and is restored in
  `finally`. These mechanisms observe the literal complete consumer without
  adding an unrelated imported API or changing its source. There is no
  user-supplied code or network execution.
- Rule 10: warning-strict normal/optimized execution and AST syntax/function
  inspection are the available diagnostics. Ruff is unavailable. No separate
  lint or static-type pass is claimed; shared CI settings are unchanged.
