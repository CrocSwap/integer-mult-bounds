# Cross-platform byte and codec reproducibility of the `make verify` surface

Verification engineering (sprint track 85–94), assignment seed 85.  Base
commit `91a2094f2e022930069e8cfdc810a3ea1b81cd09`.  Prepared with help from
opencode.  **Tooling improvement; no new kappa, no change to any mathematical
claim, certificate value, or the selected frontier.**

## Findings at the base commit (Windows 11, CPython 3.13.15, cp1252)

Running the offline `make verify` surface on a non-UTF-8 host reproduced three
concrete failures, none of them mathematical:

1. **`ranked-pair-check` crashes.**
   `research/ranked-pair-verification/verify.py` decoded `lean/CappedMass.lean`
   and `lean/ConcreteAssembly.lean` with `Path.read_text()` and no `encoding=`,
   so the locale codec applied: `UnicodeDecodeError: 'charmap' codec can't
   decode byte 0x9d` (cp1252), or silently wrong text where the bytes happen
   to decode.  On UTF-8 hosts the same command passes, so the check's outcome
   depended on the host locale.

2. **`machine-transfer-check` crashes.**  Same root cause inside
   `research/machine-transfer-verification/next-proof/analytic/check.py`
   (`row_region.count("⟨")` counted 0 against cp1252 mojibake, raising
   `Unexpected literal row constructors`).  The whole 240-file package is
   frozen byte-for-byte by its own `publication-manifest.json`, so its sources
   cannot be edited without invalidating the reviewed publication bytes.

3. **Every regenerated certificate was byte-different.**  `scripts/` generators
   wrote certificates through unpinned text writes, so `'\\n'` was translated
   to `os.linesep` (CRLF on Windows).  39 certificates regenerated by the
   audited checks differed from their tracked bytes in **every line**, while
   being equal after newline normalization (verified for 39/39 files).  Any
   byte-level receipt (`sha256` of a regenerated artifact) diverges from the
   Linux reference this way.

A static inventory (`locale_inventory.py`) found 7157 locale-dependent text
I/O sites across `scripts/`, `research/`, `tests/` and `formal/` at the base
commit; 150 of the write sites are in the `scripts/` generator surface that
`make verify` runs.

## What changed

- **`Makefile`**: `export PYTHONUTF8=1` for all recipes.  Checks run under the
  same text codec on every host; on Linux nothing changes (the locale codec
  is already UTF-8).  This is what makes `machine-transfer-check` pass without
  touching its publication-frozen sources.
- **`research/ranked-pair-verification/verify.py`**: explicit
  `encoding='utf-8'` on its three text reads (this chain is not hash-pinned by
  any manifest or receipt), so direct invocation also works without env help.
- **`scripts/`**: 139 text writes across 126 files pinned to
  `encoding='utf-8', newline='\\n'` — one keyword pair per call, nothing else
  changed.  Applied mechanically by `pin_text_writes.py --fix` (ast-based; the
  diff is one line per call).  Frontier- and receipt-frozen scripts are
  skipped (below).
- **27 certificates regenerated** (`certificates/*.json`).  Their only change
  is the recorded `source_sha256` of the generator sources that were edited;
  every other field and every line count is unchanged (machine-checked in
  `evidence/regeneration-receipt.json`).  This is the repository's documented
  "include regenerated certificates in the same change" step.
- **`tests/test_locale_reproducibility.py`**: four regression guards (below).

## What is frozen and therefore not touched

`pin_text_writes.py` refuses to modify a script when

- it is named by path in `certificates/selected-result.json`, a
  `certificates/checkpoints/*.json` record, or
  `research/community-frontier799-audit/SELECTED-SOURCE.json` (9 frontier
  replay drivers), or
- its sha256 appears in a frozen `docs/research/*.json` receipt.

The second rule caught three files after the first mechanical pass and their
edits were reverted: `scripts/audit_community_candidate.py` (its bytes are
pinned by `docs/research/community-followup-arithmetic.json`, which
`audit_followup_candidate.py --check` compares against — the check failed
until the revert) and `scripts/verify_frontier617.py` /
`verify_frontier617_bindings.py` (tested-source digests recorded in
`docs/research/community-cold617-integration.json`).  43 scripts are skipped
as frozen in total.  `docs/research/preserved-research-manifest.json` records
`original_sha256` — the bytes as of its historical `base_commit` — and does
not freeze current sources; the 30 scripts it documents by original digest do
carry the mechanical pin in this change.

## Reproduce

One command (the regression guards):

    python3 -B -m unittest discover -s tests -p 'test_locale_reproducibility.py' -v

Expected: `Ran 4 tests ... OK`.  The four guards:

1. `ranked-pair-check` passes under a hostile locale (LC_ALL=C, no UTF-8 mode)
   with its `PASS ranked pair` receipt line.
2. `machine-transfer-check` passes the way `make` runs it (UTF-8 mode pinned)
   with `PASS machine-transfer offline checkpoint`, and the Makefile keeps
   that pin.
3. A real generator (`scripts/audit_cube_cores.py`, from `make verify-research`)
   regenerates `certificates/cube-core-family.json` byte-identically.
4. `pin_text_writes.py --check` reports `0 unpinned text writes` in `scripts/`.

Supporting evidence commands:

    python3 -B research/agent-08-verifeng-seed85/pin_text_writes.py --check
    python3 -B research/agent-08-verifeng-seed85/locale_inventory.py
    python3 -B research/agent-08-verifeng-seed85/survey.py --output evidence/survey-after-fix.json

`survey.py` runs the runnable `make verify` surface in fresh processes and
records wall time, exit codes and output digests;
`evidence/survey-baseline.json` is the pre-fix run (at the base commit),
`evidence/survey-after-fix.json` the post-fix run.  After the post-fix run the
regenerated artifacts differ from the tracked ones only in recorded source
digests (`evidence/regeneration-receipt.json`).

## Measured before/after on this host

- `ranked-pair-check`: `UnicodeDecodeError` exit 1 → `PASS ranked pair`
  exit 0 (1.3 s), in a hostile locale.
- `machine-transfer-check` under `PYTHONUTF8=1`: `Unexpected literal row
  constructors` exit 1 → `PASS machine-transfer offline checkpoint` exit 0.
- Regenerated certificates: 39/39 byte-different (CRLF in every line) before,
  0/27 byte-different except recorded source digests after.
- Full isolated test suite: failing set after the change is exactly the
  15-module environmental set recorded for the base commit in PR #921's
  benchmark evidence (no test outcome changed).

## Scope and unresolved obligations

- **No mathematical content changed.**  No certificate value, constraint,
  kappa, patch payload or proof source differs; only generator text-write
  keywords, three read call sites, one Makefile export, and the recorded
  generator-source digests of 27 certificates.
- `machine-transfer-check` invoked **directly** (without the Makefile's UTF-8
  mode) still fails on non-UTF-8 hosts: its checker sources are frozen by
  `publication-manifest.json`.  `make verify` runs it correctly.
- Residual, unchanged by design: 14 `open()` calls in `scripts/` with
  non-literal file modes (the lint leaves them alone and reports them), the
  43 frontier/receipt-frozen scripts, and all `research/` package generators —
  a `research/`-side generator that writes tracked text can still emit
  CRLF-translated output on Windows.  The repository-wide inventory
  (`locale_inventory.py`) lists the sites; this change deliberately fixes only
  the `scripts/` make surface.
- Not re-run here (no numpy/sympy/scipy, no C++ toolchain on this host):
  `gen4-bank-verify`, `frontier741/799-verify` chains, `prime_field_network`
  and `audit_positive_skip_exact` (both compile C++ producers), the Lean
  builds, and the 15 environmental Windows test modules (e.g. `resource`
  imports).  None of their bytes changed.
- Under Python 3.15+ UTF-8 mode is expected to become the default (PEP 686);
  the pinned mode and explicit encodings stay correct there.
