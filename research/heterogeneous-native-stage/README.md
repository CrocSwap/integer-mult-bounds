# Heterogeneous native stages: a changed-demand screen

A partial native stage on 60 of the 112 ports returns the original paid
profile plus 120 rank-one children, with all 408 original helper jobs.
That returned invoice loses after complete controller repricing. There is
no cheaper native word, supplier admission or higher kappa.

## Scope and evidence

The previous five-choice fixed-demand screen in PR5212 found no gain. This
changes the native endpoint demand instead: at each of 60 actual central
lines contained in ker(1), intersect both main exit charts with ker(1).
Their dimensions fall from 9/8 to 8/7, while the central line remains in
the X chart and outside the Y chart. The other 52 ports stay unchanged.
Main inputs, scalar word, common scalar contacts and all eight paid centers
remain. Both helper boundaries and 72 late native maps are variable, with
the twelve prelude line relations preserved. Other native boundaries stay
fixed. All former zero bridges are charged.

This is outside the full/query-only alphabet in the path-thinning ceiling.
The first optional binary solve used 9,188 contacts and 14,480 pair terms.
SciPy 1.18.1/HiGHS returned no internal moves, the source plus 120 H1,
in .951 seconds under a 120-second cap. Its status 0 and floating dual zero
are not an exact lower bound for that model. DISCOVERY.json records the run.

The relative price proof in [PROOF.md](PROOF.md) covers every nonempty subset
of the 18 full stages in the actual p16 controller when each selected stage
uses that returned invoice. All changed main and idle ranks are repriced,
and no productive helper is lost. For every saving C in [0,17/5000], the
complete target-minus-paid margin decreases by at least 1038/5 per changed
stage. This is a scoped all-subset statement about the returned cost, not
an optimal native-cost theorem or a universal stage obstruction.

At C=.00302177585, the 18 single-stage replacements have complete negative
margins between approximately -237.853 and -237.771. Replacing all stages
gives approximately -4281.04033. The original margin is about .00000513644.
Exact rational intervals and stage incidences are in [RESULT.json](RESULT.json).

## Reproduce

Registered verification uses Python 3.12 and its standard library:

```sh
python3 -B scripts/research_package.py --package research/heterogeneous-native-stage
python3 -I -O -B research/heterogeneous-native-stage/verify.py
```

The read-only checks authenticate every imported input, check all 120 fixed
changed endpoints, reconstruct the returned local invoice, independently
bind the complete baseline controller to the source arithmetic, reprice
every single-stage case, and check the exact derivative/incidence bound for
all subsets. They reject thin/nonexistent stage choices and releasing a
forced output. The first-stage rank-mass loss is checked as 240, including
both target and paid changes.

Optional discovery needs NumPy 2.5.4 and SciPy 1.18.1 and writes DISCOVERY.json:

```sh
python3 -B research/heterogeneous-native-stage/stage.py
```

Normal replay runs no solver. Sources and invalidation are pinned in
[SOURCES.json](SOURCES.json). Frozen predecessors and the selected conditional
kappa .00302015 remain unchanged. The proposed heterogeneous Gaussian
endpoint/normalizers, signed native maps, both literal orientations, owned
restoration, uniform compiler, precision/tape and outer transfer have not
been admitted. The price screen grants the proposed ranks; it does not
establish the corresponding physical endpoint.

## Open next questions

A different partial-stage invoice must save enough local paid-minus-helper
cost to fund the lost main targets and changed idle work. The returned
terminal adapters do the opposite. Name an actual removed paid operation
and test the complete replacement invoice before expanding the stage family.
Larger output-mask scans have no support from this result. Even a favorable
invoice needs shared-G synthesis, exact phases and supplier/outer funding.
