# Independent agent review: fixed packet limits

The review accepts the two finite negative results in the stated models. It
does not certify a new supplier, an unrestricted centre-encoding lower bound,
or a kappa improvement. This is an independent OpenAI Codex agent review. It is
not human review or proof-assistant verification.

The review applies to the package bytes in `CHECKED-FILES.json`. The exact
replay commands and their results are in `REVIEW-RESULT.json`. The publication
comparison uses upstream commit `cef4b52f2a59009865bf8eabde1be3f159063703`.

## Joint partial-basis result

I read the proof, both matrix engines, the command driver, the literal packet
factory proof, the source pins, and the source notices. I checked the following
argument against the implementations.

At the forty-operation factory cut, each tetrahedron has twelve existing
two-source directions. A choice of four independent rows gives a query matrix
Q. The required own-block response O fixes the output matrix K = O Q^-1.
The identity KQ = O is checked with exact rational arithmetic.

The model requires every early query to fit the common final output cap of its
connected output component. This is a hypothesis of the screen. It must not be
inferred for an arbitrary ordered scalar implementation merely from the
undirected support graph of K. The factory, twelve second face copies, ordinary
late pair operator, and early retired-donor centre interface also remain fixed.

Under that contract, the component test is a necessary clean-source test.
Different face keys have disjoint source support, so recombination of these
keys cannot cancel an excluded source coefficient. A four-output component has
no early face key. The three paired bases each have four early keys. The exact
enumeration gives 495 subsets and 315 independent bases per tetrahedron:
312 have one component of size four, and three have two components of size two.
The second engine uses SymPy determinants and graph closure. It does not import
the Fraction producer.

For every paired choice, the centre deficit is the rational quotient rank of
the four coordinate totals modulo the rows of donors retired by disjoint face
assemblies that avoid the eight protected query carriers. Granting one new
carrier per missing scalar direction is a favorable inventory relaxation. The
possible triples (centre deficit, ordinary clones, helper inventory) are
(0,8,36), (1,8,37), and (4,4,36). A case with a four-output component already
needs at least eight ordinary clones, even if its centre storage is free.

The replay checks all fourteen blocks, 13,860 subsets, 8,820 independent bases,
and 126 paired centre cases. The minimum is 36 slots per block and 504 in total
in this inventory model. The current first-partition case attains that inventory.
This does not emit or admit a changed scalar word. Arbitrary query directions,
different restoration schedules, shared centre state, new packet factories,
and new late delivery operators are outside this result.

## Delayed injection result

I read both propagation engines and the handoff. The necessary correction at a
B prefix is the original cut column multiplied by that prefix's target block.
The background never reads a target into a non-target. Target additions and
nonzero scales make the target block invertible. Thus the prefix transport is
valid for an unchanged saved centre value and unchanged B word.

The tested boundaries are before B, after a scalar event, and after a full
annotated target-frame change before its scalar event. Each word has 1,893
scalar events and 544 target-frame changes, for 2,438 boundaries. Injection
inside a frame-transition implementation is not included.

For canonical frame subspaces, the transition distance is
dim(F)+dim(G)-2 dim(F intersection G). It is a metric. A path that serves all
nonzero transported target entries must visit their actual frames. Remove
intermediate path vertices by the triangle inequality, and then remove a
cycle if necessary. The minimum spanning tree on the start and served frames
therefore gives a valid path lower bound. The proof grants arbitrary delivery
order and arbitrary intermediate canonical frames. Storage and other positive
costs are omitted.

The productive variant has a separate hypothesis: there is one distinct
productive carrier per centre, exchange at its original rank-eight frame is
free, its exit is FULL9, and only its old rank-one completion is subtracted.
The path must include FULL9 and every served frame. In addition to the tree
bound, it has length at least d(start,F)+d(F,FULL9) for each served F. The parity
of total canonical distance is the endpoint dimension difference, which is
odd. The code takes the larger bound and rounds up to this parity before it
subtracts one. This proves an extra rank bound in that favorable model; it does
not prove the scalar exchange exists or price a general productive encoding.

The forward engine uses rational column propagation, binary elimination, and
Prim's tree algorithm. The second engine reconstructs the terminal R/4 decoder,
undoes target operations, restores prior target frames, uses complete binary
subspace point sets, and uses Kruskal's tree algorithm. It verifies return to
the original cut column and frame-zero targets.

For each of the zero-, four-, and eight-cold words, both methods give eight
private bounds of eight, with total 64. The productive extra bounds are eight
copies of sixteen, with total 128. Separate cuts for separate centres do not
reduce these bounds. These are rank bounds, not native fee or kappa bounds.

## Negative checks and reproduction

The joint driver changes a true centre deficit of four to zero. The independent
engine rejects it with `An unpaid center direction was claimed free.` It also
replaces the common output cap with the full nine-dimensional frame. The
independent engine rejects it with
`The printed output cap includes a forbidden restored direction.`

For each delayed word, omission of the first cut term changes two terminal
decoder entries. Additional review controls change a private per-centre bound
from eight to seven, and a productive extra bound from sixteen to fifteen.
The reverse engine rejects them at the corresponding exact bound comparisons.
These controls operate on copied output trees only.

The wrapper rejects optimized Python, an existing output directory, and a
changed frozen proof byte. The source-hash failure occurs before output is
created. An initial review harness expected a prose message for the existing
directory case; the wrapper raises `FileExistsError`. The corrected harness
checks that actual exception. This was a review-harness expectation error.

The fresh replay used CPython 3.14.7 and SymPy 1.14.0 from the retained main
environment. It ran one subprocess at a time with thread limits of one. Its
five top-level checks passed. Exact commands, per-check exits, semantic control
exits, and script/input hashes are retained with this review.

A later wrapper correction removes `PYTHONOPTIMIZE` from the environment that
it passes to children. Without that correction, a parent started with `-I`
can ignore this variable while its children still consume it. I read the
correction and tested the supplied child environment for all five wrapper
calls. With `PYTHONOPTIMIZE=1` and parent `-I`, real child and grandchild probes
each had optimization level zero and active assertions. This was a narrow
environment test, not a second mathematical replay. The finite mathematical
scripts and compressed inputs remain byte-equal to my fresh replay. The
packaging agent also ran the actual corrected wrapper under that environment;
its separate receipt records five passing checks.

## Limits

The finite arithmetic checks and the stated metric argument support the exact
scoped claims. They do not verify arbitrary borrowed-state correctness of a
new construction, source access for a new operator, native phases, whole-owner
hosting, all-size composition, a full invoice, or an outer recurrence. No
current selected supplier replay, full PR531/PR564/PR569 replay, Lean run,
hosted CI run, or kappa calculation was performed for this review.

The publication should say that these are two scoped obstructions. It should
not call them a strict performance improvement or a complete centre-encoding
solution. The original breakthrough objective remains unresolved.
