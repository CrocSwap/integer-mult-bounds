# Delayed center injection checkpoint

No new word or kappa gain was found. This screen keeps each old center value,
one held copy per center, the existing B decoder and its actual TARGET frames.
It permits a different cut and delivery order for each center, then removes
storage, owner, wrapper and ordinary costs from the lower bill.

- Zero: 2438 cuts; private rank lower bound 64; productive extra rank lower bound 128.
- Four: 2438 cuts; private rank lower bound 64; productive extra rank lower bound 128.
- Eight: 2438 cuts; private rank lower bound 64; productive extra rank lower bound 128.

The canonical transition metric is dim(F)+dim(G)-2dim(F intersect G).
A route that visits every served frame has cost at least the minimum spanning
tree on those frames and its start. The screen uses this necessary bound.
A late cut can reduce the support, but its surviving TARGET frames differ.
The endpoint-only relaxation omitted that visiting cost and suggested rank16.
It was not a construction. That failed hint remains saved separately.

The first checker propagates the correction through B and uses Prim's tree
algorithm. The second checker starts at the full decoder R/4, moves backwards,
uses literal binary subspace point sets and Kruskal's tree algorithm. The root
read the argument and reran the second method with exit0. Omission of the first
cut term gives a nonzero output in each provider. This is a finite, canonical
frame screen. It does not close split injections, shared carriers, a new B word,
a joint SOURCE/TARGET operator, different tags or a new controller. The proposed
productive scalar exchange was relaxed for a lower bound; it was not built.

Run from the autonomous run directory:

    venv/bin/python -B productive-joint-research/check_delayed_injection.py

and checker. Source inputs come from eumemic's PR564 at
