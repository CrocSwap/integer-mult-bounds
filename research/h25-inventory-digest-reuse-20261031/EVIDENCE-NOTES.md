# Executed-evidence appendix: provenance and reproduction limits

This appendix retains execution source, proposals, source reviews and raw records
from the named digest stream. The fixed schedule completed once; independent
reviews accepted the 54 controls and narrow inventory F7 comparison. Actual
metrics and limitations are recorded in PUBLIC-OUTCOME.json. The initial source
commit is retained separately through unchanged TREE-SOURCE-v1.json.

`execution-source/` contains the exact 11 source files proposed for the adapter,
parent envelope, jobs, source audits and runtime/file identity manifests.
`validation/controls/` preserves both operation proposals, their launcher/phase
bindings, the rejected v1 boundary finding and v2 source admission review.
`validation/source-publication/` preserves independent acceptance of the original
60-file source export. These are scoped historical reviews, not a blanket replay
or final-scientific acceptance.

`evidence/execution-v1/` preserves the new stream's raw runner/envelope, stage,
admissions/ledgers, attempt stdout/stderr/time reports and per-operation retained
runtime records. Empty stderr files are retained as observations. The active
`runtime/science.lock` is excluded: lock state is not a scientific observation.
Raw JSON and command arrays retain absolute original paths and exact host pins;
no original path, hash, label or result is silently rebound to the export.
The export manifest maps each copy to its exact original workspace file.

BOUNDARY-01 rejected proposal v1 before execution because the proposed outer
measurement omitted independent parent output/boundary checks. It is a blocking
source-design finding, not a failed target execution. The additive parent
envelope and proposal v2 preserve that objection and move the required finite
checks inside the timed boundary. Only actual evidence can establish whether
those checks returned successfully on an executed operation.

The original absolute argv, Python/runtime/module origins, host file identities,
source/stage/runner hashes, locks and one-use grants are provenance for one host.
The publication export is not a portable grant or a directly reusable launcher.
Reproduction requires a fresh independently reviewed operation proposal with
actual host/path/runtime/source and resource/ledger bindings, disjoint fresh
outputs, and a newly admitted one-use command. Restoring the 48 original source
modes is necessary for the accepted consumer contract; it does not rewrite or
admit the execution-source host pins. Do not edit historical pins/receipts to
manufacture a successful replay on another host.

All observations, including first samples and any errors/timeouts, must remain
visible. Comparison metrics use the same declared complete outer boundary for
both arms; inner target counters and nested times are not additive. GNU time's
wall/user/system observations have hundredth-second reporting resolution. Inner
target-group samples and per-process RSS observations are not an exact
simultaneous whole-process-forest peak. Two samples per arm do not establish
statistical significance, full H25/caller performance or a universal speedup.
Preparation/review/staging/mode restoration/publication and final reporting
outside the declared measurement boundary remain separately known or unknown;
none is silently assigned zero. The original goal's historical timing and final
metadata-publication obligations remain open.
