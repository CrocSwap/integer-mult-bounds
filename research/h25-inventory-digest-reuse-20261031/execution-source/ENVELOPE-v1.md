# Additive inventory parent validation envelope

The original component, execution adapter, seven-file execution source package
and their prior pins remain unchanged. This additive source repairs the concrete
measurement gap: the unchanged inner guard validates stage and retained logs but
does not independently inspect component output. `parent_envelope.py` runs the
unchanged guard and completes independent output/status/custody checks under the
same outer GNU time command. No component or adapter is imported by the envelope.

The parent copies the exact envelope to its execution-v1 root. Its only command
is `/usr/bin/python3.12 -B parent_envelope.py inventory-v1 JOB JOB`, where JOB is
one of the six fixed declared names. The envelope pins the actual existing
inventory-v1 STAGE, unchanged runner, JOBS, package and runtime manifest digests.
It rejects another root/stage/job/label or an existing evidence folder. No
caller-supplied output path, retry, alternate workload or detached child is used.

The exact parent outer launcher must use GNU timeout `--foreground --signal=INT
--kill-after=3s 117s` beneath GNU time. Foreground mode sends the timeout signal
to the envelope only; its signal handler forwards SIGINT once to the unchanged
guard child, which shares the envelope session/group. The guard's existing
finally kills/reaps its own detached target. The envelope waits for the guard
and runs its own finally checks even after nonzero exit/interruption. Duplicate
process-group SIGINT can interrupt guard cleanup, so omission of --foreground
is not admitted for this route. SIGKILL after the grace period can prevent
finally/receipt completion; preserve all files and mark that attempt STOP,
never successful closed validation or retry permission. This source was not
executed to establish timeout/reaping behavior; independent source review and
actual exact launcher admission remain mandatory.

The timed envelope performs fresh stage/package/external/runtime authentication
before dispatch. In finally it independently attempts each source category,
guard receipt/logs, component outputs, its own source identity and retained root
census. Package checks cover all11 payloads; external checks cover all36 original
source/fixture files; runtime checks cover all86 pins and actual envelope module
origins. File hashing streams bounded chunks and preserves regular-file/path/
descriptor identities. Malformed/missing/changed files cause STOP. Each failed
check is retained; one failure does not suppress later independent categories.

For successful guard receipt verification it binds the exact stage/runner/job/
label/command, START fields, original fractions readback, log byte counts/hashes,
empty stderr/exact adapter stdout, usage, memory/time caps, and guard source/log
stability flags. It reads adapter before/after runtime/package/external counts,
source anchors, module origins, mode, returned status and exact cleanup record.
Component custody is reconstructed independently from the accepted manifest,
not accepted from either arm's claimed result.

Normal/-O controls require the original eleven exact ordered names/outcomes,
their flags/status, sixteen additional exact ordered names/count/status/flags,
and independently declared hash/read sequences and totals for every new row.
Representative arms require the declared32file/453700byte/128call dimensions,
source-derived read/hash counts, an independent expected mapping from exact
FIXTURE rows and original source pins, and exact canonical inventory.json bytes.
This compares both arms against the same independently derived fixed expectation;
it does not claim a separate cross-arm comparison already executed. Stage and
manifest authentication covers the expected fixture's own identity. Scratch,
science/component inventories, and retained run output census must be exact.

`parent-validation.json` is additive, written/readback before envelope exit and
therefore inside GNU time. On prelaunch/guard failure leaving no run folder,
a distinct fixed control/parent-validation-JOB.json retains failure without
fabricating a successful run. Primary nonzero/interruption is preserved even if
postchecks appear valid. Existing validation evidence is never overwritten.
Any missing/incomplete envelope result is STOP. Its new imports signal and
subprocess and their ordinary dependencies already occur in the accepted80-origin
runtime map; no runtime manifest change or target import is needed.
