# A 54-batch phase-B witness for the fixed gauge44 word

This construction and verifier were produced by Nick Petalas. Apache-2.0.

Claim type: **finite certificate with a scoped substitution proof**. Each of
both frozen gauge44 orientations admits 54 disjoint batches of sixteen
rank-one climbs in phase B. This raises the known feasible count from the
52 batches reported by Josie Elliston's [PR #1817](https://github.com/CrocSwap/integer-mult-bounds/pull/1817)
to 54. The exact maximum remains in **[54, 67]**.

The new witness uses 864 of the 1,072 phase-B rank-one climbs. Its reordered
word preserves every original event, the non-rank-one skeleton and all 712
shared-role occurrence traces of each 24,767-event orientation. The two new
word hashes are generated by the verifier. No physical rank-16 child,
recursive saving, new kappa or selected-frontier change is claimed.

## Contract

The input is the historical #1094 gauge44 provider retained in
`research/community-frontier1094-audit/selected-replay.tar.gz`, member
`candidate/strict/global/base/providers/gauge44/LOCAL-PROGRAMS.json.gz`.
The archive and member SHA256 values are hard-pinned in `verify.py`.
`SOURCES.json` pins the archive and the predecessor documentation/code.

Only rank-one climb occurrences may move. They stay in phase B and may
cross only events that touch no register of their own. All other events
retain their order. Each batch has sixteen different destinations and no
climb belongs to two batches. The witness groups the original climbs; it
does not replace them with a native rank-16 operation.

`CERTIFICATE.json` gives the skeleton gap and sixteen original global event
indices for each batch. Gap zero precedes the first non-rank-one event of
phase B. Gap g follows exactly g such events. Indices refer to the original
whole program, starting at zero. One table works for both orientations;
the verifier checks each orientation separately.

## Construction and proof

Delete the rank-one climbs from phase B to obtain the fixed skeleton. For
a climb at original gap g on register r, its legal interval begins just
after the last skeleton event touching r before g. It ends just before the
first skeleton event touching r at or after g. Both endpoints are legal
gaps. These are the legal windows introduced by #1817.

The new deterministic pass considers every original right endpoint. At each
endpoint, it selects the sixteen available climbs with shortest window
width, then earliest right endpoint, then original event index. It chooses
the candidate group with least total window width, breaking ties by gap,
and removes those climbs. It repeats until no group remains. The first pass
produced 54 groups. No further search was made for a larger result.

The verifier's default path checks the committed certificate without
running this heuristic. It reconstructs all legal windows from source
bytes, checks event uniqueness, window membership and distinct
destinations, emits batches before unbatched climbs at each gap, and checks
that every batch is contiguous in the resulting word. Unbatched climbs
retain their original gaps and order. The phase-B skeleton has 2,630 events.
Exactly 208 rank-one climbs remain unbatched.

The checker then compares the complete ordered list of original occurrence
indices touching each role, including scalar reads and writes, all adapters
and centre roles. It also checks the whole event permutation, skeleton and
unchanged events outside phase B. Equality of these traces proves that the
new word is a linear extension of the original shared-role dependency order.
To transform one order into the other, move each next desired event left
across intervening events. None can share a role with it, since that would
reverse their common-role trace. Thus each swap commutes as a complete
logical operation on disjoint registers. Induction proves the same map on
arbitrary inputs under the retained logical operation semantics.

This substitution criterion also appears in ToikY's
[PR #1833](https://github.com/CrocSwap/integer-mult-bounds/pull/1833).
Here it is applied only to the new witness. The predecessor's hosting
projection result is not extended or replayed. Shared physical scratch,
native compilation and tape behavior require their own implementation
contracts.

The cardinality bound is floor(1072/16)=67. The certificate supplies the
lower bound 54. No optimum or exclusion of counts 55 through 67 is claimed.

## Reproduce

From the repository root, with CPython 3.12 and its standard library:

```sh
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -I -W error -B research/phase-b-54-batches/verify.py --check-discovery
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -I -O -W error -B research/phase-b-54-batches/verify.py
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/research_package.py --package research/phase-b-54-batches
/Users/nick/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/check_research_commit.py --package research/phase-b-54-batches --check-source-history
```

Another CPython 3.12 executable may replace the absolute path. The direct
marker is `PASS_PHASE_B_54_BATCHES`; the package marker is
`PASS_REGISTERED_RESEARCH_PACKAGE`. The generated stdout receipt binds every
package file, the frozen archive/member and both new logical word hashes.
Default verification writes no files. `--check-discovery` additionally
reconstructs the deterministic witness and compares it to the certificate.
`--write-certificate /external/scratch/NEW.json` regenerates the certificate
at an unoccupied path and refuses to overwrite an existing file.

Eight rejection controls run on each orientation: a short batch, reused
climb, out-of-range gap, non-rank-one event, cross-phase climb, a gap outside
a climb's legal window, repeated destination and a climb swapped across its own preceding
operation. Checks use explicit exceptions and remain active under `-O`.

## Scope and engineering notes

This is a historical scheduling side result under a changed
`complex-rank-shape-decoder` scope. Current selected #7000 at
kappa 0.00363005817 is unchanged. The actual paid profile is unchanged because
all original climbs remain. A batching invoice would require a legal new
child and a complete bill. No old zero-charge ceiling is transferred to the
current supplier. The advance exact-optimum goal was narrowed in the
[scope update](https://github.com/CrocSwap/integer-mult-bounds/discussions/1166#discussioncomment-19601520)
after this first improvement.

No predecessor scientific verifier, native or selected cold replay, physical
hosting/precision/compiler check, Lean or Docker build was run. The complete
multiplication theorem, five inherited assumptions, independent human review
and formal proof-kernel review remain outside the result.

New functions are shorter than sixty lines and use bounded nonrecursive
loops. Source inputs are authenticated before parsing. Archive and payload
sizes are capped at eight MiB, the compressed member at one MiB, the
certificate at 64 KiB, and each orientation at 25,000 events. Discovery has
at most floor(N/16) rounds, N candidate endpoints and N interval tests per
endpoint, for N phase-B climbs. All direct check failures raise exceptions;
file handles close on every exit. Warning-strict normal and optimized runs
supply the available Python diagnostics. No optional linter or static type
checker is installed in the reproduction interpreter.

Power of Ten rule 3 requires a managed-runtime deviation: Python and its
standard JSON, tar and gzip readers allocate dynamically. This is confined
to the authenticated fixed input and bounded witness above; no service loop
or unbounded queue exists. Fixed-capacity buffers would require replacing
those standard readers and are outside this research package. The finite
input/loop bounds and replay are the compensating controls. A future
untrusted or variable-size interface must revisit that allocation contract.
