# Compiler refinement and admission argument

This does not replace the recursive supplier or its logical word. It replaces
the primitive expansion of 56 disjoint, frame-zero target blocks. The literal
forward expansion has matrix `((-1/2,1/2),(1/2,1/2))`; the backward expansion
has matrix `((-1,1),(1,1))`, the inverse transpose. The independently implemented
two-row checker computes each emitted matrix from the instructions themselves.
It rejects a nonzero frame, a register outside the pair, a private scratch read,
an incorrect coefficient type, or an unequal endpoint.

Both targets begin at the zero frame. Every primitive acts on those same targets
at that frame, with no recursive query or new carrier. At the end of each block,
all native registers therefore have exactly their retained values. The original
coefficient work can retain its entering dirt across the fused interval; the
unchanged suffix explicitly clears it before any read. Complete emitted scalar
replay checks that property with nine independent dirty private columns in
addition to all 728 native columns. Exact clearing is not an initialization
assumption.

Each physical non-scalar event is retained literally and in order. The complete
source-bound native/frame/phase/wrapper receipts and controller audit are required
before refinement. Equality at each block boundary transports those operator
obligations to the primitive implementation: the changed block has no phase or
frame transition to readmit. This is a certified compiler refinement, rather
than a claim that the historical verifier natively parses the new primitive
format. That verifier checks the logical interface; this checker verifies the
concrete implementation and their relation.

Original scalar bounds charge eleven primitives per component per pair. The
new literal expansions charge four. For 56 pairs and two real components this
is `56*2*(11-4)=784` per orientation. The original two ADD expansions use nine
coefficient-work operations per component per pair; the new block uses none.
That is 504 fewer operations in the predecessor's coefficient-work convention.
The original invoice has 72 complete calls, so its selected sums fall by 56,448
and 36,288 respectively. Coefficient work is already included in the primitive
sum; the reductions are not added together.

Logical macro, adapter, center, wrapper, child, stock, dispatch, owner, source
access, routing and old pervertex overcharge reserves are retained. The compiler
can expand a logical three-macro block jointly using the certified four-operation
word. All added primitive work is explicitly counted, and no new physical
frame adapter is required inside a frame-zero target block. Existing adapter
reserves cover the unchanged boundary/physical event interface.

Complete emitted exact row-L1 and fractional-grid maxima agree with PR883's
retained whole-program comparison. The isolated forward pair temporarily grows
from 1 to 2, but the complete original absolute-envelope reserve already covers
the new exact maxima. Both final native values and the old logical prefix
contract remain valid at every block boundary. The refinement retains that
larger reserve and checks exact intermediate magnitude and denominator bounds;
it does not infer a rounded physical execution theorem from rational replay.

The retained invoice function independently validates the original fresh
provider before its counts can be refined. The new lowering receipt and concrete
program digest are part of the generated provider contract. The full invoice
function then recomputes every selected call, parent/pervertex allowance, stock,
prefix, router, literal, mass, precision, tape, row and halving guard. A separate
candidate SPEC changes only the refined provider contract and local-count fields.
The unchanged assembly executes its conservative admission, exact moment
engines, bit surcharge/deficit checks, bootstrap, native correction and 47 strict
outer constraints. The recursive profile and final kappa are unchanged.

All original source bytes remain immutable. PR865's source-versioned coverage
gate additionally rejects missing required evidence before the original binder.
These are finite operator/compiler/accounting checks under inherited all-size,
realization, hosting, precision/tape and analytic hypotheses, not a complete
integer multiplication theorem.
