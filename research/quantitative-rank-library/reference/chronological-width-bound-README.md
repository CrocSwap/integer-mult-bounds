# A quasipolynomial width bound for chronological batching

**Result: for a fixed default-height mixed rule, the least per-cut widths of
[#4507](https://github.com/CrocSwap/integer-mult-bounds/pull/4507) satisfy**

\[
\log B_N=O((\log N)^{d+1}),
\]

where `d` is the number of distinct primes dividing the target and paid
ranks. Equivalently, `B_N = exp(O((log N)^(d+1)))`. This sharpens the
default-height bound `log B_N = O((1+log N)^(d+2))` already proved in
[#4586](https://github.com/CrocSwap/integer-mult-bounds/pull/4586) at
`aadb7bc59390683450b1969e4632f546929dc569`: bounded visits to each
source-count plateau remove one logarithmic factor. It sharpens the answer
to the all-rank width question in [Discussion #4503](https://github.com/CrocSwap/integer-mult-bounds/discussions/4503)
without changing the normalized leaf cost. It is an upper bound, not a
tight growth law or a practical size estimate.

The proof is a prime-valuation argument over contracting rank chains.
Finite replays below exercise its hypotheses; they are not the proof of
an asymptotic claim. **No new κ, convergence theorem, physical supplier
admission or selected-frontier change is claimed.**

This is one contribution with two separately replayable packages. This
package retains the default-height proof and witnesses; the companion
[adaptive package](../adaptive-chronological-batching/README.md) proves
arbitrary-height cut transfer and its conditional all-rank width bound.
Neither package is a second batching algorithm or a separate submission.

## 1. Exact boundary and predecessor delta

Let a fixed native rule have target multiplicities `W_k > 0` and paid
multiplicities `P_r > 0`, with

```text
2 <= k_min <= k <= m = max target rank,
1 <= r <= r_max < m,
W = sum_k W_k,    P = sum_r P_r.
```

The multiplicities are positive integers. `P` counts paid positions, not
just distinct paid ranks. At rank `n >= m`, use precisely #4436's default
height

```text
C_n = floor(n/m),
G_n = floor(log_(k_min) C_n).
```

Use ordinary base widths `B_j = 1` for `0 <= j < m`. For every larger
rank, #4507's policy groups all source complements upfront, and groups
unmatched exits at one paid position of one chronological path class.
Repeated paths and paid positions remain separate cuts. If its source
count is `S_n` and its rank/count batches are `(e,q)`, its least replication
factor and width are

```text
a_n = lcm_(e,q) B_e / gcd(B_e,q),
B_n = S_n * a_n.
```

Every parent waits for its exits and child before resuming. There is no
cross-cut pooling or fractional invocation. The correctness and minimality
of that policy are Mihir Srivastava's #4507 result; the integer flow is
zxv's #4436, building on Jacob Alan Sussman's compiler. This package adds
a **uniform growth bound for their width sequence**, not a new batching
algorithm. #4519 separately recomputes the predecessor's finite numbers.
[#4588](https://github.com/CrocSwap/integer-mult-bounds/pull/4588) at
`2f6578907b7f8718a13921552cc3069d3908e936` adds independent finite
default-height checks, not the new `d+1` proof.

The fixed native word's arbitrary-input/all-column correctness, whole-job
adapters, owned state and physical execution contracts remain premises.
The theorem below is also a statement about an integer recurrence without
those physical premises. Positive rank surplus is not needed for the
width bound itself; resource consequences using surplus are conditional
on it, as in #4436.

**Specialization and nonemptiness.** The default root has a unit because
`k_min^G <= C`; no paid rank-one position is required. The companion
[WIDTH.md](../adaptive-chronological-batching/WIDTH.md) assumes paid rank
one as a sufficient nonemptiness condition for arbitrary heights. At
`M=k_min, g=1` its symbolic formula gives `d'=d, z=0` and the same `d+1`
order on their common hypotheses. Its named adaptive height interface uses
positive `a,b` with `g=a+b>=2`, so that route does not exercise `g=1`.
The default plateau-product divisor here and the companion level-LCM
divisor are different certificates; no universal finite numerical dominance
is claimed. [#4591](https://github.com/CrocSwap/integer-mult-bounds/pull/4591)
at `84c0fb3a39bcb1e4b8c48892bfdd8a6e7ae58a50` checks arbitrary-height
aggregate identities, not the actual cut divisibility proved by the companion.

## 2. Source-count plateaus

Let `Γ` be the multiplicative semigroup generated by all target and paid
ranks, including `1`. Let `Π` be their prime support and `d = |Π|`. For a
positive integer cap `C`, the entire default flow depends only on

```text
{ gamma in Γ : gamma <= C }.
```

To see this, the target-word counts at each degree are fixed integer
coefficients. The cap only tests target products, paid path products,
their products, and the powers of `k_min` determining the height. Every
threshold is in `Γ`. The child demand uses a target word with one factor
removed, then its paid-prefix product; this is still in `Γ`. Path
multiplicities and repeated paid positions do not introduce new threshold
values. Consequently sources, exits, cuts (including their repetition
counts), and `S` are constant between consecutive elements of `Γ`.

Write `S(γ)` for the source count on the plateau starting at `γ`, and
`γ+` for the next semigroup element. Since `k_min * γ` is in `Γ`,

```text
γ+ <= k_min * γ.
```

The plateaus need not have distinct source counts. Counting them rather
than deduplicating equal counts is safe. For `X >= 1`,

\[
|\Gamma\cap[1,X]|
\le \prod_{p\in\Pi}(1+\lfloor\log_p X\rfloor)
\le (1+\lfloor\log_2 X\rfloor)^d.
\]

This is just the exponent box containing every `Π`-smooth product. The
box can contain numbers not in `Γ`; only an upper bound is used.

At depth `h`, there are at most `P^h` paid paths and `W^(G-h)` units per
path. Thus, including degree zero,

\[
U\le\sum_{h=0}^G P^hW^{G-h}\le(W+P)^G,
\qquad 1\le S\le WU\le W(W+P)^G.
\]

The middle inequality follows from the binomial expansion, whose
coefficients are at least one. A root unit with product `k_min^G <= C`
always exists; its target demands also give `S >= W`.

## 3. Every recursive rank contracts

Every source has rank `s > n/m`. A root source has target degree `G+1`,
so its product is at least `k_min^(G+1) > C_n`; integrality gives
`s >= C_n+1 > n/m`. A nonroot source comes from an absent parent point.
That parent's integer product exceeds `C_n`; multiplying by a paid rank
at least one retains the strict lower bound. Every source fits `n`, since
it is the target of an eligible native unit.

Therefore a complement rank satisfies

```text
0 <= n-s < (m-1)n/m.
```

An exit is a rank-`r` job from a unit of column at most `C_n`, hence

```text
0 < e <= r_max * C_n <= (m-1)n/m < n.
```

Set `α = (m-1)/m < 1`. Every recursive edge has rank at most `α` times
its parent's rank. This specific fact is why the default-height boundary
matters. It is not inferred merely from strict descent.

## 4. Prime valuations follow a contracting chain

Fix any prime `p`, not necessarily a prime dividing a native rank. For a
batch `(e,q)`,

```text
v_p(B_e/gcd(B_e,q)) <= v_p(B_e).
```

Since the valuation of an LCM is the maximum,

\[
v_p(B_n)\le v_p(S_n)+\max_{e\text{ invoked at }n}v_p(B_e).
\]

Strong induction bounds this by the largest sum of source-count valuations
along a recursive rank chain ending below `m`. The maximizing chain may
be different for each prime; the next bound holds for **every** chain.
No joint choice of a maximizing chain is assumed.

Put

```text
τ = m * ceil(log2 k_min).
```

Bernoulli's inequality gives

\[
(m/(m-1))^m=(1+1/(m-1))^m
\ge1+m/(m-1)>2,
\]

so `α^m < 1/2`, and `α^τ < 1/k_min`. A descending chain can visit a
single cap plateau at most `τ` times. Otherwise, let its first and
`τ`-steps-later ranks be `n_i` and `n_(i+τ)` in the same plateau `γ`.
The cap condition gives `mγ <= n_(i+τ)` and `n_i < mγ+`, while

\[
n_{i+\tau}\le\alpha^\tau n_i
< m\gamma^+/k_{\min}\le m\gamma,
\]

contradiction. Caps never increase, so visits to one plateau are
contiguous.

It follows for **every prime** that

\[
v_p(B_n)\le\tau\sum_{\gamma\in\Gamma,\ \gamma\le\lfloor N/m\rfloor}
v_p(S(\gamma)),\qquad n\le N.
\]

Hence the explicit integer divisibility certificate is

\[
\boxed{\quad B_n\mid Q_N:=
\prod_{\gamma\in\Gamma,\ \gamma\le\lfloor N/m\rfloor}S(\gamma)^\tau,
\quad 0\le n\le N.\quad}
\]

Repeated equal `S(γ)` values intentionally retain one factor per plateau.
Their prime factors need not lie in `Π`; `Π` bounds plateau **locations**,
not the prime support of the widths.

## 5. Uniform logarithmic bound and consequence

Let `C = floor(N/m)` and `G = floor(log_(k_min) C)` for `N >= m`.
Combining the preceding bounds yields

\[
\log_2 B_N\le
\tau\prod_{p\in\Pi}(1+\lfloor\log_p C\rfloor)
\bigl(\log_2 W+G\log_2(W+P)\bigr).
\]

Replacing each logarithm on the right by its integer ceiling produces the
explicit bit envelope checked by `verify.py`. All parameters of the
native rule are fixed, so the right-hand side is
`O((log N)^(d+1))`. This proves the stated result for all ranks.

The proof does not need the gcd savings: the same upper bound applies
when replication is the LCM of the invoked child widths without dividing
by batch counts. The structural improvement over #4436's nested choice
comes from using **only actually invoked, contracting ranks**, rather
than insisting that `B_(n-1)` divide each replication factor.

When `W >= 2`, the old nested policy has
`B_N(old) = product_(n=m..N) S_n >= W^(N-m+1)`, an exponential lower bound.
The quasipolynomial upper bound is therefore an asymptotic width
improvement in that case. This does not say that the new upper bound is
tight. In the degenerate rule `{2:1} <- {1:1}`, both widths stay one.

The normalized leaf recurrence is unchanged by valid replication,

```text
L(n) = [sum_s S_s L(n-s) + sum_e E_e L(e)] / S_n.
```

Thus no saving exponent improves merely from this theorem. Where a
positive rank surplus `Δ` and the source native contracts apply, #4436's
identity `B_N*N - P_N = Δ*Qcol_N` also gives the same quasipolynomial
upper order for its raw-instance and owned-center counts. No unpriced
router, full fixed-tape constant or eventual multiplication threshold is
included in that consequence.

New checks include full flow/cut plateau signatures, exponent-box counts,
source bounds, every child contraction, chain-depth and per-plateau-visit
dynamic programs, eleven explicit prime-valuation recurrences, and exact
**all-prime integer divisibility** for every computed width. The eleven
sampled valuations are diagnostics only; they are not substituted for the
all-prime divisibility check or the quantified proof.

Four boundary controls are exercised:

1. Omitting paid-rank generator `3` from `{2,5} <- {1,3}` misses the real
   cap-3 change, where source count increases from 3 to 4.
2. Changing the height base to `5` at `n=50` introduces root source rank
   `4 <= n/m=10`, invalidating the source lower bound used here.
3. The retained rank-12 pooled multiplier `175` fails the separate
   one-job rank-8 cuts; the chronological multiplier is `700`.
4. Erasing prime `5` from the proposed divisor fails the actual rank-3
   width `5`, even if other-prime checks are retained.

`verify.py` authenticates all live inputs before loading two predecessor
implementations. It **does not claim an independently written width
compiler**: #4507's compiler produces the widths, #4436's exponent-vector
flow cross-checks its source census, and the new checks certify the stated
bounds on those outputs. Cut correctness is inherited from #4507's literal
fixtures; this package does not replay that independent cut oracle. The
normalized-cost gate is the retained compiler's exact cross-product equality
between least-batch and nested leaf totals at every rank, not a separately
implemented rational recurrence. The symbolic proof is complete above.
Separate Anthropic-model review challenged it and supplied the sharper
bounded plateau-visit argument; that is not human or proof-kernel verification.

## Open next questions

1. **Can the logarithmic degree or constants be sharpened?** The prime-box
   count ignores dependencies among generator exponent vectors. A first
   step is to replace it by a rigorously bounded exponent lattice of lower
   rank. The present argument supplies no tight lower bound for `B_N`.
2. **How can the adaptive envelope be sharpened?** The companion
   [WIDTH.md](../adaptive-chronological-batching/WIDTH.md) now supplies a
   root/decrement and level-visit argument for fixed adaptive parameters.
   A next step is to retain actual gcd savings or narrower semigroup counts.
   The rank-4 source control above still blocks copying the default
   fixed-contraction proof unchanged to arbitrary heights.
3. **Which physical constants inherit the improved width?** Substitute
   the bound into one actual emitted compiler's owned-state and routing
   ledger, preserving encoded addresses and all temporary stock. Physical
   realization and the retained analytic/precision/recovery contracts have
   not been re-proved here.
