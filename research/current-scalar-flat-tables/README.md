# Current ADD/SCALE services as executable finite tables

Prepared for **@CubeJerry**, with substantial OpenAI assistance. **No new κ.**

This package supplies actual finite tables for the original ADD/SCALE services
of the current selected caller. They execute through the unchanged published
owned-lifecycle `execute_table` and `Controller.primitive`, on the current
three-bit coded signed-component format. There is no runtime numerical callback,
decoded field length or host integer arithmetic in the generated table.

For each fixed rational coefficient, the table accepts exactly those complete
fields whose requested outputs are integral on the common grid and fit the
original signed width. It stages the whole field before writing its target,
preserves the ADD source and component delimiters, and returns with physically
blank work under the original success wrapper. It uses two work ports and
linear complete-field time, including source access, staging, guided rewinds,
output installation, head return and erasure.

This removes recipe-specific temporary-word headroom conditions. For example,
four-bit SCALE(-1/2) accepts -8 and returns +4 without an overflowing temporary
+8; four-bit ADD(2) accepts target -7 and source +7 and returns +7. The written
finite-carry proof supplies the all-width statement. These finite examples
are discriminating checks, not its justification.

## Verification and limits

The bounded physical oracle checks all 10,870 width-1-through-4 signed cases
for the current catalogue, with 2,887 accepted and 7,983 correctly rejected.
Additional complete fields reach width 129. Four hundred extra rational cases
check the generic odd-denominator primitive independently of the concrete
dyadic-source application. Negative controls cover signed overflow, inexact
division, short widths, malformed codewords and component shapes, owner aliases,
source-token corruption, the final-carry sign, missing sign extension, omitted
raw retirement and retained backing after a shrinking call.

The common input format, actual geometric alignment and successful precision
cuts remain explicit premises. The whole-field staging preserves public
contents on arithmetic rejection, but the inherited exception path can leave
heads advanced and work occupied. Rejection rollback is not claimed.

The complete successful bill is `O_q(V+D+Q)`: V is one field's physical size,
D is initially occupied current work, and Q is the fixed supplied inventory.
Current work backing is at most `2V+3+O(1)` plus explicit caller storage; erased
historical backing remains counted. This is a positive scalar-service bill,
not validation of the old raw numerical allowance or an improved full exponent.
