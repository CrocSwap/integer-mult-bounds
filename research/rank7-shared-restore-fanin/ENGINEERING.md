# Engineering and verification limits

Build the Lever led to a deterministic rewriter rather than hand-edited final
words. Retained word containers bind the actual released source and native run.
Prove It Works led to actual-word forward/dual audits, a separate frame census
and an explicit complete source release. Power of Ten
shaped the bounded inputs, process cleanup and refusal of existing work paths.

## Scope and bounds

New code has no recursive algorithm, retry loop or concurrent writer. The
rewriter touches one pinned pair of words. It accepts restore lengths 203 or
204, checks literal source and consumer contacts, and changes only restore,
report and derived cleanup. The separate frame census has at most 4,100 A
gates, 1,900 B gates, 204 restore gates, 72 warps and four registers. Its
subspaces contain at most 512 vectors; its cache holds at most 128 entries.

The finite check also compares all 704 columns of the literal restore operator
with a separate rational implementation. Its bounded matrix has 704 rows and
at most 204 gates. It runs eight positive actual-word audits and fourteen
rejecting audits, sequentially, each with a 30-second timeout. Two additional
controls exercise the source-observer boundary. Unit tests cover the exact consumer
preimage, source-address order, unchanged scalar count, pin failures and recipe
argument changes. New checks use exceptions, not disableable assertions.

The complete release is opt-in. It requires POSIX and enabled assertions for
the inherited validators. A stage has a 1,800-second timeout and its process
group is terminated on every exit. One recipe has thirteen stages including
preflight, and jobs are fixed at one. A new external work path owns all exports,
words and logs. Failures retain that explicit directory. The cheap default
verification uses a private temporary directory and removes it on normal
success or exception. Hard kills may bypass cleanup.

Every external Python engine is authenticated before loading. A fresh
bytecode namespace prevents preexisting caches from replacing source bytes.
The inherited script runner receives the same isolation. Direct driver calls
can still read preexisting caches for their own initial imports; use a clean
checkout or a fresh PYTHONPYCACHEPREFIX. The registered launcher isolates the
whole interpreter. No claim is made that -B alone prevents cache reads. The
source release exports one exact Git package, validates its complete manifest,
and changes
only declared data and descriptive source labels. No frozen input is edited.
The stage program copies and their notices remain byte-identical.

## Runtime deviations

- Rule 1, library recursion. Python's JSON and deepcopy implementations may
  recurse through the fixed acyclic word containers. Source authentication
  fixes their shape and finite size. No new recursive traversal is introduced.
  The interpreter's library stack is outside this package's control. An
  iterative copier would be needed if arbitrary nested input were admitted.
- Rule 3, allocation. Python's containers, exact integers, JSON and subprocess
  libraries allocate dynamically. Fixed input pins, at most 2 MB per ordinary
  input, the explicit frame limits and serial audits bound the new computation.
  The full inherited scientific toolchain has its own memory costs. It is not
  claimed to be a fixed-memory implementation. Reassess capacity before adding
  arbitrary words, larger geometries or parallel execution.
- Rules 8 and 9, source loading. Three fixed, pinned inherited Python engines
  are loaded from explicit paths. This avoids copying or modifying scientific
  predecessors. No user-selected module or evaluation string is accepted.
  The full recipe invokes the pinned predecessor's literal code adapters;
  their generation mechanisms and inherited assertions are unchanged. Moving
  those adapters into shared code would need a separate source-binding review.
- Rule 10, inherited diagnostics. The new Python paths receive configured Ruff
  checks and Python warning/compilation checks. Upstream Python and C++ tools
  keep their original diagnostics and proof checks. Reformatting or repairing
  frozen source packages is outside this change; their assumptions remain
  explicit rather than being described as universally verified.

Before publication, run configured Ruff plus `--select E,F,I,B,UP,C4,SIM`,
`ruff format --check`, warning-as-error unit tests, and Python compilation with
a fresh cache prefix. The actual full environment is in
`evidence/ENVIRONMENT.json`. Normal and optimized finite runs check the same
literal evidence. All new functions remain below 60 physical lines. Every new file is scoped
to this package. Stored scientific evidence omits disposable exports, binaries
and regenerated fill files. Compression-container hashes bind recorded replay
inputs; canonical decoded word hashes establish cross-environment equality.
The pinned R1 JSON retains its original CRLF bytes. Its single-file
`whitespace=cr-at-eol` attribute recognizes that source convention without
normalizing the scientific input or changing its hash.
