complete characteristic-zero proof, replayed finite dependencies and exact

## Power of Ten assessment

Production control flow is structured and nonrecursive. All functions are
below sixty physical lines. Loop bounds follow from fixed dimensions: 120
roots, eight coordinates, 7,140 root-plane pairs with 120 candidate thirds,
3,309,747 five-flats, piece counts five through eleven and weights two through
seven. Each application's prior-basis check has exactly 462 subsets. Matching
controls accept sizes one through eight; the largest enumerator considers
24,158 edge subsets and retains 764 partitions. Two sequential registered
commands each have a 120-second limit.

Runtime contracts use `require`, which stays active under optimization. External
input size is checked before reading, then its exact hash, labels and root order
are checked. Invalid weights and support thresholds fail explicitly. New receipt
output must be outside the checkout and uses exclusive file creation. Files
close through context managers; command failures propagate. Mathematical
functions have explicit local state and calls, with no network or shared writes.

Rule 3 deviation, managed allocation. Python integer arithmetic, Fraction and
containers allocate during this finite replay. Fixed dimensions, the two-million
byte input bound and sequential command limits bound the scope. The flat census
streams into 113 histogram bins instead of storing every flat. Verification
includes the complete census and source mutation control. A larger parameter
domain would require a new capacity assessment rather than extending these bounds.

Rules 8 and 9 deviation, test dispatch. `unittest` discovers the seventeen local
methods in the one registered test module. Its bounded dispatch supplies failure
reporting under optimization. Production uses direct calls. The test module's
success/failure status is the compensating control. Adding a test plugin or
external discovery path would require a separate lifecycle assessment.

Rule 10 diagnostics cover warnings-as-errors execution and compilation, plus
Ruff's E,F,B,I,UP,SIM,RUF rules at the Python 3.12 target. Import ordering,
line-length and collection-expression findings were corrected. An exploratory
ALL scan records style and annotation suggestions separately; inherited geometry
keeps its exact source bytes. No lint suppressions or shared build changes were
introduced. Adding a typed public interface would justify a separate type-checking
configuration; this bounded executable package has no shared library API.

## Decision trail

1. Inspected both worktrees, all tracked/untracked/ignored files, process cwd
   and active T3 sessions. Reused the clean sparse worker on a fresh canonical
   main branch, preserving the old branch and commit. Main stayed clean.
2. Read revision-six priorities, family gates, selected review and source
   manifest. The card's first command initially needed a sparse dependency;
   materializing it produced `PASS_COMPLEX_LOCAL_WORD_CEILING`.
3. Read live handoffs and complete cached open-PR/discussion pagination.
   Kept the active larger-simplex claim separate. Recorded the changed scope
   and posted the precise eleven-piece claim before implementation.
4. A root-triple support probe suggested exclusions for larger-b profiles
   `4,5^(b+4)`. A read-only reviewer caught that deleting pieces applies PR3171
   directly. Rejected the proposed novelty claim and discarded the probe.
5. The three eleven-piece profiles have no support-certified six-piece bases.
   The root-rigidity kernel lemma supplies a different five-piece
   selection. The existing A5 count suffices with margin 39.
6. Complete receipts, seventeen controls, cross-version export replay and
   publication-byte checks are recorded in CHECKS.json. Disposable probes,
   logs and exports are removed after publication. Scientific scope stays
   limited to these explicit exclusions and the proved support lemma.
