# Bounds, diagnostics and verification limits

Engineering-mode uses the autonomous-run playbook. The exit predicate is a
proved complete pair/carry boundary, a strict fully charged local saving,
source-bound reproducibility and a focused published package. The decision
trail records the choice and completed checks. Build the Lever changed the
deliverable into a retained circuit generator and cold verifier. Prove It Works
required literal complete-state, inverse, fresh dispatch and publication-byte
checks. Boundary Discipline placed coefficient/range/stock checks at the public
SCALE boundary and authenticated external implementations before import.

The code has no recursion, background work, eval, generated Python or mutable
shared writer. New functions fit within 60 physical lines after formatting.
Only the opted-in package is changed. Frozen sources, selected result and shared
tools are left untouched. Exceptions propagate and fail the replay. Direct
`--work` failures intentionally retain evidence in the named external directory;
the default temporary context removes it on success or failure.

## Power of Ten inspection

The circuit has two W-bit words and one carry, `4 <= W <= 256`, with at most
29,112 literal gates in the reused-partner control, or 24,500 in the new circuit.
The coefficient exponent is bounded by 12. The actual
native streams are bounded by 30,000 events, four provider/orientation cases,
29 histogram entries and 9,992 macros. The invoice checks seven widths.
The all-width NEG tariff pass has 253 iterations. The exhaustive domain has
five widths and at most 16 coefficient encodings. A packed batch has at most
65,536 pair inputs, with at most 17 packed bit rows at the tested widths.
Independent fixtures have five widths, at most 16 encodings and 12 pairs each.
The pair validator/interpreter uses at most two batches of 20,000 gates,
retaining the vendor's smaller single-real bound. Source authentication bounds
64 manifest rows plus two vendor rows and each file at 8 MB. The native replay retains its predecessor's own input guards.

Contracts use explicit `require` calls, not Python assertions, so optimized
execution retains them. They enforce coefficient/recipe equality, disjoint
wires, complete pair and carry return, exact tariffs and fresh-source binding.
The endpoint guard rejects invalid data before gate execution. The tests check
missing cleanup, wrong coefficients, signed overflow, alignment, aliasing,
dirty carry, missing calls and changed input bytes. There is no pointer
arithmetic or callback-based gate dispatch. Wire access has one indexed read
or update per operand; gate targets are the two words and carry only.

Rule 3 deviation, managed memory. Python and the inherited exact native engine
allocate integers, lists and dictionaries during execution. The circuit and
truth-batch bounds above limit new work; registered commands have 300-second
and 60-second timeouts. This is an offline exact verifier, not a steady-state
allocation-free implementation. Porting to a fixed-buffer runtime would require
preallocated word, gate and truth-row arrays and a separate physical execution
budget. No allocation-free or complete inherited-engine memory claim is made.

Rule 8/9 deviation, test framework. The standard unittest runner discovers and
dispatches a fixed 14 test methods. Production gate evaluation has direct
CX/CCX branches. The runner's dynamic dispatch and Python import machinery are
bounded framework operations; no arbitrary gate callbacks or generated code
are introduced. Replacing the test framework is outside this isolated package.

Rule 10 diagnostics. Ruff E/F/B/SIM/UP and formatting checks cover all new
Python files. Warnings-as-errors compilation and execution are used. The
byte-identical vendor file is hash-checked rather than reformatted. The
registered Python 3.12 commands repeat warnings-as-errors execution, but the
generic workflow does not run Ruff on each build. Adding repository-wide lint
configuration would broaden this contribution; the exact local lint command
and result are retained in CHECKS.json. A future recurring lint hook should be
owned by the shared workflow rather than changing frozen packages here.

The native compiler and one-carry adder are executed inherited implementations.
The ring proof, complete-state truth checks and separate Boolean-list evaluator
add different coverage, but do not constitute independent human scientific
review, a proof-kernel check, physical routing verification or supplier admission.
