## Why the checks correspond

The root witness authenticates R and the actual handed rows R/A. The child
receives copies of those exact tapes and the returned modulus/width/depth
words; `new_context` obtains its Program view from the handed Program tape.
The retained Callback checks its chronological source codes/ranks/extents,
field-directory code association and runtime width/depth before evaluating
coordinate 0. Thus the positive case does not substitute a separately invented
Program fixture for the descendant.

An independent finite calculation checks `low × preparation = I (mod 3)`.
At w1 the unique high field is zero, so the good preparation pivots are 1.
The GOOD recursion at coordinate 0 multiplies the inherited root unit 2 by 1;
the actual returned value is 2. This is a field-specific fixture fact, not a
universal coefficient bound.

The child quotient uses the same unchanged q=3/w=1 context, family count and
real binary Count implementation as its parent. Exact integer observation
checks `(R/A)/A = R/A²` and divisibility by 9475. The unchanged PR4685 arithmetic
checker still certifies the root→child path. No second transition is added to
that path certificate.

The positive ingress preserves the Program, old-directory and source bytes
and heads, all inherited Count **values** and heads, and the numerical live
sets. `normalize()` changes the padded representations of `before`, `gap`
and `suffix`; that expected normalization is explicitly recorded rather than
reported as byte preservation. The original parent capsule remains unchanged
through all controls. No general abort-cleanup theorem is claimed.
