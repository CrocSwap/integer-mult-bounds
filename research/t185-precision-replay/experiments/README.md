## Exact frame test and its limits

`entry_lift_screen.py` fixes operation order, all original gate-frame lower
bounds, warp operators and their input/output frames, centre paths, target
levels, final frames, private-buffer contract, and scalar operations. Only a
single helper entry frame and gate frames may grow. At each scalar gate the
required frame is the GF(2) span of the original gate frame and both current
register frames. It is the least forward choice containing them. If this
least choice violates a fixed warp/centre/final interface, a larger choice
cannot repair it within this monotone enlargement model. This argument does
not permit arbitrary retiming, frame replacement by incomparable spaces,
different warp factorizations, or added source-consuming gates.

The unmodified positive control reproduces the exact local paid profile
`{1:2394,2:642,3:266,4:128,5:26,8:8}` for both providers. Corrupting a centre
frame and a helper endpoint causes actual rejection. The span test has a
positive duplicate-column control and an independent-row negative control.
Source bytes are pinned. No assertions are used as admission guards.

This is a finite frame-constraint screen. It does not replay the native
free-operator identity, all cone caps, cleanup, owner allocation, precision or
outer transfer. Since every candidate fails an earlier necessary constraint,
those expensive checks were not started. Failed candidates have no kappa.
