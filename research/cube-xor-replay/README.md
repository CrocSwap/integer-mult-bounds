# Exact cached XOR permutations for quadratic-code replay

The [2026-10-16 review follow-up](FOLLOWUP.md) completes the reviewed-head
verification and records a three-file transitive-import compatibility refresh
against canonical main. Historical source manifests, fixtures and benchmark
receipts below are retained unchanged; the current command additionally
authenticates `COMPATIBILITY.json`.

**Tooling improvement; no new kappa or impossibility result.** This opt-in
adapter makes the existing bounded quadratic-code rank screen cheaper by
constructing each permutation mask once per replay. It preserves the complete
original receipt, all scheduled rows, ordered binary elimination, witness
indices and hashes, and the existing stopping rule. Original generators,
certificates, source pins, `upstream/`, and the selected frontier are untouched.

The target is the largest input already admitted by
`scripts/experiments/cube_core_family.py`: `quadratic_rank_screen(6)` with its
unchanged default `maximum_rows=4096`. This is a verification workload, not a
new search for a construction. The historical integrated audit uses only
`t=3,4,5`; its entire certificate is also reproduced byte for byte.

## Reproduce

Python **3.10+**, standard library only, from a full repository checkout:

```sh
python3 -I -O -B research/cube-xor-replay/verify.py
```

Expected final marker:

```text
PASS_CUBE_XOR_VERIFICATION rows=4324 coefficients=8596927616 t6_rank=3088 t6_excluded=false
```

The default verification compares every row generated by the retained and
cached implementations, including rows that elimination finds dependent.
It reconstructs the complete historical certificate, the full bounded `t=6`
receipt, and runs the local controls. The original implementation is deliberately
included here, so this differential verification is slower than an accelerated
replay alone. Neither command expands the entire square matrix.

For the accelerated replay, with all original rank checks and a frozen complete
receipt comparison:

```sh
python3 -I -B research/cube-xor-replay/replay.py --case t6
python3 -I -O -B research/cube-xor-replay/test_replay.py
```

Expected replay receipt SHA256:
`1c790023631dc5390ed599f499b0d660d5099ee20427aadb894087163dba9186`.
The `--backend original` option runs the unmodified source. Optional
`--output PATH` creates a new file only after validation and refuses to replace
an existing file. No tracked artifact is regenerated by default.

## Equivalence argument

Let the row contain `n=2^k` bits, indexed by `j=0,...,n-1`. For one set bit
`b` of the XOR index, write `s=2^b`. The retained mask is

```text
M(n,s) = ((2^n - 1) / (2^(2s) - 1)) * (2^s - 1).
```

Since `2s` divides `n`, the quotient is the exact finite geometric sum
`sum(2^(2s*r), r=0,...,n/(2s)-1)`. Multiplication by `2^s-1` selects precisely
the low `s` positions of every `2s`-bit block, with no carries between blocks.
Thus

```text
((bits & M) << s) | ((bits >> s) & M)
```

swaps the two halves of every block. Their destinations are disjoint, so the
OR is exact. The position map is `j -> j xor 2^b`. Composing these swaps in
the original increasing-bit order gives `j -> j xor index`. For `index=0`
(including `n=1`) the empty composition returns the row unchanged.

`CachedXorPermuter` uses **the identical integer mask expression** and stores
only its value under `(n,s)`. The mask depends on neither the row nor any rank
decision. The original input guard still runs on every call, including warm
cache hits. The replay creates a new cache for each invocation and restores
the source module's function in a `finally` block. No source file is edited.
The adapter is intended for its standalone process; its temporary module-level
substitution is not a concurrent/thread-safe public API.

For the measured workload only 12 masks are needed, at most about 3 MiB of
integer payload beyond the original rows and pivot basis. The cache is discarded
after the replay. The implementation does not cache rows, eliminate fewer rows,
change a rank method, or substitute a probabilistic equality test.

This algebraic identity supplies the equivalence argument for the valid
permutation domain. Finite differential tests corroborate its implementation;
they are not a formal proof of the multiplication theorem.

## Coverage and limits

The original `t=6` result is:

| Field | Value |
| --- | ---: |
| Code coefficient dimension | 21 |
| Columns / labels | 2,097,152 |
| Rational label dimension | 64 |
| Scheduled and checked rows | 4,096 |
| Certified binary rank lower bound | 3,088 |
| Rank needed to exclude positive deficit | 5,462 |
| Positive deficit excluded | **false** |

Every one of its **8,589,934,592** binary coefficient positions is covered by
direct equality of the 4,096 complete packed rows. Historical screens add 228
complete rows / 6,993,024 coefficients. The row cap itself is below the exclusion
threshold at `t=6`; this run makes no new rejection claim, no exact full-rank
claim, and no claim about other supported matrices or subcodes.

The complete `EXPECTED-T6.json` was produced by the unmodified source before
the adapter's first large replay. Its base-row and independent-row-stream
digests are, respectively:

```text
d827dc1177f1fb5ad20593cc2615777a4919cf634a06ede0ec85bb672c3855a3
97651a704aa273443d6f3168a93b57de2e70a551ed4de487db7c2d42c4f43c8d
```

Controls cover all 2,122 small `(row,index)` combinations for `n=1,2,4,8`,
all 21,760 basis/index pairs for `n=16,32,64,128`, seeded dense rows, involution
and composition, high coordinates through `n=2^21`, mixed-width cache keys,
invalid input before and after cache warming, incomplete screens, and source/
fixture/manifest corruption. A common column permutation preserves every rank
but changes the witness hash; full receipt comparison rejects it. A dropped
row and a corrupt cached mask are also detected. Replays work under `-O` and
from an offline minimal checkout in a path containing spaces.

This package does not accelerate the selected U8/T37 supplier replay, change
the historical negative results, certify new physical/compiler interfaces, or
discharge any all-size, hosting, precision/tape, bit-interface or analytic
assumptions. No full `make verify`, native cold replay, Lean, or multiplication
runtime improvement is claimed.

## Benchmark

Three alternating fresh-process pairs on macOS arm64 / CPython 3.14.6 gave:

| Complete bounded `t=6` replay | Median wall time |
| --- | ---: |
| Original | 87.6626 s |
| Cached masks | 18.3572 s |
| Speedup | **4.7754x** |

All six complete receipts are byte-identical. This measures the named bounded
rank replay, not the historical default audit or the selected frontier.

```sh
python3 -I -B research/cube-xor-replay/benchmark.py \
  --case t6 --pairs 3 --output /tmp/cube-xor-benchmark.json
```

Use a new output path. Each of the six samples starts a fresh process and an
empty mask cache, regenerates the same base, processes the same 4,096 rows,
performs unchanged ordered elimination, and checks and writes the complete
receipt. The order alternates by pair. The harness compares full output bytes
after every sample and launches no overlapping replay. Wall time includes
imports, source checks, computation, receipt validation and output. Background
system load and interpreter/hardware differences can affect the measurements.
`BENCHMARK.json` records all samples and environment; the preliminary probe
(87.561 s original, 18.39 s cached) is excluded from those samples.
