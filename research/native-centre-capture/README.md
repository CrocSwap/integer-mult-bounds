# Native centre capture and complete fixed-reader services

This package gives exact local native constructions that place sixteen
centre records in existing data fields. It includes productive row capture,
a clean selected exchange and its dual, native row involutions, a complete
D25 fixed-reader forward/dual pair, and a route-preserving rank32 response
with two scalar capture codes. A direct clean pair gives a separate

The result is a construction and a set of scoped exact checks. It does not
improve the complete kappa calculation. A recursive helper host, a closed
caller, a finite price for the physical maps, terminal decoding, and the
complete precision argument remain open.

## The common contract

There are 112 X fields, 112 Y fields, and 416 outside fields. All 640 input
fields are arbitrary. The local words preserve the 416 outside values.
They neither require a zero field nor give productive progress to those
outside fields. The retained recursive child contract remains a premise.

Let P be the fixed sixteen ports. Let R be the other 96 ports. Let Q be
the diagonal positive line operator, q=Q^-1, and F9 the full nine-axis
operator. The row reader L has L_P=I and the code C has selected rows L
and ordinary rows I. Physical types are part of each result. A selected
FULL output, a selected Q input, and an ordinary hole output are different
types; the counts do not pay for a caller conversion between them.

The clean exchange puts Lx in selected Y and the arbitrary old selected
baseline in selected X with a minus sign. Thus the centres are clean of
that baseline, and the baseline remains in the complete state.

Python 3.14.7. No network, Git object,
producer compiler, or third-party Python package is needed. Each runner
uses one child process at a time and requires at least 3 GiB of free disk.

```sh

python3 -I -B replay_budgets.py --out /tmp/native-centre-capture-budgets-normal
```

```text
PASS_NATIVE_CENTRE_CAPTURE_REPLAY
PASS_NATIVE_CAPTURE_HISTORICAL_BUDGETS
```

`-O`. The eleven native/model review scripts are byte-exact originals.
Their new receipts must equal the frozen receipts. The runner also checks
the original input receipts where these exist. All checks run from a copied
source tree and write only into the chosen output directory.
