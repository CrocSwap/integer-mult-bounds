# Sparse independent execution method — pre-first source record

The primary executes the complete literal recursive core through a new sparse-dictionary tape interpreter. It was written from the frozen CONTRACT/CASES and source-aware static code/entry-layout review. This author previously inspected the original recursion, producer/router/counter/machine text and B11 producer work; it is not blind discovery. The current peer engine, peer receipts, source checker/expected-output functions and author runtime results were not read or copied. No scientific execution, import, compilation, test or AST evaluation occurred during authoring. The coordinator owns first execution and immutable receipts.

All three metadata hashes are literal code gates. Before any source import, all14 original objects receive exact size/SHA256/Git-blob authentication. Bounded reads and capped gzip expansion precede parsing. The original TABLE packet is read as inert program/metadata data. Only the authenticated five-module original constructor closure is imported, bytecode writing is disabled, and `R.build(4,3,1)` is called once per process. The complete normalized constructed program **and metadata** must equal the entire original table data. Source Program/Assembler construction is deliberately shared by both new engines; this is not independent end-to-end table construction. No source Machine/Tape instance, step/run, checker, observer or fixture expectation is invoked.

Each tape has its own dictionary of nonblank physical symbols and integer head. Every literal branch/write/unit move/goto/halt/reject is dispatched independently. HALT costs one transition; visits begin empty and include scanned branch/write positions plus both ends of each move. Clearing a symbol removes its dictionary entry but never removes a visited position. The retained-backing count is the sum of initial-support/visited unions, including prepared prefixes, markers and far spectators. Instruction, step and address caps are hard failures, not successful semantic-control rejections.

Fixtures use the frozen new bit pattern and exact LEFT/BASE initialization, original source/A/R/width packets, readonly unary depth and immutable guards. Every write attempt, including an idempotent write, is checked against protected original packet cells, prepared markers/prefixes/far guards and the complete width/depth tapes. Child source/A/R segments beyond the original packets remain writable owned regions. Full original borrowed inputs and all25 final raw maps/heads are compared against an independently assembled expected endpoint.

The external observer is read-only and never changes machine decisions. At actual node entries it decodes live A/R/H/source packets and depth; at both grant-ready PCs it checks actual divisibility, generated values and complete selected-bank size. It retains literal actual source/bank bit lists, not only lengths. At push_begin it saves every complete payload map/head plus complete control/phase map/head. At pop_end it compares the actual complete snapshot before hashing and checks that the depth head is still one position to the right: the source's return-left instruction follows that observation PC. Return records retain chronological parent depth/site, actual before/after snapshot hashes and the actual protected output bit list. The output is independently captured before protection and compared with the separate relay before any child retirement. All observed frames/output obligations must be consumed at final halt.

Expected output is a new recursive bitvector implementation of the written grammar: split by A/L/R address order, recursively transform complete banks0 and1 with child A/(LH),HR, complement bank0 only at remaining depth zero, then merge. It is separate host-side verification and supplies no runtime branch, product, input or program value. The source expected function and source fixtures are not imported. The oracle is expected to use its separately assigned iterative original-index method.

Five frozen changed-word controls use the same sparse dispatcher, observer, protection and whole endpoint/ownership checks. They skip actual output protection, omit the actual return-left move, remap the actual H operands to current R (one-edge positive and two-edge negative), and swap the actual post-pop phase branch. Each mutation has a static predicate before execution; a malformed mutation or generic implementation exception cannot pass. Only deliberate semantic assertion/reject failures count as `semantic_rejected`; caps and malformed tables remain hard failures. The positive H case must pass every healthy check.

Emission produces the complete canonical actual certificate. Default and `--check PATH` independently regenerate every healthy execution and control, recursively validate incoming exact types/key sets/list lengths (including integer versus Boolean distinction), and compare the **entire canonical bytes**, not summary flags. Strict JSON rejects duplicate keys, floats and nonfinite tokens. All correctness gates are ordinary exceptions rather than assertions, so optimized Python keeps them. `--certificate-out PATH` is the explicit authoring mode; `--inputs PATH` selects an authenticated full input bundle. No default mode writes proof inputs.

The180-second/128MiB bounds are a forecast until coordinator measurements exist. Four finite cases are not an all-input or all-depth proof. The prior S4 written induction remains separate, and the actual source already supplied the theorem and author-side evidence. This checks one fixed two-site complement grammar, not a Gaussian/BIT leaf, full paid invoice, natural-root prefix, ancestor weights, stock/precision/compiler/outer preparation or selected all-five assumptions. No frontier change or scientific self-admission is claimed.
