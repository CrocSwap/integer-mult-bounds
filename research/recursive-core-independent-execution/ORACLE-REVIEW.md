## Independent expected model

The oracle's `index_mask_output` is meaningfully distinct from the primary's recursive split/transform/merge bitvectors. For each original position x it computes a=floor(x/(L*R)), low=floor(x/R) mod L, r=x mod R. If the current low label is outside0/1 at an internal node, that bit is in an untouched bank and cannot be affected by any deeper child. Otherwise deleting low gives the child index a*R+r, while child dimensions become A/(L*H), H*R. Their total child volume is exactly A*R, so the new index remains in range; the fresh high coordinate is retained inside the enlarged R coordinate. At remaining depth zero only low0 complements the bit. Since merge reinstates the deleted low label, the final global address is unchanged and this path test determines exactly one output XOR bit. The method preserves every original bit and does not invoke a host recursive vector transformation or source expected function.

The original-index calculation is external verification only: its products, division, decoded packets and branch choices never enter the literal program's cells or PC. This is a source-aware independently authored expected model, not a new address theorem or independent end-to-end constructor.

## Real defect found and its closure

First v2 protected only the explicitly initialized negative guard positions-2/-1 plus0..prefix and far sentinels, rather than **every** position<=prefix as required by CONTRACT. A write attempt at an initially blank position-8..-3 could therefore escape the write-protection predicate; an idempotent BLANK write would also escape a final-map-only check. This was a genuine mismatch in the stated general guard, promptly reported to the coordinator. It does not falsify the already observed healthy cases: the retained correction receipt reports every nonempty actual healthy visit set has minimum at least7, with null for untouched tapes.

The reviewer independently read the exact diff between original v2 and public v3: its **only code change** is adding `tape.head > pref` to the actual write predicate, before `tape.put`. Thus the v3 rejects every attempted write at any position<=prefix, including a BLANK-to-BLANK write. Whole width/depth readonly roles and existing packet/far guards remain in that same predicate. Static inspection closes the reported gap without changing healthy execution semantics.

`POST-FIRST-GUARD-CORRECTION.json` preserves both code hashes, explicitly says firsts were not relabelled, and records normal/optimized public-v3 whole-packet checks passing with the same392,273-byte/d41ee0... packet. `NEGATIVE-PREFIX-CONTROLS.json` records four actual tiny-program idempotent BLANK writes at-3,-8,0,7; each fails specifically with `Semantic: protected write attempt`. These are coordinator-run receipts inspected here, not new runs performed by this reviewer. The original v2 first/seal remains evidence for its actual cases; v3 correction/replay evidence has its own chronology.

## Semantic controls and complete receipts

The five controls mutate the actual emitted instructions at named original PCs/ranges: skip output protection, skip return-left, remap H operands to current R in both grant blocks, or swap the unique actual phase branch after pop. Their construction predicates prevent silently testing a nonexistent mutation. They use the same dense dispatcher, observer and complete endpoint/ownership checks. Strict JSON rejects duplicate keys, floats and nonfinite tokens. A Boolean numeric alias, extra/missing field, reordered/noncanonical text or changed bit/snapshot/visit/endpoint therefore cannot pass.
