# A complete odd-order character screen before bit-word search

This package decides every nonzero-label counting rank cut from odd-order
cyclic characters of a bounded rational paid-frame input. It has no character
order cutoff. Rejection gives exact paid/target subsets and a positive rational
avoidance density proving that a violating character exists. Passing establishes
only these necessary cuts, not a formal word, feasible supplier or new kappa.

The retained rational and generated-lattice binary/ternary screens already
supply useful pre-search rejections. This contribution closes the finite
coverage question for the entire odd-order scalar-character family, including
composite orders. It does not add another scalar-word census or enlarge a
construction family. The inherited projection/telescoping inequality and
source attribution remain unchanged.

## Result and algorithm

[PROOF.md](PROOF.md) proves a finite target-avoidance criterion. For a subgroup
L generated by a chosen paid zero subset, and target subset T, compute

```text
alpha_L(T) = sum over U subset T of
             (-1)^|U| / oddpart([L + Z U : L]).
```

An infinite index contributes zero. A positive value is equivalent to the
existence of an odd-order character killing L while avoiding every target
in T. The proof separates finite torsion from free quotient directions;
assuming a generic character exists on a finite group would be wrong.
The checker enumerates positional paid subsets S and target subsets of size
`n-|S|+1`. This rejects exactly when some odd-order character retains fewer
paid calls than target roles. Repeated labels retain their multiplicity.

Indices use exact rational rank and gcds of integer minors after clearing one
common denominator. They preserve the actual generated group, without rational
saturation. The full formal dirty-restored endpoint contract makes every
rejection independent of factor order and any finite dirty-role count.

[EXAMPLE.json](EXAMPLE.json) is a small diagnostic with paid scalar labels
15 and 1 and targets 6 and 10. Determinant equality and every prime-order
counting cut pass. At order 15 only one paid label survives against both
targets. The exact avoidance density is `8/15`. This explains why even testing
all prime orders would not complete this screen. It is not a dimension-three
eight-call construction or lower bound for multiplication.

## Reproduce and use

Python 3.12 or later, standard library only, from the repository root:

```sh
python3.12 -I -B scripts/research_package.py --package research/bit-odd-character-screen
python3.12 -I -O -B research/bit-odd-character-screen/verify.py
python3.12 -I -B research/bit-odd-character-screen/verify.py --input research/bit-odd-character-screen/EXAMPLE.json
```

The last command intentionally exits 1 with `REJECT_ODD_CHARACTER_CUT` and
density `8/15`. Exit 0 means `PASS_ALL_ODD_CHARACTER_CUTS_ONLY`. A target
outside the actual generated paid lattice also rejects with exit 1 and a
separate status. Malformed or over-capacity inputs and failed checks exit 2.
Input keys are exactly `address_dimension`, `paid_frames`, `target_frames`.
Matrices are square row lists containing integers or rational strings. Floats,
booleans, duplicate JSON keys and rank-zero/rank-two paid frames are invalid.

The CLI accepts address dimensions 1 through 3, zero through nine paid frames
and one through three target roles. Reduced rational numerators in absolute
value and denominators are at most 65,535. Files are at most 65,536 bytes.
These are implementation limits, not hypotheses of the completeness proof.
Normal replay writes nothing. `--write` regenerates only RESULT.json and
cannot be combined with `--input`.

Expected direct replay:

```text
PASS_ODD_CHARACTER_SCREEN composite=8/15 direct=pass retained_ternary=reject no_new_kappa
```

## Evidence and limits

The registered replay screens a known direct nine-call fixture, the composite
example and PR2949's exact dimension-three ternary example. It separately
recovers that predecessor's one-paid/three-target cut with density `2/3`.
[RESULT.json](RESULT.json) stores the deterministic screen outputs.

Eight behavioral groups include:

- 784 screen comparisons with an independent direct modulus-45 character
  oracle on two-dimensional integer inputs;
- 476 exact finite-quotient avoidance densities counted directly, and 144
  independent Leibniz determinant comparisons through size six;
- invisible 2-primary torsion, mixed torsion, free and zero targets, repeated
  labels, fractional lattice membership, input capacities and malformed data;
- Git-free relocated normal/optimized CLI runs, read-only checks, corrupted
  receipts and four actual executable implementation mutants.

The modulus-45 oracle is complete on its explicitly small domain. Paid rows
always include the two integer coordinate vectors. Other rows lie in
`(1,0),(0,1),(1,1),(1,-1),(2,0),(3,0),(0,3)`. Rank-two quotient odd torsion
exponent divides nine. Rank-one quotient odd torsion exponent divides three.
The order-five free component can avoid at most two target hyperplanes,
and nonzero free target coordinates in this domain are not all divisible by
five. Thus these tests independently decide their small all-odd domains;
they do not establish the universal proof by a bounded modulus scan.

The scalar input `paid=(1,1), target=(3)` passes every odd-character cut yet
fails the idempotent determinant condition. This actual passing control makes
the necessary-only status explicit. The checker does not test determinant
equality, complete dyadic cuts, matrix-valued representations, scalar
couplings, full formal coefficients, native tariffs, physical hosting,
precision/tape, all-size compilation or a completed supplier moment.
No selected or complete predecessor cold replay was run. The written lemmas
remain subject to mathematical review, not a proof-assistant kernel.

## Implementation review

Power of Ten inspection covers verify.py and test_verify.py. There is no
recursion, generated code, external-code execution or network access in the
checker. All functions are below 60 physical lines. Loops are bounded by at
most 512 paid subsets, three chosen target subsets per paid subset, eight
inclusion-exclusion terms, at most 12 integer rows and nine columns, and at
most 924 minors per index calculation. Rank and determinant elimination have
at most nine pivots. Exact-division, integral-index and density-range contracts
remain enabled with Python optimization. JSON reads have a byte bound and
files/subprocesses have scoped lifetimes.

Rule 3 deviation: Python and Fraction allocate at runtime. The enforced
input dimensions bound live collections and integer bit lengths; the two
registered commands each have a 120-second timeout. Direct CLI capacity is
not a latency guarantee. A fixed-memory implementation is needed before
service use. Tests use fixed local fixtures and sequential subprocesses with
60-second timeouts, closed temporary directories and checked exit codes.
Rule 9 deviation: Unittest dispatch, the fixed JSON object-pair hook and one
local test-module import have explicit bounded targets. There is no runtime
plugin registry. Rule 10 uses Ruff and warning-as-error Python compilation;
no shared runtime or repository-wide diagnostics change is required.
