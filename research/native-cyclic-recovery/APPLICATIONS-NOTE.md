# Concrete native odd-scan services

This note instantiates the fixed-divisor theorem in existing public component
invoices. It changes the scalar implementation on the declared both-shifts
Word RAM. It does not replace a Turing-tape head-step tariff by the same numeric
RAM count, and does not claim a better kappa or a completed productive caller.

## Existing centre-code scan obligations

Ali Romman's PR #4733 at commit
`dd6948e95eb002d903ce36dd21e0c075e00790ed` gives exact component scan counts.
The current
[component README](https://github.com/aliromman/integer-mult-bounds/blob/dd6948e95eb002d903ce36dd21e0c075e00790ed/research/centre-code-services/README.md)
and
[pivot-code proof](https://github.com/aliromman/integer-mult-bounds/blob/dd6948e95eb002d903ce36dd21e0c075e00790ed/research/centre-code-services/annexes/pivot-code-invoice/PROOF.md)
were read directly. Their unchanged matrix identities, code image tests and
precision obligations are retained source premises, not newly replayed here.
No predecessor scientific certificate is copied or rebranded.

For n scalar records in each real stream, assume each prescribed signed
numerator fits a word after the stated constant guard headroom. Applying the
new exact unsigned quotient/remainder scan and restoring signs supplies the
following sufficient implementations:

| Source service, inverse direction | Exact fixed-odd divisions | New scalar Word RAM work |
|---|---|---|
| Rank-16 whole-bank code E | 16 at 5 and 16 at 7 | O(32 n log(2+w)) |
| Rank-30 capture | 22 at 3 and 22 at 5 | O(44 n log(2+w)) |
| Rank-30 capture/action/decode | 22 at 3 and 22 at 5, plus the separately charged fixed multiplications | O(44 n log(2+w)) for division, O(44 n) for its fixed-integer multiplications |
| Fixed-reader section swap | 60 at 15, with 60 separately charged multiplication-by-15 scans | O(60 n log(2+w)) for division and O(60 n) for those multiplications |
| Pivot-code inverse annex | 16 at 3 | O(16 n log(2+w)) |

The fixed constants hidden by O differ with the listed denominator. These are
asymptotic instruction upper bounds, not exact small-word scan tariffs. The
source's 3,420, 2,910, 6,090, 208,028 and 2,078 dyadic scalar accounts, native
translation calls, routing, root conversions and descriptors remain additional.
The two rank-30 rows describe different source service scopes; their bills
must not be added or interchanged without selecting the actual caller.

On a valid code image, each source inverse requires exact odd divisibility.
The new scan computes q,r with x=dq+r exactly. It therefore checks r=0 and
returns the exact quotient on precisely that domain; it does not replace an
exact inverse by rounded division. A nonzero remainder rejects that exact
service. Arbitrary code coordinates do not acquire missing image membership
from this implementation. Common-grid, matching code types, preservation by
middle operations, full parent height and outer unscaling remain source
premises. The source's generic inverse coefficient 1/12 is not a dyadic unit.

The pivot annex explicitly charges at most 64 n (w_g+1) arithmetic head steps
for its sixteen fixed-three scans. The theorem here supplies a different,
fully specified Word RAM realization of those exact scalar quotients in
O(16 n log(2+w_g)) instructions, when a bounded word or constant number of
limbs holds the guarded numerator. It is a model-specific alternative,
not a claimed reduction of the original tape head-step count. A practical
constant or crossover improvement has not been measured.
