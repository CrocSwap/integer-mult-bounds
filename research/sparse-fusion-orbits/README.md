## Reproduce

From the repository root with **Python 3.11+**, standard library only:

```sh
python3 -I -B research/sparse-fusion-orbits/verify.py
python3 -I -O -B research/sparse-fusion-orbits/verify.py
```

Expected final marker:

```text
PASS_SPARSE_FUSION_ORBITS frames=64 joint_pairs=4096 h=22,25,28 tests=12 kappa=unchanged
```

The verifier admits the pinned inputs, recomputes the original and accelerated
complete certificates, checks every field against the historical committed
certificate and EXPECTED.json, then runs the independent finite tests. JSON
receipt comparisons preserve types; boolean/integer/float substitutions are
not treated as equal. Tests use unittest assertions and explicit exceptions,
so their checks remain active under optimized Python.

To use just the accelerated complete certificate, without tests or timings:

```sh
python3 -I -B research/sparse-fusion-orbits/accelerator.py
```

This emits the original complete JSON certificate. `--mode reference` runs
the original engine through the same source-admission wrapper. No artifact is
regenerated by either command.

## Exact scope and coverage

PROOF.md gives the permutation-conjugation argument for all admitted h>=22
and all 64 embedded symmetric blocks. At h=25, unary rank calls fall from
**147,200 to 512**. The 128 other frame ranks and 4,096 joint-pair ranks stay
unchanged. This does not sample or discard any triple's contribution.

Finite checks cover h=22 (admission boundary), h=25 (historical default) and
h=28 (`22 + 91 mod 17`). An independent row-elimination implementation checks
**455,424 frame/triple cases** against the original column-basis rank engine.
Every triple has an explicit spectator permutation to its representative;
conjugation is checked directly. Full screen dictionaries and all **8,256
original check predicates/messages per h** agree. The complete historical
phase and budget certificate also agrees.

Negative controls alter a multiplicity, omit an orbit, change a representative,
corrupt the source or historical certificate, and install two faulty rank
kernels. The wrong-representative control deliberately demonstrates that
final minima can stay identical despite changed intermediate unary totals;
the independent per-block checks detect it. Matching final minima alone is
therefore insufficient evidence of this reduction's correctness.

SOURCES.json pins SHA-256 and Git blob identities for imported modules,
scientific receipts, source documents, selected context and all original
upstream inputs. The implementation refuses drift before importing the
checker. EXPECTED.json retains the exact complete certificate and all three
screen receipts. VALIDATION.md records actual checks and limitations.

## Benchmark

```sh
python3 -I -B research/sparse-fusion-orbits/benchmark.py --pairs 5 --output /tmp/new-sparse-fusion-benchmark.json
```

Use a fresh output path. Expected marker:
`PASS_IDENTICAL_SPARSE_FUSION_BENCHMARK_RECEIPTS`.

BENCHMARK.json records five alternating fresh-process A/B pairs for the
complete h=25 certificate and the h=25/h=28 central screens. Every timed full
receipt must match exactly. Wall time includes process startup, source hashing,
imports, exact checks and serialization. OS caches are not flushed and the
host is not isolated. On recorded CPython 3.12.14 / macOS arm64:

| Same input | Reference median | Accelerated median | Ratio |
|---|---:|---:|---:|
| Complete h=25 certificate | 0.376574 s | 0.084435 s | 4.460x |
| h=25 central screen | 0.382510 s | 0.060782 s | 6.293x |
| h=28 central screen | 0.517353 s | 0.061301 s | 8.440x |

The measured ratios apply to this historical verifier
on the recorded environment, not the selected supplier's cold replay or
integer multiplication. There is no timing pass threshold.
