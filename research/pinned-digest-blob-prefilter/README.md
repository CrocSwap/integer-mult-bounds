# Path-safe unique-blob digest prefilter

An opt-in adapter for Nick Petalas's [PR6428](https://github.com/CrocSwap/integer-mult-bounds/pull/6428)
digest-search handoff: read each distinct regular blob once to find raw digest
candidates, expand every matching path alias, and let the original Git grep
decide per-path text/binary treatment. The shared scanner is unchanged.

Identical blob bytes do **not** imply identical `git grep -I` results: attributes
can make one alias text and another binary. `PROOF.md` states the preservation
conditions and explains why caching one representative's verdict fails. The
adapter preserves literal 64-hex substring matches, including inside longer
strings and across stream boundaries. It delegates unsupported/error cases to
the original command.

## Replay

Python 3.12, Git and a POSIX filesystem are required for these LF/CR/colon-name
fixtures; no Python dependencies or network are needed. Windows lifecycle and
filename compatibility are outside this result.
All source bytes are package-local and authenticated before intentional source
checker execution. `sources/research_package.py` remains inert except for the
three authenticated source-environment declarations extracted by AST. The old
scanner and PR6428 reuse implementation execute only in temporary Git fixtures.

```sh
python3.12 -I -W error -B research/pinned-digest-blob-prefilter/verify.py
python3.12 -I -W error -B research/pinned-digest-blob-prefilter/oracle.py
```

Default commands compare the entire regenerated result against strict typed
retained JSON and fail on drift. `--emit` writes a candidate receipt to stdout;
it does not overwrite the retained result. Both commands must also pass with
`-O`. `VERIFY.json` declares the two bounded replays. A Git-free/empty-PATH replay
is inapplicable because Git is the tool being checked.

For deliberate opt-in use on another repository, with the source scan's normal
base/head arguments:

```sh
python3.12 -I -W error -B research/pinned-digest-blob-prefilter/adapter.py prefilter --root /path/to/repository --base COMMIT --head COMMIT --json
```

Use `predecessor` or `reuse` instead of `prefilter` to invoke the authenticated
source variants. Pass `--root` explicitly: the verbatim source's default is
derived from its exported file location. This package does not install any
adapter in shared tooling.

## Evidence and boundary

`RESULT.json` retains every row of one mixed controlled-history report, all
three source/adapter CLI stdout digests and exits, path-policy counterexamples,
an actual alias-drop mutant, empty-diff/no-match checks, advisory/strict exits,
and recursion/argument/reader fallback controls. `ORACLE.json` is generated by a
separately implemented checker sealed before reading the primary receipt.
`VALIDATION.md` records actual runs, source pins, timings, review and corrections.

The primary's mixed fixture has 52 regular tree paths, 9 distinct blobs and 15
candidate aliases passed to final Git grep. Its complete report has 26 rows,
22 stale and 13 frozen stale. The independent fixture has 26 blob paths, 12
distinct blobs, 17 candidate aliases and 13 accepted aliases; its complete report
has 28 rows. These are separate histories with independent expected outcomes,
not competing measurements of one fixture.

Work units are explicit: unique raw-blob transfers in the prefilter, bytes
returned to Python, retained aliases and final Git pathspecs. The original
changed-target and pinner reads remain, and final Git grep reads candidates
again. No physical I/O, decompression saving or speedup follows from these counts.
No canonical PR6428 154-row historical replay was performed in this session.
The proof assumes stable readable objects/configuration/attributes and does not
promise identical diagnostics under arbitrary resource failures or races.

Five alternating warm complete-CLI trials on the same small fixture produced
median times of 0.138180 s (repaired predecessor), 0.109483 s (PR6428 reuse) and
0.143418 s (prefilter). Every full JSON output and exit matched. The extra pass
was slower here. `BENCHMARK.json` retains every trial; the optional `benchmark.py`
prints a fresh comparison without changing retained files.
