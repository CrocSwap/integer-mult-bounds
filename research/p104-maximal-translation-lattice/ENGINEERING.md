# Verification and resource decisions

The deliverable is a written all-rank mathematical theorem and finite
supporting checks. The attempted numerical improvement was a coset domain
smaller than 343 bits. It failed because the full translation group equals
the known sufficient lattice. The retained result is the necessity proof,
not an improvement of that metric or a new multiplication exponent.

Build the Lever led to `model.census`, a deterministic exhaustive shift
check with explicit separating inputs. Prove It Works led to literal signed
fixtures, source authentication, wrong-inverse-lattice rejection, typed
receipt controls and read-only Git-free replay. `decisions.tsv` records the
bounded hypotheses and disposition. Unslop shaped the explanatory prose.

## Power of Ten inspection

1. New code has structured loops and exceptions, with no recursive call
   cycle. The written induction is a mathematical proof, not code recursion.
2. Public vector checks cap rank at seven, dimension at 256 and input
   magnitudes at 4,096 bits. Pair checks use 625 inputs and 81 by 16 shift
   cases. Censuses accept only rank one or two, with at most 65,536 shifts,
   eight components and three probes. The retained index checker has at
   most 896 constraint rows and 256 columns. Its subprocess has a 30-second
   timeout; export subprocesses have a 60-second timeout. Registered
   commands have 60/90-second bounds.
3. See the managed-runtime deviation below. New code owns its vectors and
   sets locally. Every test export belongs to one TemporaryDirectory,
   removed after the suite. No generated mathematical output is written
   during ordinary verification.
4. Every new function is at most 60 physical lines after formatting. The
   largest responsibility is the 35-line signed translation/inverse check.
   The retained source is byte-identical and retains its own bounded design.
5. Explicit `need` checks, active under optimization, enforce prefix
   integrality, source hashes, correct periods, exact ideal increments and
   receipt equality. Boundary errors use ValueError. No correctness
   assertion depends on Python's optional `assert` statement.
6. New state is local, except the immutable package path. Each subprocess
   has one owner and bounded lifetime. There is no shared mutable writer.
7. Subprocess status, source hashes, Git-blob identity, index status and
   exact JSON receipt are checked. Nonzero exits propagate as failure.
   Test commands inspect both status and observable output. File writes
   occur only in disposable test exports and are managed by Path contexts.
8. No new dynamic evaluation, generated code or runtime registration is
   used. The retained checker runs as an authenticated `.py` entry point,
   avoiding import-bytecode substitution. It imports only the standard
   library. The source file is not edited between checking and execution.
9. Calls and array access are direct and shallow. Standard unittest
   discovery is the only new framework dispatch; its finite method set
   is declared in `test_verify.py`.
10. Registered commands use warnings-as-errors. Ruff's correctness,
    imports, bugbear and modernization rules cover the three new Python
    files. No new diagnostics are suppressed. The vendored source is
    not reformatted or changed. The generic registered workflow runs
    these bounded behavioral checks for this opt-in package.

## Managed-runtime deviation

Rule: 3, fixed allocation after initialization.
Location: `model.py`, `verify.py`, `test_verify.py` and retained index replay.
Reason: Python arithmetic, lists and JSON require runtime allocation.
Scope: finite exact research checks only, not a production arithmetic circuit.
Compensating control: census tables have at most 65,536 eight-component
vectors and errors, plus bounded index lists; index matrices have at most
896 by 256 residues plus two 256-square prefixes. Ranks and input sizes are
checked before constructing those collections. Subprocesses run serially.
Verification: registered ordinary and optimized replay, exhaustive-domain
checks, explicit over-limit tests and a peak-memory observation.
Follow-up: a production reducer must use an explicitly priced bounded
storage contract. This Python checker supplies no such implementation claim.

## Review boundary

A separate internal read-only review derived pair rigidity and checked
the induction, the rank-zero base, inverse correspondence, index transfer
and coset-only optimality. It also checked the pinned predecessor's word
and conventions. It did not independently certify the index algorithm.
The source index is replayed here with exact pins, with no new independent
index-implementation claim. No formal proof kernel or complete supplier
replay is part of these checks.
