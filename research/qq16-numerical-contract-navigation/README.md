# QQ16 numerical-contract navigation audit

The [numerical-contract map](../../docs/research/qq16-numerical-contract-map.md)
connects the zero-retention QQ16 decoder's completed-error, rounded-line,
finite-format, pair-circuit and common-scale results. It separates relative
Hilbert error, component width, Boolean gates and physical caller costs. The
observation map and bottleneck brief now point to this successor.

This is a source-bound navigation result, not a new mathematical construction
or supplier. Five decoder/numerical predecessors are incorporated scoped
research; PR2876 remains pending at `28c5c068b64c18074ab4044e47a7c9f52eb6e5de`.
Their exact source heads, credit, premises and remaining obligations are in
the map. The selected frontier and frozen predecessor files are unchanged.

## Evidence and reproduction

From the repository root, with standard-library Python 3.12:

```sh
python3.12 -Werror -I -B scripts/research_package.py \
  --package research/qq16-numerical-contract-navigation
```

Expected, in both normal and optimized replay:

```text
PASS_QQ16_NUMERICAL_NAVIGATION retained=5 pending=1 controls=7 bindings_only no_new_kappa
```

The checker authenticates eleven retained source files, checks exact
incorporation heads and attribution against two integration receipts, binds
two pending source snapshots, recomputes the shared register/gate example,
and checks the map's local file links. Seven controls reject missing review
evidence, an altered relative guard, an understated register width, an omitted
scan charge, premature incorporation, a pair-only subtotal and changed source
bytes. These checks do not validate every sentence or proof. They do not
contact GitHub or establish future PR status, and local link checks do not
validate anchors or external URLs.

[SOURCES.json](SOURCES.json) pins live retained inputs and historical task
provenance. [PENDING.json](PENDING.json) records the exact PR2876 head, Git blobs
and SHA256 hashes of its verbatim README/receipt snapshots. Their source
notices are preserved; they are documentary inputs, not a copied executable
package. [REPLAY.json](REPLAY.json) records the five primary checkers actually
run during this audit and their environment/output. PR2736/2771/2807/2811 ran
from this main worktree; PR2876 ran from twelve exact-head files downloaded
outside the checkout. Their primary checks all passed. This one-time replay
is distinct from the small registered navigation check above. The complete
predecessor suites, native PR2707 replay, full selected cold replay and
proof-assistant verification were not run for this contribution.

## Implementation constraints

The checker has no solver, subprocess, network access or predecessor imports.
It bounds each read to 1 MiB, the retained inventory to eleven files, the
pending inventory to two snapshots, each review to 100 rows, the navigation
page to 30,000 characters, links to 100, and controls to seven. The example's
popcount sum has 331 iterations. It writes no artifacts. Explicit exceptions
keep all acceptance checks enabled under `-O`; all functions are below 60
lines. The registered commands have 60-second timeouts. JSON documents are
trusted repository artifacts after source authentication, not an untrusted
service protocol. The generic metadata runner checks provenance against Git.

Power-of-Ten rule 3 deviation applies to managed Python/JSON integers and
collections: this offline checker allocates during checking. Its fixed input
counts/read caps bound retained data; each control replaces the preceding
copy. No fixed-allocation runtime is claimed. Python's JSON and deepcopy
implementations may recurse internally over the fixed source shapes, a rule 1
deviation confined to those library routines. Source digests bind those shapes;
no application recursion is introduced. A fixed-buffer or iterative parser
would be required before reusing this as an allocation-constrained runtime.
Warnings, compilation and Ruff cover the new code; no repository-wide analyzer
configuration is changed for this scoped audit.

Build the Lever shaped the small rerunnable binding/example checker. Prove It
Works shaped the exact-source primary replays and failure controls. The
append-only [decision trail](decisions.tsv) records scope and verification.
