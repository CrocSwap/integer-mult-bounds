# A concrete cross-characteristic decoder, and its density limit

The fractional-Haemers literature does not, by itself, repair the target.
The following explicit construction does produce a scalar decoder with a
small, fully priced copy ratio. Its binary geometry has insufficient label
density, and the same graph cannot acquire a dense block representation.
This is a completed local construction and rejection, not a supplier or a
claim that all cross-characteristic constructions fail.

## Primary-source route

[Bukh and Cox, *On a fractional version of Haemers' bound*, arXiv:1802.00476v2](https://arxiv.org/pdf/1802.00476),
Section 2, defines block representations with identity diagonal blocks and
prescribed zero blocks. Proposition 5 equivalently uses pairs of matrices
`A_v,B_v` with `A_v^T B_v=I`; these need not be a common symmetric Gram
representation. Their Section 4 constructs characteristic separations.
For characteristic two, the three-subset graph in Lemma 12 and Proposition
17 is particularly explicit. For `4|n`, Lemma 12 gives fractional binary
Haemers bound exactly `n`. The strong-product multiplicativity theorem does
not reduce this parameter. The general separation theorem also does not
assert constant binary fractional rank or provide native query tariffs.

The calculation below specializes that three-subset construction and prices
its actual scalar factorization. The tariff and target test are additional
calculations for the repository's complete-support pairing model.

## Geometry and an explicit Gaussian-dyadic decoder

Let `n>=4` be divisible by four. For each three-subset `X` of `[n]`, take
the binary line generated by its incidence vector `v_X`. Then

```
h=n,       k=1,       V=binomial(n,3).
```

Every line is nondegenerate since its self-pairing is `3 mod 2 = 1`.
For distinct labels, their binary pairing is nonzero exactly when
`|X intersect Y|=1`. Thus the permitted scalar fitting entries are the
pairs with intersection size zero or two. Define the rational matrix

```
M_XY = (|X intersect Y|-1)/2.
```

It has diagonal one and vanishes at every forbidden off-diagonal entry.
Writing `a_i(X)=1[i in X]` gives the concrete scalar-query decomposition

```
M = (1/2)*sum_(i=1)^n a_i*a_i^T - (1/2)*1*1^T.
```

These are `n+1` actual outer products with Gaussian-dyadic coefficients;
there is no inference from low matrix rank to low native cost.

For the query indexed by `i`, the complete source and reader spans coincide
with

```
U_i = span(e_i) direct-sum {x on [n]\{i}: sum_j x_j=0}.
```

To see the equality, three triples containing `i` and using a triangle on
three other coordinates sum to `e_i`; their differences generate the
even-weight subspace on the other coordinates. Since `n-1` is odd, that
even-weight subspace is nondegenerate for the dot product. The tariff of
each coordinate query is therefore `n-1`. All triples span the full ambient
space, so the final all-ones query has tariff `n`. The total invoice is

```
C = n*(n-1)+n = n^2,
C/(V*k) = 6*n/((n-1)*(n-2)).
```

For example, `n=100` gives `V=161700`, `C=10000`, and copy ratio
`100/1617 = 0.061842918985...`. This is below the approximately `0.063046`
allowance of a **different**, density-one-third geometry. Transferring that
allowance to this construction would be invalid: here the density is `1/100`.

## Why the concrete family still misses the target

Under the three-stage, separate-public-leg law, its data-only moment is

```
3*((n-1)/(3*n-2))^(8/9).
```

It already exceeds one for every `n>=4`: the ratio inside the power is
increasing, and at `n=4` the required strict comparison is `3^17>10^8`.
The exact verifier also includes every query tariff in the attempted bill.
Every other expense was granted free. Large `n` reduces the copy ratio but
cannot correct this data failure.

This is not repairable by a block representation of the same graph.
Partition `[n]` into four-element sets, and retain all four triples inside
each part. These `n` labels are pairwise binary-orthogonal: within a part
they intersect in two points, and between parts they are disjoint. In the
complementary binary fitting pattern, their principal block submatrix is
therefore the identity. For a representation with diagonal block rank `d`,
that principal submatrix has rank at least `n*d`. Hence every such binary
representation satisfies

```
h/d >= n.
```

This applies to arbitrary two-sided block representations as well as
symmetric nondegenerate port spaces. Payload replication does not change
the ratio. Tensor powers of this particular binary representation multiply
the ratio, rather than lower it. Changing the graph or its free mask,
possibly through a noncommuting block construction, would require a new
explicit representation and a new scalar-query invoice. Noncommutativity
alone cannot evade the same-mask identity witness.

## Replay and remaining construction problem

```sh
python3 -I -O -B research/kappa01-haemers-repair/verify.py
```

The verifier reconstructs every pairing, scalar fitting entry, query support
rank and independent-set witness for `n=4,8,12`. It checks exact rational
moment enclosures for those cases and `n=100`, and detects the two invalid
promotions: pricing each query at one and reusing the density-one-third data
bill. It does not enumerate all possible decoders or graphs.

A viable escape still needs a binary block representation at
`h/k<3.264451...` and an actual scalar/query program with the appropriate
complete-support invoice. General cross-characteristic separation alone
supplies neither condition. Noncommuting block geometries with a different
mask remain outside the failed construction above; no successful instance
is asserted here.
