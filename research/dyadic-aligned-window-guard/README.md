# An exact guard for dyadic aligned target windows

**Scoped proof with an exact finite check. No new κ, no supplier admission; the
selected frontier is unchanged.**

CubeJerry's merged [PR #6972](https://github.com/CrocSwap/integer-mult-bounds/pull/6972)
(`research/core-production-nonempty`) shows that the capped carve has a nonempty
interior in a target window iff the longest selected run `M` exceeds `6W`, and that
`S >= e(6W+1)` with `L >= 12W+2` admits every original start. Its open question 2 asks
whether a sharper guard exists for **dyadic aligned sections**: `N = S+e` and the
window length `L` powers of two, every window starting at a multiple of `L`.
This package answers it in full for the length half of the guard.

## Results

Write `e = 2^j t` with `t` odd, `N = 2^n`, `L = 2^l`, and assume `S >= e(6W+1)`.

1. **Exact classification (Theorem 2).** All aligned windows of length `L` have
   `M > 6W` if and only if one of: **(I)** `l >= n-j+1`; **(II)** `l = n-j` and (`t >= 3`
   or `L >= 12W+2`); **(III)** `l <= n-j-1` and `(t+1) L > t(12W+3)`. The deciding data
   are the odd part `t` of `e` and `n-j`, not `S/e`. The proof reduces to where the
   `e` holes of the source sit modulo `L`: they repeat with period `N/2^j`, and in
   case (III) their offsets modulo `L` are exactly the nearest integers to `L rho/t`.
2. **The single-hole band (Theorem 1).** Under `S >= e(6W+1)`, a window of length
   `L >= 6W+1` is bad iff it holds a hole at offset in `[L-1-6W, 6W]`; such a hole is
   automatically the only one in its window. This holds for every window, aligned or not.
3. **The length threshold cannot be lowered (Theorem 3).** For every `W >= 1` and every
   power of two `L <= 12W` there is a dyadic instance with `S >= e(6W+1)` in which every
   aligned window of length `L` is bad (`e = N/L`, one hole at offset `L/2`, `M = L/2`).
   So `L >= 12W+2` is exactly the universal dyadic length condition of #6972's guard.
4. **The guard does sharpen for particular `e`.** For `e` a power of two in case (III),
   `L >= 6W+2` is necessary and sufficient, half the uniform length. Least dyadic `L`
   in case (III), generated by `verify.py`:

   | W | uniform 12W+2 | t=1 | t=3 | t=5 | t=7 | t=9 | t=11 | t=13 | t=15 |
   |---|---|---|---|---|---|---|---|---|---|
   | 1 | 16 | 8 | 16 | 16 | 16 | 16 | 16 | 16 | 16 |
   | 2 | 32 | 16 | 32 | 32 | 32 | 32 | 32 | 32 | 32 |
   | 3 | 64 | 32 | 32 | 64 | 64 | 64 | 64 | 64 | 64 |
   | 4 | 64 | 32 | 64 | 64 | 64 | 64 | 64 | 64 | 64 |
   | 5 | 64 | 32 | 64 | 64 | 64 | 64 | 64 | 64 | 64 |
   | 6 | 128 | 64 | 64 | 64 | 128 | 128 | 128 | 128 | 128 |

5. **Neither adverse family of #6972 is dyadic.** One has odd length `12W+1`, the other
   odd period `18W+5`. In a dyadic instance `S = e(6W+1)-1` never occurs.

[PROOF.md](PROOF.md) has the statements and proofs.

## Evidence

`verify.py` uses a literal coordinate walk of `q(j) = j + floor(e j/S + 1/2)` as the
independent oracle. All counts below are reproduced by the script.

| Check | Coverage |
|---|---|
| Oracle fidelity | The literal walk equals #6972's closed-form longest run on all 72,611 ordinary windows with `S <= 22` (the pinned `guard.py` is hash-checked) |
| Lemmas 1 and 2 | Hole formula, cell lengths and run formula against the literal walk: 400 pairs `(S,e)` with `S >= 2e`, `S <= 40`, 273,910 windows |
| Lemma P | The periodicity `H_(c+t) = H_c + N/2^j` for every `e < N`, `N = 2^n <= 4096`: 8,178 cases |
| Theorems 1 and 2, literal | Every `e` with `N >= 8e`, every `l`, every allowed `W`, for `N <= 256`: 2,070 cases, 1,415 bad; the band criterion and the closed form both equal the oracle |
| Theorems 1 and 2, hole list | The same for `512 <= N <= 4096`: 90,820 cases, 57,364 bad |
| Gain over the uniform length | 1,858 of those cases are exactly admissible with `L < 12W+2` (1,260 with `t = 1`, 598 with `t >= 3`) |
| Theorem 3 | 495 families for `W <= 64`, checked literally; parity remark for `W <= 200` |
| Controls | Seven wrong variants (threshold `12W+2`, case II merged, `e` for its odd part, uniform guard only, case II always admissible, band end shifted by one in each direction) each contradict the oracle in at least one case |

The check runs in about 6 seconds.

## Reproduce

From the repository root, with CPython 3.12:

```sh
python3.12 -I -B research/dyadic-aligned-window-guard/verify.py
python3.12 -I -O -B research/dyadic-aligned-window-guard/verify.py
python3.12 -B scripts/research_package.py --package research/dyadic-aligned-window-guard
```

Each verifier run ends with `PASS_DYADIC_ALIGNED_WINDOW_GUARD`; add `--json` for the
certificate.

## Scope and limits

Everything is under `S >= e(6W+1)`, that is `floor(S/e) >= 6W+1`. The equivalence
"interior nonempty iff `M > 6W`", the cap and width admissions, source accuracy,
`N - L >= W` in applications and every native, compiler and precision obligation stay
as in #6972. In #6972's asymptotic family (`L >= p^400`, `W = O(sqrt(p) polylog p)`) the
length `L` already exceeds `12W+2`, so this classification changes nothing there; it
decides finite short dyadic sections, and so says exactly which of them are genuinely
empty. The proofs are written by hand; the finite check corroborates them and is not a
proof. No proof-kernel check was run and no independent human review is claimed.

## Open next questions

1. **Dyadic instances with `floor(S/e) <= 6W`.** Which aligned windows fail there?
   Why it matters: this is the `S/e` half of the guard, which this package does not
   touch; the parity remark shows #6972's one-unit family never occurs dyadically, but
   the next case `S = e(6W+1)-2` is open. First step: apply the same hole-offset
   method with internal cells of length `6W` or `6W+1`, and test which aligned windows
   see no `(6W+1)`-cell. Blocker: the positions of the `(6W+1)`-cells form a Sturmian
   pattern whose offsets modulo `L` need a separate argument.
2. **Aligned windows when `N` is not a power of two.** The periodicity lemma uses
   `N = 2^n`. First step: for `N = 2^a b` with `b` odd, test whether the holes repeat
   with period `N/2^j` times a factor of `b`. Blocker: `L | N` then no longer forces
   the residues to depend only on `t` and `L`.
3. **Use in #6972's open question 3.** The classification names the empty short
   aligned sections exactly; whether the zero-dimensional branch can be implemented at
   those sections is a native question, outside this package.
