# A marked resident tape removes the DDG stopping counter

For the fixed `(1,1)` paired sampler, one owned blank beside the random segment
replaces the unbounded stopping counter of [JoyboyBrian's PR #6102](https://github.com/CrocSwap/integer-mult-bounds/pull/6102).
The new finite-state two-tape machine prepares a delimiter, copies the sampled
two-bit output into a dirty XOR accumulator, reverses to that delimiter, clears
it and returns both heads. For every terminating path of depth T it uses exactly
**3T+4 finite-alphabet transitions** and **2T+4 input-head moves**.
The controller has **1,563 states and 10,000 rules**, independent of T.

This is a **scoped proof with a finite machine certificate**. It supplies a
counterless local tape service under the stated changed boundary. The resident
random transcript and head excursion remain unbounded. The output accumulator
becomes A XOR i; its old value is not erased or required to be zero. The random
tape, its owned blank and both head positions are restored.

[PROOF.md](PROOF.md) states the machine model, proves the arbitrary-path
induction and one-step injectivity, and derives the exact bill. Preparation and
marker erasure are included. The random alphabet is `{0,1,_,#}` and the output
cell has four symbols. The second head stays stationary. This is a concrete
finite transition system; its rule selection does not use a RAM oracle.
Binary-alphabet lowering and repository native paid calls have different costs.

## Evidence and reproduction

From the repository root, using Python 3.12 and the standard library:

```sh
~/git/integer-mult-bounds/.venv/bin/python3.12 -I -W error -B research/marked-tape-ddg-reversal/verify.py
~/git/integer-mult-bounds/.venv/bin/python3.12 -I -W error -O -B research/marked-tape-ddg-reversal/verify.py
~/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/research_package.py --package research/marked-tape-ddg-reversal
~/git/integer-mult-bounds/.venv/bin/python3.12 -B scripts/check_research_commit.py --package research/marked-tape-ddg-reversal --check-source-history
```

`PASS_MARKED_TAPE_DDG_REVERSAL` enumerates every rule and state, checks local
injectivity and permitted writes, then runs 4,088 short dirty-output fixtures
and all 938 terminating prefixes through depth 470. The long fixtures contain
942 reverse root revisits. Each run checks exact steps/travel, output XOR,
complete tape restoration, returned head and delimiter erasure. Controls reject
wrong output, exhausted fixtures, bad input, missing marker return and premature
halting on a wrapped root. Finite tests support the implementation; the proof's
induction establishes arbitrary finite stopping depth.

[RESULT.json](RESULT.json) is generated by the verifier and binds the proof,
machine, verifier and retained source bytes by SHA256. The verifier writes
nothing during ordinary replay. Its optional `--write-result` path is only for
explicit regeneration. The Python interpreter's position and bounded observer
counter are measurement state. They do not occur in the machine's rule keys.

Using zxv's cited source expectation, the new exact bill has expected value
`48479692514343769953106/4649714690825496825793 < 43/4` transitions.
This is a consequence of the predecessor law, not a new sampling optimum or
runtime benchmark. The source's probability/census suite is not rerun.

## Scope and credit

The changed `formal-interface-lemma` task takes the first Open next question of
PR #6102 and supplies one local service boundary. It is not a proof-assistant
formalization. An actual caller must provide the owned adjacent blank and the
stationary output head; it must also preserve the random segment throughout
cleanup. No conditional freshness of reused bits, parameter selection, binary
gate tariff, native supplier, complete multiplier or new kappa is claimed.
The five selected framework assumptions are not discharged.

This scoped construction was produced by Nick Petalas. New work is Apache-2.0.
Independent human and formal proof-kernel review are unclaimed.
zxv's PR #6072 supplies the fixed DDG, classical sampling argument and mean.
JoyboyBrian's PR #6102 supplies the phase-and-coin edge inverse and identifies
physical tape/counter costs as open. Their exact sources and original credit
are retained unchanged in `vendor/`; [vendor/ORIGIN.json](vendor/ORIGIN.json)
records public origin heads and hashes. The new contribution is the delimiter
construction, explicit local machine and exact counterless tariff. It does not
claim the classical technique of reversing a recorded computation as new.

The frozen card, base and source pins are in [TASK.json](TASK.json) and
[SOURCES.json](SOURCES.json). The [advance claim](https://github.com/CrocSwap/integer-mult-bounds/discussions/1166#discussioncomment-19241748)

## Open next questions

Can one actual nonadaptive caller supply the owned adjacent blank and stationary
output head at the point it needs both decisions? Start with one reached residue
pair and its tape ownership layout. The missing caller and conditionally fresh
input randomness are the blockers; restoring consumed bits does not fund reuse.

What is the explicit binary-alphabet transition constant for this fixed
finite-control machine? Start by encoding each four-symbol cell by two bits and
lowering every local rule while preserving head return and scratch cleanup.
The current exact bill counts finite-alphabet two-tape steps, so the binary
constant must be proved before comparison with a binary physical tariff.
