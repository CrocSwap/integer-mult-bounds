# Conditional κ = 0.003519487 (+0.154% over #6902): 8 ports keep the hosted form

**Result.** The exact-kernel crossing of the complete signed invoice is **0.0035194870841667550646**, which is **+0.15439% over #6902** (0.0035140618674216889; ratio − 1 = 0.0015438592).
The claim for the outer statement is **κ = 0.003519487** with tested price 0.00351948707 (grid 10⁻¹¹), both strictly below the raw crossing, which lies in (0.003519487084166, 0.003519487084167).
The package builds on #6902 (one native word serves two #6833 root chains) and changes one thing: **8 of the 104 ports keep the hosted form** of #6889 (one plane per port, pair (α, β) = (−1, 1/2), no second mains), while the other 96 ports keep the two-chain form.

**Conditional statement.** The result holds under the five framework assumptions of #6833; under assumption A6 (owned ascent) as declared in #6883; under the BIT saving of the open #6726 (necessary, below); and under the new form declared next, together with every declaration of #6902, which this package keeps (the reducible type A root and its three family lines, HOST2, same-label second mains, LAMBDA, IDLE_ONE, the row 19 accounting: a shared helper is one field, one job, one credit).

## What is new: a per-port root
* **The root is a pair.** Type A (96 ports) is the root of #6902: two #6833 chain roots, n = 40, t = 0. Type B (8 ports) is the hosted root of #6889: n = 38, t = −1/2, pairs (−1, 1/2). Both have 18 stages with the same mask-rank profile, one stage variable per stage and M(D) = −diag(∏D^ε). A port instantiates only the roles of its own type; over the **78 roles** (type A 0-39, type B 40-77) the caller is **block diagonal**, with one stage value D_s per stage common to both types and **18 joint contacts**, each one native event serving both types (HOST2 at the type A ports, HOST at the type B ports). The cross-type blocks vanish (`check.py` replays the whole 78×78 matrix at the four central characters, 12 evaluations, 0 bad of 6,084 entries each; each type alone also replays).
* **Roots checked separately.** Type A by `root_check.py` (21/21 units of each chain regenerated from the closed form, cross Gram 0, SPEC-level identities, each stage variable once and affine); type B by `root_check_hosted.py`, the checker of the #6889 hosted root, every line passing. A wrong X entry in either root fails its checker; two swapped unit rows in the type A root fail.
* **Port types tied to the word.** The caller's type A ports equal the word's list of two-chain ports (96) and its type B ports the other 8; `check.py` asserts it and shows that exchanging the types of one port of each kind breaks the match. `cover_check.py` rejects, on a random-evaluation replay, a **wrong port type** (one two-chain port declared hosted) and a **swapped assignment** (a two-chain port and a hosted port exchanged), and also rejects a wrong weight, a missing event and an event taken twice on 16 sampled events that touch second mains or hosted-port mains.
* **The word.** Endpoint at the two-chain ports X = x, Y = x + y, X2 = x2 − y2, Y2 = y2; at the 8 hosted ports X = x − y, Y = (x + y)/2; helpers identity. 59,918 events, 1367 public registers (400 mains: 96·4 + 8·2, and 967 helpers), 6421 MOVEs; the opening gauge SCALE 1/2 acts on exactly the 8 hosted-port mains X. Helpers are shared across ports of both types by the #6902 rule; **Cross-type traffic, counted by definition** (an ADD or COPY whose destination and source are both mains and whose ports have different types): **180 events**, of which **96 involve a second main** (X2 or Y2 of a two-chain port with X or Y of a hosted port; 16 of those at a frame other than 127). They are legal (common chart, frame law clean), the endpoint rows of all 400 mains hold no input of a port of the other type, and transiently a main holds a foreign-type input after 3,053 events, which cancels. **279 helpers** have ADD events directly against mains of both types: the 8 hosted ports share 279 helpers with the two-chain ports. Separately, of the 397 events that couple a second main with a first-plane main of any port, 385 lie in the two gate blocks and 12 inside the core (all with hosted-port mains, ports 17, 34, 42, 47, 55; the other definition, a subset in kind).
* **Invoice.** The root part is per port (type A for 96 ports, type B for 8), the native part is one call per stage: `check.py` recounts it from the emitted joint events and again from the two roots plus the word, and the two agree term for term. S = 1520. The #6902 word through the type A root alone reproduces its crossing 0.00351406186742169, and #6833 is rebuilt by the same code.

## Raw bound, logarithm power, LAMBDA
* Raw bound, all three definitions below 10⁹: literal **962,308,192**; actual per-call work **968,225,044**; reviewed scalar upper **978,594,376** (margins 37.7M, 31.8M, 21.4M). Per call 10,328,714 (allowance) or 10,904,788 (reviewed upper), above the displayed 10⁷. Substitution (FP:278-283): scalar allowance 557,714 or reviewed upper 1,133,788; routes 9,771,000; paid rank mass R = 317,516; growth bound 2^(978,594,376 + 317,516·f) on the conservative count. No term of the outer ledger reads it (`check.py` verifies that the ledger source has none).
* **Logarithm power: minimum 2159, written 2160.** The capacity line is taken on the literal carrier of **153** axes (9 base rows and 8 per stage × 18; the 8 complement rows of q lie in no target, so the carrier exceeds the largest target rank 145), since the fit m·c ≤ N of FP:111-114 is on the carrier. **An earlier version of this package used m = 145 in that line and wrote 2137, which was too low; no κ changes.** 2100, 2137 and 2158 fail. It is a free parameter of the compiler theorem (`research/higher-moment-strictification/vendor/LOG-MAJORANT.md:110-122`; stated with an integer q and 1/q in the bound, its literal conditions fail for the real exponent used, and the code uses the same argument with a real p, which a reviewer of #6884 re-walked and I did not). Rational interval engines at the tested price: α = 0.99999999998, γ = 0.9484, δ = 0.8129 (< 31/32); composite bound holds; 54 strict and 4 functional inequalities positive (their smallest value is the chosen parameter r0 = gap/10).
* Also declared, inherited: **LAMBDA 206 events** (124 type A, 82 type B), **IDLE_ONE 100 events** (32 type A, 68 type B) and the opening **gauge SCALE 1/2** on the 8 hosted-port mains.
* **LAMBDA is a review question.** Type A callers have 124 LAMBDA events and type B callers 82. If each LAMBDA had to be paid as a rank-1 job per port, the cost is 96·124 + 8·82 = 12,560 and S = 1520 − 12,560 = **−11,040 < 0**: no crossing exists. The κ rests on pricing LAMBDA as ordinary work, as in every caller of this line from #6726 on. **Reading, by an independent review, stated as the reading it is (not proved here, not on main):** Q = C^{⊗f} on (q,…,q) and C² = X (`upstream/build/sections/05-layers.tex:65`: "C^2=X, C^4=I"), so Q² = T, a pure translation, at every f; the reviews of #5599 and #6030 already use it ("Q^2 is the native translation with phase +1 at every width; scalar signs stay outside tensor powers", `docs/research/pr-intake-evidence/pr5599-completion/PROOF-REVIEW.md:59-60`; `pr6030-audit/PROOF-REVIEW.md:80-83`). Then LAMBDA = aI + bT with a, b = (1±i)/2 has row support 2 at every f (it is not the f-th tensor power), and compiles as `INIT t; COPY t = x; T(t); x := a x + b t` (numerator first); `CLEAR t`, with T the native translation: the macro of the thin query of the open #6900 (not on main) with its paid Q⁻¹ replaced by the ordinary translation. The lift is "substitution of the fixed coordinate, phase and scalar generators. It does not tensor a sum of matrix operators" (`research/higher-moment-strictification/vendor/p7-TENSOR.md:42-44`), native monomial maps and quadratic phases "lift column by column" (`research/kappa-rebuild/architecture/FINITE-PRECOMPILATION.md:243-248`), and finite compositions of permitted words are permitted (FP:45-46). Under this reading LAMBDA costs ordinary work and S does not go negative; I have not verified the tape-level implementation, and the κ is unchanged by it.
