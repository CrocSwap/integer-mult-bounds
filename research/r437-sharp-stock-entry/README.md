isolated copy of the authenticated `checked_entry` accepts the known one-factor
NODE stock `9475 A^D`, while retaining every non-stock statement of the original
entry AST. At q=2^127−1, e=n=128, h=0, w=2, D=2, the minimal guard-contract stock

frozen backend or selected supplier. It executes host root-parameter validation,
not binary Count guards, a Program path or a giant payload. The inherited
`numerical_admitted: true` field means the source's root parameter checks passed;

## Exact transformation and checks

The verifier parses the authenticated `admission.checked_entry`. It requires
exactly one call with the source expression
`numerical.check_stock_rows(domain.rows, domain.n, cat.q, domain.w)`, replaces
only the callee with the package-local fixed guard, restores that callee in a
copy, and checks complete AST equality. The clone is compiled in a separate
namespace. The original module function object is unchanged throughout.
The replacement requires a positive row integer divisible by
`stock.stock_divisor(n,q,w)` and returns its positive quotient. The retained
checker is authenticated before import; callers cannot supply another divisor.

Thus the original source/request/view/rank, domain, exact L/I/Q widths,
original-root n=e/h=0, certified prime-constructor provenance, coupled precision,
and fallback checks remain in order before the original zero-argument callback.
The actual SelectedBinding uses stock_multiple=9475 and has a pass-only residual
`check_stock`; both are source-checked. This inventory is scoped to the pinned
caller contract, not arbitrary future predicates.

The fixture uses the certified Mersenne prime constructor and actual R437 D
SOURCE87 request 1676 (`MOVE,0,0,22397`), common view, rank 2, with the inverse of
its actual preparation chart. It authenticates the source, decodes the actual
handle and checks the inverse product. Exact widths are L=255, I=9, Q=520213.
The sharp row integer has 2,080,811 bits; the conservative integer 2,080,825 bits.
Host integers are parameter certificates, not materialized payload tapes.

PR4734's `install_ordinal_counts` function is retained exactly, with its own
minimal helpers/imports and provenance hash. It uses exact admissible-candidate
prefix counts for rank/unrank and bounded caching; its q3/dimension2 parity and
invalid-ordinal controls run before q127 construction. This changes the bound
codebook methods in this isolated process. The original compiler identity hashes
original source bytes, so the separately retained adapter hash is part of the
explicit evidence; source identity alone does not authenticate the adapter.
No new ordinal algorithm or physical complexity claim is made.

Sixteen negative cases reject before the continuation, including the original
entry rejecting the sharp stock, missing 9475, missing one A, incompatible or
zero rows, reset precision, descendant-as-root, nonzero history, wrong widths,
source identity/request/view, foreign Specifications and forged prime-constructor
provenance. Four accepted continuations cover the sharp stock, old stock under
both entries, and a final sharp-stock repeat after all controls. No check relies
on Python assert, so optimized replay retains these guards.

The arithmetic certificate also checks the rank-ceiling path 128→84→42.
It is labelled **abstract**, not an observed Program path of this rank-2 source.
The word minimal refers to the established complete rank-ceiling NODE guard
model, not minimum stock needed by this source's actual rank sequence.
