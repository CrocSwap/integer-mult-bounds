# Every wire permutation has an exact cycle layout of peak bond d^2

This contribution was produced by Nick Petalas. Apache-2.0.

Claim type: scoped written proof with exact finite corroboration.
For n sites of equal dimension d >= 2, route source i to destination pi(i).
Use the same column order for the operator's input and output sites.
If c wires leave a prefix, exactly c enter it, and its coefficient unfolding
has rank d^(2c). All its nonzero squared singular values equal d^(n-2c).

The minimum exact matrix-product peak bond in that order is the largest
of these cut ranks. Optimizing the simultaneous column order gives exactly
one for identity routing and d^2 for every nonidentity permutation.
Consecutive directed cycles attain the optimum with an explicit wire-label
tensor train. [PROOF.md](PROOF.md) proves the statements for every n and d
in the mathematical contract. The executable caps formula/layout inputs
at 64 sites and local dimension 16; materialized trains have smaller caps.

For the half-swap of 2k sites, the natural order needs peak d^(2k).
The order 0,k,1,k+1,...,k-1,2k-1 has peak d^2. At d=2 and k=2 this
changes the exact representation requirement from 16 to 4. The full cut
spectrum also gives a necessary operator-error bound and a sharp
single-cut relative Frobenius approximation bound, with their scopes
separated in the proof.

## What this adds

[zxv #5441](https://github.com/CrocSwap/integer-mult-bounds/pull/5441)
supplies the physical-column transfer contract, cut-rank method and
fixed-order half-swap obstruction, and explicitly leaves column reordering
as an escape. This package determines the algebraic optimum under
unrestricted simultaneous reordering and constructs the attaining train.
It does not replay the predecessor's verifier or audit its result.
Classical cycle decomposition, operator-Schmidt rank and tensor-network
factorization retain their credit. Global literature priority is unclaimed.

The card `formal-interface-lemma` is explicitly changed to this algebraic
side result. It can prevent a fixed-order lower bound from being treated as
a representation-independent routing obstruction. It does not establish
that a physical caller permits this order or pays less for it. Site-dependent
fixed-width tensors do not automatically form a fixed finite transfer table
uniform across widths. No supplier admission, new kappa or complete
multiplication theorem is claimed, and the selected frontier is unchanged.

## Open next questions

Structured questions, relevance and blockers are in [TASK.json](TASK.json).

1. Which actual caller permits a cycle order on both input and output sites?
   Bind its requested wire permutation and complete bank layout, then price
   preparation and restoration of that layout. The layout permission and
   physical movement cost are currently missing.
2. Can one useful restricted permutation family be represented by a fixed
   transfer table in its legal order, uniformly across widths? Start with
   adjacent paired swaps after interleaving and declare the schedule state.
   The present position-dependent trains do not establish that contract.
3. How does the optimum change with retained side information or unequal
   site dimensions? First specify which input and output coordinates remain
   demanded; the disjoint crossing-label argument then needs a new endpoint
   and dimension calculation.

optional dependencies. All functions are shorter than 60 lines. Formula
inputs are capped at 64 sites and dimension 16. Materialization is capped
at six sites and 64 virtual labels per cut. Literal spectra use at most
81 routed basis inputs and a smaller-side unfolding with at most 81 rows.

permutations, orders and unsupported dimensions. Checks use explicit

verify.py: Python allocates integers and containers during exact arithmetic.

files. These bounds and rejection controls constrain live allocations;
platform allocator behavior is not instrumented. Any interface expansion
must set new caps and recheck this resource contract first.

calls four explicitly listed verification functions, and the rejection helper
accepts only three listed boundary-check targets in this closed verifier.
These seven fixed targets have no recursive call paths. The registered warning-strict
normal and optimized runs exercise every target. No generic Python static
