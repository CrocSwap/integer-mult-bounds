## Source integrity and provenance

The portable registered replay checks source bytes against the package's own RETAINED.json and recomputes science. It is useful for accidental corruption and reproducibility, but does not establish external origin when code and manifest can be replaced together.

`check_source_objects.py` is a separate, optional Git-dependent comparison. Supply a full publication SHA obtained through a trusted channel and make that publication and the three pinned source commits available in the object database. The checker reads the manifest from that publication commit, requires the working manifest to match, and compares every retained file with its original commit/path and both recorded hashes. It compares working retained files, not the publication commit's stored copies, code or RESULT; the separate committed-byte preflight checks those published bytes. A Git object comparison alone does not establish which remote repository supplied the object. It does not fetch or execute source code. Its own code and the supplied publication pin must be trusted; this is not a defense against an attacker replacing the checker, trusted pin and all evidence.

```sh
python3 -I -B research/pr6551-retirement-audit/check_source_objects.py --repository . --publication-commit FULL_PUBLICATION_SHA
```

The three source commits are #6551 `11ca568cd1a16776ade02b4df09ea04a784cc674`, #6545 `775722aa94a5e85b05d1d704d7dca10cbf016f0c`, and #6398 `dee2663ba0918be86993fd9d63c8d64b020f4c83`. The publication record supplies the full contribution SHA; a branch name is deliberately rejected as an anchor. A network-free export does not require this optional check or these Git objects.
