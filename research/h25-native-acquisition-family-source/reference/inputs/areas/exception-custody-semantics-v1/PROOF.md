The old reference matters: `Include/object.h:696–706` dispatches `_Py_Dealloc` at zero; destructors may execute arbitrary code. Never overwrite a retained foreign error merely to reuse capacity. The compiler also clears an `except … as caught` binding (`compile.c:3395–3445`), so keep a separate strong primary root before leaving that handler.

`sys.exception()` is ambient handled state, not operation-local failure state: `sysmodule.c:777–796` and `errors.c:125–136` explicitly walk older handled frames. A successful operation executed inside someone else’s rejection handler must still propagate its own close failure.

The implementer recipe is:

1. Before protected I/O, capture authentic `BaseException` and original native `posix.close`; validate the admission bound and private ownership. Allocate caller-rooted primary, secondary, first-overflow, descriptor, status and marker slots; precreate keys/labels and successor values. Capacity must cover every admitted failure, remaining close attempt and reporting failure. Initialize cleanup temporaries before acquisition. Construction failure while a caller already owns an FD belongs to that caller’s existing cleanup scope.
2. At successful handler entry, first retain `caught` in an initialized local and unused exact-list primary slot. Do no tuple construction, append, helper validation, attribute inspection, formatting or logging first. Use explicit operation-local primary state initialized to `None`; retain expected target rejections separately from writer errors.
3. Put every acquired descriptor immediately under `finally`. Move its exact-int token to a prepared local and clear ownership before calling captured close with one positional argument. Close remaining independently owned descriptors through their own protected blocks; unroll fixed slots or use a bounded scalar loop without constructing an iterator or descriptor tuple. Record failures only in unused preallocated slots; maintain a bounded cursor. On saturation retain the first overflow error, mark evidence incomplete and stop acquisition while completing owned-FD cleanup. Further unrooted foreign exceptions exceed this contract. Do not recycle live error slots.
4. Enclose cleanup and any nonprimitive bookkeeping in a secondary `try/except BaseException`. A cleanup failure cannot replace an already saved primary under the stated delivery/store premises; without a local body failure, the first cleanup failure becomes outward primary. Prefer bare re-raise while the original handler is active. Keep secondary objects rooted through terminal handoff.
5. Serialize only after all descriptor attempts. Catch serialization failure, preserve it if capacity permits, and select a preexisting literal incomplete-evidence marker. Writing that marker is best effort and can fail; neither persistence nor successful close may be invented.

`posixmodule.c:10288–10304` issues one `close(fd)` and deliberately never retries EINTR. Its clinic wrapper (`Modules/clinic/posixmodule.c.h:6251–6299`) converts the FD; the one-positional-argument macro fast path is in `Include/cpython/modsupport.h:102–106`. Native vectorcall still has a recursion check (`methodobject.c:399–440`). This proves an at-most-once attempt after token consumption, not descriptor release. Entry failure, close error or interrupted completion leaves closure unconfirmed and prohibits reacquisition under a strict descriptor budget.

Python helper entry is separately fallible: `bytecodes.c:2689–2700` and `ceval.c:1583–1611` can fail frame creation before any helper store. Inline-retain the caught error before an optional helper, then guard that call. Crypto V2’s `retain_io_close` calls at lines 138/179/265 are not protected by its internal JSON try; their entry can displace a local body primary. Native recursion headroom does not excuse Python helper-allocation failures.

Acquisition has another concrete gap: `clinic/posixmodule.c.h:6225–6235` boxes a successful native `open` result with `PyLong_FromLong`, then only cleans the path. For FD>256, boxing can allocate and fail without closing the acquired FD (`longobject.c:204–218,295–307`). A descriptor-count cap does not bound numeric FD. `scandir(fd)` instead allocates its iterator before duplication, closes the duplicate if `fdopendir` fails, and returns the existing iterator (`posixmodule.c:15443–15523`); native release remains conditional.

The contract requires authentic pinned runtime/code/primitives, sufficient native-call recursion headroom, untouched private slots, and no intervening tracing/profiling/monitoring, asynchronous exception injection, hostile finalizers or concurrent mutation. `ceval.c:933–988` can allocate frame/traceback/lasti objects and decref stack objects before dispatching a handler; `traceback.c:44–57,265–279` confirms allocation. Delivery and later unwinding therefore remain explicit obligations. OOM kill, process termination, untrusted OS, forged owners/classes and arbitrary memory corruption are unsupported.

Smallest acquisition repair: set a preallocated pending token before open; clear only after FD storage. Any acquisition exception quarantines all further acquisition/capture, cleans known tokens, and stops with at most one unknown FD pending parent kernel teardown. Never claim its closure. Alternatively, complete total occupancy ≤240 plus ≤3 acquisitions implies FD≤256 under trusted Linux lowest-free allocation; inherited/census/transient FDs count. Neither that census nor pinned kernel allocator semantics was established here. `scandir` clears `dirp` and ignores `closedir` return (`posixmodule.c:15254–15270`); successful Python close is insufficient release evidence. Its finalizer can warn (`15346–15367`).
