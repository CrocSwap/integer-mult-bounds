# Approximate terminal decoding still needs growing scalar work

This contribution was produced by Nick Petalas. Apache-2.0.
Claim type: scoped proof with finite exact corroboration. Independent human
and formal proof-kernel review are unclaimed.

For the two-stage inverse postdecoder targets in the actual negative banks
0 and 8 of Dillon's PR4933, **Euclidean operator error at most `1/208` still
requires at least `2(f-1)` scalar ADDs** at every positive digit-column width f.
Cinna Davis's [PR5065](../two-stage-coded-terminal/README.md) proved this
floor for exact decoding. The new result makes that obstruction quantitative
for uniform linear approximation, using the same operation alphabet.

For all four forward/inverse sign choices, let m be the number of inverse
factors, alpha=1/(8*13^m) and R=4^(f-1). Every linear scalar/monomial program
using g ADDs obeys

```text
||approximation - terminal_operator||_(2->2)^2
    >= alpha^2 max(0, 1 - 2^g/R).
```

For the actual inverse postdecoder targets, m=1 and alpha=1/104. Any fixed
ADD budget has limiting inferior error at least 1/104 as f grows, even if
the program's coefficients vary with f. The sparse-row inequality is sharp;
attainability by a complete decoder is unclaimed. See [PROOF.md](PROOF.md).

## Evidence and predecessor boundary

The proof cites PR5065's isolated marker tensor identity and four-entry flat
row. It adds the sparse approximation inequality, projection argument and
positive-tolerance corollary. The predecessor identity is a premise, not a
newly audited or replayed deliverable. The verifier hashes its exact README
and proof bytes and never executes predecessor code.

The standalone verifier uses exact integer and rational arithmetic. It checks
all support subsets of the new flat-row fixtures through sixteen coordinates,
a complete finite Gaussian coefficient box, tensor-row truncations through
width six, and bounded integer instances of the all-width corollary. It also
checks invalid arguments and discriminating false-strengthening controls.
[RESULT.json](RESULT.json) is generated by the verifier and binds the package
and cited inputs by SHA256. Universal coverage comes from the written proof,
not these finite fixtures.

## Scope and implementation bounds

This is an algebraic boundary result on the changed complex-rank-shape-decoder
card. Its old fixed-profile packing ceiling is inapplicable. The historical
first command was attempted and fails with `KeyError: 'complex_profile'` on
the selected schema. The current `research_selected_baseline.py` orientation
passes source bindings only. Neither run certifies a supplier.

The model permits arbitrary complex scalars, monomial maps, owned COPY/CLEAR
and arbitrary independent dirty scratch, counting every scalar ADD. It is a
linear operator-approximation model. Nonlinear rounded execution, approximation
of the composed caller in a different norm, paid Gaussian decoding, changed
recursive job types and complete physical costs are outside the theorem.
Native all-column, ownership, routing, storage, precision/tape, compiler and
outer assumptions remain unresolved or inherited. No new kappa or selected
frontier change is claimed.

Only this new package changes. Code uses direct calls without recursion,
subprocesses, network access or predecessor imports. Tensor fixtures have at
most 1,024 entries; the support census visits at most 65,536 subsets per row;
the coefficient box has 9^4 rows. Corollary loops use width at most 200 and
at most 398 ADD counts per sign case. The arithmetic entry point rejects
widths above 1,000 and ADD budgets above 2,000. Every function is below sixty
physical lines. Both registered modes enable warning errors, and explicit
exceptions keep invariants active under optimization. No external static
analyzer or formal proof kernel is claimed.

Power of Ten rule 3 deviation: CPython allocates arithmetic objects and
collections. These bounded one-shot checks cannot prohibit runtime allocation.
At most one tensor row, its approximation and one current census candidate
are live; integer sizes are bounded by the enforced inputs. Both execution
modes exercise the endpoint limits. A future native steady-operation port
would need fixed-capacity storage before removing this deviation.

## Open next questions

1. Can a linear scalar/monomial word attain a comparable whole-operator error
   with O(f) ADDs? Start with the isolated block, then require all owner blocks
   and dirty restoration. A sharp row inequality alone is not such a word.
2. Can this operator floor be translated to final Gaussian-output error for
   the actual caller? First bind the entrance operator's least singular value
   and the caller's norm and precision contract. Conditioning and complete
   physical costs remain blockers; this result makes no such transfer claim.
