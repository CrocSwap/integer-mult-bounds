# Verification design

The executable claim is finite geometry supporting the written mixed-rank
support 38 theorem. No supplier implementation is changed.

Separate Before Serializing Shared State shaped the workspace boundary. This
package, branch, status file and session cache have one writer. Shared Git
metadata operations use the batch's OS-released lock. Research arithmetic runs
without that lock. Peer checks read frozen source and write only reviewer-owned
receipts.

Prove It Works shaped the publication gate. Run the actual registered commands,
then replay exact committed export bytes from a read-only Git-free tree under
a second Python version before freezing the peer-review tree.

## Power of Ten

1. The three scripts use structured loops and explicit ValueError exits. There
   is no recursion. File contexts and temporary-directory contexts own cleanup.
2. Root inventories have 120 full/112 live entries. Binary inputs have at most 512
   labels of at most 18 bits. D6 has 3780 planes,448 minimum planes and 896 live-axis
   fibers. A fiber has 256 functionals and 10795 dual two-spaces. The alternate
   ambient census has 788035 three-dimensional annihilators. A2 has 1120 planes
   and its orbit queue can contain at most 1120 items. The alternate D6 orbit
   queue has at most 3780 items. Source inventories have 5 rows and 4 retained rows.
   Registered command timeouts are 120 seconds, sequentially.
3. CPython requires dynamic allocation. This managed-runtime deviation covers
   only the bounded inventories above. Source files are at most 1 MB each; the
   largest retained primary census serialization has 896 rows with bounded
   histograms. Bit masks have at most 33 bits for D6 fibers. The alternate full
   inventory retains only 16 maximal supports. No asynchronous work or subprocess
   remains after a command. Direct allocation instrumentation is unrun.
4. The largest new function is a 2_receipt at 60 physical lines after Ruff format.
   Other functions are below 60 lines. It owns one plane classification and
   orbit/fiber receipt; splitting it further would add a single-use forwarding
   boundary without a separate ownership requirement.
5. Runtime require checks validate source pins, exact cardinalities, label
   ranges, census totals, orbit coverage and arithmetic implications. They
   remain active with Python optimization. Controls run with -O.
6. Module globals identify immutable paths and finite expected inventories.
   Geometry, bit masks, queues and receipts stay local. No peer artifact is
   writable through the verifier.
7. Read and parse failures propagate. Output uses exclusive creation. Source
   inventory lengths and exact allowed paths are checked before reading or
   importing sources. Hash and Git-blob checks bind retained bytes without Git.
8. The fixed geometry module is loaded after authentication. No input supplies
   code, module names or call targets. No generated code or eval is used.
9. The import loader is the sole dynamic call boundary and loads one fixed
   authenticated local module. All mathematical helpers otherwise have visible
   direct call targets. This Python import boundary is a bounded runtime
   deviation from a ban on indirect calls.
10. Registered replays enable -W error. Ruff check and formatting checks cover
    every new Python file. There is no compiled component or compiler warning
    configuration. The standard-library runtime and inherited geometry internals
    retain their existing contracts.

The managed-runtime allocation and fixed import-loader deviations stay confined
to these offline checks. Revisit them if inputs become user-sized, the module
path becomes configurable, or the verifier becomes a service. Keep the bounds
and authentication tests when changing the implementation.
