## Conditional provider interface

The selected family is GNU time. The proposed format is `O03_TIME_V3 {"wall_seconds":%e,"user_seconds":%U,"system_seconds":%S,"kernel_individual_maxrss_kib":%M,"utility_exit":%x}` followed by LF. A SHA-256 for that format is not a seal of actual expansion semantics. Actual current utility bytes/version/build, locale providers, startup dependencies, exact diagnostic behavior and current launcher/wait provider have not been acquired. W3 must seal and independently review them before admission. This packet supplies no fictional provider identity and no integration acceptance.

The current intended locale/environment remains LC_ALL=C.UTF-8 and TZ=UTC with an empty inherited environment and an explicit PATH. Historical ordering was env -> timeout TERM/kill-after 1s/179s -> time -> python observer. A future command contract must pin complete argv, environment, redirection, timer endpoints, the process actually timed, timeout order, signal forwarding, wait/reaping and raw-file custody. Only the reviewed topology whose timed subject is the observer is accepted by this draft. A different topology needs a source/interface review. Setup/teardown outside the GNU child's interval, final observer write, parent readback, report publication and physical totals remain OPEN_NOT_ZERO. This parser never treats the outer wall observation as complete physical accounting.

`utility_exit` is the time utility's integer field. For an independently corroborated ordinary exit it must match that exit. For a signal or timeout it remains opaque. The parser does not manufacture signal facts from %x, 128+signal, a diagnostic line, observer STOP or a missing record. A timeout may prevent the time utility from producing a record; that remains STOP. CPU and peak-RSS units/coverage must be independently admitted with the provider; KiB is never conflated with simultaneous group RSS.

The proposed future `run(request)` returns a `ReadbackOutcome` containing state plus the exact primary exception object/traceback. A caller may re-raise that object with `raise_primary()`. The source has no CLI or automatic invocation. A trusted future controller supplies independently authenticated expected digests for admission, observer, launcher receipt, raw stream, command contract, current W3 seal and current ledger. Matching a hash supplied by the same untrusted input is not authentication. The parser checks consistency against that trusted request; it does not discover providers, verify W3 seal contents, establish a current ledger, issue authority or launch a process. Literal fixture authority is synthetic and may never be adopted as current authority.

## Raw grammar and caps

All sizes are bytes. A raw input is at most 65,536 bytes. The tagged line from the first O through the closing JSON object, excluding LF, is at most 4,096 bytes. The derived report including final LF is at most 65,536 bytes. Each external admission/observer/termination JSON file is separately capped at 65,536 bytes. These caps are construction gates, not after-the-fact size claims.

The grammar `gnu-time-tagged-v3` is exactly:

```
raw             = prefix tagged-line [LF whitespace]
tagged-line     = "O03_TIME_V3 " strict-measurement-object
whitespace      = *(SP / HTAB / CR / LF)
prefix          = empty / nonzero-prefix / signal-prefix
nonzero-prefix  = "Command exited with non-zero status " exit-number LF
signal-prefix   = "Command terminated by signal " signal-number LF
exit-number     = canonical decimal integer 1..255
signal-number   = canonical decimal integer 1..64
```

Admission selects exactly one prefix kind (`empty`, `gnu-nonzero`, `gnu-signal`). There is at most one prefix line. Its numeric value must match the independent launcher receipt. Prefix spellings are conditional GNU-family choices until W3's actual provider is sealed and future controls validate them. Exactly one timing tag must occur in the whole raw stream, anchored immediately after the selected prefix. No scanning for a plausible/last JSON object occurs. Suffix whitespace is admitted; every other suffix byte is rejected, including a second line of JSON. Extra bytes on the tagged line are rejected by strict JSON decoding. CRLF prefix spellings are not admitted. Valid trailing JSON whitespace on that same tagged line remains strict JSON whitespace and counts against the tag cap.

The JSON object has exactly these keys: `wall_seconds`, `user_seconds`, `system_seconds`, `kernel_individual_maxrss_kib`, `utility_exit`. Measurement numbers must be JSON numbers, finite, nonnegative and at most 10^12. RSS must be integer-valued; utility_exit must be an actual integer in 0..255. Strings and Booleans fail numeric slots. Duplicate keys fail at every nesting level. NaN/Infinity constants fail. Each numeric token has at most 32 characters before conversion; exponent digit length is at most 3 and absolute exponent at most 12; out-of-range values fail. There is no binary floating overflow conversion. Numeric token construction by the JSON scanner remains bounded by the already enforced input cap. Nesting is checked before JSON materialization with a maximum of 24. Measurements are projected to exact decimal strings; unknown measurements remain null, never zero substitutes. All fields required by a selected grammar use strict UTF-8. Raw bytes survive invalid encoding unchanged.

The explicitly selected optional `historical-two-line-failed-only-v1` grammar accepts the exact nonzero-1 prefix and one LF-terminated JSON line with the old five keys (`exit` instead of `utility_exit`). It checks the same numeric/JSON limits and derives failed accounting only. It neither requires nor fabricates a current admission, matching contemporary observer or launcher receipt. It never becomes a successful/current readback; termination remains uncorroborated and complete accounting false. The historical source hash in INPUTS and T04 fixture custody identifies the specific retained 148 bytes. Any nominal wall upper bound is historical information, not a new ledger debit. The source intentionally leaves current policy charge null in this branch.

## Independent record schemas

The draft admission schema is `o03-timing-admission-v3`. Its exact keys are in ADMISSION_KEYS in the source: operation, current W3 seal digest, timing-contract digest, command-contract digest, timed_subject=`observer`, selected prefix, rounding quantum, limits and canonical ledger. All three provider/command digests and the current-ledger digest must equal trusted request pins. Limits remain 180 outer seconds, 1,073,741,824 bytes and 2,400 aggregate seconds only when independently reaffirmed by a new current admission. The explicit upper rounding quantum is 0.01 seconds. SHA values in synthetic fixtures are examples, never actual provider/admission claims.

The new separate receipt schema is `o03-launcher-termination-v3`. Exact keys are WAIT_KEYS in source: schema, admission/contract/command digests, timed_subject, raw/observer digests, kind, exit_code, signal_number, reaped, tree_complete, cpu_complete. `kind` is exit/signal/timeout. Exit has an integer exit_code and null signal; signal/timeout has null exit_code and an explicit signal 1..64. Booleans are actual Boolean completeness facts. The independently authenticated launcher must establish those facts and their coverage; an assertion in a self-authored JSON file alone is insufficient. The two new schemas have no current producer integration; W3 acquisition, source review and future admission must resolve that dependency.

Observer readback retains `o03-inclusive-observer-v1`. Required and permitted optional fields are explicitly enumerated in source from the pinned A observer. Unknown fields/schema changes fail. Required scalar numerics and CPU keys are type/range checked; original error/runtime/measurement objects stay in their retained raw record and are not copied to the report. The original source's `COMPLETE_FOR_SOURCE_FIXED_REAPED_SUCCESS_TREE` string is required for complete CPU accounting, together with independently asserted launcher reaping/tree/CPU completeness. A failed historical observer carries its original incomplete accounting string. A future failure-complete accounting extension needs an explicit source review rather than relabeling the old failed attempt.

## Structured failures and bounded reports

Before external reads, the draft creates a minimal STOP state with null measurements, null charge, unknown termination/caps/ledger/accounting, fixed scope/tail statements and bounded diagnostic slots. Request validation, path walks, admission/observer/wait/raw reads, parsing, hash/identity capture and all validation occur within the primary failure boundary. The first exception object is saved. Close, reporting and fallback diagnostic errors are recorded separately through protected best-effort bookkeeping. No exception text/repr is requested. No `assert` controls correctness, so normal and -O source behavior should match; neither mode has been executed here.

Input opens use O_NONBLOCK/O_NOFOLLOW and descriptor-relative directory walks. The final object must be a regular 0444 file with one hard link, capped by stat before the first data read. Identity checks cover mode/owner/link/size/timestamps/dev/inode before open, on descriptor open/close and on a fresh path walk. Ancestor directory identities use stable identity/owner/mode/link fields so creation of a report does not inherently fail its own check. Symlinks, nonregular objects, aliases across inputs, duplicate output/input names, link count changes, path replacement and observable identity drift fail. The cap is never exceeded in the assembled buffer; a separate one-byte growth sentinel is never appended. Closing failures are secondary if a primary exists; otherwise they become the primary. All raw references are retained; no input is rewritten.

Custody still requires a separately authenticated protected parent tree and no concurrent hostile writable handles. Stat/hash checks cannot prove absence of an adversarial ABA mutation restored between observations, physical media durability, or provider identity. These are explicit future custody assumptions, not deductions from pathname checks.

The report is a bounded projection: fixed status fields, bounded per-file pins, fixed byte-range diagnostics references, measurement strings and at most 12 short type/code entries in each diagnostic list. It includes no raw log text, arbitrary external object, full path, exception text or unbounded nested payload. JSON iterencoding checks each ASCII fragment and the accumulated bound before appending it. The construction is bounded under the stated metadata/numeric limits; it does not claim immunity to real allocation failure. Separate raw diagnostics remain verbatim in the retained stream and are identified by hash and byte range.

Report creation is exclusive and no-follow, checks regularity/alias/identity, uses bounded data, fsyncs, and captures write/close failure. There is no retry or overwrite. A failed report may be absent or partial and is not a completion receipt. The returned outcome preserves primary and secondary evidence even when no report can be written. The serialized report says ATTEMPTED; the caller must authenticate actual successful completion/close through a separate controller receipt. A fallible fallback stderr record includes only bounded primary/reporting types; its failure is separately best effort. This cannot guarantee delivery when every diagnostic channel fails, and it never substitutes a secondary exception for the primary.
