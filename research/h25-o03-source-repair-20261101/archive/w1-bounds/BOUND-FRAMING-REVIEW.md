## Scalar bounds derived independently

Write `u(x)` for a returned estimator and B for `batch_bytes`, with allowed exact-int limits `64 <= B <= 1,048,576`, `1 <= R <= 1,024`, `1 <= C_copy <= 1,048,576`. A factory bool fails these exact-int guards.

For exact integer n, let k be the bit length of |n|. Zero has k=0, encoding length 1 and estimate 2. For nonzero n, decimal digit count is `floor(log10(|n|))+1`. Since `|n| < 2^k` and `log10(2) < 30103/100000`, the positive digit count is at most `floor(k*30103/100000)+1`. Adding at most one minus sign gives `|C(n)| <= floor(k*30103/100000)+2 = u(n)`. Python's arbitrary-width multiplication and division in this estimator do not invoke decimal conversion or impose a machine-word cap. They can still allocate and fail. Decimal digit-limit and large-int helper behaviour remain the original encoder/provider's behaviour; fitting the estimator does not promise conversion success.

For an exact string of n Python code points, `u(s)=12*n+2`. Two quotes cost two bytes. Each ordinary ASCII character costs one, quote/backslash/control escapes cost at most six, BMP non-ASCII and a lone surrogate cost six, and a supplementary code point can cost two six-byte surrogate escapes. Therefore every code point costs at most twelve. A pre-existing surrogate pair is two Python code points; the same bound still applies. `ensure_ascii=True` delegates the exact lower-case hex spelling, short escapes and surrogate ordering to the original provider. Empty string has exact length and estimate two. This conservative estimate can reject a record whose actual encoding is small; the domain is estimator admission, not every byte-fitting record.

None is four bytes and estimate four. True is four bytes and estimate five; False is five and estimate five. The type branch separates bool from int.

For float, 32 bytes is a conditional provider premise. Under the intended CPython-compatible binary64 shortest-round-trip formatter, finite nonzero output uses at most 17 significant digits. A scientific spelling needs at most 17 digits, one decimal point, `e`, exponent sign, three exponent digits (decimal exponents within −324 through 308), and one value sign: at most 24 bytes. Fixed notation under the usual formatter cutovers (decimal exponent −4 through 15) is shorter: at most a sign, `0.`, three leading fractional zeros and 17 significant digits, or the corresponding integer/fractional spelling. Signed zero `-0.0` has four bytes. Default JSON nonfinite spellings are NaN (3), Infinity (8), and -Infinity (9). Thus 32 dominates those stated semantics. Neither the binary64/formatter contract nor its workspace has been authenticated for the intended host here; arbitrary Python implementations are not covered. Boundary cases in the companion JSON are proposed independent literals, not observed outputs.

## Structural induction, early cutoff, aliases, and depth

For a fully traversed exact list/tuple with m children, the estimate is `2 + sum(1+u(child))`. Actual bracket/comma cost is `2 + max(m-1,0)`; the estimate pays one extra byte when nonempty. For an exact dictionary with m exact-str keys, the estimate is `2 + sum((12*len(key)+2) + 2 + u(value))`. The extra two per pair pay a colon and a conservative comma; actual commas total `max(m-1,0)`. Empty containers have estimate and length two. Induction using the scalar cases establishes the upper bound whenever traversal completes successfully and no intermediate over-limit return was taken. Dictionary traversal order used to estimate does not matter to the sum; exact lexical key sorting and actual key spelling are delegated to `C`.

An early container return occurs after a partial sum exceeds B. That value need not bound the entire unvisited subtree and does not certify its types or absence of a later cycle. It is only an admission rejection witness. Result/roles reject an estimate over B; array records reject `u+3>B`; later emission checks the same per-record condition under the frozen-input premise. No successful admission relies on the unread remainder of an early-cutoff subtree. It is incorrect to advertise every numeric `_bound` return as an unconditional full-tree upper bound.

Ancestor IDs describe the active path and are removed in `finally`. A repeated acyclic child in separate positions is admitted and encoded separately at both positions. A self-cycle or longer back edge on the current path is unsupported and selects literal fallback before staging. There is no global visited-set deduplication and no alias normalization.

Depth is tested only for containers: root container depth 0 through container depth 31 is allowed; a container reached at depth 32 is unsupported, while a scalar reached at depth 32 is allowed because scalar branches run first. There can therefore be 32 nested containers in one admitted record. `_array_admitted` starts a fresh traversal for each element; the outer field array and witness/code dictionaries are not included in that record counter. Candidate `C(batch)` adds a batch wrapper, so it can encode 33 nested containers; the equivalent full witness can contain 34 containers on a non-code path or 35 on a code-array path. Rank records have their separately constrained event/rows shape. Result has its own depth-rooted check, and roles is scalar. These are structural depths, not a claim about the provider's precise recursion-counter increments. Successful original whole-value encoding and sufficient original/candidate recursion budget are separate premises.

## Auxiliary live storage and provider obligations

The honest source-facing expression is `M_aux = O(R + C_copy + D + U + K) + E_runtime(B,D)`. It is a bound on successful fast-path live auxiliary storage beyond already retained input values, not process RSS. R counts copied element references, not encoded bytes or entire record payloads; C_copy caps a stage-read bytes object; D includes the wrapper-adjusted depth actually handed to the encoder; U is the number of distinct exact row tuples referenced by the temporary receipt set; K covers captured function/global/default/class metadata, fixed three-file operational structures, path lengths, stream buffers, and scalar counter storage. The O(U) set contribution owns table slots and references, not copies of the already retained row tuples or their arbitrary-width integers. Generic rows have exact-int leaves at record depth 2 and a variable tuple width w. Since each int estimate is at least 2, a rank event estimate is at least `8+3*w`; per-record admission implies `11+3*w<=B`. Thus row width is bounded by B on the fast path, independently of U. Hashing/equality scratch and numeric-conversion scratch still require provider premises.

For arbitrary growing generic streams, K must explicitly include the bits for byte/batch counters (O(log(total emitted bytes))) or a fixed-machine representable-size premise must bound those counters. K is not silently a universal constant under every mathematical input-size model. Exact built-in dict/set and tuple/int hash providers must have the usual bounded-table/stack workspace; unknown provider scratch cannot be dismissed by counting U references alone.

Define E_runtime as the maximum simultaneous encoder-related live storage for bounded successful canonical calls, including returned bytes, Unicode/ASCII conversion, escaping, sorting, numeric-conversion helpers and overlapping old/new results. It is not merely an output-length variable. Individual result, roles, keys and batch calls have encoded size at most B under the premises above. Batch slices can overlap during assignment (two O(R) reference arrays); an old raw batch can remain live while its replacement is encoded. During C's ASCII conversion, the new Unicode representation and new bytes can coexist, together with that old raw batch. A memoryview avoids copying a batch interior but keeps its raw backing bytes alive. The writer does not intentionally retain a growing list of prior batches, and production emission returns synchronously.

Staging and copy occur sequentially. Even a conservative lifetime allowance includes a last raw encoding, a current and replacement copy-read object of size at most C_copy, stream buffers, digest state and views; it must not claim that only one batch-sized allocation is ever live. Exact source liveness constants and allocator retention require provider evidence. Whole retained inputs, input-loader parsed/restored overlap, independent-validator allocations, disk/page cache, allocator-retained free arenas, interpreter baseline, and caller construction are outside this live writer-only bound.

If and only if the actual authenticated encoder, sorting, escape, hash/set and reachable integer/float conversion providers establish `E_runtime(B,D)=O(B+D)` with compatible representation costs, the expression reduces to `O(B+R+C_copy+D+U+K)`. The supplied sources establish bounded canonical inputs, selected references and read requests; they do not establish that provider premise. Large-integer helper selection, decimal digit limits, recursion settings, actual module/callable origins, binary/build dependencies and IO/hash buffering are unresolved. The upstream sources mentioned by the audit are not actual-host metadata and were not fetched in W1.

Fallback remains the original eager writer. Failure handling formats `str(error)` before slicing it and canonicalizes the failure info before checking the 64-KiB manifest cap. Therefore no all-path bounded-allocation theorem follows, including after primary-exception hardening. No numerical peak RSS, physical memory, disk-block cost, speedup or full-caller saving follows from B=1 MiB. Complete historical/publication physical costs remain OPEN_NOT_ZERO.
