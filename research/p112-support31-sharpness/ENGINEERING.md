# Engineering and replay scope

Engineering-mode used its autonomous-run playbook. The exit predicate was one
exact, independently reviewable P112 boundary result with source pins,
meaningful rejection controls and a focused publication. The accepted iteration
balances the earlier cost120 equality into six actual support20 endpoints.
The decision trail is [decisions.tsv](decisions.tsv).

Build the Lever changed the deliverable from a cost calculation to a literal
witness and two rerunnable checks. Prove It Works required collective rank,
five codeword inclusion identities and the exact intersection dimension.
The modular checker supplies rational lower bounds through nonzero minors,
with a separate algebraic upper bound. Unslop kept the proof and scope claims
direct. The contribution preserves all predecessor inputs.

## Power of Ten inspection

1. The three new Python entry points use structured finite loops, without
   recursion or background processes. Tests run three serial subprocesses,
   each with a ten-second timeout and consumed return status.
2. Root generation uses 56 two-sparse representatives plus 256 sign patterns.
   The separate lattice check considers exactly `5^8` tuples. Every linear
   algebra matrix has at most 19 rows and 112 columns. Binary labels use an
   eight-by-sixteen inverse and at most 112 eight-coordinate solves.
3. Runtime allocation has the managed-language deviation below. No search,
   solver or replay evidence grows with an external parameter.
4. After formatting, `verify.check_witness` is 58 lines and
   `independent.check` is 56. All other functions are shorter than 55 lines.
5. Explicit ValueError guards enforce inventory, shape, integer ranges,
   source hashes, support, independence and inclusion identities under `-OO`.
   No mathematical guard depends on an assertion statement.
6. Matrices, roots and witness state are local. Constants are the package
   path, prime and predecessor simple system. No global mutable cache exists.
7. JSON inputs have file-size caps. Sparse endpoints have exact dimensions,
   unique indices and bounded nonzero integer coefficients. Rank functions
   validate dimensions. CLI writes use exclusive creation outside the checkout;
   tests check success, overwrite refusal, checkout refusal and source tampering.
8. No dynamic code execution, generated modules or registration is used.
   The standard unittest framework has its bounded discovery convention.
9. Ordinary direct helper calls keep witness construction visible. The modal
   choice callback has at most six possible values and deterministic tie handling.
10. Python runs with warnings promoted to errors. Formatting and Ruff's
    E,F,B,UP,I,C4,PIE,RUF checks run on all new Python files. The registered
    hook executes all mathematical checks and behavioral tests. Ruff's ALL
    selection also enables mutually incompatible docstring rules and library
    conventions such as banning CLI print; those are not this package's policy.
    No diagnostic suppression or inherited configuration change is introduced.

## Managed-language allocation deviation

Rule: 3, fix memory capacity before steady operation.
Location: the three new Python files, including Fraction elimination and JSON.
Reason: Python allocates tuples, integers, fractions and dictionaries at runtime;
prohibiting allocation would require replacing the interpreter and standard library.
Scope: this finite, parameter-free witness replay only.
Compensating control: JSON files are capped at 100,000 bytes; parsed vectors have
fixed dimensions and integer ranges; the largest matrix has 2,128 entries and
the lattice list retains only 120 roots from 390,625 candidates. External outputs
use one new file, while tests own and remove temporary directories. Input-size
bounds cap arithmetic growth; no runtime memory-performance guarantee is claimed.
Verification: both registered checkers and all fourteen optimized tests, including
malformed entries, source tampering and output-path failure controls.
Follow-up: replace this allocation model only if a caller needs an explicitly
bounded memory backend or a parameterized family. Do not extrapolate this finite
Python checker into such a backend.

The standard-library unittest dispatch is bounded to fourteen methods in one
class. It is the test-framework exception to rule9's direct-call preference;
it is not used in either mathematical checker. Every subprocess is waited for
and no new shared code or historical scientific input changes.
