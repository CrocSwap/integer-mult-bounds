# Signed application adapter for the fixed #7623 splice

This is a preparation design, not an executed application or an admission. `adapt_signed.py` starts with the authenticated prepared predecessor signed runner (SHA-256 `c26b0c59b44eaab54a5f275eeffe77f7e5cbb7316b255d7c3ea127b9ce32b997`, exactly 136 CRLFs). It requires the completed fixed differential gate, verifies its receipt hashes and price/manifest/source bindings, reads the candidate canonical hash and claim/probe dynamically, and makes uniquely counted patches. It records the original and normalized byte hashes, each old/new patch, and adapted hash. No engine rerun is part of this adapter.

The launcher must prepare `frozen-composition/7623-WORD.json.gz`, `7623-INVOICE.json` and `CONTACT7623-PRICE.json` from the authenticated current source and positive first gate, alongside the candidate overlays and native result. The launcher and adapter ledger must be named `CONTACT7623-LAUNCHER.py` and `CONTACT7623-ADAPTERS.json`. The signed runner requires the same current run ID, candidate canonical hash, native-result hash, launcher hash and adapter-ledger hash in the fresh native receipt; a predecessor result cannot substitute for it. The source word is independently canonical-checked and the original complete source invoice is pinned to `5be4724fde8264b8b1b4a565ea2eb1a56339f29528db40728b3fab210c44208d`.

The retained signed runner reconstructs the 17-call caller, predecessor #7546 and #7604 invoices, fresh candidate invoice and, with this adapter, the current #7623 source invoice. The complete actual signed source/candidate paid delta is checked as `{1:-51,2:17,4:-17,5:17}`; targets are equal, paid counts 110145 and 110111, targets 22461 and surplus 1424. Comparisons with the old #7546 and #7604 baselines are derived from their reconstructed actual invoices plus this checked fresh source/candidate delta, rather than copied as constants. The official retained pricing path compares actual complete invoices and checks the dynamically bound first-gate claim and probe above source upper `0.0036624027916` against its fresh bracket.

The signed runner retains the full catalogue loop, including its actual denominator, contiguous slices, phase controls and 104-boundary evidence; the launcher must independently validate full closure, the 17 calls and 58 outer predicates. It runs seven fresh source checks and seven candidate checks with a common signed caller and separately reports matched 17-call ordinary totals. Source native resource fields come from the freshly calculated paired source branch of the candidate-bound native run, **not** an independently rerun source native application; the source catalogue is explicitly marked not rerun. Any source application transfer remains contingent on paired operator, phase, boundary and resource proof. Paired precision and tape evidence are recorded. This adapter stops if independently derived source/candidate context height, mass bits or precision differ, or precision exceeds 4096; a differing context requires a freshly justified and charged common context, not a silent cap. Equality alone is not a complete numerical service proof.

The distinct common-U qualification must cover every actual private extent and numerical envelope, allocation/return and public/spectator preservation. It must account for 180 lifetime pairs per occurrence (3060 across 17 calls) with 1156 reserved banks; the 4000-unit lifetime-routing item, 32 scalar-service units at every INIT/CLEAR and normalized 2^20 coefficient retain all size, precision, descriptor, storage, tape and conversion factors. The lifecycle budget is not spare reset funding; no physical provider is implemented. The compared actual 17-call source and candidate ordinary figures are freshly recomputed and cannot be replaced by the published 785,921,632 value from another context.

No preparation, run, candidate price or source scientific code execution was performed by this author. A future run remains subject to the one authorized envelope: one CPU, 2 GiB, no swap, signed subcap 900 seconds, descendant accounting, no retries or widening. Missing resources, stale source/receipt, unequal precision contexts, broken inherited anchors or a failed gate stop the case. Static syntax validation alone does not establish that the adapted predecessor runner's source anchors match or that its mathematical assertions succeed.
