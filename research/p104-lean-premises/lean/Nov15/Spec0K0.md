# Spec0K0*.lean: spec-break survivor #0, k = 0 radical certificates 
Core: `Spec0K0Core.lean` (explicit 4x4 matrices, jobs MJ, flags MEm/MFm, omega, LLm = (DU)^2 - I, Rel, Kill). Field K, CharZero (needed: certificates have denominators 2^k).
Pipeline (internal notes): gen7-style model -> Singular `lift` of 1 = c0 (1 - t f) + sum c_k g_k over Q for each target f (4 omegas + 64 entries of (D_mu U_mu)^2 - I) -> Lean: by_contra, t = f^-1, `linear_combination` with the cofactors (each c_k g_k separate `have` via mul_eq_zero_of_right to keep elaboration small). One certificate per CLASS, over the whole ideal J (W3 = Z4, W7 = I, unit blocks, job relations): f in rad(J) iff f vanishes on every component, so this is equivalent to (and replaces) the 292 per-component tests.
Class ABCEDF (the audited one, 4 components): 68 targets: 28 are identically zero polynomials (`ring`), 32 certified by radical certificates (files Spec0K0_ABCEDF_s0..s6.lean, each 34-81 s, <= 2.7 GB, axioms [propext, Classical.choice, Quot.sound]), 8 NOT certified: omega_1, omega_2, omega_5, omega_6 and the four (1,4) entries (equal to omega-type polynomials). Singular proves all 8 are in J itself (m = 1) in the 31-variable ring, and in rad(J) with W7, U5, U6 dropped (om1: 36 nonzero cofactors, 3.8k terms; with prefix-product node variables 65 cofactors, 327 KB), but Lean `ring` on any of these identities exceeds the 3.5 GB guard (flat base ring: 86-200 KB per certificate; node form: elaboration fixed by splitting, ring still > 3.5 GB). Coverage: classes 0.9 of 90 (ABCEDF at 60/68 targets); batching other classes would only add the same 60/68 and was not run.
Next step (not done): a reflective polynomial-identity checker (monomials as sorted index lists, kernel `decide`) or staged Groebner-chain certificates with small cofactors for the four omega identities.
