# CK helper-run sign normalization

**Finite complex-supplier circuit construction; no new kappa.** Deferring register
negations inside one scalar frame, then paying every required boundary negation,
saves **224 real primitives per orientation** of the historical PR626 CK word
after Sagar Thakrar's accepted PR696 lowering.

| Complete scalar projection | PR696 baseline | Replacement | Saved |
| --- | ---: | ---: | ---: |
| Forward | 169,618 | 169,394 | 224 |
| Backward / inverse transpose | 169,634 | 169,410 | 224 |

Counts include both real and imaginary components, all coefficient preparation,
source reads, copies, clears and boundary restoration. They are instruction
counts, not measured runtime gains. The 21,936 scalar macros are partitioned
into 2,219 maximal same-frame runs in each orientation. Exactly 14 runs save
16 real primitives each; 2,205 have zero cost change and none increases cost.
The changed runs have frames `52 + 29*k`, `0 <= k < 14`, on the helper blocks
within logical registers 224 through 447. Every changed event interval is listed
in [EXPECTED.json](EXPECTED.json).

The complete paid recursive profile remains
`{1:2596, 2:552, 3:304, 4:160, 5:70, 6:8, 8:8}`. This historical supplier is not
the selected #799 X4 supplier. At the exact base below, the selected conditional
value is **0.001661634653669567**; this package neither changes nor recomputes it.

## Reproduce

From the repository root, standard-library Python 3.9+:

```sh
python3 -I -O -B research/ck-sign-normalization-seed22/check.py
```

Expected final line:

```text
PASS_CK_SIGN_PACKAGE runs=2219+2219 columns=725 saved=224/224 kappa=unchanged
```

The command checks the source pins, recomputes both committed receipts, and
compares the independently generated primitive-stream hashes and costs. It is
offline and writes nothing. The exact new circuit is generated by
`compile.optimize_run` applied to each `verify.segments` run of the pinned
program, using the pinned `lower.py`. Each primitive retains that run's frame.
All non-scalar events remain in their original order and are emitted unchanged
when composing these substitutions with the original program. No original
generator, selected certificate, or `upstream/` file is edited.

Additional adverse and portability checks:

```sh
python3 -I -O -B research/ck-sign-normalization-seed22/test_package.py
```

Expected: three tests pass. They include 56 actual-run deletion/sign mutations,
a copy-fanout accounting case, isolated optimized execution from a minimal
source closure with spaces in its path, alternate gzip encoding, and rejection
of a changed source or forged saving. The independent checker additionally
rejects five toy mutations and checks frame/non-scalar/end segmentation. A
positive segmentation check is not counted as a rejected mutation.

## Mechanism and complete cost

Maintain `logical[r] = sign[r] * physical[r]`. A negate toggles the compile-time
sign; signed addition changes sign when its two operands have different signs;
copy inherits its source sign; clear resets it. Emit an actual negate for every
remaining negative sign before a non-scalar event, any scalar frame change, or
the program end. The compiler emits an ordinary fixed primitive circuit; there
is no runtime metadata or additional helper.

Every non-negation remains one operation, including all operand accesses.
Per real component, each orientation removes 348 negations and pays 236 boundary
negations. The complete reduction is `2*(348-236)=224`. In general this rule can
increase cost when a negated source is copied into several outputs; the package
explicitly tests that case rather than assuming omitted negations are free.

The [proof](PROOF.md) establishes exact boundary equality and unchanged absolute
prefix envelopes for arbitrary dirty inputs. For an inherited cost
`R = sum_i m_i R_i + C + A`, the substitution changes only `C` to `C-224`;
every child multiplicity `m_i` and the unchanged adapter/frame/hosting charge `A`
is retained. This fixed scalar saving does not change the recursive moment or
justify a new exponent. There is no supplier search or favorable unimplemented
cost model being promoted to a kappa claim.

## Verification scope

Two independently written arithmetic interpreters check different bases:

* The primary Fraction interpreter replays both complete **scalar projections**
  on 725 arbitrary initial columns: 716 logical and nine private. It checks
  every run boundary, the expected final shear, all helper restoration and
  private clearing. Exact scalar-projection prefix row-l1 maxima remain
  5,120 forward and 4,847 backward; fractional depths remain 3 and 8 bits.
* The second interpreter uses normalized integer dyadic rows and an independent
  event splitter. Every touched register starts as an independent input at
  **each run**, including private work. It checks full endpoint operators and
  every candidate prefix row against exact baseline prefix rows modulo sign.
  The largest local basis has 547 columns. Its run-input l1 maxima are 1,034 and
  4,145, and denominator exponents 4 and 6. These are different coordinates from
  the complete scalar-projection quantities and must not be compared as if they
  were competing global bounds.

Neither interpreter executes Clifford/frame/non-scalar event semantics. The
arbitrary run-input operator equality proves an exact local substitution across
those unchanged opaque boundaries; it is not a fresh native physical replay.
The independent checker shares the pinned predecessor lowering and candidate
compiler, but not the primary interpreter, splitter, or Fraction row arithmetic.
The original 192-bit local allocation is retained, not reduced. Native admission,
typed production integration, physical rounded precision/tape realization, and
fresh owner/invoice/assembly bindings remain separate obligations. All-size
compiler, hosting and analytic assumptions remain inherited. Finite checking
does not formally verify the full integer-multiplication theorem.
