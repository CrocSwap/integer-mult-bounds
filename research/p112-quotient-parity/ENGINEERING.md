# Implementation bounds and decisions

The checkable predicate is one new exclusion for the literal TWOSIDE profile
`4,5^9`, with all finite geometric dependencies replayed and a complete
characteristic-zero proof. The outcome meets that predicate. No broader
census, supplier replay or selected-frontier change was attempted.

Build the Lever changed the deliverable from a prose argument to a registered
standard-library replay. Prove It Works changed verification to exact source
binding, full five-flat/root-plane enumeration, a rational circuit fixture,
optimized failure controls and publication-byte comparison. Unslop shaped the
scope and limitations in the proof and README. The retained code is assessed
against Power of Ten as follows.

- All control flow is structured and nonrecursive. Each function is below
  sixty physical lines. Command failures propagate; external receipt output
  is created exclusively and cannot overwrite a file or write inside the
  checkout. Source input size is bounded before reading.
- Loops use fixed E8 dimensions or validated bounded collections. The five-flat
  census has exactly 3,309,747 states. Root-plane checking uses 7,140 pairs
  times 120 possible lines. Reflection checking uses 120 times eight states.
  The largest matching enumerator visits 24,158 edge subsets at size eight
  and retains at most 764 matchings. The application uses exactly ten pieces.
- Runtime contracts remain active with optimization; mathematical validity
  does not rely on Python `assert`. Imported geometry validates its fixed
  root/label inventories. No shared mutable state, network calls, recursion,
  dynamic evaluation or plugin dispatch occurs in the production replay.
- Rule 3 deviation: Python integers, Fraction and containers allocate during
  operation. Scope is this finite standard-library verifier; fixed dimensions,
  bounded input size and sequential 120-second command limits constrain it.
  The census streams masks into a 113-bin histogram rather than retaining
  millions of spaces. Revisit allocation only if the domain is expanded.
- Rules 8 and 9 deviation: unittest discovers fourteen local test methods and
  uses runtime dispatch. The production verifier uses explicit calls. The
  fixed test module runs under optimization and returns failure status.
  No additional discovery paths or registrations are admitted by VERIFY.json.
- Rule 10: warnings-as-errors execution, source compilation and Ruff's
  E,F,B,I,UP,SIM,RUF checks cover the retained Python paths. An exploratory
  Ruff ALL scan also reported annotation/docstring/copyright conventions,
  pytest-only suggestions and magic-number style rules. Those conventions
  do not match this standard-library executable proof package; replacing
  unittest assertions would disable the optimized controls. Applicable import,
  line-length and collection-expression findings were corrected. No lint
  suppressions were added. Further type-checking would require an explicit
  typed interface for inherited geometry, outside this proof's change.

## Decision trail

1. Reused the clean sparse worker from a fresh canonical-main baseline and
   preserved all prior branches. Live overlap and the released PR3169 handoff
   selected the quotient-independence question before implementation.
2. Rejected the individual root-restricted flat-capacity idea. Complete probes
   for representative support-53/support-56 roots retained maxima eight and
   twelve, so that approach did not improve the failed support estimate.
3. Used the six-circuit/root-plane restriction and odd proportionality classes
   to select a valid four-piece quotient set. The older endpoint inequality
   already gives margin 39; the stronger PR3169 count was unnecessary.
4. A first test wrongly assumed the first eight ordered live roots span eight
   dimensions. Their measured rank is four. The corrected independent control
   computes the full live-root Gram matrix and verifies rank eight.
5. The first receipt equality check compared tuples with parsed JSON lists.
   Canonical JSON conversion fixes the representation comparison without
   changing any proof-relevant value. Cross-version replay checks it directly.
6. Exact environments, source pins, complete receipts and commands are retained
   in CHECKS.json, SOURCES.json, RESULT.json and VERIFY.json. Disposable probes,
   logs and exports are removed after publication.

Internal read-only mathematical reviews corroborated the six-circuit,
odd-class and characteristic-zero arguments. They do not substitute for
independent human review or proof-kernel verification.
