# R437: join an actual Program handoff to descendant stock

**One source-bound semantic witness; no new kappa or numerical admission.**
This answers the first handoff in [PR4685](https://github.com/CrocSwap/integer-mult-bounds/pull/4685):
its arithmetic path is now connected to a source-authenticated root, the actual
produced chronological Program STEP, and the literal `Machine.prepare_child`
row port. Only this new research package is changed.

For the paid R437 D carrier's SOURCE87 request **1676**, semantic root width
**2048**, field **q=3**, precision **w=1**, root unit **2**, and the predecessor's
conservative stock **K^7**, the actual good-child itinerary produces width
**64**, depth **1** and the same modulus **3**. The handoff copies exactly
**R/A** rows, where `A=28416 |GL64(F_3)|`. It does not divide those rows again by
9475. The unchanged PR4685 arithmetic checker accepts the resulting two-node
path, including the internally stopped child and its remaining stock obligation.

The witness connects boundaries that were previously checked separately. It
is not another stock-divisor proof, an installed runtime guard, a completed
supplier, or evidence that the smaller `9475 A^D` stock is admitted by PR4176.
The frozen semantic entry still requires its stronger `K^D` stock.

## What actually executes

The replay executes the boundaries below. Prefix production, quotient/guard
and handoff run inside PR4176's unchanged `checked_entry` continuation; the
event metadata is source-derived beforehand:

1. `directory.produce` from the empty root history. At w=1 its unique high
   field is the zero matrix; the produced bytes are compared with that fixture.
2. The unchanged four-statement quotient/save/stock-check AST from
   `Machine.node`, using the **real binary Count tapes**, not PR4685's integer
   Count adapter. The rest of `Machine.node` is not executed.
3. `residual_blocks.events(page, ('good', 1, 0))`, which derives the event from
   the actual rank-two source plan: first 0, second 4032, width 64, depth 1.
4. The literal `Machine.prepare_child`, including `SelectedBinding.child_program`
   and `children.extend`, then the actual `Program.root` and `Program.step`
   readers on the handed-off Program.

`prepare_child` uses the retained source-bound three-power implementation of
`Layout.child_extents` from the PR4176/encoded-child-spectators lineage. This
is an explicit geometry adapter; neither it nor the caller is modified.
The capsule's `current` payload is empty. Only the metadata and stock transfer
are executed; there is no materialized production packet, CALL/RETURN,
recursive payload or numerical coefficient execution in this witness.
`Word.inspect` is disabled during `prepare_child`; the observations are read
only after it returns. Parent tapes, Program bytes, heads and numerical live
sets are checked at the handoff boundary.

The separately written `bind` witness checker anchors the observed root
width/unit/depth, runtime width/depth, q/w/modulus, original row count, source
identity/code/request, produced STEP, event and grants before calling the
unchanged PR4685 `certify_path`. The source bytes and fixture are part of the
certificate; `bind` alone does not authenticate arbitrary user-supplied integers.

## Discriminating controls

The deterministic [RESULT.json](RESULT.json) contains 19 rejecting controls.
They include changed root rows/unit/width/depth, source identity/request/code,
field/precision/moduli, STEP rank, and the prepared rows. Doubling both the
claimed unused stock and handed stock still satisfies local child divisibility
but fails the exact parent quotient.

Two direct-method controls distinguish responsibilities: `prepare_child`
accepts a supplied width 63 or depth 2 while the produced Program still says
width 64/depth 1. The new witness check rejects the mismatch. These are **not
reported caller bugs**: retained descendant ingress checks Program width/depth,
and width 63 would not pass `Machine.block`'s internal-recursion cutoff. A
foreign parent object and foreign source code are rejected by `prepare_child`
itself. No malformed event is claimed to arise from the actual producer.

The frozen caller loader only recognizes its two historical complete selected
records. It rejects the current #4470 record. The verifier therefore copies
its eleven declared external inputs to a temporary directory, substituting
only the exact retained historical selected-record bytes with Git blob
`b1fea0c94436b236cc2b7d41a7be032811b94c81` and SHA256
`bb2eaa58647b353f88d0aec2eafb9d30df1be53589231b23e12ceef3e4bad129`.
It points `loader.REPOSITORY` at that projection and runs the unchanged loader's
full authentication and selected-record rejection controls. No loader guard
is disabled, no frozen input is edited, and the temporary projection is removed.

This intentionally exercises the historical R437 constructor. The current
selected record remains conditional kappa **0.00302015**. The q=3,w=1 fixture
is outside the numerical domain: q is below 2^80 and w is below the original
root's required coupled precision (2 here). `numerical_admitted` is explicitly
false. Larger-prime admission, guard tariffs, source-table construction,
whole-packet backing, restoration after recursive execution, and complete
supplier/outer costs remain open.
