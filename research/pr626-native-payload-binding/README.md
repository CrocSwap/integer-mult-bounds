# Portable native-byte binding for the PR626 independent owner check

**Tooling improvement; no new κ.** The selected independent owner checker rejects
an unchanged native program when only the gzip timestamp changes. This opt-in
adapter binds all decompressed bytes instead, then executes the original owner,
profile and exact rational-moment code. It changes no existing repository file.

## Reproduce

From a checkout containing upstream base
`66849e1475c930fd7732b1a0067ffee7e1e95f60`, with Python 3.10+ (standard library):

```sh
python3 -I -B research/pr626-native-payload-binding/verify.py
```

Expected:

```text
PASS_PR626_NATIVE_PAYLOAD_BINDING inputs=4 representations=16 rejected_mutants=16 additional=6
Identical full receipts: 72 calls, 35424 roles, rank mass 520704, both exact moments.
```

Fresh timings follow; they are not acceptance criteria. For a rebuilt native
directory, use the same arguments as the original independent checker:

```sh
python3 -I -O -B research/pr626-native-payload-binding/check_owner_map.py \
  --work /absolute/path/to/complex-replay --out /absolute/path/to/owner-check.json
```

The original `--provider PID=DIR` overrides are preserved. The default repository
replay continues to use its original checker. This adapter is an independently
reviewable, opt-in replacement for that one step, not a modified selected
certificate or a claim that the entire cold replay is now portable.

## Concrete finding and remedy

The original comparison in
`research/complex-k492-owner-repair/extras/check_owner_map.py` hashes
`CANONICAL-WORD.json.gz` and `LOCAL-PROGRAMS.json.gz` for both `ck` and `jp8`.
Those files are regenerated by the cold replay. The comparison uses
`comparison/PR622-NATIVE-HASHES.json`, a historical compressed-byte receipt.

On the pinned original containers, the check succeeds. For each of the four
inputs, changing only bytes 4–7 of the gzip header to timestamp 88 leaves every
decompressed byte identical but causes:

```text
ValueError: unchanged PR622 native word and program
```

This is a concrete representation-only false rejection. It is not evidence
against the selected construction, an observed failure of a particular CI run,
or a missing mathematical proof.

The adapter pins the exact original checker, its rational interval engine and
the historical native-hash receipt. It verifies those hashes, requires exactly
one occurrence of the old comparison, and replaces only that comparison in
memory. All original path resolution, owner checks, source/data comparisons,
both native orientations, width recounting, profile assembly and both exact
moment evaluations execute unchanged. No global function or hash implementation
is monkeypatched; the original source is never edited.

Four constants bind the SHA-256 of the complete decompressed native byte
streams. `verify.py` independently derives those constants from the archived
PR622 containers and verifies their original Git blob IDs and historical
container hashes. `SOURCES.json` pins all twelve executable/input dependencies.

### Why the scope of the check is preserved

For a gzip container `C`, let `D(C)` denote its checked decompression. The
original mathematical checks consume `json.loads(D(C))`. The adapter requires
`SHA256(D(C)) = SHA256(D(C_reference))`, under the same collision-resistance
assumption already used for source and container pins. Thus each accepted
candidate supplies exactly the reference byte stream to every downstream
calculation. Compression headers, level and member boundaries can differ.

No JSON field is omitted or normalized. Even a whitespace-only change in the
decompressed JSON is intentionally rejected. The new acceptance class contains
additional encodings of the same payload, not additional mathematical words.
Malformed/truncated streams and CRC failures remain errors. This is an argument
about the pinned finite checker; it is not a formal proof of the multiplication
theorem or an adversarial concurrent-filesystem model.

## Completed coverage

The finite test domain is the four selected native files, without random search.
Seed 88 selects the scalar mutation sites, timestamp and counterbalanced
benchmark order.

| Controls | Count | Expected result |
|---|---:|---|
| Timestamp only, levels 1 and 9, two gzip members, independently on each input | 16 | Original rejects; adapter emits the identical complete receipt |
| Scalar coefficient changed, JSON whitespace added, CRC damaged, trailer truncated, on each input | 16 | Both reject without emitting a receipt |
| Explicit recompressed provider overrides; relocated adapter | 2 | Identical complete receipt |
| Unknown provider; drift in checker, interval engine or historical native receipt | 4 | Rejected |

The four scalar mutations preserve the quantities this owner checker recounts:
native widths/profile or forward/backward child counts. Their rejection shows
why binding only aggregate profiles would be too weak. This implementation
retains the complete native-byte binding.

The original and adapted complete receipts are compared byte for byte with
`EXPECTED-OWNER-CHECK.json`: 72 calls, 35,424 roles, rank mass 520,704, all idle
counts, both rational interval endpoints and margins, and unchanged
κ = 51110230636731/31250000000000000. All child processes run with `-I -O -B`;
rejection checks do not rely on Python assertions.

## Timing and execution evidence

`EVIDENCE.json` records the complete final experiment, every control and the
environment. Five same-input pairs alternate original/adapted order in fresh
processes. On Linux x86-64, CPython 3.14.7, zlib-ng 1.3.1, the medians were
**0.336487 s original** and **0.315098 s adapted**. OS caches were not flushed.
This is a reproducibility fix; no reliable speedup or end-to-end cold-replay
performance claim is made.

The ordinary and optimized parent runs, an unrelated-working-directory replay,
and a relocated minimal source snapshot are covered by the handoff checks.
All original source/input bytes remain unchanged. Full `make verify`,
`make frontier626-verify`, Lean and remote CI were not run for this additive
package. The local input set is an exact GitHub-API-fetched subset, not a full
clone; every execution input has a verified Git blob ID.
