## Exact result and independent methods

Both implementations compare all **2,048 columns and 1,048,576 complex
coordinate positions**, including zeros. Their four normalized matrix digests
agree; there are 26,624 nonzero coefficients. All arithmetic uses Gaussian
integers with powers-of-two denominators, without numerical tolerances.

`verify.py` constructs canonical-frame kernels by literal span completion,
exhaustive coordinate inversion and the quadratic chart formula. It composes
`Gamma_B Gamma_A^†` by exact finite convolution, independently of the compiler.
It separately interprets the compiled right monomial, positive rank-r child
and left monomial.

`oracle.py` builds independent dense P/D/C circuits using binary elimination
and basis completion, then applies them to each computational basis vector.
Its recipe side uses a separate direct monomial/child kernel. Neither
scientific consumer imports the source compiler, author checker or the other
consumer. Complete column equality gives equality on every complex input
vector in this fixed 512-dimensional space by linearity.

The exact compiler recipes are generated by `produce.py`, which authenticates
and executes the retained source compiler bytes directly. **Generation is
source provenance, not independent verification.** Default execution
regenerates and compares every typed canonical JSON field with `RECIPES.json`;
`--emit` prints a fresh candidate without writing files. Both normal and
optimized regeneration are registered. The source compiler's own assertions
are not the scientific trust boundary: the two consumers check full operators.

## Controls and prior coverage

The primary records concrete coefficient witnesses for a global-i phase fault,
a right-factor phase fault that preserves all of column zero but changes
column one, and a wrong child rank. The dense oracle independently supplies
phase-only and inverse-child witnesses for each map. These are in-memory
operator/recipe faults, not claims of malformed physical source-word replays.

The predecessor checker already combines signed Pauli images with an exact
global-phase state column. That criterion logically determines a Clifford
operator. The column-zero control does **not** identify a flaw in that method;
it demonstrates coverage in this separate complete-column implementation.

Selected6030's fresh dense review names seven earlier tasks:
helper3→189, helper76→394, helper749→127, move3→189, move3→714,
move595→637 and move714→127. Its other source checks and reuse retain credit.
The old composite714→127 is not an independent check of each new factor's
phase. This contribution checks these four exact producer instances. Old
245/246 normalizers are not counted as new cases; no global comparison with
every previously published operator is claimed.
