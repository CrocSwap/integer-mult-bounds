# PR589 five-helper feasibility and whole-call hosting

The five-helper feasibility gate passed. This package supplies a **written
whole-call and chronological operator proof in the exact stream model**, with
independent source-bound certificates. It does not claim a new kappa, a Lean
proof for PR589, or completion of the all-size compiler and finite invoice.

The concrete starting case is stage 2, replica 0, pair 0: helpers 232 through
236 share physical family 666, but have different cover classes. Their residual
supports are 1..8, 9..16, 17..24, 25..32 and 33..40 of child 4's 42-dimensional
pending projector. The last two axes remain with the idle child. The proof
uses actual chart maps to distinguish owners; different route names alone
would not establish this.

After that gate, the audit was extended to both complete 27,234-instruction
programs, all 661 symbolic input columns, all 636 frame projectors, all 288
stage/replica descriptors, and the actual chronological idle/bridge schedule.
Those 288 descriptors represent cover sweeps; they are not an enumeration of
the much larger set of physical cover-class calls.

The source-specific extension over the older PR540 provider is the selected
PR589 word with its nine **rank-seven** COPY/ERASE pairs, and a complete
retained-state composition argument. A full rank-eight swap is incorrect here.
The proof keeps actual outputs between calls and does not reset dirty helpers,
bank outputs, or hosted data. Helpers can have arbitrarily correlated values.

## Evidence and scope

- [PROOF.md](PROOF.md) states the exact stream model, constructs injective
  owners, proves frame-relative simulation, and composes whole calls through
  the real untouched windows. The full-cover argument explicitly requires
  enumeration of every element of the orthogonal group.
- [verify.py](verify.py) is an independent standard-library checker. It imports
  no producer or predecessor checker, reconstructs both programs from the word,
  checks exact dyadic matrix identities and chronological guards, and rejects
  ten malformed controls. It also checks the five-helper completion on all 128
  address basis columns and compares its deterministic result with the receipt.
- [RESULT.json](RESULT.json) records exact hashes, COPY locations, owner supports,
  complete local profiles, and rejected controls. The same verification is
  registered with assertions enabled and disabled.
- [xcheck-source.json](xcheck-source.json) is a fresh run of the predecessor's
  independent checker, covering the 661 columns and H1-H5. It is supporting
  evidence, not an import used by the new checker.

The recursive profile is unchanged, with rank mass 1808352 and deficit 10272.
This checks recursive rank accounting only; the explicit charts still need
compiler and route-cost admission. The selected frontier remains untouched.
The distinction between a certificate, a written scoped proof and a complete
multiplication theorem is intentional.

Exact source pins are in [SOURCES.json](SOURCES.json). [TASK.json](TASK.json)
records the donor's explicit assignment and the change from the catalogue's
helper-mixing question to the separate physical-hosting question. No claim of
novelty follows merely from that scope change.

## Reproduce

From the repository root, with Python 3.12 and no third-party dependencies:

```sh
python3 scripts/research_package.py --package research/pr589-five-helper-hosting --check-only
python3.12 scripts/research_package.py --package research/pr589-five-helper-hosting
```

To reproduce the supporting predecessor check, use Python with SymPy:

```sh
python3 -B research/e8-bit-p111-tuned/code/xcheck_p.py \
  research/e8-bit-p111-tuned/tune/bitE8mut-p111-tuned.json.gz
```

The first local runs used Windows Python 3.12.2. The supporting check used
SymPy 1.13.3. Native supplier replay and environment details are recorded
separately in [VALIDATION.md](VALIDATION.md); the registered hook is not a
replacement for a full supplier replay.
