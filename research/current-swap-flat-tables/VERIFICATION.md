## Controls and failure detection

The current signed guard is tested at the first and last components, width
one, the most-negative second operand, equal signed values on distinct ports
and heterogeneous matching widths. Input controls reject empty fields, empty
components, missing delimiters, odd component counts, partial physical codes,
unequal widths and unequal record counts before any public write.

Source controls reject duplicate owner labels, actual repeated physical tape
objects, reversed unremapped operand order, changed opcode, wrong source site,
malformed remap wrappers, unsupported operations and corrupted input/dependency
bytes. The positive nested product test separates the active operation from
the original issuing PAID token.

Four independent injected code defects are detected by the same exact oracle:
omitted negation, reversed output order, omitted final overflow guard, and an
early public write before whole-field validation. The last is caught on a late
component overflow even when earlier components were valid.

A literal second call with reversed ordered physical ports restores both
original signed-swap inputs, including a most-negative second operand. Other
controls check arbitrary binary dirt on used and extra work, a protected
read-only descriptor, missing raw retirement, and a shrinking call on retained
erased backing. Fresh and warm small calls have exactly the same 1,685 physical
actions and 226 table steps, while retaining the larger historical high-water
coordinates 12,713 and 12,728.

An explicit rejection control confirms the stated cleanup boundary: a late
failure preserves both public contents while leaving advanced heads and
occupied work. No exception-safe physical rollback has been added or claimed.
