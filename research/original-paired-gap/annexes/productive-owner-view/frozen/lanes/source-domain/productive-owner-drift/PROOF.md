# Old productive owners at the paired mode ports

The selected allocation can remove all cross-core mode aliases with 37
exchanges of complete width-nine jobs. Each exchange stays within one call.
It changes 74 local role assignments in 14 calls. It does not change a job's
time, physical owner, pending axes, or address route. The global content
map still needs a proof. In particular, this result does not show that the
changed old owners return their required outputs.

## Exact source and event scope

`extract.py` reads the pinned selected 1094 archive and the accepted
280-role paired owner patch. It emits `SKELETON.json.gz`. The decompressed
SHA-256 is
`653b5f47d14d88cab23420796597e860a8bab73e86aa31fd471c3843c079e6d0`.
The file has all 144 calls, all 704 owner roles in each call, and the exact
626-position paired schedule. It retains the old 14,336 productive families
and all 490 private families.

The eight mode roles in each call are
`[225,226,229,232,241,242,257,258]`. Before the new repair, 11 pairs have
36 cross-core incidences. These are 15 first-mode/second-helper incidences,
20 second-mode/first-helper incidences, and one shared mode owner. The last
case is family 991 in calls 64 and 65. Both appearances must change if each
mode is to avoid every role in the other core. Thus there are 37 bad mode
positions.

The first skeleton is a literal input for a scalar-sector check. The check
must use the paired prefix, the first raw core, the second raw core, and
the paired suffix in that order. It must not replace these events with a
formula that assumes 16 distinct mode owners. Native operators and cover
permutations fix a constant array, so a negative exact vector in this
sector rejects the full proposed content word. A successful sector check
would not prove native access.

## Inherited frames

`frames.py` reads the original `DATA-PHASES.json` member and replays the
complete native owner history under the old paired patch. It checks all
69,120 complete helper jobs, 7,526 idle suffixes, 35,840 complete idle phase
slots, 32,256 bridge frame pairs, and 1,008 original Y-entry phase maps.
The decompressed `FRAMES.json.gz` SHA-256 is
`05fea8db6582bab35fe457bb333f0e7b3c6bd35c48c668ecea59457e2b6d50f7`.

For a physical owner with port label q, use its pinned orthonormal basis
B=(q,b1,...,b8,e9,...,e72). Its exact frame is

    X_delta product_{i in W} C_(B[i]).

The code retains both the axis set W and the translation delta. It checks
phase equality as a polynomial over Z/4, including all quadratic terms.
Every operator has eigenvalue 1 on the zero Fourier character, so these
polynomials do not omit a scalar phase.

For a width-nine helper job, sigma has the nine pending B axes first and
the remaining B axes after them. The owner class is g=d sigma^-1. Thus its
frame in invocation coordinates is

    X_(sigma^-1 delta) product_{j in sigma^-1 W} C_(e_j).

The pending nine axes are absent from W. The inherited frame is therefore
outside the nine local axes. The exact active Y input at stage s has the
coordinate Fourier frame on axes 9 through 8s+8, after the original entry
translation. The code checks this last assertion directly against every
serialized original phase map.

The relative native rank is the size of the symmetric difference of these
two coordinate axis sets. It is zero for 40 of the 1,152 occurrences.
The translation also vanishes in 34 cases. The largest relative rank is
49. This is a statement about the logical interpretation of the old owner.
It is not a mandatory added circuit cost: the physical paired graphs can
use the inherited owner arrays, with this relative operator included in
the resulting content map. A conversion cost arises if a construction
requires the fresh-mode logical interface instead.

The table has 973 distinct promoted owners. Of the 1,152 occurrences,
493 have a later active data use and 179 have a later promoted use. Each
record gives its next active role and its complete later native,
bridge, and terminal event list. These are baseline paths. They do not
assert that a modified owner content is harmless at those later uses.

## A repair within the same complete calls

Each of the 37 bad mode positions has an ordinary width-nine role in the
same call whose owner is absent from the other core. `repair.py` constructs
and checks a matching to distinct such roles. It exchanges the two
complete job descriptors, including the physical owner and its route.
The resulting `REPAIRED-SKELETON.json.gz` has decompressed SHA-256
`fc9b441fbb8c41aaa9ed41df3cb4ec853008affededadf328dc0185bb4614e00`.
`REPAIR.json` gives all candidate sets, matchings, and exchanges.

Every width-nine role has canonical input frame I and output frame FULL.
The exact whole-job wrappers must remain those for the destination local
role. The source owner descriptor supplies the same physical pending
nine-axis job as before. This uses the already reviewed complete-helper
contract; it does not replace a partial internal program by its endpoint.

The complete job multiset in each call is unchanged. Therefore every old
strict owner window remains valid. Each call has the same 704 distinct
owners, and both active data sets are unchanged. All 16 promoted owners
in a pair are now distinct and avoid every role in the other core. The
1,369 owners shared between the two cores have ordinary helper roles on
both sides. Their complete native jobs use the same disjoint pending
slices as the accepted paired schedule. Their arbitrary contents can be
correlated; the complete helper contract preserves these contents.

Within this fixed-call owner class, at least 74 positions must change.
Each of the 37 bad owners must leave a mode position. All of them must
enter ordinary positions, since their owner also occurs in the other
core. At least 37 ordinary positions must supply replacement owners.
The 37 disjoint exchanges attain this count. This is not a minimum over
different call orders or owner stocks.

There is no added native child, private family, or productive family in
this repair. If all 144 centre-free FULL-MODE calls are used, their native
profile is the selected profile with 1,152 rank-eight centre children
removed. The resulting mass is 1,032,192. This is a conditional circuit
profile, not a Fourier supplier: the old productive owners now carry mode
drift. The paired physical graphs and their explicit entry/exit views also
need their full scalar and address costs.
