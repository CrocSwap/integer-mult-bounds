## The event order

Consecutive calls `(2j,2j+1)` have the same stage, orientation, and bank
pair. Their replicas are `r` and `r+8`. Use this order for each of the
72 pairs:

1. Prepare both fresh mode cohorts.
2. Run the paired input graph over the complete cover.
3. Run the first core's eight old-owner backfills, then its core sweep.
4. Run the second core's eight old-owner backfills, then its core sweep.
5. Run the paired output graph over the complete cover.
6. Complete both fresh mode cohorts.
7. Run the original first tail, then the original second tail.

Each prefix and suffix is a complete cover sweep. It is not an operation
on one cover class followed immediately by both cores at that class.
The complete sweeps are required because a helper route can read a
different cover class. The two core sweeps run in sequence and reuse the
same private work fields under the retained core workspace contract.
The literal full-mode cores contain no C references, so they preserve
those eight fields by non-use. The other private work fields remain
reserved.

The old schedule has 482 events. The accepted paired schedule contains
those same events once each, plus 144 endpoint markers. Its 626 positions
retain the exact event order within each replica. The new mode operations
use only fresh families and therefore add no release or deadline for an
old helper owner. The input and output markers already account for every
new scalar touch of the two active old data pairs.
