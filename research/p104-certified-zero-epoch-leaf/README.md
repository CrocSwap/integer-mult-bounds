# A certified zero loan in the powered BIT compiler

This is an exploratory compiler construction, **not a new κ bound**. In the pinned 268-factor, floor-15 BIT source, the first powered paid tuple is an actual rank-one block whose data is zero for every admitted input. A prototype retains the chronological `ISSUE`, generator state, private owners and normal cleanup, and skips the final leaf only when a typed first-loan certificate applies and the loan has neither been borrowed nor aliased. It is not installed in #8035's physical compiler.

A hand-built finite one-unit epoch using the authentic powered iterator and the pinned complete 36-call graph executes 285,600 elementary leaf actions before the change and 285,599 after. All output forms match for 5,772 independent input bits, and all private owners return. This exact finite control uses a symbolic two-point address permutation and a power-1/floor-29 diagnostic, not the deployed power-268 geometry. It exposes only the first paid block to the epoch, issuing all later blocks inside that single frame in their original order. It is deliberately not a production planner replay. An unsafe control with floor 8 makes the first helper a retained input: the certificate rejects it, and forcing the skip changes 109 output owners.

Separately, a nonconstant sparse physical control executes the real pinned projector and 36-call source at power 1 and floor 15, verifies 13,824 zero blocks, skips them, checks the first result against an independent coordinate-exchange oracle, and recovers the original inputs on the second invocation. These finite controls support the construction but do not enumerate or physically replay the astronomical 268-factor product.

## Exact source and residuals

The first paid label is `('move', 4, 2, 630)`: immediately before it, the graph initializes owner 630 at chart 0 and XORs into it the event-4 helper 222. Its productive target has rank 8 and its paid contact has rank 1. In a `v`-factor source the tuple consisting solely of that paid label recursively selects the original productive tuple consisting solely of helper `(4,222)`. At `v=268`, its rank is `8^268`, below `15^268`, so the actual `PoweredWord.native` constructs it with `physical.fresh`, a separate zero field. Every source-prefix operation and chart route on this dependency preserves zero; no earlier paid operation can have influenced it. The emitted tuple is one rank-one block, scaled by the current column count.

At a deepest unit in any nonempty finite installed band, the original `ISSUE` is followed by a `FINISH` with no child consumption. The unit has at least one column. The issued zero loan is therefore an elementary-leaf opportunity. The prototype skips only a certified unborrowed, unaliased loan at `FINISH`; it keeps the `ISSUE` and every generator/owner operation. Its extra frame/loan counters, alias and borrow tracking, metadata and ordinary control-machine work are not yet priced in the installed physical model. A production implementation must bind the actual source implementation, generate and validate the certificate, propagate it through real epochs, and charge all added control and routing. The code here is a prototype and does not itself certify an arbitrary machine or generator that happens to supply the same labels.

The complete public forward map is unchanged when the skipped loan is zero for every admitted input. Thus its linear transpose is unchanged as a mathematical operator; the original target projector is involutive, so a correctly installed forward service can be called twice for the inverse. Literal reversal of dirty private `CLEAR`s is a separate physical obligation and is not asserted.

## Family and price

The conservative dependency scan finds 13,824 of the 104,904 raw paid labels whose payload depends on exactly one rank-4 or rank-8 helper and has no earlier paid operation on any contributing field. Their paid ranks are 8,136 of rank 1, 5,616 of rank 2 and 72 of rank 4. Each of the `13,824^268` tuples drawn solely from these labels is sourced from an already omitted helper tuple of rank at most `8^268`. Each is one powered block because its rank is at most `4^268`, below the `12^268` cap. This is a sufficient family, not a claim of all possible zero jobs. The executable prototype implements the first tuple only.

At κ = 0.00389046, an integer-root directed bound gives the entire family's rank moment divided by the full productive moment below `10^-300`. Even granting deletion of the entire family, retaining all productive credit and ignoring all split penalties, the paid-minus-target raw moment remains greater than `10^-4` times the target moment. This does not fund the requested trial.

[#8034](https://github.com/CrocSwap/integer-mult-bounds/pull/8034) already covers suppression of paid tuples whose conservative Cartesian support misses retained productive tuples and proves a scoped raw moment ceiling for that model. The family here is inside that scope. The bounded epoch mechanism, owner and timing controls are presented as an implementation experiment, not as a route around that result.

## Boundary of clean helpers

The same physical powered source also has retained helper inputs: for 267 other factor targets of rank 127, `4·127^267 > 15^268`, so every first-factor target port is retained. On the constant-field subclass, explicit complete-caller replays show the chart-510 one-export edits fail on retained helper 266 or 254. A paired version has two independent kernel witnesses. For the #8041 chart-531 relay, even when all its first-call helpers are zero, a retained root input makes the residual nonzero and breaks the complete caller. These witnesses concern the source's arbitrary-field interface; reachability from a particular pair of top-level integer operands is not established here.

An opposite slice already has fresh-zero helpers: 186 rank-eight and 81 rank-64 suffix targets give `8·2^1044 < 15^268 ≤ 15·2^1044`. On that slice, a constant-field symbolic replay verifies both chart-510 readouts together for 3,774 retained root bits. It does not prove a powered paid saving: the original tensor code synchronizes all suffixes at each paid label.

## Cold replay

With Python 3.12 and the standard library:

```sh
python3.12 -I -B verify.py
```

The isolated replay authenticates the #8027 graph, the paired caller, the #8030 predecessor archive retained by #8035, and the #8041 price reader; it stages everything in a temporary directory. It runs the source-domain examples, local clean slice, single-source dependency census, toy powered scheduler, v=1 nonconstant physical control, bounded epoch and unsafe control, and directed arithmetic. The verifier does not mutate the package, submit a contribution or install the compiler.
