# Engineering decisions and limits

## Predicate and measured attempts

Workload is both frozen providers, forward and inverse-transpose, from the
zero-frame prelude to the first centre phase. The acceptance predicate is
complete scalar-microstate coverage within seven fractional bits and P+20
common signed bits, without changing the exact macro endpoints. Three
attempts measured scratch, source-walk and target-walk independently. All
pass at 84 bits for P=64; the two walks reduce the covered real instruction
slots from 64,782 to 57,710. Exact rational arithmetic has no numerical noise.
The unit ADD is the easy fixture; 7/8 tests a three-shift recipe. No mixed
policy was needed. No capacity condition was relaxed.

The pre-submission refresh found concurrent PR3090, whose construction claim
supersedes this work's original construction scope. The contribution was
narrowed to a source-bound independent corroboration. Its added coverage is
an integer engine that independently propagates original macro/warp rows,
rather than sharing the per-macro inputs with the Fraction engine. All twelve
literal recipe, census and capacity comparisons agree; no defect was found.
Only PR3090's frozen receipt is read, not its executable implementation.

Build the Lever changed the deliverable from a range estimate into a retained
literal JSONL generator and two rerunnable prefix interpreters. Prove It
Works required fresh native emission, reference receipt equality, reading the
actual serialized instructions and rejection controls. Power of Ten required
bounded streams, checked divisions, explicit cleanup paths and the deviations
below. These are internal checks; no independent human review is claimed.

The first new integer replay rejected a literal inverse negation because it
incorrectly required a positive raw denominator. An inverse SCALE can be
serialized as 1/-1. The boundary now permits a nonzero signed divisor and
still requires zero division remainder. A regression checks this case. No
source byte or mathematical endpoint condition changed. Ruff found two
reassigned loop variables; they were renamed without changing arithmetic.

## Power of Ten assessment

1. New call paths are acyclic and structured. Explicit --work retains only
   the requested external diagnostics; default TemporaryDirectory cleanup
   runs on success and exceptions. Files use context managers. The inherited
   compiler children have 90-second deadlines; registered commands have
   240/60-second limits. No concurrent writer regenerates an artifact.
2. Two providers, two orientations, three fixed policies, at most 30,000
   events, 9,992 covered macros and 40,000 unit instructions per real stream.
   A recipe has at most 32 instructions. The literal reader caps each line at
   16,384 bytes and rejects trailing data. State has 632 ordinary rows, each
   with at most 4,096 formal atoms, warp words of length at most 256 and
   Fraction numerators of at most 256 bits. The scalar ledger has fewer than
   53,000 observations, below its enforced 100,000 cap. Frozen inventory is
   exactly 25 regular files of at most eight million bytes each. Inputs are
   fixed authenticated scientific sources, not an arbitrary streaming API.
3. Python/Fraction/JSON and subprocess libraries allocate dynamically. This
   is a managed-runtime deviation. The finite capacities above, serial
   replay, streaming JSONL/digests and one three-row macro workspace bound
   live work. Runtime allocator internals are not instrumented. If variable
   input/service modes are added, replace these fixed-source assumptions
   with explicit input admission and measured memory limits before reuse.
4. Every new function is at most 60 physical lines after formatting. Each
   owns one transformation, replay pass or verification responsibility.
5. Executable require checks enforce frame chronology, source/scratch return,
   exact integer division, full literal consumption, source hashes/blob
   identities, deterministic evidence and strict signed capacity. They stay
   enabled under -O. No Python assert is used as a new acceptance condition.
6. State is local to one stream or macro; source manifests and policies are
   immutable inputs. Scratch ownership is explicit. No shared registry or
   concurrent mutable output is introduced.
7. Literal writes, generator process statuses and timeouts, arithmetic
   remainders, source digests and expected receipts are checked. CLI rejects
   internal/existing output paths. Failure controls exercise incorrect
   source return, scratch return, division, serialization and capacity.
8. New code has no eval, executable code generation or reflective dispatch.
   JSONL instructions are bounded data with a fixed interpreted alphabet.
   Reused scientific emitters are frozen, authenticated and not rewritten.
9. Calls and data access are direct. The fixed unittest method set and
   standard-library context-manager dispatch are Python framework deviations
   with bounded targets/lifetimes. Local test mutation callbacks have a fixed
   target set. No pointer ownership or arbitrary callback interface exists.
10. New Python passes warnings-as-errors compilation, Ruff formatting and
    E4,E7,E9,F,I,B,UP,C4,SIM,RUF,PLE,PLW correctness diagnostics. Normal and
    optimized execution and Python 3.12/3.13 equality pass. The registered
    replay runs warnings-as-errors and optimized controls on each selected
    package build. No full-program static type proof is claimed. Optional
    annotation/docstring/style rules are not repository requirements.

Frozen dependencies retain their preexisting assertion-heavy generator and
local style contracts. Their runtime is authenticated and freshly checked,
not refactored to claim unrelated safety compliance. The existing exact
adapter/monomial assumptions remain material. A future source replacement
must refresh its pins and rerun the applicable scientific checks.

## Verification scope

The Fraction engine and new integer engine share only canonical encoding and
the requirement helper. Their row updates and recipe execution are separate.
The compiler, scalar recipe selector and native frame theorem are deliberately
reused; this package is not independent verification of those predecessors.

The common signed-capacity rejection at 83 bits rejects this sufficient
upper envelope, not every possible 83-bit implementation. Destructive CLEAR
is an explicitly counted arithmetic primitive, not a synthesized physical
or reversible cleanup. Clean stock, routing, adapter interiors, recursive
approximation, later consumer and complete invoice remain separate.

The generic runner isolates Python bytecode caches. Direct reproduction uses
a fresh external bytecode-prefix namespace as documented in README.md.
Source hash checks alone do not validate unrelated preexisting bytecode.
