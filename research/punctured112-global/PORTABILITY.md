# Serialization and execution scope

The clean reconstruction was executed with CPython 3.12.14 on Linux, using
only the Python standard library. Python 3.11 or later is the source-level
requirement. That receipt describes the original Pro execution. Local submission validation
is recorded separately in `LOCAL-VALIDATION.json`. The checks below address specific identified serialization
dependencies; they are not a claim of exhaustive platform testing.

## Text files

Manifest entries marked `lf-text` normalize only CRLF to LF. The inherited
runner materializes its plain-text working inputs with LF endings and runs
its retained scripts with UTF-8/LF output. The new scripts use that same
portable launcher.

The 112-port emitter normalizes LF/CRLF when binding the nominated plan. This
is necessary because that plan digest is embedded in the canonical global
template. No other character or JSON token is discarded by that binding.
The fixed owner-map gzip input is binary and is validated without text
normalization.

## Generated gzip files

The official Python gzip documentation records changes to the generated
gzip OS byte and default compression level:
https://docs.python.org/3/library/gzip.html#gzip.compress

The two new generated-gzip provenance fields embedded in the template are
explicitly named `parent_global_template_content_sha256` and
`canonical_word_content_sha256`. They hash the exact decompressed bytes,
which contain the canonical JSON instructions. Container headers and
compression levels do not change the mathematical object.

Raw file hashes remain in auxiliary receipts and are compared against the
files generated by that same run. The predecessor's expected template already
uses semantic event lists and plain JSON recipe hashes; it has no regenerated
raw-gzip binding embedded in the fixed expected template. Its immutable
binary input owner map remains bound byte-for-byte.

The final whole-owner template hash is likewise the SHA256 of its decompressed
canonical content. The serialization correction changes the template's
provenance metadata and therefore its identifier, but no instruction, frame,
owner, paid child, exact moment or kappa changes.

## Runtime requirements

Keep Python assertions enabled. The main runner refuses `-O`, older Python,
an existing output directory, or a changed/missing manifest input before
starting reconstruction. The output directory can be anywhere outside this
package and the command can be launched from any working directory.

No network or optimizer is needed for replay. Timing fields and raw compressed
file bytes can differ between environments, while the canonical mathematical
content, exact rates and final expected template remain the comparison targets.
