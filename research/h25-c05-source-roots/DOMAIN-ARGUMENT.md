# Source roots and the conditional prefix lemma

This is a complete implementation of two limited pure functions. It is not a complete C05 inventory, genuine preparation observer, compiler model or original V03 control family.

## Fixed-source root construction

`source_roots` receives exactly six `(role, filename)` keys and exact bytes. It verifies each role-specific whole-source size/SHA256, emits six path occurrences with required installation mode0444, and constructs the unchanged list-valued GCC argv for each role. The known original sources contain20 literal include sites (ten per role). Whole-source binding plus independent enumeration of all literal directives establishes this fixed-source site list; the function is not a general C/preprocessor parser. Site serialization is deterministic C/loader/service order, not preprocessing event order. Identical payloads still retain distinct role/path occurrences.

The returned `mode` is supplied binding data, not evidence of actual interpreter flags. Mode292 is the required installation permission, not an observation of local snapshot permissions. `CONFIGURATION`, `SOURCE_REVIEW` and `EXECUTION` remainNone selection markers; they are not an execution guard for these intentionally callable pure functions and do not activate any original gate. Returned records are data, not capabilities or an admission certificate.

## Conditional ordinary-header prefix

Let the supplied finite ordered effective chain be d1,...,dn, and name be the supported ordinary relative header name. Each candidate pair is `(di/name.gch, di/name)`. Under the stated no-PCH subcase, the constructor requires each reached .gch candidate to be MISSING, and records the preceding ordinary misses until the first REGULAR ordinary header. It returns that ordered prefix and its winner.

Induction on the supplied chain proves the abstract first-match statement: every completed earlier pair has been recorded missing; the first regular ordinary candidate determines the returned result. Missing observations or unsupported outcomes leave the component open. Validation of all supplied facts and all chain paths precedes selection, including unused suffix paths. A later unused *lookup record* is not required once an earlier ordinary winner is reached.

Agreement with the actual compiler is conditional on independently established effective-chain semantics, authentic/stable namespace facts, compatible cache state, and inactive remapping/custom header construction. The function establishes none of those premises. It conservatively rejects present PCHs, aliases, unsupported objects and read errors; those are open subcases, not proof that every legal original C05 configuration must be rejected. Root search directories, absolute includes and other unsupported forms remain outside this partial function's local domain. These local bounds do not redefine the original C05 domain or increase its caps.

The [GCC13.4 PCH manual](https://gcc.gnu.org/onlinedocs/gcc-13.4.0/gcc/Precompiled-Headers.html) describes .gch consideration before ordinary headers and eligibility conditions. This is a mechanism reference, not proof of correspondence to the pinned Ubuntu compiler. The [preprocessor-options manual](https://gcc.gnu.org/onlinedocs/gcc-13.4.0/gcc/Preprocessor-Options.html) also explains why -M/-MM reports are not the unchanged original compilation: -M changes the processing mode, while -MM omits system headers. No such diagnostic was executed here.

## Why this is partial C05

C05 requires independent complete project/system-header/include-search/macro/compiler/specs/linker/library witnesses. A fixed point F0=R(D,Gamma), F[n+1]=F[n] union E(F[n]) is complete only after root completeness, complete applicable edge expansion, authentic/current facts, termination with no unresolved edges, and actual projection/resource bounds are proved. The first-uncovered-input argument is conditional on those facts; an empty unresolved list cannot replace them.

An absence is not a zero-byte regular file. A witness JSON hash authenticates bytes, not assertions of absence or effective search order. The pure tests explicitly retain a stale-facts counterexample: identical supplied observations can return the same certificate despite a changed latent namespace. An actual observer and its ownership/currentness proof remain missing. No fake Root, owner, syscall failure or native observation is used.

The exact original helper body, SHA256aa0a315110e031e19291970c9611fe5e0f91465fa20eaec51e81186099563f78, is newly retained as inert input. The call-site audit observes no `env` or `cwd` keyword on its Popen call; that does not itself qualify the inherited caller context, module initialisation or runtime operation. Full C05 still needs the installed configured-rule edge, transitive original bytes, namespace authority evidence and selected parent limits. `OPEN-EDGES.json` preserves those obligations.

All original APIs, commands, source selections, source_files meaning and caps remain unchanged. Original first-error/cleanup obligations remain due for any future acquiring observer. No new trust premise, generic accounting API, universal interpreter theorem, runtime qualification, complete cost fit, performance or selected-frontier result follows.
