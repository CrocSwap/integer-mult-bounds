# Canonical receipt comparison

The scientific engine's Python histograms use integer rank keys, while JSON object keys are necessarily strings. Its original direct main function compares those two Python objects without serialisation, which cannot validate a stored receipt even when all mathematical fields agree. The registered command now uses replay.py. It authenticates the unchanged engine at Git blob d91cfcffe9963b9df42e3874f09b29627edd2565, executes run() with every original source and scientific check, and compares both results in their canonical JSON representation. It never executes the authoring --write path and never modifies RESULT.json.

No field is dropped or value rounded. Sorted object order and JSON's required string key representation are the only representational normalisation. Arrays remain ordered. Boolean versus integer and integer versus float values remain distinct in the encoded comparison. Six controls reject changed counts, changed flag type, numeric type substitution, changed order, missing fields and extra fields, in normal and optimised runs. The source-bound numerical receipt remains unchanged. Use the registered command or replay.py for stored-receipt verification; the unchanged original --self-test command remains valid. This is an explicit comparison adapter, not an adjustment to mathematical acceptance.
