# Global minimum of a fixed chronological batching library

A scoped proof, produced by Nick Petalas.

For a fixed descending batch system, the recursively least LCM construction
has a stronger property than local minimality: its width at every rank divides
the width of every feasible competing library. Jointly enlarging earlier
libraries cannot reduce a later width. This settles the joint-library part of
Open next question 1 in Mihir Srivastava's
[PR #4507](https://github.com/CrocSwap/integer-mult-bounds/pull/4507), within
its fixed batching policy. It does not optimize different policies or schedules.
No new kappa is claimed.

## Statement

Fix base widths `b_0,...,b_(m-1) > 0`. For every `n >= m`, fix a positive
integer source count `S_n` and a finite list `C_n` of batches `(e,q)` with
`0 <= e < n` and positive integer `q`. The lists are fixed independently of
the chosen widths. Repeated cuts stay separate; an empty list is allowed.

A feasible library has the prescribed base widths and, at every nonbase rank,

```text
B_n = S_n A_n,       A_n is a positive integer,
B_e divides A_n q    for each (e,q) in C_n.
```

The last condition is the whole-invocation contract of #4507. It is a
conditional compiler model, not a new claim about physical realization.
Define

```text
M_n(B) = lcm over (e,q) in C_n of B_e/gcd(B_e,q),
b_n = S_n M_n(b),    with lcm(empty)=1.
```

**Theorem.** For any finite terminal rank, the recursively defined `b` is
feasible and `b_n | B_n` at every rank of every feasible library `B` with the
same base widths. In particular, it simultaneously minimizes all widths in
ordinary numerical order. It is the unique componentwise least library.
The conclusion holds at every rank of an infinite descending system as well,
by applying the finite assertion to each initial segment.

**Proof.** The elementary identity

```text
d divides a q  iff  d/gcd(d,q) divides a
```

shows that a library is feasible at rank `n` exactly when `M_n(B) | A_n`.
This is #4507's local lemma. It proves feasibility of `b` by induction.

The new induction compares `b` with an arbitrary feasible library, allowing
all its earlier widths to differ. For positive integers `d | D`,

```text
d/gcd(d,q) divides D/gcd(D,q).
```

For each prime `p`, the valuations of these two quotients are
`max(v_p(d)-v_p(q),0)` and `max(v_p(D)-v_p(q),0)`. The first is at most the
second. Thus `b_e | B_e` for earlier ranks implies `M_n(b) | M_n(B)`.
Feasibility gives `M_n(B) | A_n`, so
`b_n = S_n M_n(b) | S_n A_n = B_n`. The bases agree, completing the induction.
All widths are positive, so divisibility implies the claimed numerical order
and uniqueness. This uses elementary integer divisibility; no literature
priority is claimed for the underlying identity.

## Exact feasible-library description and normalization

Every feasible library has a unique positive integer slack at each nonbase rank:

```text
B_n = S_n M_n(B) t_n,       t_n >= 1.
```

Conversely, independently choosing any positive integer sequence `t_n` and
using this recurrence produces a feasible library. Necessity and uniqueness
follow by integer division using the local lemma; sufficiency follows directly
from the displayed batch divisibilities. Thus there is no hidden joint search
within this policy: all feasible alternatives are obtained by these slacks,
and the all-one slack vector is a simultaneous minimum.

One can normalize any feasible library in increasing rank order by replacing
`B_n` with `b_n` while retaining every later width. Earlier ranks already equal
`b`; the new rank is feasible by definition. Every later constraint remains
valid because its newly substituted child width divides its previous value.
The later source counts and replication factors stay fixed. This gives a
feasible sequence of local replacements ending at the least library.

The converse to the theorem alone is false: arbitrary coordinate multiples of
`b` need not be feasible. With base `1`, source counts `2,1`, an empty first
batch list and second list `[(1,1)]`, the least library is `(1,2,2)`.
The coordinate multiples `(1,6,2)` fail because `6` does not divide `2`.
The slack recurrence, rather than unrestricted coordinate multiplication,
is the exact description.

## First fixture and executed evidence

The three-rank fixture uses base `2`, source counts `3,5,2`, and batch lists
`[(0,1)]`, `[(0,2),(1,4)]`, `[(1,3),(2,5)]`. It gives
`b=(2,6,15,12)`. Slacks `(2,3,2)` instead give `(2,12,45,144)`.
Both are feasible and the least widths divide the enlarged ones coordinatewise.
The least sequence decreases at its last rank; monotonicity in rank is not
needed.

`library.py` and `verify.py` are new implementations. They import no predecessor
programs and do not recount any predecessor width or flow. `RESULT.json` is
generated by the verifier and binds its exact implementation, statement and
metadata hashes. The finite checks enumerate candidate libraries directly,
independently of the slack constructor, then check divisibility, slack recovery
and feasibility after every normalization step. Larger deterministic systems
cover empty batch lists, repeated child ranks and nonunit bases. Semantic
controls distinguish source multiples, separate cuts, gcd savings and LCM from
product. Invalid inputs and the largest allowed rank/scalar boundary are tested.
The receipt reports the exact enumerated counts. These checks corroborate the
written all-size proof; they are not its substitute.

## Scope, limits and provenance

The explicit scope change from `independent-moment` is a compiler-width side
result answering #4507, rather than a new paid moment or an audit. The current
source-binding orientation command passed. The card's historical
`scripts/research_baseline.py` first step was also attempted and failed with
`KeyError: 'bit_lower'` on the current selected schema; it is not a claimed pass.
Neither command replays a scientific predecessor result.

The theorem assumes fixed source counts and batch lists, fixed bases, rank
descent, whole invocations and one common replication factor per rank.
It compares libraries built with that contract. Arbitrary alternative suppliers,
changed batch lists, per-class replication and cross-cut pooling are different
models. It gives no tighter asymptotic growth order, native admission, physical
routing or storage bill, new normalized leaf cost, full multiplication theorem
or selected-frontier change. Independent human and formal proof-kernel review
are unclaimed.

Executable limits are 32 total ranks, 32 batches per rank, and positive source,
base, batch and slack values at most 65,535. Every constructed width divides the
product of all bases and all source/slack factors in its initial segment, so
its bit length is bounded by 16 times the number of factors. Python's managed
integer/collection allocation is a documented Power of Ten deviation; these
limits bound live storage and all loops. The constructor enforces its slack
limit; the literal feasibility predicate and slack recovery also accept wider
feasible libraries below their separate 1,536-bit width cap. Recompiling a
recovered slack above 65,535 is intentionally rejected. The executable
round-trip claim therefore covers the constructor domain only; a boundary
control demonstrates the distinction. There is no recursion or dynamic code
execution. Functions stay below 60 lines. Explicit exceptions preserve checks
under optimization. Warning-strict normal and optimized replay are registered;
no additional static analyzer or proof assistant is claimed.

## Open next questions

Can independent replication of different path classes beat the common-factor
minimum without changing chronology or productive-input accounting? This is a
changed model and could escape the present obstruction. Start with one actual
flow containing two path classes with coprime local moduli; state how native
calls match and how completed arrays rejoin before computing a width. The
missing per-class matching and return contract blocks applying that relaxation
to the existing compiler. No new construction round is justified by this
integer result alone.
