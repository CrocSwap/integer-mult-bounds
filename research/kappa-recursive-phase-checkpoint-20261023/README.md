  an explicit 128-owner dyadic adapter satisfies A^3 = I on arbitrary owners.
  Its emitted 2,356-operation scalar word has tariff 26,632 and no Gaussian
  oracle calls. It earns no productive Gaussian credit by itself, and its
  proposed shared-owner tensor split fails. A separate dirty-helper word
  computes `(x,y,h) -> (x,y+Fx,Fh)` exactly using three oracle calls; after
  the independent helper reward its net bill is twice the replaced center
  bill. The three generic algebraic Lean theorems do not certify a supplier.
* [Recursive row-query interface](../kappa-round8-recursive-phase-20261023/README.md):
  a changed query producer and its actual split/merge bill are specified.
  Exact transported-projector countercontrols also reject the proposed
  scalar Temperley-Lieb closure. These are gates on particular constructions,
  not a universal impossibility theorem.
* [Complementary supplier audit](../kappa-round8-complement-audit-20261023/README.md):
  exact retained PR4703 inputs are checked by a separate free-group endpoint
  and cost evaluator. The quotient and restriction have different actual
  typed interfaces and helper profiles. A local paid-moment improvement
  does not supply a profitable full gauged controller.

## Verification and reproducibility

The two new Lean modules contain eight exported axiom reports: three owner
identities and five row/column query identities. Their fresh compilation
receipts and source/log bindings are retained. The reports use only
`propext`, `Classical.choice` and `Quot.sound`, with no `sorry`, custom axiom,
`native_decide` or kernel bypass. This count is separate from the earlier
round-seven evidence.

The retained source copies have exact commit/path/blob/SHA-256 origin
records. They are committed inputs to ordinary offline checks; unmerged
origin commits are not assumed to be ancestors of this publication.
Origin-object audits, native functional checks, finite cost calculations,
Lean source/log receipt checks, and actual Lean compilations are distinct
operations. Each subpackage records its own coverage and commands.

From the repository root:

```sh

python3 scripts/research_package.py --package research/kappa-recursive-phase-checkpoint-20261023 --check-only
python3.12 scripts/research_package.py --package research/kappa-recursive-phase-checkpoint-20261023
```

The direct aggregate command and metadata/pin check passed locally with the
requested global Python 3.14. The generic launcher's exact Python 3.12
version requirement was retained; that launcher was not executed here with
Python 3.12. The complete 127-file publication byte check passed. The
optional source-history preflight requires a full Git history and could
not pass in this shallow repository; offline mathematical replay uses the
retained exact source exports instead of unmerged origin objects.

The registered replay uses only the Python standard library and the retained
source exports. It validates the frozen inventory and invokes the declared
small checks. The complementary-supplier checker reruns its independent
scalar/frame audit and authenticates the completed 335.65-second Clifford
replay's source, logs and receipt. It does not regenerate those full
Clifford artifacts; the subpackage's optional `replay.py` does that.
The registered replay does not install or compile Lean, launch an optimizer,
or rerun every historical suite. Fresh Lean commands require the recorded
Lean 4.21.0 / mathlib setup and are documented separately. No compiler binary,
compiled Lean object, solver cache or virtual environment is published.

These are scoped algebraic proofs and finite native checks. They do not
formalize the all-size physical implementation, native phase evaluator,
complete multiplication compiler, or outer transfer. No practical speedup,
independent human review, hosted proof replay, or higher kappa is claimed.
