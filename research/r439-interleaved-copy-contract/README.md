## Why the implication holds

PR1627 section 3 uses decoded rows `c_i = f_i composed with Gamma_i`.
Owner alignment `g sigma=d` makes equal-frame ADDs operate at the common
address, even when two targets have different physical data charts.
COPY establishes

```
f_temp = f_source composed with Gamma_source composed with Gamma_temp^-1.
```

Every interior operation writes only a distinct target owner. Both sides of
this equation remain unchanged, so the actual ERASE guard holds. The ordered
target action is exactly the source's undo/tap action. The full local replay
establishes the same arbitrary-dirty endpoint and boundary frames as PR589.
PR1627 section 4 then applies unchanged: reduce complete calls to their
endpoints before moving disjoint hosted residuals to their idle deadlines.

The checker constructs the adapted template in memory and verifies that only
`local_programs`, `source_record_sha256`, and each call's `local_hash` change.
It records a canonical adapted-template hash; it does not edit or promote the
selected template. The old local hashes are explicitly rejected when attached
to the new program. Frozen predecessor sources remain unchanged.
