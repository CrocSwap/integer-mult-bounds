# Uniform R437 complete-prefix leaf/consumer fusion

This package proves a source-bound schedule change for the actual leaf and XOR
consumer: execute a complete leaf on one complete prefix, consume its returned
fibre immediately, erase local copies, then advance. The original primitive
order within each prefix is preserved. The proof applies to every finite
complete prefix directory, including the full high cube when that directory
and matching packets are supplied. It does not infer uniformity from samples.

The new opt-in adapter removes the intermediate whole-child returned packet
from this interface. It does not replace the original callback, numeric
primitive or consumer. The complete borrowed directory, source and dirty target,
final output, local copies, trace setup, and every visited backing cell remain
paid. This is a functional composition and lifetime result, not a physical-space
or runtime improvement, supplier admission, or a new bound.

## Source contract and increment

`PROOF.md` derives the direct-product structure from authenticated
`packet_engine.run_generator`: copy one fibre, apply the primitive using only
that prefix and restored borrowed Program, append the local result. Distinct
prefix effects commute; effects within one prefix retain their original order.
The original `episode.xor_packet` is pointwise on the same fibres, so its
consumption may follow each completed local leaf. `adapter.py` checks the encoded
prefix product C*H, complete packet and directory consumption, and separate
borrowed roles. Canonical producer contents are a hypothesis, not inferred from
equal counts. A trace factory must return the same closed finite trace, and an
optional observation callback must be read-only.

The positive theorem assumes successful valid primitive/callback contracts.
Owned parsing/copy counters have explicit cleanup, and borrowed heads rewind.
It does not claim to repair arbitrary inherited inner callback exceptions.

#4793 (8ef4afcfba50c7f118d4787e34dda437192458ea) already established the two
nonzero-high physical fibres and their independent permutation oracle. This
package reuses that corroboration to compare a new prefix-major schedule with
the original primitive-major schedule and actual SOURCE87 consumer. #4176 by
Chris R / Clear1nsight supplied the produced-child physical bridge; #4759's
metadata-only dispatch is not a physical ancestry proof here. #4854 by Nick
Petalas covers local shared-radix quotient traversal, and Discussion #4927 audits
directory/reserve serialization; neither is claimed again or used to assume
free directory storage.

## Actual differential certificate

Both schedules execute actual R437 D request 1676, a source-valid borrowed
2048→64 Program and actual 64→2 child construction, modulo 9 at q=3,w=2. The
two distinct canonical high prefixes give weights [8,2] and [5,8]. Each schedule
executes 24 real coefficient callbacks and 13,122 dirty payload bits. All output
bits match the independent permutation oracle and each other. Global callback
order changes; each prefix's callback chronology agrees exactly. The actual
SOURCE87 XOR event [1,467,87,1,509,0] occurs at source position 22398. The fused
consumer observes two 6,561-bit returns instead of a single 13,122-bit return.
The consumer SHA256 is
`0f8e16924fd79d5c002ecafd4b77ac929a97f186b71c9fcf64992c6490a126f2`.

This q3 fixture is not numerically admitted by the selected root domain. It
executes two represented complete fibres, not all 3^4096 high matrices, GL64
gather, production parent spectators, or an original admitted root. The uniform
claim rests on the source contract and proof above. No full Machine.node or
supplier claim is made.

Checks include omitted-prefix product rejection before payload, role alias
rejection, truncated raw-prefix cleanup, actual bad high digit and rank
rejections, wrong returned bit changing the real consumer, and independent
stale/inverse-weight controls. Borrowed bytes/heads, unrelated numerical state,
and erased owned record backing are checked. Runtime numerical decoding is
disabled; host oracles only observe results and never drive the algorithm.
