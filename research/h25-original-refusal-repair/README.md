# Preserve startup evidence in H25 optimized-refusal handling

The original optimized scientific invocation creates its output directory and initial native-control directory before raising its intended assertion-enabled-entry refusal. The candidate runner incorrectly required the entire output directory to be absent, so it rejected that expected negative result.

This source successor permits those legitimate startup artifacts. It still requires the original exit-1 traceback and guard cause, empty stdout, no positive scientific receipt or STOP artifact, complete bounded capture, and the existing terminal wait, source-currentness, writer-retirement and retention checks. Nothing deletes or filters startup evidence. Normal successful-result logic is unchanged.

The command profile now describes separate exact normal and optimized runner commands and their full Root/provider/scientific/anchor arguments. This also corrects the previous profile's normal-source literal for the optimized case.

## Evidence and scope

An independent AI reviewer accepted the connected refusal/profile correction. The authenticated pure predicate passed **22 fixed controls in normal mode and 22 with optimization enabled**, including the legitimate startup case, wrong exits/errors, truncated or appended errors, positive artifacts/output, incomplete evidence, strict types, exact-cap input and the first extra byte.

These are evaluations of the actual runner's AST-extracted pure predicate. They do not execute the complete runner, native entry, compiler or scientific program. The startup-directory fixture records original source behavior as literal data; it is not an actual filesystem run. Genuine EOF, process retirement, original controls and full retention remain separate owning checks.

Complete-caller acceptance, native/environment compatibility, complete resource fit, actual baseline/candidate equality and performance qualification remain open. This package claims no speedup or multiplication-bound improvement.

## Files and reproduction

- `snapshots/` contains byte-exact inert source and profile snapshots. Python/C/header source uses a `.txt` suffix to prevent accidental full execution.
- `SNAPSHOTS.json` maps retained original source paths to committed files, byte lengths and SHA-256 values.
- `diffs/` gives the semantic runner/profile changes after normalizing only the prospective workspace path.
- `REFUSAL-FIXTURES-v1.json` contains the fixed independent expected cases.
- `evidence/` retains the actual raw control reports and their qualification boundary.
- `check_refusal_controls.py` is a package-local adapter of the reviewed control runner. Only its three source/fixture location bindings differ.
- `verify_integrity.py` checks committed package membership and bytes only; it does not import the snapshots or validate their mathematics.

From the repository root, the intended pure checks are:

```sh
python3.12 -I -S -B research/h25-original-refusal-repair/verify_integrity.py
python3.12 -I -S -B research/h25-original-refusal-repair/check_refusal_controls.py --mode normal
python3.12 -I -S -B -O research/h25-original-refusal-repair/check_refusal_controls.py --mode optimized
```

The original admitted controls used a clean interpreter, serial normal then optimized execution, 2-second wall and 1-second CPU limits per process, 128 MiB address space and 64 KiB per raw capture. They require only the standard library. Export-adapter execution and its exact result are recorded separately in `evidence/RESULT.json`.

This is an inert source handoff with a narrow pure-control command, not a registered complete-science replay package. No generic replay hook is added to execute the unqualified caller.

## External inputs and availability limits

The source snapshots preserve their prospective absolute runtime paths and all original source/profile pins. They are not an installer, supplied grant, current kernel profile or runtime capability.

The 390 full scientific payload occurrences are intentionally external. `EXTERNAL-INPUTS.json` lists every omitted path, original hash/mode and verified frozen byte length, together with the original public source archive and payload binding. A future complete replay must reconstruct and authenticate that payload, original transitive source/control inputs, current native associations and genuine admission/ownership inputs. This publication has not verified that complete cold reconstruction. The pure predicate checks need none of those external payloads.
