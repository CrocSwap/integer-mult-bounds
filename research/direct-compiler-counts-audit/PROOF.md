## Two expected models and the actual consumer

Let S_n be the full source count from the finite flow, including a source whose
complement child has rank0. Let h_n(e) include source multiplicities at child
rank e=n-s and exit multiplicities at child rank e=r; coincident ranks add.
For n<m, B_n=1, L_n=n and U_n=C_n=R_n=0. For the declared default policy,
a_n=B_(n-1) and B_n=a_n S_n. The complete integer recurrence is

    X_n = a_n x_n + sum_e h_n(e) (a_n/B_e) X_e,

where x_n is respectively0, flow.units, flow.column_mass, or
S_n + sum(flow.exits.values()) + (W+P) flow.units for L,U,C,R.
Whole child copies require every indicated quotient to be an integer. All
child ranks are strictly less than n. These equations describe this precise
compiler policy, not an optimal or universal compiler.

The primary model uses a separately written weighted ordered-support-word
flow calculation, then accumulates whole integer copies. The oracle uses a
separate factorial-multiset/signed-pair flow calculation and the normalized
Fraction recurrence

    X_n/B_n = (x_n + sum_e h_n(e) X_e/B_e) / S_n.

It multiplies the exact normalized result by B_n and requires integral
counts. Widths use cumulative products. These are distinct expected methods,
with explicit reuse of their respective historical PR6742 flow algorithms.
Both are source-aware. Common source/data/domain definitions and the
coordinating author preclude a fresh blind or end-to-end independence claim.
No current peer program or result is used before both expected firsts finish.

The source adapter executes actual `compile_counts` as a third program. It
does not use either expected engine. Complete canonical packet bytes are the
acceptance object; selected probes, bit lengths, scalar conservation and
Python dict equality are insufficient. First code/input seals and every actual
first attempt remain preserved, including any failures and corrections.

## Actual failure controls

The predetermined controls edit the actual compiler text, leaving its scalar
guards in place: omit local source routing slots; omit recursive child slots;
zero the instance and slot invoices; omit the whole-child divisor; use the
wrong source-complement rank; omit local column mass; and invoke the actual
forced-unit-replication option. Each textual anchor must occur exactly once.
The control runner first requires the complete healthy packet to match exact
reference bytes. It then reports actual source rejection or complete output
differences, including first changed ranks, full exact changed values and
whole mutant-case hashes. Outcomes are execution evidence, not assertions of
what an unrun mutant would do.

At raw rank121 the healthy slot count is127372. Dropping only local source
slots gives119684 while all inline guards still pass. Zeroing U and R gives
U=R=0 with unchanged B,L,C; the guards likewise pass. The missing child-slot
accumulation first differs at126 and remains guard-passing through606. These
are count-report faults, not valid physical programs with zero-cost instances.
They do not weaken or refute the source's stated construction. The structural
reason to test these faults is that the source's rank-one
identity constrains B,L,C, while its unit and slot predicates are upper bounds.
An undercount in U or R may therefore survive those guards. A passing scalar
predicate is not an exact invoice certificate. The complete comparison can
detect such finite undercounts without changing the original frozen checker.
