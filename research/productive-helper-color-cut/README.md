# A color-cut obstruction to a productive-helper encoder

**Scoped impossibility theorem; no improved bound.** A source-derived change of basis would let a native helper enter on `span(73)` instead of its original five-dimensional chart. The required scalar encoder passes ordinary forward and inverse support tests. Nevertheless, no ascending common-chart scalar circuit realizes this local boundary problem, even with arbitrary scalar preparation and interleaving.

The obstruction is exact: a 15-output hot-input block has rank **7**, while its intersections with four separate input groups span only **5** dimensions. A monotone circuit would force these spaces to span the entire block. This is a proof about arbitrary circuit length and rational coefficients, not a failed search over pivots.

## Source and boundary

The only live input is the integrated [combined 98-instruction compression certificate](../productive-helper-fusion-certificate/README.md). Remove `climb` records and take scalar interval `[9961,10111)`, using zero-based indices. Its 150 gates act on 24 independent fields: mains 13,16,43,44,51,78,99,104 and arbitrary dirty helpers 416--431. Let the exact rational transfer be `M`.

On output 417/419 apply `T=[[1/2,-1],[1/2,1]]`, then swap outputs 416/417 with `P`, defining `H=P T M`. The resulting output 416 is exactly `entry13+dirty_entry416`. Give it final chart `span(73)`; give 417 the old 416 exit chart and retain the other original local exits. All actual input charts are retained. No dirty input is assumed zero.

The eight hot input lines split into four groups:

| Input roles | Entry lines | Single-group output roles |
| --- | --- | --- |
|13,51|73,100|13,51 and protected 416|
|78,99|506,471|78,99|
|16,44|49,28|427,429|
|43,104|386,431|425,431|

The nine listed output charts contain hot lines from only their nominated group. The remaining 15 output roles are 16,43,44,104,417,418,419,420,421,422,423,424,426,428,430. The verifier rebuilds every chart and coefficient from the source.

## Why interleaving cannot repair it

Color a chart by the input groups whose hot entry lines it contains. Inclusion-monotone transports can only add colors. Every scalar ADD uses a common chart on both fields. Once a gate has multiple colors, no later single-color gate can share one of its physical fields. Those scalar matrices therefore commute, allowing an **algebraic** ordering with all zero/single-color gates first and all multi-color gates last. This does not assert that the reordered physical word has the same cost.

The nine single-color output fields never participate in the last part. On the other 15 fields the last part is an invertible matrix `R`. If `B` is the first part's hot-input block and `G` the required final block, then `G=R B`. Each row of `B` is supported within one input group. Consequently the rowspace of `G` must be generated by its intersections with the four group coordinate spaces.

Direct exact calculation gives `rank(G)=7` and intersection dimensions `1,1,2,1`. The contradiction is already visible in its kernel relation:

```
2 beta13 - beta43 - beta78 - beta99 + beta104 = 0.
```

A row supported on group 13/51 must therefore have `beta13=0`; rows supported on any other group also have that coordinate zero. But `G` has a nonzero 13 column. [PROOF.md](PROOF.md) states all hypotheses and the complete argument.

The obstruction also covers every invertible basis change within the complete
three-helper common-native-map class that preserves the desired output
`u=entry13+dirty_entry416`. After an invertible mixing of the other two rows,
the only remaining choices are `419 += lambda*u` and `421 += mu*u`. Their hot
block always has rank 7, while the single-group intersections span at most 6
dimensions for every rational `lambda,mu`. This is an exact symbolic family,
not a parameter grid. [PROOF-FAMILY.md](PROOF-FAMILY.md) gives the affine kernel
certificate and precise boundary assumptions.

The proof fixes the 24-register local boundary, pure invertible scalar ADD/SCALE operations, common canonical charts at contacts, and chart inclusion on every paid edge. The proof also survives adding independent zero-chart workspace that must be returned unchanged. It does not rule out paid nonascending steps, a changed productive output or boundary, a native-bearing region, or other productive-helper targets. No physical supplier, compiler admission, multiplication theorem or new kappa is claimed.

## Reproduction

From the repository root with Python 3.12 and its standard library:

```sh
python3 -I -B research/productive-helper-color-cut/verify.py
python3 -I -O -B research/productive-helper-color-cut/verify.py
```

The default replay is read-only. It authenticates the source bytes, reconstructs the scalar matrix and boundary charts, verifies the exact ranks and kernel relation, and runs positive and corruption controls. The original 150-gate source has hot rank 8 and group-intersection dimensions 2,2,2,2, so it is not falsely rejected. `SOURCES.json` records provenance and `VERIFY.json` registers the isolated replay. No solver, network, Git history or discovery receipt is needed for direct replay.

Independent agents reconstructed the source matrices, checked the normal-form proof and audited the packaged implementation. This is AI-assisted verification, not independent human or proof-kernel acceptance.
