## 1. Frozen construction and general weighted recursion

At level d, start with the inherited ordered groups of size one or two. The selected vectors are h23 `['first6',1,1]` and h25 `['first9',1,1,2]`. The `firstK` choice requests the first K original group indices, while 1 requests the first group and 2 requests the middle group. Requested indices are deduplicated, valid, and must contain two points. Before admitting the kth split require `number_of_groups + admitted_splits + 1 < number_of_points`. This is the cap `admitted_splits ≤ number_of_points − number_of_groups − 1`. Apply admitted splits in decreasing index order so earlier indices keep their meaning. Each split replaces one pair by its two ordered singletons; the point partition and order are unchanged. Omitted depths request no split.

The admission guard proves that the final number of groups is strictly less than the number of points, even for multiple requested splits and overlapping first/middle indices. Splits are disabled for n≤3; n=3 has two coarse groups and n≤2 uses the direct base case. Thus every recursive call strictly contracts, for every input size allowed by the grouping interface.

Coarse vertex weights contain the original vertex weights in that group and its internal edges. Each coarse edge contains exactly the Cartesian-product edges between its two groups. These sets partition the original weighted total. Recursive total and single/pair exclusions therefore have the required support by induction on size. Row and column coarse parenthesizations partition the same Cartesian product into disjoint sets, so changing between them preserves every identity. The original attributed PR74 coarse fragment uses `COARSE="hhh"`: at depths 0,1,2 choose columns when i+j<g−1, rows otherwise; at later depths use columns. Only fixed recursion depth and group indices enter this choice. ## 3. Exact retired and pending indexes

For frames `(core,cover)`, containment F⊆E means `core(E)⊆core(F)` and `cover(F)⊆cover(E)`. The retired index intersects active-role core bitmaps for each coordinate in core(E), and removes roles whose cover includes any coordinate outside cover(E). This selects exactly the eligible roles. Rank bitmaps partition that set; descending rank and ascending set-bit order exactly reproduce the original `(-rank,slot)` enumeration.

The pending index first enforces F⊆E using the same lower-frame index. It then removes target cores containing coordinates outside core(E) and intersects target-cover bitmaps for coordinates in cover(E). The result is precisely F⊆E⊆G. Each insertion receives a serial; removal deletes it; frame moves keep it. Sorting eligible roles by serial reproduces pending dictionary insertion order, including removal/reinsertion of reused slots.

Insertion, reclamation and incoming-use removal update both representations. Every frame raise updates a retired role's old/new rank/frame index, or a pending control's lower frame without changing serial order. Retired and pending lifecycles remain disjoint. Actual-source exhaustive and randomized audits compare ordered queries with the direct predicates and exercise actual frame-raise functions, not copies of those functions. These indexes preserve compiler semantics; no measured speedup is claimed.

## 4. Carry exchanges, two-cycles, and output routing

Candidate edges remain subject to inherited temporal/frame eligibility. A single exchange removes the selected owner of an occupied future use, or drops a carrier from the receiving region for an unoccupied future use. The full output/carrier basis of the receiving region is checked after the removal. A distinct donor region only loses a row, preserving independence. Thus cardinality, linear independence and unique future-use ownership remain valid. Each accepted exchange decreases a fixed integer score; at most three deterministic passes execute.

A two-cycle swaps carriers between distinct regions and distinct already-owned future uses. For new edge e and its complementary edge other, `carry_can(e,z)` checks the receiving region after removing z and `carry_can(other,f)` checks the other region after removing f. Because the regions differ, these tests describe exactly the final two bases. Remove both old edges before inserting either new edge; the two freed future uses are distinct, so unique ownership and global cardinality are preserved. Both regions lose and gain one carrier. The `(region,use)` lookup is checked for uniqueness. Accept only a strictly positive decrease of the sum of the two fixed integer scores; execute at most three passes. The source audit instruments every accepted exchange in 1,204 cases, including adverse linear dependence, equal-price, missing-complement and duplicate-key cases. This is a bounded legal heuristic, not an optimality proof.

Three-donor exchanges generalize the two-cycle argument to three distinct regions. Each region loses one selected vector and gains a candidate checked by `carry_can` against its full final output/carrier basis. The three distinct already-owned use IDs are cyclically reassigned, so their set and global cardinality stay fixed. All three old edges are removed before any new edge is inserted. Distinct-region and distinct-edge assertions prevent overlapping local replacements. Acceptance requires a strict decrease of the sum of fixed integer prices; deterministic candidate keys choose the best available cycle for that step. h23 uses zero passes; h25 uses at most three, with 60 accepted cycles in this frozen witness. The actual-source audit covers 1,604 cases, including a strict three-cycle with no legal single/two-cycle alternative, equal/worsening costs, dependent replacements and randomized independent bases. This establishes legality, not global cost optimality.

For h25, outgoing non-carrier uses are visited by descending fixed future-region deadline, with original use ID as tie-breaker. Terminal uses keep the explicit terminal deadline. This permutes a fixed list of uses; each is still assigned exactly once to a physical role. It may affect later reclamation choices, but changes no scalar target or candidate legality. h23 retains baseline output order. Both final physical words are independently regenerated and checked, including every charged allocation, XOR, raise and copy.
