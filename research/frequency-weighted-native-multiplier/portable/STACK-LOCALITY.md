# A smaller clock for the same fixed compiler

The ordinary WebAssembly instructions operate on the current activation, linear memory and fixed code. The interpreter in the preceding proof already parks its other stack heads beyond the current suffix. Pricing this placement removes the scan of every suspended activation from the coefficient for an ordinary instruction. The full high-water allowance remains in the cleanup term. ## Cost-free instructions within one function

In the pinned Cranelift translation a conditional or unconditional branch and every call cost fuel. The free forms are `nop`, `drop`, `block`, `loop`, `else`, `end`, `return` and `unreachable`. The last traps. Returning to a caller ends an interval within the current function. A new interval may start at any instruction after that return. All other free steps within a function move strictly forward.

Index the instructions in a single decoded body by their positions. For every `else` use the structured block stack to find its matching `end`. Compute a suffix table $R$ in decreasing position order. Give a paid instruction and the one-past-end position value zero. Give a return or trap value one. For a free fallthrough instruction use $1+R(i+1)$. For an `else` at position $i$ with matching end $j$ use $1+\max(R(j),R(j+1))$. This includes an accounting convention that counts the matching end separately. Every free successor lies in the listed forward set. Backward induction bounds every consecutive unpaid interval within that function. A function-ending `end` has value one by the zero sentinel.

The byte parser consumes every immediate before adding its opcode to that body's instruction sequence. It checks all 2,665,134 operators. The greatest $R$ is 274. An independent forward scan found the same value in function 9176. All 116,086 block, loop and if signatures have no parameters. Their single-byte types are empty (111,485), i32 (4,388), i64 (123), f64 (87) and f32 (3). The complete decoder rejects every other block-type encoding for this image. Thus a branch to a loop transfers zero parameters and all other branch targets have at most one result. There are at most $F$ paid instructions in an execution with $F$ fuel. The number of exits to other functions is at most $F+2$. Splitting at the paid instructions and exits leaves at most $2F+3$ unpaid intervals. Thus the whole execution has at most $(2F+4)275$ guest steps, including paid instructions and transfers. This bound admits arbitrary mixtures of nested calls and loop branches. ## Active and suspended spans

Keep the call frames, label records and operand values on separate stack tapes. Their heads remain at the top between instructions. Code, fixed metadata, globals, the indirect table and linear memory together require less than $2^{37}$ cells, as priced in the original bill. A frame contains at most 205 local and parameter slots in total, 284 labels and five fixed descriptors, each using at most 512 cells. An operator addresses locals in its own frame. A branch can read its target label by scanning the current function's part of the label tape. A call appends a new frame adjacent to the suspended one. It transfers at most 18 arguments and stores the absolute bytecode return and operand height. A return drops the current frame and exposes the immediately preceding frame at the stack head. Rewinding a bytecode or memory head on a call transition uses only the fixed code or bounded linear-memory tape. A table-indirect call uses the same frame operation after its index lookup.

A separate static estimate bounds the complete operand span of any current activation. In a validated function each reachable instruction has the height prescribed by its structured type derivation. Labels restore their entry height and their declared continuation arguments. A loop back-edge cannot accumulate additional live values. In a forward type check, each parsed instruction increases the abstract height by at most 19: the maximal function parameter arity is 18 and every result arity is at most one. Reopening an else arm or ending a scope first returns to the known enclosing height. The parser checks all block signatures have no incoming parameters. The stack floor at an unreachable point is its enclosing label height. Starting with at most 18 entries, even $19\cdot106184+18$ value records occupy less than $2^{30}$ cells.

Integer and floating arithmetic read a bounded suffix of the operand stack. Keep its current logical height in a small binary counter. Save a height at every label and function entry. A branch or return that transfers a result copies that single top value to a short temporary. It can then walk down to the saved operand height, erasing intervening records before it restores the preserved result. Charge the bounded top-result movement within the ordinary per-instruction charge. Each additional erased operand record represents a true decrease in logical value count. A free block or loop preserves its parameters already on the stack. An end or return preserves at most its one existing result. No unpaid operator creates an additional live operand. Each paid instruction increases total operand count by at most one, across all open frames; parameters entering a function move to locals. The whole trace can therefore discard at most $F+2$ operand records in addition to the one local result handled at each transfer. This also pays a long discarded suffix reached from a single branch. At 512 cells per record allow $2^{14}$ transitions per cell for reverse movement, clearing, height decrements, tests and returning the short result. This gives a separate global charge $E=(F+2)512\,2^{14}$.

With this extra operand charge, a single non-host instruction can access at most two adjacent frame spans, the current activation’s operand span, and the $2^{37}$ cells on the ordinary fixed and memory tapes. Four copies of the combined allowance, including the entire bounded operand span, fit below $A=2^{40}$ cells. The previously proved maximum of 256 passes with 4096 transitions per cell applies to this accessible range. An instruction does not scan the suspended frame stack or the virtual filesystem. File operations use their full separate $2^{92}$ price per host call. Initialization and final erasure still apply to the complete $L=2^{64}$ high-water allowance. Dynamic stack growth, large file writes, memory growth and final restoration thus enter the bill at their respective extents.
