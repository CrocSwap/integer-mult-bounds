# Tape clock of the fixed WebAssembly installation

This argument concerns the deterministic fixed installation defined by `run.py`, its public interpreter image, the pinned source and the directory receiver. It prices a sequential interpreter for that image. The Wasmtime execution checks the finite instruction budget. The JIT time is a separate measurement. The guest emits the scientific data after checking the source digests and deriving all the chart, coefficient, grade and recipe data. The initial image contains the ordinary CPython 3.12.0 interpreter for WASI. Installing and reading those 26,267,204 bytes, its 3.4 MiB zipped library, the compiler source, and clearing the transient state are part of the price.

## Sequential interpreter

Use separate binary work tapes for the bytecode, linear memory, table and globals, call frames with local and label records, operand stack, file catalogue, file bodies, and fixed argument scratch. The number of tapes is constant. Store the remaining code offset and type, local and operand base, frame flags and return location in five 512-bit records per activation. A local or argument needs one such record. One control record carries the block kind, code start/end/else offsets, operand restoration depth and result arity, with room for delimiters. A branch to a loop discards the intervening controls before executing that loop again. Thus at most the static maximum of 284 labels live in each frame. Function calls are charged. The occupied part of all frames has at most $(F+2)\cdot512(187+18+284+5)$ cells. The operand stack can gain at most one value per charged instruction. Branches preserve at most one result, or re-expose an existing value. The uncharged controls have no additional value result above the previous stack height. The operand stack needs at most $512(F+2)$ cells. The code, globals, data segments, function metadata, table, linear memory and fixed buffer descriptors occupy less than $2^{37}$ cells. The private file bound below is less than $2^{50}$ cells. Four full copies of this combined allowance fit in $L=2^{64}$ cells. This includes the current layout, a rewrite stream, output and restoration work. Data-dependent numerical multiplication uses its own tapes after installation.

The interpreter keeps the active head on the top of each stack between instructions. All stored offsets fit 64 bits. A full pass includes an arbitrary sequential seek, copy, or restoration of up to $L$ cells. Allow 4096 transitions per cell. A pass uses at most two 128-bit counters. A counter update, comparison to a bound, and reset of its head require at most eight transitions per bit for each of two traversals. Reading, copying or clearing the current symbol and moving the source and destination heads fit the remaining steps by using the 64-bit offsets, or by using separate passes for the two counters. The following limits are expressed in complete passes. They include backing up and clearing each traversed scratch area.

- Fetch the opcode and immediate from the code tape, or fetch a module descriptor from its directory. Up to 20 passes cover the code offset, function/type/global addresses, an indirect table index and the return to the initial heads. A branch-table immediate is one sequential list of LEB words. The same pass can count delimiters and stop at the requested entry. To find a structural end or else target, scan forward within the function, maintaining the current static depth. Ignore immediate bytes as in the checked opcode decoder. No branch requires a second search per scanned opcode.
- A scalar memory operation reads or writes at most eight aligned or unaligned bytes and performs bounds checks. A successful `memory.grow` initializes the entire new interval. Rewriting a complete linear memory and restoring the head takes at most 12 passes. Constants, selection, `local.get`, `local.set`, `local.tee`, `global.get`, and `global.set` require a bounded number of record scans on their named tapes.
- A call has at most 18 arguments. Even saving, moving, writing and restoring each through six complete sweeps costs at most 108 passes. An activation initializes its contiguous segment of at most 187 local slots in one pass. The return moves at most one value, scans back to the saved operand base and clears the discarded frame. A branch compares its depth with the marker stack in one pass, clears the selected suffix and restores the operand height. Up to 32 additional passes suffice for these frame, stack and branch transfers. Instructions with no operands also fit these allowances.
- Allow another 64 passes for copying output tags, saving offsets and scrubbing temporary buffers. The sum of these alternatives is below 256 passes per instruction. There is no table bulk-copy opcode, SIMD, concurrent memory, continuations, exceptions or garbage-collected reference instruction in the parsed image. The total non-arithmetic transition cost per interpreted instruction is at most $2^{20}L$.

For scalar arithmetic store exact binary integers on separate work tapes. Addition, shifts, schoolbook multiplication and a shift/subtract unsigned division of $h$ bits cost at most $2^{16}(h+4)^2$ transitions each including copying and returns. For binary32 and binary64 use explicit special cases for signed zero, NaN, infinity, overflow, integer conversion and trap conditions. Finite values are signed integers with at most 53 significant bits times powers of two with exponents between $-1074$ and $971$. Keep exact addends, products, ratios, and midpoint tests as integer numerators and positive denominators. All need less than 16,384 bits, even after squaring a midpoint for a square-root comparison. For example, scaling one finite binary64 number by $2^{1074}$ gives an integer of less than 2099 bits. A product of two such integers has less than 4198 bits, and one more product to cross-multiply an exact quotient or a squared midpoint is less than 8396 bits. Include the common powers of two in this bound or cancel them before multiplication. Binary search the ordered finite encodings of the required sign, allowing 64 steps. At the two adjacent encodings compare their exact midpoint and use the even endpoint on a tie. Handle overflow at the last endpoint and subnormals at the zero endpoint. For a positive square root compare the input with the square of each candidate and the square of their midpoint. Integer-conversion tests use exact numerator shifts and division. Reinterpretation, signed zeros, signs and canonical NaNs use the instruction's bit rule. $128\cdot64\cdot2^{16}(2^{14}+4)^2<2^{58}$ local transitions cover the comparisons, products, quotient, sign and scratch erasure for any instruction. The basic operations per candidate are at most 16. The larger allowance also covers the final rounding and exact special cases. This cost is additional to tape movement.

## Host calls, fixed receiver and cleanup

The run has fewer than $2^{16}$ host calls. Source files and all initially seeded names fit in $2^{16}$ entries. A directory creation checks the entire entry count against $2^{16}$. Between directory creations there can be fewer than $2^{16}$ successful new file creations since each needs a distinct host call. Seed files and every generated file are shorter than $2^{29}$ bytes. Thus a full file-body tape, record tags and the pathname catalogue together fit below $2^{50}$ cells. Keep descriptor metadata and names on a separate tape from file contents. Every pathname has at most 4095 bytes. Normalizing a path and looking it up can use 4096 passes over the metadata, with a component stack and sequential path comparisons. Directory enumeration can select names in sorted order with one metadata scan per candidate and a separate mark tape. Its name-only catalogue has fewer than $2^{17}$ rows with names and metadata of fewer than $2^{16}$ bits each, so even $2^{18}$ complete selection passes fit $2^{64}$ transitions. No data files are traversed within those name comparisons. Each scatter/gather vector actually has one segment. Even with $2^{16}$ segments, each can locate both offsets, rewrite or read the complete body, copy contiguous bytes, update the descriptor, return and erase in 32 sweeps of the file or memory tape. At 4096 transitions per cell this costs at most $2^{83}$ transitions. The byte generator uses one elementary 32-bit recurrence for each byte requested and writes sequentially. The source file flags, seeks, reads, writes, stats, clock, bounded argument/environment copying and closes lie within $2^{92}$ per host call. These costs are separate from the guest `call` itself. Repeated readback, deleting a virtual file and preserving a still-open output charge the actual length or the complete prefix traversed. [Implemented service](bounded_wasi.py)

The receiver can take the produced output tape directly. A record has a one-byte domain tag, a four-byte body length, and scalar bytes or four-byte backward child numbers. The 18 tags distinguish each named compiler data type. The last record is the root with all recipe handles. A streaming pass numbers records in order. To materialize the predecessor's indexed representation emit one named entry per scalar or outgoing reference and preserve each dictionary's insertion order. A compound key takes at most 28 bytes of expanded structural representation on the generated image, verified by induction on backward references. There are fewer than $2^{23}$ references in all. For sets and maps, the same ordered numerical, string and tuple comparison applies to each actual key. Reconstructing a structural key of this length takes at most 28 prior-record locates. Bounded-rational construction uses the generated canonical numerator and denominator, each with fewer than 4096 bits on this image. The full directory has fewer than $2^{26}$ bytes. Even allowing $2^{10}$ records of 4096 bits per reference, followed by $2^{10}$ complete record-store sweeps at 4096 transitions per cell per reference, uses fewer than $2^{90}$ transitions.
