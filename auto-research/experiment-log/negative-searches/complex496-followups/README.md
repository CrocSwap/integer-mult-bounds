The fractional model has the same floating objective and an integer primal at eight replicas. This is evidence of no rounding gain in this model, not an exact dual/global optimality certificate. Model: 1,604 variables, 126 equalities, fixed word, widths and windows, at most eight slots per copy.

- [Rational basis exchanges](complex496-basis-search/COMPLETE.json): 112 cases including baseline, one exchange within an existing kernel class followed by response-support reduction and maximal common-entrance promotion. One resulting paid-profile class; no improvement. All ledger outcomes retained. No search of arbitrary multi-class changes is claimed.
- Retiming: [existing frames](complex496-retiming-fixed/RESULT.json), [new extreme frames](complex496-retiming-extremes/RESULT.json), [connected groups](complex496-retiming-groups/RESULT.json), [centre-intermediate moves](complex496-retiming-centres-fixed/RESULT.json), and [centre-intermediate groups](complex496-retiming-centre-groups-fixed/RESULT.json) all accept zero moves. Counts overlap across searches and must not be summed as independent trials. The last two screens allow intermediate centre operations while keeping final centre frames fixed; their inherited RESULT scope string saying “centres frozen” is too broad and is corrected here.
- [Fallback arithmetic screen](complex496-count-screen/RESULT.json): transferring PR491's count-only formula from the bit fallback to m=73 gives count 128328 instead of 170528 and proposed kappa 0.001332077359905113. Two rational engines certify the arithmetic and reject the old count at the proposed new root. **This is not an admitted new bound:** the transfer to the actual complex fallback compiler has not been justified. The probability stays at 10^-16. No stronger GL-to-orthogonal probability transfer is used. Do not publish the arithmetic proposal as a verified result.

## Failures and reproducibility

The first retiming launch failed while treating a centre-scatter `None` marker as a frame; only A/B gate frames are valid candidates. Two initial centre searches failed on a centre that is already a source and has no A-gate touch; the fixed versions skip that absent endpoint constraint. Original tracebacks remain in their logs, alongside fresh corrected runs. They are execution errors, not mathematical failures.

Scripts use the original frontier390 directory layout and the source-pinned upstream code; they are retained discovery recipes, not a standalone verifier. The saved base word and selections make local candidate inputs explicit. Constructor/profile checks are not independent dirty-column, Gaussian-phase or physical-controller certificates. No full replay is claimed for any changed candidate. A separate fresh replay of the unchanged PR484 provider was running when this record was prepared; its result must be recorded separately.

Retry guidance: simple replica scaling, fixed-role promotions and these single-exchange/retiming neighborhoods found no gain. Change the complex local word, coordinate multiple gauge/donor changes, or justify a sharper complete fallback count before retrying. Any new packing must satisfy whole-family ownership and be priced with the complete moment; a better local score alone is insufficient.
