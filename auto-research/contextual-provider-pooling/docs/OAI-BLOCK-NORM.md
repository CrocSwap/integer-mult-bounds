# OpenAI block-operator transfer and scope

Read source: OAI/Topology/CoarseAssembly/BlockOperators.lean, SHA256 0cc11714ca746be1e1bba6925731221d8f81138d48445714a50f7676675a6d52. Theorems blockLinear_norm_le and blockOperator_norm_le prove that an orthogonal direct sum of operators each bounded byC is bounded byC, independently of the number of blocks. partitionCompression_norm_le in the adjacent PartitionCompression file proves a related partition-of-unity compression estimate; it does not supply free recursive work.

Sufficient transfer: fix a finite partition of live data families into copied original controllers. At each complete local-call boundary, suppose the exact normalized endpoint has its data shear entirely inside the active copy, and acts on every borrowed family separately by its exact unitary residual/spectator map; shared private work is zero. Then each boundary operator is block diagonal in the copy partition. Products remain block diagonal even when the scalar interior used another copy as temporary helper. If each copy has at mostK data shears andJ factor-two bridges, with all other boundary factors unitary, every complete boundary prefix has norm at most2^(K+J), not2^(q*(K+J)). This follows by submultiplicativity within each block and the cited block-sum norm bound. A partial active call is additionally bounded by the maximum actual local scalar-prefix envelope, with its own coefficient-work and input conversion charges. Boundary semantics must be proved first: zeroing dirty helper scalars alone is insufficient.

This can avoid a prefix penalty linear in the copy count. It is not presently counted as extra kappa; the candidate may retain the more conservative full-call charge when that already fits. The actual current construction must still pay total operations, storage, tables, routing and every child. Approximation or operator-norm closeness cannot replace the exact column/phase identity.

The block invariant is a reusable sufficient theorem, not a claim that the external source already proves this multiplication controller. No fresh Lean certification is claimed. We will not use the stronger bound in the final invoice without auditing its boundary partition conditions.
