Turyn code-space fitting search
==============================

This package tests exact code-coordinate transformations of the previously
constructed 23,040-port, real rank 512 Turyn kernel. No improved kappa or
complete scalar supplier is claimed.

The main result is now exact: every binary fitting representation constant
on the eight-port glue classes needs at least 27 dimensions, and the known
representation attains 27. A nine-clique parity certificate proves this
without a SAT solver. It closes the rank 25 search on these classes,
including arbitrary nonlinear labels and the entire quadratic family.

The concrete results are:

* Grouping the 8 orthogonal high lines with identical low roots gives 2,880
  glue classes. Their exact quotient graph is 1136-regular. Nine cliques of
  size 24 cover every used vertex an even number of times. The resulting
  rank 27 bound applies also to block fits, after normalizing by block size.
* Each profile has 13 independent affine glue features. Every symmetric
  fitting matrix generated by arbitrary linear maps on these features has
  rank 27: all cross-profile Gram blocks vanish, and each within-profile
  block has exactly two admissible matrices, both rank 9.
* Quadratic features expand each profile's dimension to 77. Exact affine
  elimination leaves 168 free parameters in each symmetric within-profile
  block and 46 in each cross block: 642 parameters in the full family.
  This search space is preserved for reproducibility; the parity bound
  proves none of its members can have fitting rank below 27.
* A 9 by 9 fully adjacent pair of quotient sets has old-label pairing rank 9.
  It rules out rank-8 corrections in the specified common-I9 plus
  hyperbolic ansatz, including nonlinear class-constant corrections.

Reproduce the complete package with Python >= 3.10, NumPy, and a C++17
compiler:

    python3 -I research/turyn-code-space/verify.py

Use --output DIRECTORY to retain model.npz, compressed solution bases,
and receipts. --geometry-only skips the quadratic-family calculation and
requires no compiler. The default replays all six quadratic blocks.
Both Python and C++ checks use explicit conditions; Python -O is supported.
No external SAT solver is needed for these included algebraic results.

The inherited leech-lattice package is read without changes. Its used
source files are SHA256-pinned in sources/SOURCES.json. Package artifacts
are hashed in MANIFEST.json. No large equation matrices are committed:
rows stream directly to the exact C++ eliminator. Its returned solution
bases are independently checked using Python integer bit parity; bases
are compressed only in the requested output directory.

Candidate interface
-------------------
An exact proposed labeling can be supplied as JSON:

    {"kind":"explicit_quotient_labels","labels":[...2880 binary rows...]}

Then run verify.py --candidate FILE. The default maximum dimension is 25;
--maximum-dimension changes this validation target. The checker tests
all odd diagonals and all 1,635,840 quotient edges. Passing establishes
binary compatibility only. It does not construct real centers, frame
moves, dirty-helper clearing, hosting, or an exponent certificate.

The earlier quadratic_radical format is retained as a diagnostic hook:
three 77 by 8 coefficient_maps, evaluated in the recorded quadratic bases.
The included biclique proves that this restricted format cannot succeed
with the fixed old profile maps. Its zero-map instance is a negative
control; it is not the entire 642-parameter search space.

To export a system for another exact solver, first retain a model.npz,
then use code/generate_constraints.py --model FILE --profiles I J.
It writes binary to stdout, or to --output FILE. See PROOF.txt for the
format, complete affine-family interpretation, and limitation of each
obstruction. See NOTICE and sources/SOURCES.json for attribution.
