# Root integration review

Result: no correctness defect found in the four reviewed integration files for the frozen two-provider construction. This is a source review and a separate execution of the actual variant loader/invoice recounter, not an independent reimplementation, Lean certificate, or replacement for the full physical-owner audit.

## Per-call supplier binding

`meta_registry.load` derives every ordered residual width from the actual canonical start frames, checks both program hashes against the local checks, binds the full-column replay and phase recipe receipts to their source artifacts, and requires a 72-entry supplier selection. Both variants have the same 112 ports, ambient dimension nine, 504 helpers, and center indices. Each has freshly replayed normalized target and arbitrary-dirty-helper endpoints.

`emit_supplier_meta.py` selects widths separately for each physical role's invocation time and checks the role provider equals the registry selection. It binds each complete call to the selected orientation-specific program hash, counts that provider's local children for that actual call, and separately counts actual owner remainders. The program registry and source bindings are serialized into the emitted global template. Thus the nominal reference provider is not silently substituted for retargeted calls. The independent owner/controller auditor is a separate reviewer responsibility.

## Finite work and prefix charging

`invoice_meta.py` was compared with the inherited PR531 invoice. The new extraction recounts each variant independently, then sums scalar primitive work by each actual call's supplier and orientation. It sums wrappers by the actual per-call entering-helper counts. It uses the maximum adapter allowance, primitive bound, and prefix bound across the registry; this is conservative for all calls. The old complete allowance is retained and the entire fresh finite charge is added. No numerical kappa gain is inferred from smaller scalar coefficients.

## Verifier construction path

`verify.py` first checks a manifest with LF-normalized text hashes, then creates an isolated normalized source copy. It reconstructs the selected scalar factory rather than accepting the discovered word as an oracle. It applies the exact observational rewrite, regenerates both canonical variants, freshly lowers phase deltas, decodes wrappers, emits programs, and runs independent local audits. Only after that does it construct the alternating per-invocation registry, bind actual owner rows to it, emit the full controller, run the physical audit with mutation controls, recount finite work, and check the final exact assembly against frozen expected values.

The first-provider-only width inventory in the invoice is descriptive metadata. For this deliverable both ordered width vectors are explicitly equal, and the actual invoice also records every provider inventory. Future variants with different widths must not interpret that summary field as a universal width signature; the physical emitter already uses the actual per-call vector.
