substituting a coefficient.

Two concrete accounting errors to avoid follow directly from these contracts:

- Adding the route and residual peaks to #2743's data peak counts their
  content again. #2743 takes the maximum over sequential phases and includes
  them already. Directory copies of an embedded key are still separate
  physical objects, even when their bytes agree.
- Using #2758's live bound plus four LEFTs as a backing-capacity bound misses
  blank retained cells. Its actual 64-dimensional depth-two fixture has live
  continuation peak 144 and retained extent 214. Neither metric prices cursor
  movements or supplies a fixed-tape placement theorem.

## Follow the all-size stock and ledger actually used

#2753 uses a common row divisor that preserves both the logical family split
and physical-role divisibility:

```text
W = 28416                         live families
P = 28425                         physical roles
N = |GL_64(F_q)|
H = q^(4096(w-1))
K = lcm(W,P) N H = 269241600 N H
D(n) = 0 for n<64, otherwise 1+D(42 floor(n/64))
root fresh rows = t K^D(n), t >= 1
```

Its child fresh-row factor is `U=t*9475*K^(D(n)-1)`, and its complete packet
volume is `V/(WN)`. The spectator factor `B` in that source is passed
separately from `U`; their product is not interchangeable with fresh stock.
Across the one active recursion chain, the logical packet volumes are
`V_j=V_root/(WN)^j`. This geometric sum, not a first-range constant copied
per ancestor, pays for suspended parent frames.

Before canonical-width/history absorption, the proof gives

```text
F_q + sum_active_j [8V_j + 32 Delta_j + E(V_j,h_j,L,I,Q)].
```

`Delta_j` is a complete associated directory. `E` explicitly includes both
numerical arenas and templates, programs, continuation and count tapes,
finite form/role records and markers. `F_q` is the one-time fixed-q compiled
source storage. The simplified `<11V_root+F_q` requires the proof's large-q,
minimal-width and root-coupled history premises. Arbitrarily padded words or
an unrelated supplied history must use the unabsorbed ledger instead.

The same proof supplies the sufficient row-capacity exponent
`k <= 8195 w log2(e)`. This is a capacity inequality, not an executable
outer wrapper that supplies compatible `tK^D(e)` rows and restores padding.
The earlier bootstrap map's conditional coefficient 6748 and its fit test
must not be treated as that missing implementation. #2753 uses a new explicit
compatible stock and its own sufficient estimate; this map claims no
optimality comparison between those coefficients.

## Open next questions

- **Compile and price physical frame reuse.** Start from the active parking
  codec claim, then account for numerical slots, continuations, templates,
  markers, cursor movements and blank return across a nested call. This
  matters because a logical live-content bound alone does not establish a
  fixed physical tape implementation. The codec is still pending, and a
  numerical-bank result alone would leave other tape categories to place.
- **Bind the stronger H2 time contract to reached primitives.** Audit the
  actual route and ordinary leaf paths in #2753. Its `O(wV)` implementation
  charge remains even with a completed recursive callback. A faster
  implementation must preserve complete-prefix order, dirty state and
  restoration; space headroom is not a proof of that time saving.
- **Supply compatible stock through the outer wrapper.** Start with
  `tK^D(e)` divisibility, the proposed below-two padding factor and complete
  metadata restoration. This connects the logical caller to the earlier
  bootstrap implications. A row-capacity inequality and an internal caller
  do not implement that borrowing/padding boundary.

These are source-bound follow-ups, not a decision to expand a construction
family or evidence of a stronger selected frontier. Check the live thread
and [family expansion gate](research-family-status.md) before taking one.
