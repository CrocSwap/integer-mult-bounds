All rows are processed in checkpoint order; the first observed metadata wins.
Immutable starting-snapshot and earlier family metadata take precedence. No
historical checkpoint can introduce a PR absent from the current intake source.
The current source supplies new arrivals and all current-state review decisions.
This is offline repository provenance validation, not a live GitHub-state check.

When changing intake metadata for a later head, first retain the original exact
source checkpoint and register its independently authenticated commit/blob/hash
in chronological order. Never repair a failing initial-head guard by copying
expected values from the ledger, accepting any previous_head value, or changing
an existing pin. Add a new source checkpoint and strict rejection tests instead.
This policy keeps provenance loss visible rather than accepting arbitrary drift.

The generator uses this same authenticated projection and records these source
hashes in future output. Its other accumulated intake-evidence differences still
require separate review: this repair does not make a full ledger regeneration
safe. The published ledger is not regenerated by this change.
